A.13 Compute, software, and artifacts Model size and compute. The only trained com- ponent is the blend head of §3.6: two linear heads over the five standardized features of §A.9, so θ = (a, bw, c, bT ) holds 12 parameters. It fits on CPU on one workstation VM; no GPU was used at any point, so we report no GPU hours. All infer- ence ran on hosted endpoints through an internal service that does not expose per-call cost, so we report no dollar figure. The embedder and the four evaluated models are proprietary, with undisclosed parameter counts. Inference spans four models and five algorithms over five folds in six environments at each swept budget (§4.6). Software and settings. We use NumPy, scikit- learn (GROUPKFOLD for the task-grouped folds), PyTorch for the blend head, tiktoken for token counts, and the provider’s Python client for hosted inference. Decoding uses temperature 1, other pa- rameters at provider defaults. The hyperparameters in §A.8 and §A.9 were hand-picked; we ran no search. Artifacts and licenses. τ 2-bench and τ 3- Knowledge are MIT licensed, BFCL v3 is Apache- 2.0, and API-Bank is MIT; text-embedding-3-small is used under its provider’s terms of service. All six environments are English-language. We use each to evaluate tool-using agents, the purpose each was released for. We release no artifacts here; the syn- thetic trajectories and broadened policy documents we build derive from τ-bench leaderboard submis- sions and MIT-licensed benchmark data, and any later release will carry a compatible license. Risks. TRACER narrows the tools an agent sees, so a retrieval failure can hide a needed tool; the con- fidence gate and out-of-trie fallback (§3.7) bound that, and Table 16 quantifies where it still fails. Built from observed trajectories, the trie inherits their biases and will under-serve rare but legitimate tool sequences. We see no societal risk beyond those already present in tool-using agents.
