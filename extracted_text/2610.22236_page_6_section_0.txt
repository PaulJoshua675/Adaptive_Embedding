The best value of each column is in bold. 3.5 Precision Released checkpoints are stored in bfloat16, which keeps eight significant bits. Reinforcement learning with small learning rates barely moves weights at that resolution, by about one representable step (Section 4.5). A fused update is no larger, and unlike a specialist’s it is not made of whole steps. We therefore store fused models in 32-bit floats, since rounding the fused update to bfloat16 measurably distorts it. A fused model is evaluated in float16, which keeps three more significant bits than bfloat16 and fits the memory of a single GPU where float32 does not. A format change by itself shifts measured accuracy, so we state the format behind every score. 4 Experiments 4.1 Setup Models. The main experiments use the Olmo 3 RL-Zero family [6]. The base is Olmo-3-1025-7B, and the teachers are the final checkpoints of Olmo-3.1-7B-RL-Zero-Math and Olmo-3.1-7B-RL-Zero-Code, each obtained by reinforcement learning from that base on a single domain. Rollouts and statistics. For mathematics the teacher answers 256 training problems from DAPO-Math-17k [3]; for code, 256 training problems from the DeepCoder training set [39], with the instruction used by EvalPlus. Each problem is answered once. Mathematics is sampled at temperature 0.7 and top-p 0.9 with a limit of 31,744 new tokens, code at temperature 1.0 and top-p 1.0 with a limit of 32,768, matching evaluation. No evaluation problem is used. Selection keeps the 175 mathematics answers that are correct, finished and loop-free, and the 92 code answers that pass every test of their problem. We use α = 0.9 and equal domain weights.
