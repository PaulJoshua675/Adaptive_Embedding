They also expose a remaining problem: a final answer score usually supervises an entire sequence of heterogeneous memory actions, even though only a few actions supplied the evidence—or caused the failure. Hy-Memory-30B-A3B focuses on this credit-assignment problem while preserving compatibility with existing memory frameworks. Our contributions are: • A framework-integrated memory writer. Hy3-30B-A3B replaces the LLM inside Mem0, MemOS, and Hy-Memory without moving their memory logic into a custom model architecture. • State-distribution-aligned training. OPD and RL both execute the policy inside the actual harness, and later writes observe banks produced by earlier policy outputs. • Failure-surface reward data. Training questions are constructed from concrete write failures, including omission, lost specificity, semantic inversion, stale-state confusion, secondary-fact loss, and over-storage. • Attributed, non-binary feedback. Local probes provide dense per-chunk evidence, while cross- chunk outcome questions use gold facts to map recovered evidence back to source chunks. • Chunk-level policy optimization. Advantages are normalized among rollouts at the same chunk position rather than over whole trajectories, so one rollout can be credited at one chunk and penalized at another. Each rollout casts one vote per chunk even when a framework makes multiple LLM calls. • Cross-harness and OOD results. Hy-Memory-30B-A3B ranks first on Mem0, Hy-Memory, MemOS, and held-out EverMemOS, averaging 55.49% across the four harnesses versus 54.62% for Claude Opus 5. 2 Background and Related Work 2.1 External memory systems and evaluation Mem0 uses incremental extraction and consolidation to maintain a persistent memory store (Chhikara et al., 2025). A-MEM organizes memories as dynamically linked notes whose attributes and relationships evolve as new information arrives (Xu et al., 2025). MemoryOS introduces an operating-system-inspired hierarchical storage architecture that coordinates short-term, mid-term, and long-term personal memory through dialogue-chain FIFO and segmented page updates (Kang et al., 2025). MemOS treats memory as a managed system resource and emphasizes representation, scheduling, provenance, and lifecycle control (Li et al., 2025). These systems differ in schema and control flow, but all depend on an LLM to interpret new interactions and produce valid operations. DCPM argues that long-term memory should support more than surface recall: its dual-process architec- ture represents belief revisions, identity, schemas, latent intentions, and cross-domain abstractions in a capability hierarchy (Fei et al., 2026b). This direction is complementary to ours. DCPM redesigns the memory architecture and its evolution process, whereas Hy-Memory-30B-A3B trains a reusable writer that operates inside several existing memory architectures without replacing them. LoCoMo evaluates conversations containing hundreds of turns and multiple sessions, with questions requiring single-hop, multi-hop, temporal, open-domain, and adversarial reasoning (Maharana et al., 2024). LongMemEval decomposes conversational memory into information extraction, multi-session reasoning, temporal reasoning, knowledge update, and abstention (Wu et al., 2025). Together, these benchmarks motivate evaluating the full memory pipeline rather than the fluency of an extracted summary. Our work draws two conclusions from this literature. First, memory quality must be measured down- stream, after retrieval.
