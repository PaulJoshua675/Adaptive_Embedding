To isolate the effect of the current observation window while keeping the hidden-state update interval fixed, we ablate the window sizes of 1, 2, and 4 seconds, with 2 seconds corresponding to our default setting. For the 4-second window, h_ t is updated using the oldest 2-second segment evicted from the window. For the 1-second window, MaLoW accumulates consecutive observations and updates h_ t after every 2 seconds of newly observed video. The result is presented in Table 13. A larger 4-second current observation window improves real-time perception, as reflected by the higher StreamingBench score, but degrades memory performance, with EPM dropping to 60.0. In contrast, a 1-second window reduces real-time perception while yielding similar EPM performance as the 2-second window. To balance real-time perception and long-term memory, we therefore use a 2-second current observation window as the default setting. How does the refresh rate of the hidden state affect the performance? Although the main experiments in Section 4.1 treat each C_ t as a 2-second video clip, updating the hidden state h_ t every 2 seconds, the update frequency can be varied independently of the observation window. We therefore conduct an ablation with update intervals of 1, 2 (which used in the main experiments), and 4 seconds while keeping the base VLM input fixed to the most recent 2 seconds. For a 1-second interval, the hidden state is updated using the oldest 1-second segment evicted from the current 2-second observation window; for a 4-second interval, MaLoW accumulates newly observed video and updates the hidden state only after every 4 seconds of new observations. The results are presented in Table 14. We observe that less frequent updates, where each update incorporates a larger temporal chunk, slightly improve memory performance at the cost of a small drop in real-time perception. We hypothesize that this behavior is related to the State-Space Model (SSM) used for hidden-state updates. As shown in Table 11, the SSM primarily models short-term temporal dependencies. More frequent updates may therefore bias it toward shorter temporal ranges, improving current perception but slightly weakening longer-term memory, while less frequent updates have the opposite effect. Overall, performance remains stable across different update intervals. We therefore adopt a 2-second interval, which balances memory and real-time perception while matching the current observation window for a simpler design. D.2 Additional Analysis Latency Breakdown. We further analyze the latency of MaLoW (Qwen3.5-9B) reported in Figure 4, with the detailed breakdown presented in Table 15. Encoding the new frames and updating the hidden state ht, generating the LoRA tensors At+1 and Bt+1, and combining them to construct ∆θt+1 account for 7.9%, 2.1%, and 3.7% of the total latency, respectively. Importantly, these operations compute the adapter for the next temporal block and can therefore be executed in parallel with applying ∆θt and performing base-VLM prefilling and decoding for the current block. With such pipelining, only the application of ∆θt and the wrapper overhead remain on the critical inference path, adding 1.75 ms to the 130.07 ms base-model inference latency. This corresponds to approximately 1.3% of the effective end-to-end latency, demonstrating that MaLoW introduces only marginal latency overhead in practical streaming inference.
