Dual-tree traversal [38, 39] simultaneously descends query and reference trees, pruning entire (query-subtree, reference-subtree) pairs via the triangle inequality—a joint pruning that can discard more work per distance computation than batch single-tree’s per-query bounds, at the cost of more bookkeeping per node pair. As we show in Section 5, the optimal configuration depends on k, dataset geometry, and evaluation protocol in ways that are not apparent from any single comparison. 4 Implementation and Optimization Ablation 4.1 Implementation Overview RUSTKNN comprises approximately 13,000 lines of Rust organized around a generic Distance<T> trait that enables arbitrary metric spaces. After cover tree construction, pointer-based trees are con- verted to a contiguous PackedCoverTree in depth-first order (a simpler alternative to the van Emde Boas layout of Izbicki and Shelton [8]) for cache locality: each packed node occupies ∼40 bytes, fitting within a single 64-byte cache line. The dual-tree traversal adapts the framework of Curtin et al. [39] to cover trees without self-children, using a three-phase expansion with triangle inequal- ity pre-filters (details in Appendix C). 4.2 Optimization Ablation Five micro-optimizations are implemented as compile-time feature flags, enabling controlled abla- tion experiments.1 These affect query algorithms and are evaluated in Table 1: 1. Early-exit distance: Euclidean distance computation with four independent accumulators and periodic bound checks; exits early when the partial sum exceeds the pruning bound, avoiding the full O(d) computation. 2. Halfsort: Partial sort of children, O(n) versus O(n log n) full sort. 3. SmallVec: Stack-allocated child arrays for the typical 3–5 children per node at base 1.3. 4. k=1 fast path: Dedicated single-comparison path in the k-NN state machine. 5. Triangle pre-filters: Each reference child caches its parent distance dparent(rc) at con- struction time. Before computing d(q, rc), the triangle inequality gives a free lower bound |d(q, rp) −dparent(rc)| using the already-known parent score d(q, rp). If this lower bound minus the child’s maxdist exceeds the current kth-best distance, the entire subtree is skipped without a metric evaluation.
