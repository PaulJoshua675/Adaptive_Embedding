After each view is searched with BM25, the system obtains several ranked lists with different score scales and different degrees of overlap [11]. Therefore, the retrieval problem is no longer only whether the LLM can generate useful expansion text. A second problem appears after retrieval: how should evidence from several query views be fused while preserving its source and the relationships among the view rankings? Existing fusion methods address parts of this problem, but leave a gap for interpretable multi-view sparse retrieval. Direct concatenation mixes all query text into one BM25 query, so the system can no longer tell which view produced a candidate. Score-level interpolation keeps view scores separate, but typically uses fixed weights that do not adapt to how much the views overlap for each query. Unsupervised rank fusion is robust to score-scale mismatch, but it treats agreement across views through a fixed rule. Text-based neural reranking can improve final ranking, but it changes the focus from retrieval-side fusion to judg- ing relevance with query and passage text. These choices are useful baselines, but they do not jointly model BM25 evidence from each view and overlap among the view result lists. We propose XViewRank, a lightweight method for fusing BM25 results from multiple LLM-generated query views. XViewRank keeps the sparse retrieval stage intact. It searches the original query, a hypothesis view, and a step-back view separately, pools the returned documents, and learns a fusion scorer from two interpretable signals. The first signal is BM25 evidence for each candidate from each view. The second signal is how much the view result sets overlap for the current query. XViewRank therefore operates on retrieval-side evidence without requiring a text-based neural reranker. It uses the relationship among the view rankings to condition how candidate-level score evidence is interpreted. This design keeps evidence from each view visible while allowing different queries to use different fusion patterns. A candidate with similar scores from highly overlapping views should not necessarily be treated the same as a can- didate supported by one view when the views are complementary. Because the overlap values are constant across all candidates of one query, an additive linear scorer cannot use them to change the within-query order directly. XViewRank therefore uses a nonlinear scorer, which permits overlap context to change the ef- fective contribution of each view-specific score. Query-balanced training reduces the effect of highly imbalanced sparse-retrieval candidate pools. We summarize our main contributions: – We formulate multi-view sparse retrieval as a matched-input fusion problem. The original, hypothesis, and step-back queries are searched independently, and every matched fusion method receives the same three ranked lists and pooled candidates.
