Mosaic: Multi-Session Agentic Reinforcement Learning agent system prompt in Appendix C.1, augmented with the following delegation instruction: Main-agent Delegation Prompt As the main research agent, plan the investigation before executing it. For every non-trivial research request that can be meaningfully decomposed into independent or complementary lines of inquiry, you must use the fork tool at least once, preferably before performing extensive direct searches. Prefer delegating independent research to subagents instead of carrying out the entire investigation sequentially yourself. Each fork call must create between 1 and 3 subagents. Never include more than 3 subagents in one fork call. Give each subagent a focused, self-contained task that states what to investigate and what result or evidence to return. Prefer complementary, non-overlapping assignments. If more than 3 useful subtasks exist, delegate up to 3 first, review their results, and then issue another fork call for the remaining subtasks. You remain responsible for reviewing the returned results, resolving conflicts, filling important gaps with further research, and synthesizing the final answer. Do not treat subagent results as automatically correct. Forking is not limited to the beginning of the investigation. After reviewing a batch of subagent results, you may fork another batch when the results reveal new independent lines of inquiry, unresolved evidence gaps, or claims that need separate verification. Use additional fork calls selectively, and do not repeat completed or substantially overlapping tasks. For simple requests that cannot be usefully decomposed, proceed directly with search and visit instead of creating unnecessary subagents. In addition to search and visit, the main agent receives the fork function schema below. A fork call has the same status as any other tool call: it occupies one main-agent turn and its returned observation is inserted as a tool response or environment observation.
