Implementations and libraries. The original cover tree C++ reference implementation [7], last updated in 2014, is single-threaded with distance-level optimizations (batched computation, aligned memory) but no tree-level cache packing. mlpack [15] provides the most actively maintained cover tree implementation, including dual-tree traversal and extensive test coverage. FLANN [16] of- fers randomized KD-trees and is widely used in robotics and computer vision, though it targets coordinate spaces only. Among approximate and GPU-accelerated systems, FAISS [17] scales to billions of vectors with quantization-based search on GPUs; Annoy [18] uses random projection trees with memory-mapped files for production use; and ScaNN [19] employs learned anisotropic vector quantization. Existing cover tree implementations span C++, Haskell, and Java [20, 21] (e.g., JSAT & WEKA) -but no two of them implement the same set of variants, query modes, and micro- optimizations, and none is Rust-native. Critically, cross-language and cross-codebase comparisons confound algorithmic effects (e.g., nearest ancestor vs. simplified) with implementation effects (e.g., compiler optimizations, memory layout, distance computation strategy), making it difficult to at- tribute performance differences to their true cause. Our work focuses on cover trees specifically, but we believe the insight of delineating implementation details applies to other search structures and can reveal new research directions; Section 5.5 gives direct evidence for a second structure. RUSTKNN is the first Rust-native cover tree, integrating directly with the Rust data-processing ecosystem with- out foreign-function interface overhead; more importantly for this study, it implements all variants and query modes in a single codebase, enabling controlled comparisons that isolate one factor at a time. These relate to issues in both maintainability and replicability [22], to which a larger literature is relevant but beyond our scope [23–29, 26]. Rust in the ML ecosystem. Rust adoption in machine learning infrastructure has accelerated for performance-critical components. Hugging Face tokenizers [30] use a Rust backend; candle [31] and burn [32] provide Rust deep learning frameworks; Qdrant [33] and LanceDB [34] are vector databases built in Rust using HNSW for approximate search; and kiddo [35] and hora [36] provide KD-tree and approximate nearest neighbor search, respectively. These projects address approximate search or coordinate-specific structures. RUSTKNN provides exact search over arbitrary metric spaces with the full algorithmic suite from Izbicki and Shelton [8], filling a gap in the Rust ML toolchain. 3
