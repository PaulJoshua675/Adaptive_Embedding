We denote this kind of preference as Pskill. • User Profile. This type of preference uses a user profile or context as background knowledge to guide subtask-level semantic choices, such as selecting a target object or goal region. For the task “put the mug on the table”, the user profile “prefers to protect table surfaces” induces a target-selection constraint, causing the policy to choose a coaster as the support target while preserving the original task goal. We denote this kind of preference as Pprofile. Together, these three types provide a controlled taxonomy of observable preferences in simulation, from user-profile conditioning and skill-specific execution to motion-level control. The current benchmark does not model implicit inference from interaction history, non-linguistic preference signals, or open-ended preferences that lack an automatic execution metric. Detailed preference-selection criteria are provided in Appendix B. 3.2 Preference-Conditioned Data Generation Pipeline Building upon the LIBERO framework, LIBERO-PeRM provides an extensible procedural data- generation pipeline for preference learning and evaluation, as illustrated in Figure 3; model-assisted generation and validation details are given in Appendix C. The pipeline consists of three stages: (1) Preference Selection and Layout Modification; (2) Preference-Conditioned Subtask and Trajectory Generation; and (3) Satisfaction Metric Generation. Preference Selection and Layout Modification. The user first selects a preference instance and an initial LIBERO layout [23]. Given these inputs, the pipeline uses a VLM [72] to minimally modify the layout so the selected preference can be operationalized while limiting changes to the original scene. For Motion Preference and Skill Preference preferences, the layout and task language remain unchanged; the VLM only selects the target object or region, e.g., choosing the stove as the object to avoid for “avoid certain object”.
