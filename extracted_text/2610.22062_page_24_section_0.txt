Multi-phenotype run configuration. The 17-phenotype presence results in main-text Figure 3 and in Tables S3, S7, S8 and S9 were produced by the same model as the reported diarrhea configuration. Both agents ran Claude Opus 4.6 and issued 60,537 calls each, for 121,074 in total, with temperature, top-p, top-k, maximum tokens and seed all left at platform defaults. The denominator for these percentages is the 99 patients whose exposure anchor could be confirmed, which is the 108 of Table 1 less the 9 who have no reliable start date and therefore no windows to score. The two paths assign notes to windows slightly differently. The multi-phenotype path converts a day offset to months by dividing by 30.44 while the diarrhea grid uses day bounds, which places 26,773 notes in window on the multi-phenotype side against the 26,763 the diarrhea grid counts. We report the diarrhea grid figure throughout, since that is the corpus the validated result rests on. In-sample versus out-of-sample evidence. Architecture selection was informed by errors on the same 189 cells used to report the architecture comparison, and prompt selection by errors on the same 183 cells used to report the prompt comparison, so both diarrhea accuracies are in-sample estimates and are upper bounds rather than held-out validations. The architecture, the consensus gate and the prompt design were then frozen and carried to the remaining 17 phenotypes with only the phenotype definition substituted (Note S3.4), and their expert spot-check agreement in the main-text Results is the out-of-sample evidence that the design transfers. Supplementary Note S3. LLM Prompt Templates Both agents return a structured JSON object rather than a bare token. The output schema is configured in Palantir Foundry’s structured-output interface and appended to the prompt by the platform rather than typed by the prompt author, and it is shown here as it is sent to the model. The date field echoes the note’s contact date, which is already known from the EHR metadata before classification and is bundled into the same record for traceability. It is not an independent date extracted from the note text. The listings below therefore end with the author’s own instruction to answer YES or NO, and the schema is what the platform appends after it. Output format (JSON): {"answer": "YES" | "NO", "evidence": "<supporting quote or reasoning>", "date": "<note contact date>"} The two diarrhea prompts are reproduced in full below, as the base-case version V0 that Note S7 sweeps against. Each agent receives a system prompt and a user prompt. The three independent runs use byte-identical prompt text, so the run-to-run variation documented in Note S1 comes from the model rather than from the prompt, and these listings therefore cover all six V0 classification nodes, three runs for each of the two agents. [prompt_bucket] is the only interpolation point in the system prompts and takes the visit label in words, meaning Baseline, 6 months, 12 months, 18 months, 24 months or 30 months. [note_text] is the note body.
