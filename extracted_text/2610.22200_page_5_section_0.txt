Section 5 outlines our research plans and release milestones for Open Generalist CUA. 2 Generalist CUA: Definition and Positioning 2.1 Definition Agents’ Last Exam takes a system-level view and decomposes an agent into five layers: the model (Brain), GUI perception (Eyes), orchestration (Body), tools (Hands), and a runtime (Feet) (Sun et al., 2026). Under this view, a CLI agent lacks GUI perception, a GUI agent lacks most of the remaining layers, and a generalist agent spans all five. Having all five layers, however, only means an agent can act through both the GUI and the CLI; it does not mean that the agent chooses well between them. At a given step, an agent may click through a dozen screens to do what a single shell command would do, or run a script when it first needs to look at the screen. The layer view cannot tell such an agent apart from one that picks the right way to act at each step. In this report, we therefore define a generalist CUA (GCUA) by the decisions it makes at each step, not by the components it contains. A GCUA makes three decisions at each step: what to observe, how to act, and how to organize. • What to Observe. The observation can be a screenshot, an accessibility tree (AX Tree), the output of a command, the response of an API, or any combination of these. The model decides which it needs, including whether it needs a new screenshot at all. • How to Act. The action can be a GUI operation at a screen coordinate, an operation on an accessibility element, a shell command, an API call, or a program that combines several of these. The model decides which fits the step. • How to Organize. Across steps, the agent keeps a plan, tracks what has been done, and decides which past observations stay in context. Most harnesses fix these as rules set by the developer. In a GCUA, the model makes these decisions as the task requires. Four Interfaces. The first two decisions range over four interfaces to the computer, and each offers both a way to observe and a way to act. • GUI. The agent sees a screenshot and clicks, drags, scrolls, or types at a screen coordinate. This is the interface that always works, since every application has pixels. • Accessibility Tree. The agent reads the elements of a window, with their roles, names, and values, and operates on an element directly. It needs no coordinate, does not bring the window to the front, and never moves the user’s pointer on real devices. • CLI. The agent runs shell commands and reads their output. This is the natural route for files, data, and software. • API. The agent calls external services, such as web search, and reads their responses. This reaches what neither the screen nor the shell can. Each interface offers both a way to observe and a way to act, and each has its own strength. No single interface is best for every step, so what matters is choosing the right one at each step and combining them when a step needs more than one.
