Figure 2: Architecture shared by the two prompt variants. The scripted controller sends prompts and checks generic session state. Codex performs the task-solving work and uses the provided client to interact with the environment. The client is part of the agent and saves the environment description, actions, and observations. All components remain unchanged across environments. The main prompt (Appendix B.1.1) asks Codex to read the environment description and accomplish the goal stated there. It explains how to invoke the client with a JSON action and where to find the resulting observations. The client saves the description, submitted actions, and returned files, and prints their locations. Observation records use a generic step-indexed layout rather than an environment-specific organization. Codex can use files, the shell, Python, and supplied tools in its workspace. The main prompt asks it to use the workspace as it finds most effective and suggests helper indexes, access scripts, or reorganized copies of observations when useful, while prohibiting changes to the original observation records (Appendix B.1.1). It does not require a world model, planner, or verifier; Codex decides which additional files and tools to create. A single Codex invocation can include many model calls, local computations, and environment actions before returning control; it is not a single LLM call or environment step. The workspace and Codex conversation persist across ordinary continuations within a run. 4.2 Controller The controller is a small script that sends prompts and checks basic session state; it contains no task-solving logic. It follows the flow in Figure 3. First, it initializes the environment through the client, then sends the main prompt, the variant-specific continuation instruction, and the initial client output identifying the description and observation files. Appendix B.2.3 gives the exact composition. The instruction distinguishing the variants is therefore present from the first invocation. When Codex returns, the controller reads the terminal flag and latest environment-step index from saved client state. It does not interpret observations or assess Codex’s reasoning.
