More design details are deferred to Appendix B.1. 5.3.3 Latency-Centric Online Prediction The online serving path consumes materialized behavioral state and performs only request- and candidate- conditioned prediction. Its objective is therefore different from both bulk prefill and nearline maintenance: maximize request goodput while satisfying the tail-latency SLO under variable candidate fanout and state locality. A useful approximation to the latency-critical serving path is 𝑇req ≈𝑇queue + max (𝑇state,𝑇feat) + 𝑇fusion(𝑘𝑡, 𝑛𝑡) + 𝑇head, where 𝑇state is snapshot lookup/admission and transfer, 𝑇feat is request/candidate feature preparation, and 𝑇fusion and 𝑇head are the candidate-conditioned model costs. The two preparation paths can proceed concurrently. Importantly, no encoder restoration or behavioral advancement appears on this latency- critical serving path. Request readiness and state locality. At admission, each request resolves and pins one compatible behavior-memory snapshot for all candidate batches. A device-resident snapshot removes behavior- memory transfer from the latency-critical path; concurrent misses for the same snapshot are coalesced, and the resolved state remains pinned for the request lifetime. Request-side sparse features follow the same readiness discipline: GPU- and host-resident rows are served locally, while remote misses are deduplicated and batched by owning shard. Behavior-memory KV preparation and independent feature lookup proceed concurrently, and each candidate batch is admitted only after all required state is ready. Detailed sparse-embedding lookup mechanics are deferred to Appendix B.2. Fanout-efficient candidate execution. Once request state is ready, candidate fanout is the dominant model-side source of latency variation. Our production requests contain approximately 0.5K–1.2K candidate queries, with a bounded number of behavior memory states. TransX therefore evaluates candidate-to-memory attention as a rectangular operation, 𝑄cand 𝑡 (𝐾mem 𝑡 )⊤∈R𝑘𝑡×𝑛𝑡, 𝑛𝑡≪𝑘𝑡, using preprojected behavior memory KV shared across the complete candidate fanout, where 𝑄cand 𝑡 ∈ R𝑘𝑡×𝑑ℎdenotes the projected candidate-query matrix and 𝐾mem 𝑡 ∈R𝑛𝑡×𝑑ℎthe projected keys from the pinned behavior-memory snapshot. The online model cost consequently has the form 𝐶online,𝑡= 𝐶req(𝑛𝑡) + 𝑘𝑡𝐶cand(𝑛𝑡), with no dependence on the full behavioral-history length once the snapshot has been materialized. Behavior-memory KV is staged once and reused across candidate tiles and query heads sharing the same KV state. Candidate execution uses a small set of regular fanout shapes to bound temporary memory and per-kernel execution time while maintaining high GPU utilization.
