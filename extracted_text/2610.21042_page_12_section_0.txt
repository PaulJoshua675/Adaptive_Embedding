A.1 System and Orchestration The system uses a Starlette backend and a JavaScript interface. A project-level setting se- lects the model used for search setup, conversation, screening, and extraction. Each action contract specifies a component’s inputs and expected out- puts. Before reporting a stage as complete, the Lead Agent checks that the stage’s expected arti- facts exist and contain their required fields. Each skill is stored as a SKILL.md file in the Agent Skills format (Zhang et al., 2025). A fixed mapping as- signs the skills to the LLM tasks named in Sec- tion 3.1 and appends the selected skill to the task’s system prompt. Wang et al. (2023) evaluate Boolean queries of this form written by ChatGPT for sys- tematic review searches. The Literature Search Tool applies source-specific syntax for PubMed, arXiv, and OpenAlex (Priem et al., 2022) to the query while preserving its Boolean grouping, and it records the executed query, settings, counts, and errors separately for each source. A.3 Screening Preprocessing The Screening Agent first filters records by publica- tion date. Records with missing dates, or with date intervals that overlap the search range, are retained. It then removes exact and near duplicates. Exact matching normalizes title case, punctuation, and whitespace. Near-duplicate detection compares title and author signatures with term frequency– inverse document frequency (TF-IDF) cosine simi- larity, computed with scikit-learn (Pedregosa et al., 2011), at a default threshold of 0.70. Records with distinct nonempty DOIs or PubMed identifiers are kept separate. Each removal is recorded with the relevant reason. A.4 Full-Text Retrieval The PDF Download Tool selects sources from each record’s identifiers and metadata.
