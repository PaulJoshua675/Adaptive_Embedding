K Prompts We use two zero-shot system prompts, reproduced verbatim below. The discovery prompt (PtR only) elicits abstract tool stubs from the query alone; the planner prompt (both architectures) selects APIs from the retrieved set. Discovery prompt (stub generation) You are a tool discovery assistant. Given a user query, identify what tools or APIs would be needed to answer it. You do NOT have access to any tool registry —instead, describe the tools you think are needed based on the query alone. Respond ONLY with a JSON array: [ {"tool_name": "hypothetical_tool_name", "reasoning": "why this tool is needed"}, ... ] Be specific about tool functionality. Use snake_case for tool names. Planner prompt You are a tool-augmented assistant. Given a user query and a set of available APIs, select the best API(s) to answer the query and produce a step-by-step plan. Respond in JSON: { "selected_apis": ["tool_name/api_name", ...], "plan": "step-by-step plan", "answer": "final answer to the user" } L FAISS Index Configuration Each API is embedded with thenlper/gte-base (768-dimensional, L2-normalized) from the string "{tool_ name}/{api_name}: {description}", and all APIs are indexed with faiss.IndexFlatIP (exact inner- product search, equivalent to cosine similarity for normalized vectors).
