BitSparse: Compact Activation Storage 3.3 Sign-bit packing Because the output of ReLU activations is always nonnegative, our method can optionally remove the redundant sign bit. BF16 can be reduced to 15 bits and FP8 values to 7 bits. Zero entries are reconstructed as positive zero. We refer to BitSparse with sign-bit packing enabled as BitSparse-sb. GPU memory is byte-aligned, so a custom Triton kernel is written for packing individual bits. Let ui be the unsigned bit pattern of the ith compact value vi with its sign bit removed, and let wj be the jth output byte. The corresponding input index is i = ⌊8j/(d −1)⌋, with bit offset k = 8j mod (d −1) within ui. The output byte is wj = [(ui ≫k)|(ui+1 ≪(d −k −1))] & (11111111)2. (10) Here i indexes compact values, j indexes packed bytes, and k is a bit offset; out-of-range input words are treated as zero. The sign-bit packing reads two words and writes one byte at a time without atomics for high speed. Decoding works in an analogous way, also without atomics. 3.4 GPU compression and reconstruction Compression is performed entirely on the GPU in three stages. First, a Triton tile kernel loads one tile, evaluates Ht > 0, constructs m and the count st. Second, a scan over the per-tile counts constructs the starting offsets p in Equation (9). Third, a second Triton kernel expands each tile mask and scatters positive values into v according to Equation (8). Optionally, a final Triton kernel strips the sign bits and packs values into bytes according to Equation (10). Reconstruction is performed by a single Triton kernel. Each tile identifies the location of its values using pt and loads the relevant values along with the bitmask. Next, a prefix sum is used to compute the location of each value in the final array. Finally, a masked gather is used to produce the decompressed tensor H, with sign-bit unpacking if necessary. Optionally, the values may be squared during decoding for the ReLU2 activation. Two further kernels fuse the backward-pass operations. The ReLU backward pass requires only the support mask, so a single kernel multiplies the incoming gradient by that mask in place, without reconstructing the activation. The ReLU2 pass performs the same operation with an additional dependence on Z, again in a single fused kernel. Furthermore, our blockwise structure allows for computing the backward matmul (Equations 19, 2) in blocks to avoid materializing the full activation to reduce peak memory further. 3.5 Shared value buffers and implementation details The size of the value buffer v depends on the data, so allocating it on the host requires reading the device-resident count s, which interrupts asynchronous kernel submission. To avoid this, BitSparse optionally appends the values of different activations to a TensorBuffer, a large preallocated block with device memory offsets. Compressing a tensor appends its values and saves the starting offset on the device; decoding reads from the buffer using that offset, implemented in the kernels as val_idx = tl.load(prefix_ptr + tile_id) + tl.load(vals_offset_ptr). This allows BitSparse to operate completely asynchronously. The buffer is reset at the end of every train step, and must be sized to not overflow. We recommend setting it as large as possible to use the unallocated memory. The buffer gives a latency improvement for small sizes which are CPU bound. Appendix E.6 shows a 5.2% runtime reduction at 32 tokens, diminishing as batch size increases and becoming negligible beyond 128 tokens. Furthermore, this allows BitSparse to work with torch.compile. 3.6 Sparse activation checkpointing for feed-forward layers Section 2.1 shows that the positive preactivation values and their positions contain the activation-dependent information required for backpropagation. We therefore cache a compressed representation of ReLU(Z) for both activation functions. For ReLU2, the unsquared activation is stored to avoid a more unstable square root and keep numerical consistency with the forward pass. Our method is implemented in PyTorch as a custom torch.autograd.Function class that combines the ReLU or ReLU2 activation along with a linear matrix multiplication; Algorithm 1 gives its forward and backward passes. Sign-bit packing and TensorBuffer are optional, with support for Bfloat16 and FP8 (both e5m2 and e4m3) with scaling Micikevicius et al. (2022). The overhead of compressing and decompressing is fairly minimal for typical LLM training.
