G.7 EVALUATOR QUALITY REVIEW PROMPT Evaluator Quality Review Prompt (Simplified Version) # Role and Objective Critique and score the existing ‘verification‘ for one accepted task. Do not rewrite the instruction, proposal metadata, or evaluator code. Decide whether repair is required and give concise feedback for evaluator regeneration. # Review Dimensions - Coverage: verify every critical condition in ‘instruction‘, ‘success_criteria‘, and ‘evaluation_requirements_text‘, including target identity, values, counts, order, formatting, metadata, negative conditions, and any genuine dependency. - Getter correctness: require concrete absolute VM paths consistent with the task. A ‘vm_file‘ result is a local cached file path that rule code must open or parse; a ‘vm_command_line‘ result is stdout text. - Structural validity: inspect the internal content or application-specific structure that proves completion, rather than file existence or size alone. - False-positive resistance: initial, empty, partial, stale, wrong-path, wrong-file, or superficially similar states should receive low reward. - Evidence matching: use deterministic rule checks when files or commands capture the condition; use VLM evidence only for indispensable visual or unparsable state. - Safety and determinism: avoid network access, package installation, destructive commands, current external facts, and hidden assumptions. # Scoring and Repair Use integer scores from 1 (unusable) to 5 (excellent). Treat ‘evaluator_quality_score‘ as primary and use ‘coverage_score‘, ‘getter_correctness_score‘, ‘structure_validation_score‘, and ‘false_positive_resistance_score‘ to explain it. Set ‘repair_required‘ to true whenever schema/static validation or initial-state preflight failed, or whenever the review finds a material quality defect. Name the missing check, incorrect getter semantics, unsafe behavior, or false-positive path in ‘suggested_repair‘. # Output Return valid JSON only: { "evaluator_scores": { "evaluator_quality_score": 1, "coverage_score": 1, "getter_correctness_score": 1, "structure_validation_score": 1, "false_positive_resistance_score": 1 }, "rationale": "brief score rationale", "repair_required": true, "rejected": { "reason": "short_reason", "suggested_repair": "concise actionable feedback" } } 47
