The input is first flattened and padded if needed. A small GPU kernel samples up to 4096 pseudo-random elements to estimate an integer exponent center (to avoid batch correlations) and a second kernel shifts the selected encoding table to this center. The main encoding kernel assigns one program per block and one lane per stream. It reads BF16 values using the cyclic mapping, extracts and stores their unchanged sign-mantissa bytes, and packs the exponent codes into the fixed budget. Each stream records where its fixed budget is exceeded. Subsequent kernels count overflowing streams and tail bytes, compact the stream metadata, and copy raw exponent tails from the input into private or shared storage (Section 4.6), with early exit if there is no overflow. Decoding. The decoding table is first shifted by the stored exponent center. The main decoding kernel traverses each stream independently, looking up a prefix, with a lookup table for decoding. Escaped symbols additionally consume their literal bits. It combines each recovered exponent with its sign–fraction byte and writes the reconstructed BF16 bits. A separate overflow kernel reads the raw tails and overwrites the corresponding output positions. 4.5 Fused pointwise operators The optimizer requires several pointwise operations, such as adding and multiplying compressed tensors. For example, the SGD update is Wt+1 = Wt −ηMt, where Wt and Wt+1 are compressed weights, Mt is compressed momentum, and η is the learning rate. A naive implementation would require decompressing Wt and Mt, dense arithmetic, then recompressing the result. For an N-element tensor, each encode-decode cycle uses roughly 4N bytes of memory traffic. A naive SGD update would require approximately 16N bytes of memory traffic. We introduce fused operations for pointwise operations required during training. Each operation consists of two stages. First, a kernel takes in the compressed tensors, computes the output and saves the exponent and sign–fraction byte to separate arrays. Next, the exponents are compressed. This substantially reduces memory traffic. Our fused implementation requires ∼8N bytes (the first kernel requires ∼6N bytes and exponent compression requires ∼2N). A selection of kernels is provided covering all the use cases for typical training with compressed and dense outputs. GEMMs still reconstruct compressed operands as dense inputs, since we did not find significant speedup with fused encode/decode GEMMs. Table 13 lists all operators and training uses. Appendix C describes the codec and pointwise kernels, including stream parallelism, table lookups, register-based bit packing, and overflow handling. 4.6 Shared GPU buffer Our compressed tensors have variable sizes. The sizes are not known at compile time, so allocating exact-sized buffers at runtime introduces host synchronization. This slows down execution, particularly for our fused pointwise kernels. To avoid this, we introduce the shared OverflowBuffer. The OverflowBuffer reserves a large block of device memory, and allocates variable-size tensors without host synchronization. All of our kernels work with the buffer by specifying storage location through the buffer’s address and tensor-specific offset. This is an optional feature. The OverflowBuffer implements a minimal memory management framework entirely in Triton, including allocating tensors, releasing tensors, alignment, and merging adjacent free regions to reduce fragmentation. Operations are performed asynchronously. Appendix C.4 provides more details. 4.7 PyTorch training integration Compressed tensors are represented as a CompressedTensor class, storing the compressed exponents, overflow tails, sign–fraction bytes, and metadata. Custom torch.autograd.Function classes integrate support for LCT into training. These functions compress saved tensors in the forward pass and reconstruct them in the backward pass, maintaining numerical equivalence. Custom compressed optimizers support compressed momentum buffers using the fused pointwise operators. Implementations of SGD-M, Adam (Kingma and Ba, 2015), and Muon (Jordan et al., 2024b) are provided.
