Hardware Accelerators. Custom hardware accelerators ex- ploit the structure of neural network computations. Meta’s MTIA [3,4,56] an in-house family of custom AI chips, designed to provide superior cost efficiency over commercial GPUs for the company’s large-scale DLRM and GenAI workloads. Google’s TPU [50] employs systolic arrays for efficient matrix multiplication. Recent accelerators target emerging workloads: spiking neural networks [57], heterogeneous precision [58], and processing-in-memory architectures that reduce the memory bandwidth bottleneck [59]. Distributed Training Infrastructure. The LLM pretraining study on AMD MI300X GPUs [60] presents the transformer sharding strategy and the practical guidance for fault-tolerant distributed training. Scaling DLRM training requires purpose- built infrastructure. Zion [61] is a scale-up DLRM training platform that co-locates CPUs and accelerators to handle the memory capacity demands of embedding tables while leveraging GPU compute for dense operations. TorchRec [22] provides a PyTorch domain library with optimized distributed primitives, including automatic sharding planners that partition embedding tables across devices. Embedding Table Sharding and Placement. DLRMs present unique systems challenges due to their massive embedding tables, which can exceed hundreds of gigabytes and dominate both memory capacity and bandwidth requirements. Intelligent partitioning of embedding tables across heterogeneous memory hierarchies is critical for training throughput. RecShard [62] formulates embedding placement as a mixed-integer linear program, leveraging per-feature access statistics—including cat- egorical value frequency distributions and pooling factors—to achieve over 2.5× throughput improvement compared to size- based sharding. The key insight is that not all embedding rows are accessed equally; exploiting this skew enables fine-grained placement across GPU HBM, CPU DRAM, and SSDs. 2D sparse parallelism [23] combines data and model parallelism for embeddings, enabling training to scale to thousands of GPUs. Kernel-Level Optimizations. Efficient GPU kernels are es- sential for embedding operations. FBGEMM [46] provides high-performance implementations of table batched embedding lookups, fused optimizers, and quantized operations optimized for recommendation workloads. These kernels exploit memory access coalescing, warp-level parallelism, and mixed-precision computation to maximize GPU utilization. For inference, mixed- precision embeddings [63] achieve 200× compression by learning per-feature precision assignments, grouping features by frequency to reduce the search space. KernelEvolve [47] provides an agentic framework for kernel optimization; we build specialized workflows that incorporates expert-tuning heuristics and architectural insights tailored for training workloads, sim- plifying cross-platform GPU kernel porting and optimization.
