LEASH: Uncertainty-Aware Weak-to-Strong Escalation and Oversight for Computer-Use Agents A.3. Reference Banks and Threshold Calibration Reference banks. For each backbone, we construct a small held-out set of Manager-guided tra- jectories collected with escalation disabled and disjoint from the evaluation tasks. From this set, we construct the query and action representation banks: initial representations are labeled by task- level outcomes, while runtime representations inherit the outcomes of their corresponding subgoal segments. Held-out scoring. We use the same held-out reference set for both representation-bank construction and threshold calibration. Specifically, we perform task-grouped 10-fold cross-validation, keeping all steps from the same task in one fold. For each fold, an uncertainty estimator is fitted on the other nine folds and used only to score the held-out fold, yielding one out-of-fold score for every reference task. The fold-specific estimators are used only for calibration and are discarded afterwards. We then set the escalation thresholds as empirical quantiles of these out-of-fold scores. After calibration, we fit one final estimator per uncertainty channel on all tasks in the same reference set, keep the calibrated thresholds fixed, and use these final estimators to score the evaluation tasks. No evaluation data are used for either estimator fitting or threshold calibration. Targets and thresholds. All four backbones use the same targets, 𝑝𝑞= 0.25 and 𝑝esc = 0.50, so that 𝑝𝑎= (𝑝esc −𝑝𝑞)/(1 −𝑝𝑞) = 1/3. The thresholds 𝜏𝑞and 𝜏𝑎are exact order statistics of the held-out scores in Eq. (4). Because the reference set is finite, the achievable rates are discrete, with a resolution of one reference task. A.4. Post-Handoff Oversight Probe schedule and context. Shadow probes run at the first strong-agent step after handoff and at every third step thereafter. At every strong-agent step, including steps without a probe, the executed action is appended to the weak model’s history in that model’s own action format, so that each probe conditions on the actual trajectory rather than on the pre-handoff context. A probe calls the weak agent’s own action-generation routine, with its usual system prompt, tool schema, and image history, and does not invoke the Manager. The candidate action is logged for analysis but never executed or shown to the strong agent. Shadow threshold. 𝜏sh is the 90th percentile of the pooled per-step runtime scores over the 99-task reference pool, computed separately for each backbone. It is derived directly from the reference pool rather than from the escalation thresholds. For EvoCUA-8B, the in-sample value (+1.7309) is close to the corresponding out-of-fold value (+1.7106). Checkpoint budget. At most six checkpoints can fire in an episode. In addition, once two checkpoints have changed the strong agent’s action, further firings are suppressed; checkpoints that leave the action unchanged do not count toward this second limit. Because probes occur every three steps, consecutive checkpoints are at least three steps apart. Checkpoint mechanics. When a checkpoint fires, the strong agent’s conversation is truncated to its length at the start of the current step, which removes the pending action; the neutral checkpoint message in Figure 7 is appended; and the strong agent re-decides the step with a raised reasoning- effort setting. The weak model’s candidate action is deliberately excluded from the checkpoint message, so the strong agent is never steered toward a specific action proposed by the weaker model. 20
