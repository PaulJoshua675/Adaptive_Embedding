A long-term memory system for an LLM application usually contains three functional stages: (1) a writer converts an interaction into persistent memory operations; (2) a retriever selects records relevant to a future query; and (3) a reader or answer model uses the retrieved records to respond. Systems such as Mem0, A-MEM, MemoryOS, and MemOS have expanded the design space of persis- tent memory through extraction, consolidation, hierarchical paging, linking, versioning, and lifecycle management (Chhikara et al., 2025; Xu et al., 2025; Kang et al., 2025; Li et al., 2025). Benchmarks such as LoCoMo and LongMemEval have also shown that long-term memory is not a single retrieval problem: it includes precise extraction, multi-session composition, temporal reasoning, knowledge updates, and abstention (Maharana et al., 2024; Wu et al., 2025). Despite this progress, the write policy is commonly implemented by placing a general-purpose LLM behind a long, framework-specific prompt. That model must simultaneously distinguish durable user information from greetings, assistant suggestions, and transient text; preserve exact names, numbers, versions, dates, paths, and other identifying details; represent a state transition without losing either the new state or what it replaced; reconcile new evidence with retrieved memories already in the bank; and emit valid operations under the framework’s schema and control flow. The framework cannot recover information that the writer omitted, and a powerful downstream reader cannot reliably infer a fact that was never stored. Conversely, indiscriminately storing everything increases cost and retrieval interference. The desired writer is therefore not a generic summarizer: it is a policy for changing an external state under a long-horizon downstream objective. Recent work has begun to train memory operations with reinforcement learning. Memory-R1 trains a memory manager and an answer agent with final-answer rewards (Yan et al., 2025). MemAgent learns recurrent textual compression from a terminal verifier (Yu et al., 2026).
