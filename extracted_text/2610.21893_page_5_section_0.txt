A team of five human experts reviewed all benchmark instances follow- ing the automated quality checks. Each instance was reviewed by two experts to recheck all crite- ria covered by the automated checks, including whether questions were grounded in their source contexts, reference answers were supported by the source, and goals were aligned with their associated questions. The two reviewers initially disagreed on approximately 5% of the reviewed goal groups. Disagreements between the two reviewers were dis- cussed with a third expert. Instances with identified quality issues were removed. 3.3 Compression Evaluation GACC-Bench evaluates goal-adaptive compression using a two-stage Compressor–Reader framework, in which the compressor condenses the source con- text and the reader answers questions based on the resulting compressed context. Goal-conditioned context compression. Token counts are measured using cl100k_base as a com- mon reference tokenizer. For a given retention ratio, the absolute token budget is calculated by multiplying the source-context length by the reten- tion ratio and taking the floor, with a minimum budget of one token. The compressor receives the source context, the goal, and the resulting absolute token budget, and produces a compressed context that preserves goal-relevant information and rela- tions. A single compressed context is generated for each context–goal–ratio tuple and reused for all questions associated with the same goal. Af- ter generation, the output is tokenized using the same reference tokenizer. If the generated output exceeds the budget, we retain its first L tokens as the compressed memory. If the output is shorter than L tokens, it is retained without padding. No length-based regeneration or rewriting is applied. We record both the raw generated length and the final retained length. Compressed-context question answering. For each question associated with a goal, the fixed reader receives the corresponding compressed con- text and the question, and produces a candidate answer. A fixed LLM judge evaluates the candi- date answer using the original source context, the question, and the ground-truth answer. We validate the LLM judge by comparing its decisions with human expert judgments (Appendix D.1). 5
