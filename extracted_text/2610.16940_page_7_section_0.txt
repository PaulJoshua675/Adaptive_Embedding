Construction and query times are reported sep- arately; query time is further decomposed into tree-build, traversal, and result-collection phases where applicable. Distance computation counts are obtained from a separately instrumented bi- nary (compiled with --features instrument), which increments a thread-local counter on every call to the distance function—including early-exited calls that return before computing all dimen- sions. Because the counter counts invocations, not full O(d) evaluations, early-exit distance reduces the per-call work but not the count; in the dual-tree traversal it leaves the number of invocations unchanged (Section 4.2). Results were collected in several measurement campaigns (separately queued batches of allocations); between campaigns, medians can shift by 20–40% due to node place- ment. Every ranking or ratio from which we draw a conclusion is computed within a single table and therefore within a single campaign. Absolute large-dataset times also depend on node load: on an idle node, an mnist all-NN slows 1.4–1.5× when 15 copies share the node and 2.0–2.1× with 60, about equally for RUSTKNN and C++. These three baselines are compared against RUSTKNN across all 12 datasets. 5.2 Query Mode × k Interaction Table 3 presents the all-nearest-neighbor benchmark (k=1): for each point in the dataset, find its nearest neighbor. This is the standard cover tree benchmark from Izbicki and Shelton [8], exercising tree construction and exhaustive querying. RUSTKNN results use packed simplified cover trees in three query modes (dual-tree, single-tree, batch single-tree). The key finding is that no single implementation or query mode dominates. At k=1, the C++ ref- erence has the lowest median on 9 of 12 datasets—every dataset with n ≤20,000 except optdigits, plus covtype, where its interval overlaps RUSTKNN Dual—while RUSTKNN single-tree search wins on optdigits, corel, and mnist, by 1.7×, 1.6×, and 3.7× over the C++ reference.
