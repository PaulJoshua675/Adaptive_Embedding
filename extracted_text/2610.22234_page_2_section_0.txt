Yet code execution alone cannot fully address the long tail of desktop task scenarios that depends on visual layout, application-specific UI state, or software be- havior exposed only through the interface. As illustrated in Figure 1, these complementary strengths motivate a single agent that coordinates GUI and code, where GUI provides general visual access to arbitrary applications while code provides efficient and precise manipulation of programmatic state. Despite this complementarity, building a native hybrid GUI/code CUA remains an open problem. Simply attaching a code tool to a GUI model does not teach it when or why to use either modal- ity. In our preliminary experiments, as shown in Table 14, Qwen3-VL-32B-Instruct (Bai et al., 2025) achieves over ∼34% success on OSWorld-Verified (Xie et al., 2025) with GUI actions alone, but falls to roughly ∼32% when code execution is naively exposed. Prompt-level composition can therefore disrupt an existing GUI policy rather than create coordinated behavior, making it essential to internalize hybrid coordination capabilities into the model through training on high-quality hy- brid data. Several existing approaches have explored hybrid execution paradigms that combine GUI interaction with code-like actions. Framework-centric systems (Gonzalez-Pumariega et al., 2025; Hou et al., 2024; Yang et al., 2026a) rely on external harnesses to coordinate GUI, code, memory, and recovery; tool-call-based approaches (Jia et al., 2025; Yang et al., 2025b; Shi et al., 2026) ex- pose programmatic operations through predefined application-specific interfaces; and model-fusion approaches (Wang et al., 2025a; Qin et al., 2025) combine complementary capabilities through pre- defined designs. Although these systems expand the scope of hybrid computer use, they leave open how a single policy can learn the routing between the GUI and code actions through hybrid training. To address these challenges, we present OS-Helix, an end-to-end trained computer-using agent that unifies GUI interaction and code execution within a single policy. On the infrastructure side, we introduce application–artifact composition, which combines versioned applications with authentic artifacts to instantiate diverse and reproducible desktop states. An Ex- ploration Agent proposes instructions grounded in these states through brief exploration of the initialized environment, while an independent Evaluator Agent constructs task-specific, primarily rule-based evaluators. Together, this pipeline supports scalable synthesis, filtering, and collection of high-quality GUI/code trajectories for model training, thereby providing the data foundation neces- sary to internalize hybrid coordination capabilities into the model. On the training side, we first use filtered hybrid trajectories to internalize basic action semantics and modality routing, and then optimize the policy through online RL in executable desktop envi- ronments. In early RL experiments, we observe a steady increase in the proportion of code actions accompanied by a degradation in performance. We attribute this to the token-count asymmetry be- tween short GUI actions and substantially longer code actions, which causes the optimization signal to be dominated by code steps. To address this, we propose Step-balanced GSPO, which constructs the sample-level importance ratio over action steps rather than raw assistant-token counts, enabling more balanced optimization of the two modalities. These training components directly answer the open question of how a single policy can natively learn to coordinate GUI and code actions through hybrid training, yielding an agent that performs strongly and reliably across diverse desktop tasks. In summary, our contributions are: 1) We formulate native GUI/code hybrid computer use as an end-to-end policy-learning problem and show through controlled experiments that merely exposing a GUI policy to code execution fails to yield reliable routing, motivating the need to internalize coordination through hybrid training. 2) We introduce application–artifact composition and a decoupled instruction/evaluator synthesis pipeline to construct diverse, reproducible, executable desktop states and generate high-quality hy- brid data for internalizing GUI and code execution capabilities. 3) We propose Step-balanced GSPO for the agentic RL stage of native hybrid policy training, which prevents long code actions from dominating optimization, and enables a single policy to learn GUI and code coordination. 4) We will release the OS-Helix model family and research artifacts, including the desktop data- synthesis and RL environments, task and trajectory collection pipelines, approximately 9K generated 2
