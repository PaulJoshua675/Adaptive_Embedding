It is important to note that each input function u(j) is repeated p(j) times to match the number of collocation points it is evaluated at, enabling a pointwise inner product between the Branch and Trunk network outputs. In the most general setting, p(j) may vary across input functions, allowing each input–output mapping to be evaluated on a distinct amount of collocation points. However, in the labelled-data-free setting considered here, it is natural to use the same number of collocation points across all input functions, such that p(j) = p for all j. As a result, the Branch network input shape is (n × p, m), the Trunk network input shape is (n × p, d), and the PI-DeepONet’s final output has shape (n × p, 1); that is, every output function (which is a mapping of its corresponding input function) evaluated at each of its corresponding collocation points. The Vanilla architecture provides the greatest flexibility, as any number of collocation points can be used with each input function. Pseudocode for the Vanilla architecture can be seen in Algorithm 1. In particular, the input size of the Branch network becomes (n, m) and the output of the Branch network becomes (n, s), which contrasts with (n×p, m) →(n×p, s) for the Vanilla architecture. Additionally, the input data for the Trunk network is reshaped as (n, p, d) – rather than (n × p, d) as in the Vanilla architecture. This formulation requires a constant amount of collocation points across all input functions, a constraint not imposed by the Vanilla version.
