Tree reduction eliminates atomic contention, enabling MI350X to outperform B200 at high violation rates. 2) Example: Bounds Check Kernel: The kernel validates that all embedding table indices fall within valid ranges before performing lookups. When operating in WARNING mode, the kernel (1) accumulates a per-thread count of out-of-bounds violations, (2) corrects each invalid index, and (3) increments the global out-of-bounds violation counter via atomic add operations. On MI350X, atomic operations become severe bottlenecks at high violation rates. Original implementation. After each thread accumulates its violation count, threads with non-zero counts issue gpuAtomicAdds to global memory. With 1024 threads per block and thousands of blocks processing millions of indices, a typical workload can produce millions of threads that contend on a single address. Optimized implementation. In order to reduce atomic opera- tions, per-thread global adds are replaced with shared-memory parallel tree reduction followed by a single atomic add. Rather than writing to a global counter directly, each thread writes its local violation count to a shared memory buffer allocated at the block level. A 10-step binary reduction tree then sums the per-thread contributions entirely within shared memory, avoiding any cross-XCD traffic. Finally, thread 0 issues a single gpuAtomicAdd with the block-wide sum to the global counter, reducing global atomics from ∼106 to ∼103 per batch for a typical production workload. Results. Fig. 11 shows the latency on a production embedding configuration (30 tables, 13.8M indices) as violation rate varies from 0% to 20%. With per-thread atomic adds, MI350X forward latency degrades 8.5× from 0% to 20% violations while B200 degrades only 3.3×. At 10% violations, tree reduction delivers 4.26× speedup (2.1 ms vs 9.0 ms). In the backward pass, we exploit temporal locality within each thread’s iteration stream. Each thread maintains a 2-slot register cache that maps row indices to accumulated gradient values. When consecutive iterations target the same row (a cache hit), gradients are summed locally in registers with zero global memory traffic. On a miss with both slots occupied, the oldest entry is evicted via a single atomicAdd and replaced.
