Because the literal cost is constant per candidate, minimizing weighted prefix length also minimizes expected cost. Escapes matter under this cap: eight-bit prefixes force all 256 direct codewords to length eight by Kraft’s inequality, so grouping rare symbols under one escape leaf frees prefix space for frequent ones. Since the no-escape code is included, the selected model-expected exponent length is at most eight bits. The search is optimal within the class of canonical codes that use a single escape leaf, an eight-bit literal, and the prefix cap Lmax; we prove this below. Algorithm 1 states the procedure. Optimality. Sort the symbol probabilities as p1 ≥· · · ≥pn, with n = 256. Two reductions pin down the search. First, one escape leaf suffices: given several, reassigning every escaped symbol to the shortest leaf ℓpreserves Kraft’s inequality, since 2−ℓ≤P i 2−ℓi, and cannot raise the escape cost P i miℓi, since ℓi ≥ℓfor all i. Second, the escaped set is a probability suffix: exchanging an escaped symbol i with a directly coded symbol j of probability pj ≤pi reduces the cost by (pi −pj)(ℓesc + 8 −ℓj) ≥0, because ℓesc + 8 ≥9 while ℓj ≤Lmax = 8. An optimal code therefore escapes exactly the k least probable symbols for some k, and it suffices to test these probability-ranked cutoffs. For fixed k the cost is P t≤n−k ptℓt + Skℓesc + 8Sk, which equals P t wtLt + 8Sk for the weight vector w = (p1, . . . , pn−k, Sk) that treats the escape leaf as one further symbol of weight Sk. Package-Merge minimizes P t wtLt over all length assignments satisfying Kraft’s inequality and the cap (Larmore and Hirschberg, 1990), so the candidate cost ck is the minimum over all codes whose escape set is {n −k + 1, . . . , n}. The loop evaluates every k ∈{0, . . . , n −1}, the omitted case k = n being dominated: the all-eight code is Kraft-feasible and costs 8, whereas escaping everything costs at least 9. Keeping the smallest ck thus returns the optimum, with ties resolved to the smaller escape set by the strict comparison. Canonical codes are assigned in code-length order. Direct symbols use their assigned code; escaped symbols use the escape prefix followed by their eight-bit table index, which identifies the centered exponent symbol rather than the full BF16 value. Encoding and decoding use precomputed lookup tables (1 KiB and 4 KiB) rather than tree traversal, and kernels apply the sampled tensor center when loading them, adapting to scale without repeating the cutoff search. 16
