We conclude that, under a frozen document index and only a few hundred judged turns, the residual gap to the oracle upper bound reflects the intrinsic mismatch between the long, noisy full-profile conversation and the short, clean oracle rewrite. 6 Submitted Runs The interactive task evaluates a complete conversational system on- line, through the iKAT user-simulation API (Sim.API): at each turn the system receives the simulated user’s utterance, ranks passages from ClueWeb22-B, and returns a generated response. A retriever alone is therefore not enough, and, unlike the offline evaluation of Section 5, the profile is not given but accumulated on the fly. Each run wraps PCDR in a common per-turn pipeline: a gpt-5-mini model at low reasoning effort extracts new durable facts about the user from the latest exchange and adds them to the running profile that PCDR encodes; PCDR ranks passages, optionally fused with a second retriever by Reciprocal Rank Fusion (RRF) [13] and optionally reranked; and the same model generates the response from the top five passages. The personalized dense component is always the PCDR model selected in Section 4.7, which uses LoRA with 𝑟=64. A single dense leg, with no reformulation, fu- sion, or reranking. The conversation and the profile are encoded by PCDR and passages are ranked by cosine similarity. This run mea- sures the standalone effectiveness of personalized conversational dense retrieval. Run 3: fusion with a conversational dense retriever. We fuse PCDR with its own non-personalized backbone, conv-Qwen3, by RRF and without reranking. Neither leg is reformulated, which makes the run fully rewrite-free: both encode the conversation directly, and only the personalized leg additionally consumes the profile. This design follows two observations from our 2024 system [20]: fusing personalized and non-personalized rankings mitigates over- personalization, and a strong conversational dense retriever can replace the reformulate-then-retrieve pipeline. Run 5: fusion with a learned sparse retriever. We fuse PCDR with SPLADE-v3 [27], a learned sparse retriever, by RRF and with- out reranking. SPLADE-v3 is driven by a de-contextualized, non- personalized reformulation of the current question, contributing profile-free lexical evidence that complements the personalized dense ranking. As in the preceding runs, we omit reranking here: when the fused pool is already strong, our 2024 experience [20] indicates that a reranker brings little benefit and can even harm the ordering. Run 4: fusion with a lexical retriever and reranking. We fuse PCDR with BM25 [55] by RRF and rerank the top 50 fused passages with RankLLaMA [32]; BM25 is given a personalized reformulation of the question. As the lexical retriever is the weakest of the three fusion partners, we reinstate a reranking stage to consolidate the final ranking. 7 Results with Simulated Users 7.1 Evaluation Setting The iKAT 2026 interactive task evaluates each submitted system on- line against LLM-based user simulators [1].
