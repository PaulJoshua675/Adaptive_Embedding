Preprint D PROMPTS D.1 PROMPT TEMPLATES. Prompt 2 specifies the GUI actions, how to use the SoM marks or screenshot coordinates to select an action’s location, and the required output format. For each episode, we combine these shared instructions with three components. The domain instruction identifies the environment as a game or a web task and specifies how the agent should interact with it, defined in Appendix D.1.1. The clock instruction explains the clock protocols, specified in Appendix D.1.2. The task instruction states the specific objective and requirements for the current task, corresponding to the success criteria. D.1.1 DOMAIN INSTRUCTIONS. The domain instruction specifies the interaction setting and behavioral constraints. Game tasks use Prompt 3, while web tasks use Prompt 4. D.1.2 CLOCK INSTRUCTIONS. The clock instruction specifies how observations, model outputs, and action execution relate to en- vironment time: • Token clock (Prompt 5): charged output tokens determine the simulated delay between observation and action. • Paused environment (Prompt 6): output length does not advance simulated time; each action is applied at the observed tick before the environment advances one frame interval. • Wall clock (Prompt 7): environment time follows physical elapsed time. Prompt 2: Complete text-action system prompt <DOMAIN INSTRUCTION> AVAILABLE GUI ACTIONS (canonical JSON): - {”action”: ”click”, ”target”: ”P1”|”R1@u,v”, ”button”: ”left”|”middle”|”right”} - {”action”: ”right click”|”double click”|”triple click”, ”target”: ”P1”|”R1@u,v”} - {”action”: ”mouse down”|”mouse up”|”move”, ”target”: ”P1”|”R1@u,v”, ”duration”: <seconds>} - {”action”: ”type”, ”text”: ”<string>”} - {”action”: ”key”, ”key”: ”<key or combo>”, ”repeat”: <int>} (short tap; examples: ”enter”, ”ctrl+s”) - {”action”: ”hold key”, ”key”: ”<key or combo>”, ”duration”: <seconds>} (continuous control) - {”action”: ”scroll”, ”target”: ”P1”|”R1”, ”dx”: <int>, ”dy”: <int>} (positive x=right, positive y=up) - {”action”: ”drag”, ”start”: ”P1”|”R1@u,v”, ”end”: ”P2”|”R1@u,v”, ”duration”: <seconds>} - {”action”: ”wait”, ”duration”: <seconds>} - Prefer canonical JSON with double quotes. The adapter can recover one unambiguous action from common wrappers or shorthand, but canonical JSON is shortest and safest. - P/R marks belong only to the screenshot that supplies them. Pn is an exact target point. Rn@u,v addresses a continuous region using local integers from 0..1000: left/top is 0 and right/bottom is 1000. Never reuse a mark from an earlier screenshot. - Prefer a supplied mark. If no suitable mark exists, replace target with x/y, start with x1/y1, or end with x2/y2 using the screenshot coordinate space. Reference and coordinate forms may be mixed for drag endpoints, but never specify both forms for the same point. - Use the coordinate contract supplied with the current screenshot. The harness converts image coordi- nates to the executor’s 1920x1080 desktop space. - Pointer coordinates may be omitted for click variants, mouse down/up, and scroll only to act at the current cursor position. When present, x and y must be supplied together. - duration must be between 0 and 10. For hold key and wait it is simulated world time under the token clock; hold key defaults to 1 and wait without duration waits for the next observation. For move, mouse down/up, and drag it controls executor-side pointer interpolation only; GUI execution time is excluded from simulated time. 25
