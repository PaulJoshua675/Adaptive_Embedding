RALI@iKAT 2026: Retrieval-aware User Profile Denoising via Personalized Conversational Dense Retrieval 8 Visualization: What the Dense Encoder Attends To To make concrete the claim that PCDR denoises a long profile in- side the representation, we visualize which input tokens most influ- ence its query embedding. We use the generic attention-relevancy method of Chefer et al. [11], which attributes a model output back to input tokens by aggregating attention maps weighted by their gra- dients across layers; a higher relevancy means a token contributes more to the retrieval embedding. Figure 3 applies it to a representa- tive personalized turn from iKAT 2024. The input consists of the instruction, a 13-statement user profile, and a one-turn conversa- tion ending in the question “Is it suitable for me?”. Only profile statements 1, about makeup, and 5, about dry skin, are annotated as relevant; they are marked with ⊲in the figure, and the antecedent of the pronoun is boxed. The figure shows two behaviours that a dense encoder can per- form but a bag-of-words query cannot. It attenuates the irrelevant part of the profile: of the thirteen statements, relevancy concen- trates on the skin-related ones and on the current question, namely the discriminative tokens dry skin and the topically related Mac primer, Clinique, and CeraVe, while statements about travel, work, or water intake receive little. And it resolves conversational con- text, linking the pronoun “it” in the question to “double cleansing” introduced one turn earlier, without an explicit rewriting step. The contrast with query reformulation is instructive. For the same turn, the personalized LLM rewrite our pipeline produces is “Is double cleansing suitable for someone who wears makeup regularly and is looking for dry skin solu- tions?” To personalize, the rewrite must verbalize the selected profile facts as additional query text, which lengthens the query and, when the profile is long, dilutes the discriminative terms among many others [9, 26]. PCDR instead keeps the entire profile as input but internally attends to only the few relevant tokens shown in Figure 3, performing the same selection inside the representation rather than by editing text. The denoising happens in embedding space, which is exactly where dense retrieval is robust to verbosity and where reformulation is not. 9
