The browser exposes OpenResearcher’s own three tools, called from the model output as JSON: browser.search (a query, returning the top-10 hits as title, URL and summary), browser.open (a link id from the current page, a URL, or a page cursor, with loc/num lines to scroll) and browser.find (an exact-text pattern inside the currently open page). B.3.2 REWARD The environment gives a single terminal reward. It is graded by an LLM judge (qwen3.5-flash) with OpenResearcher’s HLE grading template, which extracts the final answer from the response and returns yes/no against the reference answer. Let T be the answering turn; the reward at decision t and the episode return are rt = 1[t = T] · 1[judge says the answer is correct], R = X t rt ∈{0, 1}. (6) B.3.3 EPISODE, OBSERVATION AND DECISION An episode contains at most 64 decisions. The observation is the full conversation so far: the system prompt (OpenResearcher’s browsing instructions, the date, and the three tool schemas), the question, and the alternating assistant turns and tool responses. The prompt budget is 16,384 tokens. The policy answers with reasoning followed by either one tool call or the final answer, <think>...</think><tool call>{...}</tool call> or <think>...</think><final answer>{...}</final answer>. Generation stops at <tool response>, and the tool call is executed by the browser against the search service. B.3.4 AGENT DESIGN The population consists of three agents, SEARCHER, OPENER and FINDER, each a separate full fine-tune of gemma-4-E2B-it (Team et al., 2026). They see the same conversation and partition the tool space: SEARCHER owns browser.search, OPENER owns browser.open, and FINDER owns browser.find; any agent may end the episode by giving the final answer. The monolithic agent is the same base model fine-tuned on turns spanning all three tools.
