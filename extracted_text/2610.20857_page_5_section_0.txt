3.5 Joint Expert ranking and failure handling The Expert receives the entire eligible shortlist, complete available abstracts, existing assessments, and only the PDF material actually acquired and selected. Earlier grades are evidence rather than a mandatory final ordering. Papers with unavailable or unattempted PDFs may rank first. The model returns exactly min(5, |Cq|) candidate IDs in consecutive rank order, a one- or two-sentence explanation for each, and an evidence-source label. Reasons are qualitative; the system does not claim calibrated probabilities. Validation checks candidate membership, duplicate identities, rank order, and consistency between claimed evidence sources and supplied material. A failed Expert output is recorded as a ranking failure rather than replaced silently with a rule-based Top 5. Operational completion and scientific target recovery are separate outcomes. A partial run may contain a valid ranking while recording unavailable documents or incomplete checks; a successful ranking alone does not prove a target hit. 3.6 Efficiency and optional report generation Retrieval-only optimizations include concurrent independent seed branches, reuse of valid unchanged model responses within a run, batched scholarly requests, shared HTTP con- nections, compact Expert payloads, and skipping report-only evidence processing. Reuse keys include the prompt, evidence, model, and configuration dependencies; changed evidence must be reassessed. Compact serialization preserves the abstract and selected evidence while removing duplicated or audit-only material. These choices reduce redundant work by design, but this paper does not report a controlled ablation establishing a latency or accuracy effect for each optimization. The Expert has a separate maximum output budget of 16,384 tokens. Its prompt still requests only up to five concise entries; this ceiling is not observed consumption or a request for a long reasoning transcript. Request budgets, deadlines, status records, cancellation, and provider-specific configuration are available through all entry points. The public runner does not automatically restart a whole task. In full-report mode, additional artifacts include method/experiment snippets, representative-paper selections, synthesis input, and a rendered report; these costs are outside the reported retrieval-only comparison. 4 Optional Research Extensions 4.1 Code Extractor Code Extractor takes a supplied PDF, Markdown, or text document and emits structured implementation diagnostics and a Markdown report. It combines rule-based code/pseudocode extraction with optional LLM analysis of completeness, frameworks, dependencies, model structure, and missing components. Native PDF text extraction is the default; structured MinerU parsing is explicitly optional. Model-recovered descriptions must be distinguished from verbatim executable source. The public interface separates analysis from execution. With model assistance disabled, scores are labeled heuristic; with code execution disabled, execution outcomes remain unrun even if syntax checks succeed. Missing packages, parser failures, and requested model- analysis failures are exposed as diagnostics. This tool can identify potentially missing details, but successful parsing, syntax checks, or high model scores do not establish paper-level reproducibility. 4.2 Evolution Mapper and Planner–Worker Evolution Mapper retrieves a topic’s papers and citation neighbors, builds a directed graph, groups papers by year, and exports Mermaid diagrams, key-paper summaries, and path analyses.
