ToolSafe introduces TS-Bench and TS-Guard for pre-execution, step-level tool safety [Mou et al., 2026]. TS-BENCH derives the released AGENTDOJO-TRAJ and AGENTHARM- TRAJ step records, including step-level risk scores, from AgentDojo and AgentHarm trajectories [Debenedetti et al., 2024, Andriushchenko et al., 2025]. We use these files at a pinned commit; the paired AGENTDOJO-TRAJ variants described below are the only new inputs we construct. Under ToolSafe’s strict mapping, every nonzero risk rating is unsafe. AgentDojo-Traj has 1,220 steps (352 unsafe and 868 safe) across four domains. AgentHarm-Traj has 731 steps (525 unsafe and 206 safe) in 197 released interaction-ID groups. We use released labels, TS-Guard predictions, and previously cached hosted-guard assessments from pinned source commits. No tool call in a record is executed. The aggregate code/results package is publicly available.1 It contains no raw benchmark text, arguments, identifiers, or provider responses. Audit scope. Here, an audit means applying the three-level framework in Section 2 to released evaluation artifacts. We test whether simple cues predict labels, whether input-visible cues are associated with guard decisions, and, when an edit intended to preserve the construct is available, whether paired edits change those decisions. The analysis is black-box: it uses released records, outputs, and fixed input transformations without access to guard internals. We do not test an adaptive agent, an evasion attack, or end-to-end tool execution. 3.2 Capability-poor diagnostics Level 1 begins with one deliberately limited diagnostic matched to each artifact’s construction. The aim is not to build the best classifier. It is to test whether a narrow cue recovers released labels and whether that result survives controls for duplication, source overlap, transfer, and evaluation- unit weighting. For LinuxArena, the deterministic score is the negative mean shell-command character count, so larger scores indicate shorter commands. We compare it with character n-gram TF–IDF and logistic regression trained leave-one-environment-out (LOEO). We report AUC and a clustered bootstrap over main-task/side-task groups. These are completed-trajectory diagnostics, not operational step-wise monitors. For AgentDojo-Traj, the fixed binary rule requires both the literal <INFORMATION> marker in history and a current tool whose name starts with one of 11 side-effect verbs (for example, send_, delete_, or update_). The rule and verb list were frozen after initial inspection, so this is a diagnostic audit rather than a preregistered test. A second diagnostic memorizes each exact tool’s majority label. For unseen tool names, it predicts the training fold’s overall majority label; ties are classified as unsafe. We evaluate it both with interaction- grouped five-fold cross-validation and leave-one-domain-out (LODO) transfer. The lookup explicitly uses evaluation labels and must not be described as a deployable classifier. For AgentHarm-Traj, we test the all-unsafe baseline and audit the mapping from source subset to strict label. We then recompute guard metrics at three units: rows, equal-weight interactions, and one majority prediction per interaction. This distinguishes performance over recorded steps from performance over underlying tasks. Separately, we case-fold parsed tool names, normalize their structured arguments, retain exact-execution groups containing both labels, and compare safe and unsafe context means with equal weight per execution group. 3.3 Frozen AgentDojo counterfactual cohort A frozen cohort is a fixed panel of base steps and paired edits selected before any guard is run on the edited inputs. Freezing prevents us from choosing examples after seeing intervention outcomes; pairing holds the underlying step fixed; and balancing eight marker-present safe and eight marker- present unsafe steps from each AgentDojo domain prevents one domain or label from dominating.
