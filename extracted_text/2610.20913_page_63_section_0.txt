TransX: Technical Report Model rollout and cache version transition. A full retrain can change the behavior memory repre- sentation, making the new model incompatible with the existing population-wide KV cache. Because rebuilding snapshots for all users can take substantially longer than loading new model weights, rollout proceeds as a dual-version transition rather than an in-place replacement. For notational convenience, we use the user index as a subscript in this section, rather than the superscript notation used above. Let version 𝑣denote the currently serving model/cache pair and 𝑣+ 1 the new rollout. Bulk prefill constructs the new cache namespace in the background while requests continue to use  𝜃(𝑣), V(𝑣) 𝑢  . For each user, bulk prefill records the source cursor 𝑐bulk 𝑢 through which behavior has been incorporated into the new continuation state. Behavior arriving after this cursor remains available in the source log and is either consumed concurrently by the 𝑣+ 1 nearline path or replayed after bulk construction completes: C(𝑣+1) 𝑢 (𝑐bulk 𝑢 ) + Δ𝐻𝑢  𝑐bulk 𝑢 , 𝑐current 𝑢  −→C(𝑣+1) 𝑢 (𝑐current 𝑢 ) −→V(𝑣+1) 𝑢 . Thus, no behavior acknowledged after the bulk-prefill cutoff is lost between backfill and cutover. Traffic migrates to version 𝑣+ 1 only after the user’s compatible snapshot is available and its represented cutoff satisfies the rollout freshness policy:  𝜃(𝑣), V(𝑣) 𝑢  −→  𝜃(𝑣+1), V(𝑣+1) 𝑢  . Users not yet ready remain on version 𝑣, allowing serving to continue throughout cache reconstruction. During the rollback window, the old version either continues receiving updates or retains sufficient replay coverage to catch up before traffic returns. It is reclaimed only after traffic has drained and the rollback window has expired. This temporarily duplicates model/cache state and requires additional maintenance or catch-up work, but preserves serving continuity and an explicit rollback path.
