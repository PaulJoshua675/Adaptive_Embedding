Reusable graph-dependent preprocessing. The retained eigenpairs and directional relation masks depend only on the architecture graph, so they are constructed once and reused across encoder layers, training epochs, and repeated predictions of the same architecture. This design separates graph-input construction from model evaluation and amortizes structural and spectral construction whenever an architecture is revisited. Topology- and support-aware relation handling. Deployment-oriented architecture design bal- ances predictive quality against computational cost, making sparse-to-moderately-dense connectivity a practically important regime for support-aware execution. The practical motivation for support- aware relation handling is that computational graphs exhibit structured, architecture-dependent connectivity rather than a single density regime. ResNet-style architectures introduce selected shortcut edges, whereas DenseNet-style blocks create a denser support pattern by connecting each layer to all preceding layers within a block. Deriving relation supports from the observed topology preserves this variation and provides the structural basis for sparse execution whenever the graph admits it. The six directional relations expose their supported node pairs explicitly, allowing relation construc- tion to exploit known graph structure. Let S denote the total number of supported pairs across the six relations. A support-indexed attention implementation evaluates only stored supported pairs, yielding an O(Sd) attention term, while sparse predecessor and successor aggregation costs O(md). The explicit relation supports therefore provide the execution interface for support-proportional computation as graph scale increases.
