Recommenda- tion models use large embedding tables that often reside in host memory due to GPU memory constraints. With larger HBM, embedding tables can be moved from host to HBM, eliminating PCIe transfer bottlenecks. Additionally, row-wise sharding can be replaced with table-wise or column-wise sharding, reducing AlltoAll communication and CPU/GPU synchronization overhead. Experiments on a feed ranking model show >10% speedup from embedding placement optimization, with the expectations for larger gains when combined with 2D embedding sharding strategies. Combined results. Fig. 15b shows the combined effect of co-design strategies on a feed ranking model. After porting to MI350X, we increased the batch size, removed AC, and optimized embedding placement, resulting in a 1.26× speedup. In conjunction with kernel optimizations, the model realizes a total speedup of 1.5× compared to the initial baseline. These results demonstrate that combining multiple strategies delivers substantial efficiency improvements. B. Strategies for Model Quality Model architecture upscaling. The MI350X’s expanded HBM capacity accommodates larger model architectures that would otherwise require additional GPU nodes. Increased memory footprint directly translates into superior model quality through several key avenues: (1) Longer input sequences: transformer- based recommendation models can leverage longer sequences to capture richer user context. (2) Expanded embedding tables: larger hash sizes reduce collision rates, thereby preserving higher-fidelity information within the learned representations. (3) Increased dense complexity: support for more dense layers and larger hidden dimensions enables the extraction of more expressive features. Results. This co-design principle, matching the model to the accelerator’s memory hierarchy, is not AMD-specific. It transfers directly to Meta’s MTIA training accelerator (MTIA- 300 [5]), whose larger HBM relative to the incumbent GPU is likewise exploited for larger batches and fewer trainers. The principle is direction-agnostic: on the SRAM-bound prior inference generation (MTIA-200 [6]) it instead drives the model to shrink its activation footprint to fit on chip, e.g., decomposing batched matmuls to remove redundant in-batch broadcasts cuts activation memory by ∼25%, admitting 10–50× larger embedding tables.
