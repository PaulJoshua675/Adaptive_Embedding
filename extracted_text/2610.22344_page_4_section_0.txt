The Kaggle-MLE Factory constructs executable tasks, and the interaction harness supports model-directed experimentation and trajectory collection. Hierarchical agentic SFT learns from demonstrations, while WIRL further optimizes the policy from execution feedback collected during online interaction. but their heterogeneous data organization, submission formats, and evaluation protocols make man- ual task adaptation difficult to scale. Therefore, we build the Kaggle-MLE Factory, which converts historical competitions into executable tasks with a public workspace, a hidden test split, and a unified evaluation interface. The Factory uses a multi-agent pipeline for task construction, validation, and repair. The discovery agent filters competitions by status, scale, and submission format. After competi- tion data, leaderboard information, and official descriptions are collected, the analyzer agent extracts data structures, fields, and modality characteristics to form a task specification. The generator agent then prepares task data, constructs a held-out test split with hidden labels from the original labeled data, and implements the task-specific evaluator. The task is executed on real data and iteratively repaired based on validator checks of data integrity, submission format, and evaluation behavior to produce valid executable tasks. Standardized task packages support different MLE agent frameworks. Final manual review excludes tasks with unresolved label or scoring issues before trajectory collection. Interaction Harness for Long-Horizon MLE Optimization To support model-directed long-horizon MLE optimization, we design an interaction harness that follows ReAct-style loop [9], leaving branch selection and optimization-path decisions to the model rather than an external search policy. The harness stores experimental states in solution nodes, each containing candidate code, execution logs, and metadata. Parent-linked revisions form an experiment tree that the model can revisit and compare to decide whether to continue, backtrack, or change optimization direction. The harness provides tools for solution analysis, code revision, experiment execution, history retrieval, and submission management. The model launches candidate execution through execute_code and updates its submission candidate through update_answer. The complete tool list and descriptions are provided in Appendix B. As interaction history approaches the context limit, earlier messages are summarized while recent interactions are retained. For complex analysis, analyze delegates task analysis, data exploration, and result diagnosis to an analysis sub-agent with independent context, returning only a summary to the main model.
