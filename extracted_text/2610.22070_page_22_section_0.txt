The exact question timestamp is then randomly sampled from the temporal range corresponding to the selected timestamp type. We use Qwen3.5-122B-A10B (Qwen Team, 2026) as the Question Generator. For question generation, we launch four parallel workers, each serving one Qwen3.5-122B-A10B instance with vLLM (Kwon et al., 2023) on two H200 GPUs. Answer Generation. After obtaining the generated questions and their corresponding timestamps t, we prompt the Answer Generator to produce a model answer using only the video content observable up to time t. This setup ensures that the generated answer respects the streaming setting and does not access visual information occurring after the question timestamp. We use Qwen3.5-122B-A10B (Qwen Team, 2026) as the Answer Generator. For answer generation, we launch four parallel workers, each serving one Qwen3.5-122B-A10B instance with vLLM on two H200 GPUs. Verification. After obtaining the generated question and its corresponding model answer, we prompt the Verifier to assess the quality of the generated question–answer pair. The Verifier takes as input the generated question, the expected answer, the model answer, and the original event description used during question generation. It evaluates both whether the generated question is valid and well grounded in the target event and whether the model answer is consistent with the available evidence. In particular, a substantial mismatch between the expected answer and the model answer may indicate either that the generated question is ambiguous or unreasonable, or that the model answer is incorrect. The original event description provides additional grounding information that allows the Verifier to distinguish between these cases and assess the overall validity of the question–answer pair. For verification, we launch two parallel workers, each serving one Qwen3.5-397B-A17B instance with vLLM on four H200 GPUs. Filtering and Post-Processing. We discard question–answer pairs for which the Verifier identifies an inconsistency between the expected answer and the model answer, determines that the model answer is incorrect, or judges the generated question to be invalid, ambiguous, or otherwise unreasonable. After filtering, we group questions associated with the same video and question timestamp into multi-turn conversations, which are subsequently used for training. We also include annotations from the offline video understanding from LLaVA-Video-178K to further strengthen the memory mechanism. B.3 Dataset Statistic MaLoW-Instruct contains 381K instruction samples constructed from 56K videos. Table 6 and Table 7 summarize the distribution of questions by timestamp class and question type. In terms of temporal categories, real-time questions constitute the largest proportion (46.1%), followed by past (36.4%) and future (17.4%) questions. These categories correspond to questions posed while the target event is occurring, after the event has occurred, and before the event occurs, respectively. Regarding question types, multiple-choice questions account for the largest proportion (35.0%), while open-ended (34.7%) and Yes/No (30.0%) questions are comparably represented, with counting questions comprising the remaining 14.0%. Table 8 summarizes the statistics of the questions, answers, and video durations in the dataset. Questions contain an average of 70.4 tokens, encoded by the tokenizer from Qwen3.5-9B, while answers are generally concise, with an average of 3.8 tokens. The question timestamps cover a wide temporal range, with an average question video length of 57.2 seconds, while the full videos are longer on average at 89.5 seconds, reaching up to 1,673.4 seconds.
