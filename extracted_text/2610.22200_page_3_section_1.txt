Computer use has moved to the center of attention. The GPT-6 Astra release places strong emphasis on computer use, with extensive demonstrations offering an exciting vision of what computer-use agents could make possible (OpenAI, 2026c). Much of the literature studies computer-use agents (CUAs) as GUI- only agents, asking how well models can complete computer tasks through screenshot-based observation and mouse and keyboard actions (Qin et al., 2025; Lu et al., 2026). Recent frontier systems, however, combine GUI interaction with shell commands, accessibility-tree access, and other tools, and OpenAI now recommends code execution, writing GUI operations as code and combining them with programmatic operations in a single model output (OpenAI, 2026b). These systems also target tasks on users’ own computers, where shared control, interaction with background windows, and evolving requests introduce challenges not fully captured by benchmarks. The question has changed, from how well a model operates a GUI interface to how well a system completes work on a real computer by whatever means works. We take this as a turning point in computer-use research, motivating a clearer definition of these broader agents and a systematic study of their design. We therefore adopt the term generalist computer-use agent (GCUA) to characterize this broader class of systems, following the system-level perspective of Agents’ Last Exam (Sun et al., 2026). GPT-6 Astra’s computer-use system is a representative GCUA. We define a GCUA as an agent system designed to complete diverse computer tasks through both visual interaction and programmatic access, in which the model decides how to observe, act, and organize its work as the task requires. Programmatic access includes shell commands, accessibility APIs, and application or service APIs where available. Essentially, a GCUA chooses how to use the computer to complete a task, rather than being restricted to GUI interaction. Our previous work, Qwen-UI-Agent, began exploring this direction through a unified GUI and CLI action space with batched actions (Zhou et al., 2026). Within our formulation, such GUI+CLI hybrid CUA is a special case of GCUA (Section 2). How to design such systems is an open question. A GCUA raises design questions that go beyond those of GUI-only agents: which interfaces to give the model, how to support code execution, which decisions to leave to the model and which to the harness, and what changes when the agent runs on a user’s own computer. However, frontier systems such as GPT-6 Astra remain largely closed (OpenAI, 2026a). Their model weights, full prompting setups, real-device harnesses, device-control SDKs, and execution trajectories are not available. This limits the community’s ability to reproduce system behavior, compare alternative designs, and investigate how design choices and execution mechanisms affect task completion and cost, particularly under real-device conditions. We therefore introduce Open Generalist CUA (OpenGCUA), an ongoing project to develop and open the full stack for generalist computer use with the community (Figure 2): (1) Model. Develop a model that unifies computer and browser use, with code execution and harness-to-model decision transfer central to its agent design. (2) System. A real-device harness that runs on users’ real machines, and lessons we learned in moving from benchmark harnesses to real-device deployment. A cross-device SDK that gives agent programs one interface to computers, browsers, and phones, supporting tasks that span multiple devices. (3) Trajectories. Release trajectories from evaluations of frontier models such as GPT-6 Astra to support analysis of code-execution and harness-to-model decision transfer patterns. (4) Efficiency. Systematically study and improve GCUA execution efficiency through code-execution, concise model reasoning, and harness optimization, while exploring broader system-level improvements. (5) Evaluation. Develop evaluation environments and benchmarks on real devices, particularly on macOS, to assess agents’ ability to complete tasks under real-world operating conditions. This report presents the first release of the OpenGCUA project. The release does not yet include a trained model. The report covers agent design and evaluation, execution trajectories from frontier models, and preliminary versions of the real-device harness and cross-device SDK, together with a roadmap for subsequent releases.
