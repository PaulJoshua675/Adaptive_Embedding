LLM Agent Systems and Interoperability Protocols LLM-based agent systems study reasoning, coordination, workflow execution, learning, and tool use [22]–[24]. Repre- sentative systems span multi-agent coordination [25]–[27] and reasoning, tool-use, embodied, or learning settings [28]–[31]. The present work focuses on the preceding systems question of which candidate capabilities should enter the LLM context before final arbitration. Interoperability protocols provide the machine-readable ob- jects over which such discovery can operate. MCP exposes structured tool descriptions [3], while A2A represents agents through Agent Cards containing identity, capabilities, skills, interfaces, and related metadata [4]. These protocols define capability representation and interaction but do not prescribe a large-registry relevance-ranking mechanism. SSR comple- ments them by operating directly over field-derived Agent Card information before LLM arbitration. III. STRUCTURAL SIGNAL RETRIEVER The Structural Signal Retriever (SSR) is the retrieval method proposed in this work for Agent Card discovery. It is deterministic and training-free, operates directly over machine- readable Agent Cards, and produces a compact pool of top- ranked candidates for LLM arbitration. SSR uses explicit lex- ical signals derived from capability-bearing Agent Card fields, inverse document frequency (IDF) weighting, and an Inverted Signal Index (ISI), without requiring dense representations or supervised retrieval training. In Fig. 1, Blocks 1–2 represent the offline registry and index-construction stages, Block 3 executes query-time SSR retrieval, Block 4 forms the compact candidate pool, and Block 5 performs final LLM arbitration. In the offline stage, the Agent Card registry is processed to extract structural signals, compute document frequencies and IDF weights, and construct the ISI. In the online stage, the user query is mapped to the same signal space; its signals address the ISI to retrieve matching Agent Cards, which are then scored and ranked. Finally, up to K top-ranked Agent Cards form the compact candidate pool presented to the LLM orchestrator for final agent selection. Thus, the registry may grow independently of the amount of candidate information presented to the LLM. A. Problem Formulation The problem addressed by SSR is to discover query-relevant Agent Cards from a growing registry without coupling the amount of information presented to the LLM orchestrator to the total registry size. Given a user query, the retrieval stage must identify and rank candidate Agent Cards while the orchestration stage receives only a compact candidate pool. The maximum candidate budget K controls the number of top-ranked Agent Cards presented to the LLM. Let A = {AC1, AC2, . . . , ACN} denote a registry of N Agent Cards. Let Sa be the structural- signal set of Agent Card a and Sq the corresponding signal set for query q. SSR first identifies the Agent Cards sharing at least one structural signal with the query, Cq = {a ∈A : Sq ∩Sa̸ = ∅}. (1) After ranking Cq, the candidate pool presented to the LLM is Pq = TopK(Cq, K), (2) with |Pq| = min(K, |Cq|) ≤K. (3) Thus, K is a maximum candidate budget rather than a required pool size. SSR does not add non-matching Agent Cards when fewer than K candidates are available; if Cq = ∅, then Pq = ∅. The two sets therefore serve different purposes: Cq contains the Agent Cards explicitly considered for scoring, whereas Pq contains the top-ranked Agent Cards presented to the LLM orchestrator. The SSR solution consists of two main retrieval components described next. Section III-B defines how Agent Cards and queries are represented and scored through structural signals, while Section III-C describes how the ISI retrieves the candi- dates that must be scored and how the final candidate pool is ranked. B. Signal Extraction and Scoring The first component of SSR defines an explicit and traceable representation for Agent Cards and queries. A structural signal is a lexical unit extracted deterministically from capability- bearing fields such as an Agent Card’s name, description, declared skills, capability tags, examples, or tool descriptions. Here, structural refers to signal provenance from explicit fields of the agent representation, not to syntactic or latent semantic structure. Because retained signals remain individually identi- fiable, each retrieval score can be traced to the matched signals that contributed to it. Agent Cards and queries use the same deterministic nor- malization procedure. Text is lowercased, alphanumeric units are extracted with [a-z0-9]+, tokens shorter than two characters and fixed stopwords are removed, and the retained sequence generates unigram and consecutive-bigram signals. Duplicate signals are removed, so scoring uses binary signal presence rather than term frequency. Each representation contains at most 64 signals. If more are available, unigrams are retained first in decreasing token- frequency order with lexical tie-breaking; bigrams are then considered in lexicographic order.
