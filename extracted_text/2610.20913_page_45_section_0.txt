TransX: Technical Report Long-history modeling and reusable behavioral state. Industrial recommenders amortize behavioral computation through persistent user state, selective history access, and candidate-independent prepro- cessing. SASRec and BERT4Rec established self-attentive and bidirectional history modeling (Kang and McAuley, 2018; Sun et al., 2019); industrial systems extend this line toward longer histories, high candidate fanout, and serving constraints. MIMN/UIC maintains behavior-triggered user memory (Pi et al., 2019); SIM and TWIN select target-relevant history, with TWIN V2 adding offline clustering (Pi et al., 2020; Chang et al., 2023; Si et al., 2024); TransAct combines realtime and batch representations (Xia et al., 2023). HSTU is particularly close in causal sequential transduction and M-FALCON’s candidate-side amortization (Zhai et al., 2024); LONGER reduces sequence cost through token merging and cached attention (Chai et al., 2025); and SequenceO1 separates reusable compressed sketches from target-conditioned reasoning (Guan et al., 2026a). TransX builds on this direction by exposing behavior-memory resolution as an independent scaling coordinate and by separating mutable continuation state from published behavior-memory KV. This runtime state also differs from LMN’s shared trainable memory parameters (Lu et al., 2025). Scaling architectures and compute allocation. Wukong and RankMixer scale feature interaction (Zhang et al., 2024a; Zhu et al., 2025); OneTrans unifies sequence and feature interaction within one Transformer (Zhang et al., 2025), whereas TransX preserves the boundary between candidate-independent behavioral construction and candidate-conditioned fusion. This operator view is a comparison lens, not a claim that these architectures are strict special cases of TransX. Their internal operators map to different choices for, or collapses of, encoding, memory, and candidate-conditioned interaction, without implying plug-and-play compatibility. Sequential scaling studies examine model and data size (Zhang et al., 2024b); MixFormer and UniScale also study component balance (Huang et al., 2026; Yu et al., 2026). LLaTTE is especially related in allocating asymmetric compute between an asynchronous user model and an online ranker through a fixed representation interface (Xiong et al., 2026). TransX broadens this allocation question to behavioral-encoder compute 𝐶𝐸, behavior-memory budget 𝐵𝑀, and candidate-conditioned fusion compute 𝐶𝐹, asking how their relative returns change with behavioral support and supervision. The focus is a controlled allocation surface rather than a universal one-dimensional scaling law: it exposes both where capacity is placed and how much behavioral state is available to prediction, while the execution design controls when each computational role is executed. Training reuse and capability specialization. RecD deduplicates features end to end (Zhao et al., 2023a); MTGR and Douyin batching share user-side computation across grouped examples (Han et al., 2025; Guan et al., 2026b). OneTrans-V2 and TransX both exploit causal prefix sharing (Cao et al., 2026); OneTrans-V2 uses it within a jointly optimized retrieval-to-ranking cascade, whereas TransX couples prefix reuse to bounded event memory, candidate-fanout execution, and subsequent capability specialization. MTFM and LUM likewise share behavioral representations across scenarios or tasks (Song et al., 2026; Yan et al., 2026). Generative recommenders use semantic-ID retrieval or slate generation (Rajput et al., 2023; Jiang et al., 2019); TransX treats these as capability-specific output geometries over the shared behavioral interface. In TransX’s reference recipe, core response-prediction training learns the behavioral backbone; post-training freezes the encoder and memory construction and optimizes capability-specific readers and heads. Partial adaptation and joint training remain alternatives; KV projections can remain capability-specific. Amortized serving and execution clocks. MIMN/UIC updates state on behavior events; HSTU and OneTrans reuse causal computation across candidates or requests. LLaTTE refreshes user representations on selected high-value behavior events, whereas SOLARIS speculatively caches user–item interaction features (Xiong et al., 2026; Liu et al., 2026). PagedAttention/vLLM and DistServe address KV management and prefill/decode disaggregation (Kwon et al., 2023; Zhong et al., 2024).
