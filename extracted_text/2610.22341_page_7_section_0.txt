The final group in (a) compares Claude Design with 3DCodeVerse Harness, both using Claude Opus 5.5. 5.2 FINE-TUNING OPEN MODELS ON 3DCODEVERSE-2M Setup. We fine-tune Qwen3.5-9B and Qwen3.8-27B with LoRA (Hu et al., 2021) in LLaMA- Factory (Zheng et al., 2024) on mixtures drawn from 3DCodeVerse-2M (Appendix C.1) and compare the resulting models with their respective pretrained checkpoints. Evaluation spans 805 fixed tasks across six suites: 212 text-to-Blender tasks from 3DCodeBench (Gao et al., 2026b) and five test splits drawn from 3DCodeVerse-2M: Blender (103 procedural objects), CadQuery (200 mechanical parts from DeepCAD and Articraft), OpenSCAD (50 Thingiverse models), GLSL (200 Shadertoy shaders), and Three.js (40 single-object scenes). Each task pairs a natural-language request with a reference program. Executing the reference program produces the evaluation target: a mesh for the four 3D suites, a rendered frame for GLSL, and a page screenshot for Three.js. All models receive the same request and per-dialect system prompt without examples, are decoded at T=0.7 with one seed, and have every output executed in the dialect’s pinned runtime (Appendix C.3). We report the execution rate (Table 2) and fidelity to the target (Table 3): F@0.05 between the generated and reference meshes, and DINOv2-L similarity between clay renders of the two meshes from four fixed views; failed programs score zero on both.
