AIME Agent Scaffold Optimization The outer model optimizes a Python agent scaffold that calls a fixed gpt-4.1-nano-2025-04-14 solver. All optimizers start from the same single-query scaffold and share the task environment, tools, and evaluator. Each search has a four-hour time limit and a maximum of 1,000 interaction steps, with a context limit of 200,000 tokens and an output limit of 65,536 tokens per step. The scaffold can modify prompting, calling, verification, voting, and answer-extraction procedures, with at most ten inner-model calls per problem. Initial uses one solver call, while Majority@5 takes a majority vote over five independently sampled answers. Development uses all 30 problems from AIME 2025, with three evaluations per problem for each candidate scaffold. The outer model receives aggregate accuracy, call counts, and sanitized error summaries. Exact-request response caching is used during development to reuse inner-solver responses to identical requests. After search, the selected scaffold is frozen and evaluated using fresh solver calls on AIME 2023, 2024, and 2026. Each held-out year contains 30 problems and is evaluated three times; these years provide no feedback for scaffold development or selection. Thus, each optimizer contributes one frozen scaffold, with three evaluation repetitions per year. Accuracy is the fraction of answers that exactly match the reference integer answer; missing or incorrectly formatted answers count as incorrect. Table 11 reports development accuracy, accuracy for each held-out year, the mean across the three held-out years, and mean inner-model calls per problem on the held-out evaluations. Each annual accuracy averages the three evaluations of that year’s 30 problems. Solver-call efficiency after SFT. The scaffold optimized by MLExpert-SFT achieves 38.1% held- out accuracy with 3.51 solver calls per problem, approaching the 40.0% achieved by Kimi-K3 with approximately 59% fewer calls. It also outperforms Majority@5, which reaches 24.8% with five calls per problem. MLExpert-SFT therefore improves held-out accuracy over fixed majority voting while using fewer solver calls, suggesting that its optimized scaffold uses the solver more effectively. These results indicate that SFT already supports effective scaffold optimization across held-out years. Further gains from WIRL. WIRL raises held-out accuracy from 38.1% to 43.7%, a gain of 5.6 percentage points, with improvements on all three held-out years. The resulting scaffold uses 8.40 calls per problem, compared with 3.51 for MLExpert-SFT and 8.65 for Kimi-K3. With a similar number of calls to Kimi-K3, MLExpert exceeds its 40.0% accuracy, while GLM-5.3 achieves 48.1% with 9.39 calls. The SFT and RL results therefore offer different accuracy–call trade-offs: SFT yields an effective scaffold with fewer calls, while further RL finds a more accurate scaffold that uses more calls.
