C.3 EVALUATION PROTOCOL Code extraction and geometric evaluation for open models. For open-model evaluations (§5.2), generated responses pass through a deterministic code extractor that strips reasoning blocks, collects fenced code blocks (including trailing unterminated blocks), and ranks candidates by dialect mark- ers, fence annotations, and AST syntactic validity. This extraction step is essential for pretrained reasoning checkpoints: with thinking enabled, 52 of 212 responses from the zero-shot 27B model omit markdown fences and 74 place auxiliary snippets after the main program, whereas fine-tuned models adhere strictly to the single-block output contract (100% single-fence compliance). Extracted programs execute inside the dialect’s pinned runtime under a 300 s timeout. Resulting meshes are exported to GLB, centred at the origin, normalized to unit maximum extent, uniformly sampled at 10,000 surface points, and evaluated via symmetric Chamfer-L2 distance and F-score at thresholds τ ∈{0.05, 0.10} (taking the best alignment across the four 90◦yaw rotations; ground-truth reference scripts self-verify at Chamfer ≈0.016 and F@0.05 ≈1.0). Object prompts and compared systems. The 3D object benchmark comprises 100 Three.js generation prompts stratified across three specification levels—21 concise (simple), 17 moderate (medium), and 62 richly specified (detailed) prompts—testing synthesis across varying levels of structural and stylistic complexity without prescribing explicit metric dimensions or part lists. All systems are evaluated under a uniform single-request deliverable protocol: each workflow receives the identical user prompt string and delivers a final executable program, which is rebuilt and scored by our common evaluator. For commercial product baselines such as Claude Design (powered by Claude Opus 5.5), we evaluate its released reference outputs directly in our unified evaluation pipeline without modification. We evaluate Gemini 3.8 Flash and Claude Opus 5.5 against their respective native baselines on the primary 60-prompt benchmark, and evaluate Claude Sonnet 5, GPT-6 Luna, and GPT-6 Astra on a balanced 30-prompt subset (10 prompts per specification level). Each native baseline (Table 14) synthesizes code in a single pass using its standard coding-agent backend (high reasoning effort for Claude Opus 5.5 and Sonnet 5; medium effort for GPT-6 Astra; direct API for Gemini 3.8 Flash), whereas 3DCodeVerse Harness wraps the identical backbone model with structured planning, spatial tools, and automated verification.
