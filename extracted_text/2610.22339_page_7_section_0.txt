Each problem instance contains a Lean source x with one target proof hole. At inference round t, the prover Mθ parameterized by θ generates a complete Lean source candidate Yt conditioned on the problem x, the preceding candidate Yt−1, the latest Lean compiler diagnostic et−1, optional retrieved declarations Rt, and optional failure-memory feedback mt−1 as: Yt ∼Mθ (x, Yt−1, et−1, Rt, mt−1) . (4) The Lean compiler executes Yt and returns either a successful elaboration or a structured diagnos- tic. Each failed candidate is followed by one revision conditioned on the latest verifier feedback, producing a single candidate lineage. Building on the common practice of incorporating verifier feedback into iterative proof refinement, we investigate whether LEANGRAPHSEARCH can provide useful retrieval feedback that further improves proving performance. After a failed attempt, the LLM optionally generates five search queries from the problem x, current candidate Yt, and Lean diagnostic et. Each query invokes LEANGRAPHSEARCH and returns K declarations. LEANGRAPHSEARCH deduplicates the re- trieved declarations and inserts them next to the previous candidate and diagnostic in the revision prompt. A candidate succeeds when the complete Lean source elaborates without a live sorry and satisfies the proof-hole integrity contract. Optional Formal Failure Memory. Our preliminary experiments show that the LLM prover is likely to repeat the same or similar failed proofs across multiple rounds, wasting the inference budget and limiting exploration of alternative proof strategies. To mitigate this issue, we introduce a failure memory, which augments the agentic loop with problem-local records of recurrent formal states. For each stable failure, we construct a structured failure state as: st = (ct, ¯et, Gt, Lt, τt) , (5) where ct is the error category, ¯et is the normalized diagnostic, Gt contains unresolved goals, Lt summarizes the local context, and τt is the inferred failing tactic. A deterministic serialization and SHA-256 (NIST, 2015) hash identify repeated states. When a state recurs, the next prover call receives a compact dead-end record and the failed mod- ifications that led to it, encouraging the prover to explore an alternative repair. The memory also reuses deterministic failures of identical candidates and caches retrieval responses by formal proof state and normalized query. These interventions reduce repeated compilation and retrieval while preserving the single-lineage search structure. 5.2 SETUP Benchmarks and Metrics. We consider three benchmarks with diverse fields and complexities: FATE-H (Jiang et al., 2026), MathlibMPR-Prop (Gao et al., 2026) and Lean-IMO-Bench (Kung et al., 2026). FATE-H contains 100 graduate-level algebra problems, MathlibMPR-Prop contains the 50 propositions from MathlibMPR that admit a uniform tactic-mode interface, and Lean-IMO- Bench contains 30 Basic and 30 Advanced Olympiad problems. For each problem, we allow the backbone model at most 32 reflection turns with one optional query assigned to each turn, and report pass@k for k ∈{8, 16, 32}, where k represents the number of reflection turns. We also report the normalized total cost over each group to assess cost effectiveness. Baselines. To control evaluation costs while retaining representative baselines, we mostly compare LEANGRAPHSEARCH with the state-of-the-art LeanSearch v2 (Gao et al., 2026) and the vanilla backbone LLM without retrieval.
