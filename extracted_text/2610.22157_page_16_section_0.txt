In this work, we propose a modified PI-DeepONet architecture that changes how input functions are processed within the Branch network. The key observation is that, in the Vanilla implementation of PI-DeepONets, the Branch network is evaluated repeatedly at every collocation point, even though the input function itself does not change. Addressing this redundancy yields our proposed alternative (ATenH), in which the Branch network is evaluated once per input function and its encoding is reused across all collocation points. This modification comes with the constraint that all output functions must be evaluated at the same number of collocation points. In a data-driven setting this may be restrictive because the amount of labelled training data that is available will likely vary between samples. However, DeepONets are increasingly being adopted within physics-informed frameworks (PI-DeepONets), where this limitation does not apply – collocation points can be freely generated and chosen. By reducing the dimensionality of the Branch network input tensors, the number of operations required by this subnetwork is substantially decreased. As the Branch network encodes the input functions, which may have a high number of degrees of freedom to adequately represent boundary or initial conditions, this reduction directly lowers the dominant computational cost. Importantly, the modified architecture performs the same underlying mathematical operations as the original one and, as a result, achieves comparable predictive accuracy while significantly reducing training time. For 1D linear advection, the average training time is 314s and 276s for the Vanilla and ATenH architectures, respectively, while for 2D linear advection the corresponding times are 11800s and 3360s. Most notably, the 3D linear advection problem exposed a fundamental practical limitation of the Vanilla PI-DeepONet implementation. It exceeded the available GPU memory and could not be trained on an NVIDIA A100 GPU, whereas the ATenH architecture completed training in approximately 39 hours and achieved an average relative error of 5.44%. The experimental results demonstrate that the proposed modification does more than reduce training time: by lowering memory requirements, it enables classes of higher-dimensional PI-DeepONet problems that are otherwise computationally infeasible on the same hardware. Consequently, extending PI-DeepONets to higher-dimensional problems is not simply a matter of applying the existing formulation to larger problems; careful architectural design is essential for maintaining computational tractability. A theoretical cost model was developed to quantify the training-time scaling of both architectures with respect to the number of collocation points and the number of input functions. This model predicts linear scaling with both number of collocation points and input functions for both architectures, but with larger prefactors for the Vanilla architecture, implying steeper scaling. The empirical results for the 1D and 2D linear advection problems confirm this behaviour. The agreement between the theoretical scaling laws and the empirical measurements suggests that the observed performance gains arise primarily from differences in the computational structure of the two architectures rather than implementation-specific effects. The model also predicts an asymptotic constant speed-up factor, which is reinforced by the experimental profiles seen in Figure 6; however, the observed speed-ups are smaller than the theoretical values (1.14× vs. 1.64× in 1D, and 3.49× vs. 7.46× in 2D). Despite the quantitative discrepancies, the consistency in qualitative scaling behaviour reinforces the observation that the theoretical model captures the dominant computational trends governing both architectures. Some discrepancy is expected, as the cost model accounts only for the number of summed products in forward and backward passes and therefore neglects implementation- dependent overheads such as memory allocation, activation function evaluation, data movement, automatic differentiation graph construction, and optimiser updates. 5
