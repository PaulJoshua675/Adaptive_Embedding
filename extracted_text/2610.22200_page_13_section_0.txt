Following the evaluation protocol of the GPT-6 Astra release (OpenAI, 2026c), we evaluate on the 82-task offline subset of OSWorld-v2 (v2.1) (Yuan et al., 2026), which excludes the 26 tasks that require internet access and so keeps results independent of external websites at run time. The main comparison covers eight models: Claude Opus 5, GPT-6 Astra, Gemini 3.8 Flash, Qwen3.8-Max, Qwen3.8-Flash, Kimi K3, DeepSeek-V4.1-Flash, and GLM-5.3-Flash. Execution Configurations. The CUA baseline uses GUI-only interaction with batched actions enabled. The full Open Generalist CUA (OpenGCUA) configuration combines code execution over GUI and shell operations with the model-initiated workflow control and harness-managed context policies described above. For the ablations of code execution, harness-to-model decision transfer, and harness-managed context policies, we explicitly specify which components are enabled in each setting. Metrics. We evaluate task performance and execution efficiency. Following OSWorld-v2, we report binary success and partial-credit scores to measure full and partial task completion, respectively. We measure efficiency by mean steps per task and mean output tokens per task. 3.3.2 CUA versus GCUA We compare the conventional GUI-only CUA setting with the full OpenGCUA configuration to examine the performance and efficiency gains from moving toward generalist computer use. OpenGCUA gives the model greater control over what to observe, how to act, and how to organize its work. The CUA baseline already supports batched actions, while OpenGCUA combines code execution with harness-to-model decision transfer. OpenGCUA improves task scores and reduces steps across all eight models.
