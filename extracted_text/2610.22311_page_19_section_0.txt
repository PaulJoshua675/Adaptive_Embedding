C ASYNCHRONOUS FRUSTUM SLAB CONSTRUCTION The geometry pipeline would be expensive if it were inserted serially between generated chunks. In a synchronous implementation, chunk c must be denoised, decoded, reconstructed into depth and pose state, inserted into the frustum slab table and multiwarp cache, aligned with the next target cameras, and scored before chunk c + 1 can denoise. The reconstruction and frustum slab preparation path is on the same order as one DiT denoise step in our setting, so serial execution would hide the attention-kernel gains. Velox relaxes this dependency with a two-chunk freshness lag. Target chunk c consumes a Velox state built from frustum slabs through chunk c −2, while the worker prepares states for later chunks. The state remains self-consistent: each worker task first inserts exactly one decoded chunk into the frustum slab table and multiwarp cache, then scores that table against the target chunk’s latent cameras. Chunks before the first available Velox state run dense attention, so the method never consumes an uninitialized route. The implementation uses one Python worker thread and one dedicated CUDA stream. The worker is the sole writer to the frustum slab table, pose aligner, multiwarp frame cache, and sparse-attention context. The main denoising thread submits a geometry task after a chunk decode and receives a future keyed by the target chunk. Immediately before chunk c denoises, the main stream waits on the future’s CUDA event if the worker has not already finished, then consumes the prepared geometric and importance states. This wait is a device-side stream dependency. There is no host-wide synchronization in the hot path. Each geometry task performs four operations. First, the reconstructed frames are passed through the streaming reconstruction backend to update depths, poses, confidence, and masks. Second, the relative alignment maps target camera-control poses into the reconstructed frame and refreshes stored slab cameras under the current bridge. Third, valid depth samples are converted into per-block frustum slab primitives and inserted into the versioned frustum slab table, while first and last frame depths are cached for multiwarp. Fourth, the sparse context warps cached depths into the target cameras, builds Q frustum slabs, scores OBB overlap against historical frustum slabs, computes coverage, and materializes the geometric state consumed by soft fusion at each attention layer. The implementation also moves VAE decode off the denoise critical path with a side stream, prewarms the worker thread’s cuDNN handle, prewarms segmentation and sparse-attention kernels outside the measured interval, and skips frustum slab scoring for the final chunk because no later denoise consumes it. Frames are moved to CPU after decode and copied back on the worker stream, avoiding extra GPU residency while the main stream denoises. All reported timing results use a single NVIDIA H200. The async worker and the DiT denoiser share that one GPU. Memory reconstruction is not offloaded to a second device. A second GPU could reduce CUDA-stream contention and further improve end-to-end time, but it is not part of the reported measurement protocol.
