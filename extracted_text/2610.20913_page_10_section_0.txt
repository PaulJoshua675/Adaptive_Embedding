TransX: Technical Report 3 Model Architecture The central architectural challenge is to expose computation at the granularity at which capacity can be scaled selectively and execution can be amortized, without sacrificing candidate-specific access to behavioral evidence. TransX addresses this through three coupled components: a causal sequence encoder that transforms the evolving behavioral history, a bounded behavior memory that controls the state exposed to prediction, and candidate-conditioned fusion that reads this shared state for each candidate. Figure 3 illustrates the resulting architecture. Figure 3. TransX’s Encoder-Transducer architecture overview. A causal behavior encoder produces a shared trajectory representation reused across serving events. At each event, a cutoff-specific global–local memory is projected once into shared KV state, while candidate-specific queries independently cross-attend to that memory through candidate-fanout cross-attention.
