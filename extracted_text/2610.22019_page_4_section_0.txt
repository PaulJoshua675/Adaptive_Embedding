Preprint us with 12.1 million PRs and 200 billion to 2 trillion tokens depending on how much repository context we include in each example. For issue-linked PRs, a structured LLM judge additionally checks that the issue and the patch match, and PR-only examples are filtered with deterministic rules (Appendix A.1). Repositories. Pretraining corpora have historically presented code as individual files rather than whole repositories, and even when files from one repository are packed together, a short pretraining context holds only a small part of it. Agents, however, work inside repositories far longer than that and must use code defined far from where it is called. Midtraining is where the model first reads whole repositories and predicts code that depends on files tens of thousands of tokens earlier. This helps most when the files actually depend on each other, and in many repositories they do not, since many are collections of scripts, exercises, or snippets that never import one another. We start from the repositories in the Nemotron 3 pretraining corpus (NVIDIA, 2025), build an import graph for every repository in 14 languages, and keep only repositories in which at least 20% of code files have an import edge to another file in the repository (10% for Ruby). Kept repositories are serialized with the top-level README first and connected files next to each other, and packed at 256K, with longer repositories split between connected components rather than truncated, giving about 104B tokens. Compared to alphabetical ordering, dependency ordering better separates stronger from weaker models. It lowers bits-per-byte for stronger models and raises it for weaker ones, which suggests that it exposes cross-file structure that weaker models have not yet learned. The languages, filters, and blend weights are listed in Appendix A.2. Diff data. Much of software engineering is changing existing code, such as making an edit that stays consistent across several files or keeping track of what a file looks like after a long series of changes. Repository snapshots only show code in its final state, so we build two kinds of examples from commit histories. Multi-file edits take a merged pull request, show the model the affected files before the change, and train it to produce them after the change. We keep only changes whose files are linked in the import graph used for the repository data, so that the edits are coupled. Code- evolution documents give the initial state of a file, the sequence of real commits that changed it from oldest to newest, and its final state. This trains the long-range state tracking that LoCoDiff measures (Mentat AI Team (AbanteAI), 2025). Histories range from a single commit to several dozen. Diff headers, commit hashes, authors, and dates are masked from the loss. Sources, filters, and statistics are in Appendix A.3. Build and CI logs. Agents constantly read logs, stack traces, and build output, but PR data lacks the environment’s response, so we add raw system logs from the full LogHub archives (Zhu et al., 2023) and CI/CD logs from GitHub Actions run logs and workflow-file histories (Moriconi et al., 2025; Cardoen et al., 2024), plus a small curated slice pairing log windows with diagnoses (Ap- pendix A.4). Agentic traces. We include agent trajectories to teach interaction patterns that natural software artifacts lack, such as multi-step tool use, testing changes, and recovering from failures. These trajectories are separate from the SFT data. The highest-quality trajectories are reserved for SFT, and midtraining puts the rest to use, including trajectories from earlier teacher models and tasks that do not fit post-training. The corpus used in our blend contains about 39B tokens (over one million trajectories, about 500K distinct queries, and 30M tool calls, including SWE-Zero and SWE-Hero trajectories (Ludwig et al., 2026)). A small portion of the agentic midtraining blend consists of data contributed by Perplexity as a partner in the Nemotron Coalition. The full trace corpus covers more than ten agent scaf- folds, including OpenHands (Wang et al., 2025), OpenCode, SWE-agent (Yang et al., 2024), Codex, Claude Code, and Terminus, across software engineering, terminal use, search, and general tool use, because traces from a single scaffold transfer poorly to others (Cao et al., 2026). Each trajectory keeps its scaffold’s instructions and tool definitions and is rendered in the Nemotron chat template. Appendix A.5 gives the statistics and distributions.
