In contrast, we keep the task-executing LLMs frozen and train an external agent to supervise execution and steer the system back toward its overall goal when drift occurs. 2.2 Goal Drift Mitigation To mitigate goal drift during long-horizon execution, prevalent agent systems (DeepSeek-AI, 2026; Young, 2025; OpenAI, 2025) employ planning and verification to support reliable execution. Planning decomposes a goal into manageable subgoals that guide subsequent actions (Wang et al., 2023). Verification checks whether goals have been met before an agent declares completion, prompting further execution or revision when needed (Anthropic, 2026b; Lopopolo, 2026). However, a plan does not ensure reliable execution (Sinha et al., 2026), while verification may uncover deviations after substantial effort has already been spent. These limitations motivate a natural on-the-fly supervision design, where an external supervisor monitors intermediate execution and intervenes when goal drift occurs. Recent work explores this idea with a primary focus on detection, identifying when and where an agent goes wrong (Zhang et al., 2025; 2026; Baidya et al., 2026). SupervisorAgent (Lin et al., 2026) takes a step toward correction by prompting an external LLM, but it targets easily fixable issues such as errors and repetitive actions. Goal drift, however, is more challenging to detect and correct in real time, as it emerges gradually from locally plausible actions. In this paper, we address this challenge with a steering agent that jointly learns drift detection and correction through reinforcement learning. 3 Learning to Steer LLM-based Agent Systems In this section, we begin by discussing goal drift that happens in both single-agent and multi-agent systems (Sec- tion 3.1). Then, we introduce our steering agent design (Section 3.2) and the reinforcement learning algorithm (Sec- tion 3.3). 3.1 Goal Drift in LLM-based Agent Systems An LLM-based agent executes a task with an overall goal g by interacting with an environment (Yao et al., 2023). At each step, the agent generates an action conditioned on g and the interaction history, and receives environment feed- back. A multi-agent system distributes this process across specialized agents, where each agent handles a temporary subgoal derived from g, such as retrieving evidence or verifying an answer, and hands its output to subsequent agents. In both settings, execution unfolds as a sequence of temporary subgoals in service of the overall goal (March & Simon, 1958). In LLM-based agent systems, goal drift appears when a temporary subgoal dominates the overall task goal (Arike et al., 2025), leading to unproductive actions that might be locally reasonable. Goal drift reduces execution efficiency by consuming resources on actions that contribute little to task completion. If the deviation remains uncorrected, the agent system may never finish the task or finish it with an undesired outcome. For example, in multi-hop search tasks (Ho et al., 2020; Yang et al., 2018), the agent needs to retrieve several distinct pieces of evidence and combine them to answer a question, which involves a sequence of temporary retrieval subgoals. A common failure mode is that the agent keeps searching over the same topic when key information has already been obtained. As shown in Fig. 2(a), the first search already identifies the actress required to answer the question. The agent spends three more searches on the same film instead of moving on to the next step, consistent with observed patterns of redundant and unproductive search (Liu et al., 2026a). In a multi-agent system, where specialized agents collaborate on a complex task, goal drift arises similarly when an agent prioritizes its role objective over the overall task goal. A commonly observed failure mode is over-rejection, where a verifier falsely rejects results that already satisfy the task goal (Huang et al., 2024; Stechly et al., 2025; Xu et al., 2025). As shown in Fig. 2(b), the verifier repeatedly rejects the answers the searchers have delivered, leading execution to repeated revision rounds that can turn a successful execution into a failure.
