Sensitivity design. The variant core differs from the frozen core in exactly two places: the function name, and vd=fitness<1e7 becoming vd=fitness<Inf. The build reverses both edits and requires byte-exact reproduction of the frozen source before the variant is written, so no other change can be present. Seeds, initial populations, population size, iteration count and the 1040-evaluation budget are unchanged, and the run reuses the archived seed map. Each run was additionally required to return 1040 evaluations, 25 iterations, an FE history of length 1040 and a terminal FE history value equal to the reported best. Negative controls. The 540 runs in which the frozen audit had recorded zero finite activation were run through the variant and all 540 reproduced the frozen terminal value exactly. The intervention therefore changes behaviour only where the threshold was mechanically active, which is what makes the 180 of 720 active runs interpretable as a controlled contrast. The quantities differ because log10 med(V)−log10 med(F) is not med[log10Vi −log10 Fi]; the matched-seed design makes the latter the one that supports inference. Paired analysis. Errors are floored at 10−8 before taking logarithms, the same convention used elsewhere in this work. Scope. The fctr = ∞run is a post-campaign sensitivity variant and a mechanism validation, not a replacement op- timizer campaign and not a redesign of REMBGO. A rank- or quantile-based eligibility rule would remove the scale dependence and is identified here only as a possible future refinement.
