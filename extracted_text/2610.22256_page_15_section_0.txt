BitSparse: Compact Activation Storage C.2 Forward and backward algorithm Algorithm 1 sets out the forward and backward passes of the fused ReLU–linear autograd function. The forward pass evaluates the activation in place, compresses it, and then performs a dense matrix multiplication, so the forward computation is unchanged from the dense baseline. Only the cached activation is compressed. The backward pass decompresses the activation and computes the weight gradient directly, and applies the activation derivative from the stored bitmask alone, so the dense activation is never reconstructed for the input gradient. Algorithm 1 BitSparse fused ReLU–linear layer. Require: preactivation Z ∈RM×N, weight W ∈RD×N Ensure: output Y ∈RM×D, cache holding the compressed activation 1: procedure FORWARD(Z, W) 2: H ←ReLU(Z) ▷in place 3: cache W 4: Hs ←COMPRESS(H) ▷per-tile bitmask, compact positive values, and prefix offsets; optional sign-bit packing 5: Y ←HW ⊤ ▷dense matrix multiplication 6: end procedure 7: procedure BACKWARD(G) ▷G = ∂L/∂Y ∈RM×D, the upstream gradient 8: retrieve W and Hs from the cache 9: ∂W ←SPARSEPRODUCT(G⊤, Hs) ▷dense–sparse product against the compressed activation 10: if ∂Z is required then 11: ∂H ←GW ▷dense matrix multiplication 12: ∂Z ←MASKWITHBITMASK(∂H, bitmask(Hs)) ▷in place, applying ReLU′(Z) from the bitmask alone 13: else 14: ∂Z ←∅ 15: end if 16: release Hs 17: end procedure The stored values are BF16 or FP8. For FP8 the per-tensor scale is carried in the sparse metadata and applied to the matrix products; sign-bit packing is an independent option that removes the redundant sign bit, as described in Section 3.3. The ReLU2 case follows the a similar structure, with the stored values squared when reconstruction is required and MaskWithBitmask mask replaced with a masked multiplication. D Experimental setup D.1 System setup All experiments were implemented using PyTorch 2.14 with Triton 3.7.1 in Python 3.14. All experiments were run on an NVIDIA RTX 3090 24GB with the exception of the FP8 MLP and Nemotron-H experiments, which were run on an RTX 5090 32GB, for the FP8 support and extra VRAM. CompAct used the official implementation. The nvCOMP baseline uses version 5.3.0.16. Random seed 0 is used for all experiments. Timings are averaged over 5 runs, after warmup. D.2 Baselines Activation Checkpointing. Activation checkpointing Chen et al. (2016) reduces the amount of memory required by recomputing activations in the backward pass, rather than storing them in the forward pass. This trades off storage for computation, since certain layers will have computations repeated twice in a training step. PyTorch supports activation checkpointing natively. In our method, we checkpoint the full feedforward block, including the RMS norm layer. Lossless compression. Lossless compression can be used to reduce the size of the saved activations. The activations are compressed before being cached, and decompressed in the backward pass when needed. The nvCOMP NVIDIA Corporation (2026) library provides highly optimized GPU-native codecs for this task, including LZ4 Collet (2011), Zstd Collet and Kucherawy (2021), Bitcomp, and Cascaded.
