Judge deployment. The judge is Qwen3.5-122B-A10B (FP8), served with vLLM (tensor parallelism 4, max context 32,768, CUDA graphs enabled). In the greedy main experi- ments, the target model and all judge-side calls—scoring, feedback, backward, and context rewriting—use greedy decoding. In the sampling experiments, judge scoring remains greedy with disk caching, while feedback, backward, and context rewriting use temperature 0.7, top-p 0.95, and no caching. Scoring and E-step calls use separate engine instances. Both engines disable the judge’s thinking mode. The judge never sees the gold answer; its prompt requires it to independently solve the problem, score 0–10, and—critically—produce feedback without revealing or hinting at the final answer (numbers, letters, or expressions), which keeps the E-step gradient estimate free of answer leakage. An additional regex filter rejects any rewritten context that leaks a concrete answer, retaining the previous context in that case. Answer-extraction fix and rescoring. An early version of the math boxed scorer hard- extracted digits from non-numeric boxed answers (e.g., 7π → 7), systematically under-reporting MATH-500 accuracy. After fixing the extraction cascade, we rescored all affected stored responses with the corrected rule (flips occur only on MATH-500; GPQA/MMLU/GSM8K/AIME are unchanged), and all numbers in this paper use the rescored values. The rescored greedy baseline of Qwen3-8B on MATH-500 (75.0) is consis- tent with the independently run sampling baseline (79.6±0.4 at temperature 0.6), validating the fix. Degenerate-generation handling (Llama). Llama-3.1/3.2 occasionally enter repetitive loops, filling the entire generation budget with a short cycle. Beyond the standard exact- cycle detector (10–30 token loops), we add an information-saturation detector: once a generation exceeds 4,000 tokens, it is terminated early if the novel-token rate over each of the last three 200-token windows falls below 0.10 relative to a 400-token baseline window.
