B.4 INSTRUCTION AND EVALUATOR SYNTHESIS DETAILS The primary task-synthesis pipeline instantiates states through the application–artifact compatibility graph. The pipeline then follows a one-way information flow: application and artifact configura- tions determine the initialization context; the Exploration Agent produces a structured instruction proposal and textual success conditions; the independent Evaluator Agent compiles the frozen con- ditions into rule-based or visual checks; and each independently validated instruction-evaluator pair enters the task pool. Application-centered initialization. For each application, we record a canonical name, version, supported artifact types and file formats, launch commands, and initialization templates, and use these fields to build the application–artifact compatibility graph. Each synthesis episode first restores a controlled VM snapshot and samples a primary application, then selects zero or more compatible artifacts through the graph according to the application’s initialization templates. For every sampled pre-existing artifact, initialization creates a VM-resident, evaluator-only golden copy before task execution while leaving the original path as the active task target; this copy is bound to the task con- figuration and may serve as the expected reference in subsequent content or structural comparisons. The system then provides the Exploration Agent with application metadata, exact file paths, launch configuration, an application tutorial, global application memory, and an initial screenshot. The following partial PyCharm configuration illustrates how application metadata connects applica- tion initialization with artifact-library sampling. The version field fixes the application version assumed by task synthesis, trajectory collection, and evaluator implementation, while type declares the artifact or project types that the application can directly consume. The two entries in commands are alternative initialization templates: the first launches an empty application, and the second launches the application with a sampled artifact. The position-aligned values in random are normalized into initialization probabilities; hence [10, 90] assigns approximately 10% probability to an empty PyCharm launch and 90% to a file- or project-backed launch. When the second template is selected, the system randomly samples an absolute file path whose type is compatible with type from the artifact library and substitutes it for PATH before executing the command. The related app and related type fields retain compatibility relations among applications and artifact types for selecting conventional companion applications and for the graph-guided cross-application prototype. 23
