In this section, we examine the options in greater detail through two experiments. First, we consider the computational perspective, measuring the duration of the adaptation step. Secondly, we compare the different options on a set of benchmark problems As a baseline, we use the official CMA-ES implementation from the Pycma Python library (version 4.2.0) in both experiments.4 In order to get comparable results, active update is disabled in all algorithms, and all parameters, such as µ and λ, are kept consistent betwen the compared packages. For ModCMA (version 1.1.0), only the matrix adaptation mechanism is modified; the other options are set to their default values (see Table 1). 8.1 Running Time We measure the median (single-threaded) running time for each algorithm to complete 1 000 generations. The objective function used is a d-dimensional ellipsoid, i.e., BBOB f2. For every d ∈{2, 3, 5, 10, 20, 50, 100, 200, 500, 1 000}, 15 runs are conducted. The runtime was measured using Python 3.10.12 on a desktop machine running the Windows subsystem for Linux (version 6.6.87.1) with a 12th Gen Intel i5-12400F CPU. Figure 1 (left) shows the median time in seconds for each algorithm to complete the required number of generations. The right figure shows the normalized time per update. This is added because the standard CMA (Covariance) does not update its strategy parameters at each generation. This is evident when comparing the relative performance of Covariance with the other options in the right and left figures. Especially for higher values of d, the time-per-update difference is much larger. Overall, the most computationally demanding matrix adaptation method is the Natural Gradient option based on xNES.
