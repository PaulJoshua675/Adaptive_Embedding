3DCodeVerse: Exploring 3D Worlds as Code Single-request autonomy and refinement horizons. The single-request protocol prohibits human- in-the-loop intervention: each system receives one user prompt with zero subsequent human edits or manual candidate cherry-picking, while permitting autonomous internal tool calls and verification passes. Our primary object benchmark evaluates single-round harness execution (T = 0 in the notation of §4), retaining the initial planned generation, interactive tool use, automated build repair, and final verification (using Gemini 3.8 Flash as planner and Gemini 3.1 Pro as in-loop judge for the Flash runs). Multi-round studies (T = 4) extend this autonomous loop with up to four closed-loop refinement rounds and automated post-run output selection under the same single user request. Independent evaluation judge. All Judge Scores and VLM Preferences reported in §5 are produced by a single frozen evaluation pipeline that applies the judgment architecture and track rubrics of Appendix A.4 independently of the generation workflow under test. Each delivered program is rebuilt from scratch in its pinned runtime, with failed builds scored zero, to extract geometric measurements, connectivity or kinematic-sweep telemetry, and canonical multi-view renders (fourteen shaded views plus clay views for objects, multi-pose sweeps for articulated mechanisms, authored and orbital views at two timestamps for scenes, and sampled frame sheets for graphics); Gemini 3.1 Pro then scores it three times. Three safeguards decouple evaluation from in-loop refinement: (1) clean-room rebuild and blind prompting, scoring every artifact against the raw user prompt and a prompt-derived checklist alone, with all harness-generated plans, internal checklists, and refinement histories stripped; (2) deterministic geometric caps, bounding scores via exact mesh connectivity and kinematic checks independent of VLM perception (Eq. 5); and (3) multi-metric validation, pairing Judge Scores with SigLIP-2 similarity and blind human pairwise preferences (§5), which consistently corroborate the rubric gains across all four tracks. Both human and VLM pairwise evaluations present the original user prompt alongside anonymized multi-view renders captured under matched camera poses, framing, and resolution. Evaluators judge overall preference on prompt adherence, structural plausibility, and visual craftsmanship, with ties counted as half a win; VLM preference additionally requires agreement across both presentation orders (§A.4). Human evaluations randomize left/right presentation order across a fixed, pre-registered prompt subset shared by all compared systems, with prompt-level bootstrap confidence intervals clustering repeated ratings at the task level. In end-to-end preference reporting, a valid executable artifact wins against a failed build and two failed builds tie, while conditional preference over mutually executing pairs is tracked alongside execution rate; transient provider outages are excluded from win/loss tallies. 26
