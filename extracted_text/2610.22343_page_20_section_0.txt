A.5.2 INPUT AND QUERY CONSTRUCTION Our method follows the balanced-resolution preprocessing rule of VGGT-Ω. It preserves the nomi- nal patch-token budget while adapting the height and width to the source aspect ratio and rounding both dimensions to multiples of the 16-pixel patch size; a centered crop is applied only when needed to limit extreme aspect ratios. The resulting evaluation rasters (height×width) are 416 × 624 for Waymo, 368 × 720 for KITTI, and 384 × 688 for nuScenes. Camera intrinsics are updated using the same resize factors and crop offsets. Since VGGT-Ωassumes a centered principal point, its pre- dicted intrinsics can introduce systematic errors in viewing-ray directions when the actual principal point is off-center. We therefore use dataset-calibrated intrinsics together with VGGT-Ω-estimated camera poses for source-view geometric conditioning. External baselines retain their respective preprocessing conventions. At each Waymo observation time, we use synchronized FRONT, FRONT LEFT, and FRONT RIGHT images. VGGT-Ωjointly processes all twelve historical images, placing the lat- est FRONT image first to define a shared reference frame. A timestamp-specific memory mask exposes only the three view blocks belonging to each state to the Scene Tokenizer. The four states are then supplied to the World Model in chronological order. KITTI and nuScenes use one camera view per timestamp. The World Model predicts ten successive states with a four-state sliding window. GT-camera and predicted-camera evaluations share this state trajectory and differ in the decoder query poses. The camera predictor receives four observed metric poses and the current forward-facing image, as de- tailed in Appendix A.2. Within each camera setting, Copy-Last and forecasting share query cameras and LiDAR evaluation masks. Camera-matched Copy-Last holds St fixed and evaluates Gψ(St, Qt+h), retaining the representa- tion, decoder, and query trajectory used by forecasting. Fixed-View Copy-Last repeats the raw VGGT-ΩFRONT depth map from the observed anchor at every future timestamp. The map remains fixed while the future LiDAR reference changes.
