The hybrid weight is the load-bearing innovation here: pure exploitation on historical success traps the optimizer in local optima, but forward-looking relevance to the failure analysis lets the optimizer respond to target-specific defense behavior even when there is no historical data on the relevant strategies. This mechanism is also what enables library growth: when failure analysis recommends a strategy that does not exist in the library, the reflective LLM synthesizes it, the new strategy is registered with neutral priors (𝛼𝑠, 𝛽𝑠) = (1, 1) and receives an immediate relevance boost from the feedback that prompted its creation, and subsequent runs can exploit the new strategy like any other. The framework can therefore adopt techniques from recent literature on the fly without manual library curation. Strategy selection probabilities are computed via softmax over the hybrid weights with temperature 𝑇controlling exploration sharpness, and online updates between generations apply an exponential moving average to smooth weight changes. To prevent the reflective LLM from being overwhelmed when prompted with the full 58-strategy portfolio, mutation prompts include only the top-𝐾strategies by hybrid score (default 𝐾= 8), with each strategy annotated by its hybrid weight and a one-line description. Strategies below a relevance threshold of 0.3 are excluded; if fewer than 𝐾strategies qualify, the pool is padded with next-best strategies by historical success. This focuses generation on currently promising techniques while the exploration bonus ensures under-tried strategies occasionally appear in the pool. 3.4 The Generation Cycle Each generation of REPRO runs five phases that together transform the current population 𝑃𝑔 into the next population 𝑃𝑔+1: multi-objective evaluation and parent selection, feedback-driven mutation, semantic crossover, self-refinement, and population selection. Mutation and crossover consume the reflective machinery of §3.3; the other phases are standard evolutionary operations specialized to the multi-objective, black-box setting. 3.4.1 Multi-Objective Evaluation and Pareto Selection. Each generation begins with full evaluation of the population on the four objectives from Section 3.1. Because these objectives can conflict (high ASR may require longer or more detectable prompts), REPRO uses Pareto selection rather than scalarization, which preserves multiple high-quality parents for crossover and lets the optimizer explore trade-offs the user can later choose between. Strict Pareto dominance often yields a single dominant solution and collapses crossover diversity. REPRO therefore computes the strict frontier first and applies an epsilon-Pareto relaxation only when that frontier is undersized for the caller; when the strict frontier is already large enough, the relaxation is not invoked. Under the relaxation, a candidate is excluded from the frontier only if another candidate is better by at least a factor (1 + 𝜀) on every objective, so a larger 𝜀admits more candidates. The routine is called at two points with different parameters, reflecting what each caller needs. Parent selection runs once per generation and requires several parents for multi-parent crossover, so it uses 𝜀= 0.05 with a minimum frontier size of 3. Final selection runs once at the end of a run and needs only to identify the returned solution, so it uses 𝜀= 0.03 with a minimum of 1. Both cap the frontier at 6 candidates. If the relaxed frontier is still below the minimum, REPRO expands it by including next-best candidates under lexicographic ordering (ASR ≻XFER ≻−detect ≻−len). Immediately after evaluation and before parent selection, REPRO updates strategy posteriors and ICL example statistics, and tracks the global best candidate 𝑥global_best across all generations so the best solution is never lost if later generations explore different regions of objective space.
