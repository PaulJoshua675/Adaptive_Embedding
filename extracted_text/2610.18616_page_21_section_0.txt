HybGRAG (Lee et al., 2025) is an LLM agent that routes each query to a text retriever or a hybrid retriever and refines the routing with a critic. An LLM router identifies the topic entities and the rel- evant relations. The hybrid retriever then follows these relations within the ego-graphs of the enti- ties and ranks the documents it reaches by vector similarity to the query. An LLM validator checks the top results, and an LLM commenter returns corrective feedback to the router for at most four iterations. The examples in its prompts come from the STaRK training set. We report its main con- figuration with Claude 3 Sonnet and ada-002 em- beddings from Table 5 of the paper, which covers MAG and Prime. AF-Retriever (Boer et al., 2026) is an eight-step LLM pipeline that combines graph constraints with vector similarity search. The LLM writes a Cypher query. On Prime, where answers can have sev- eral node types, it first predicts the target node type. The query is parsed into relational triples and attribute constraints, which are grounded on the graph by embedding search and set intersec- tion. Vector search fills about two thirds of the 20 final candidates from the grounded set and the rest from unconstrained candidates of the target type, and the LLM reranks these 20 pairwise. We report its zero-shot configuration with gpt-oss-120B and text-embedding-3-small. Its H@1 and MRR come from Table 3 of the paper, and its R@20 comes from the complete-pipeline row of the ablation ta- ble (Table 5). ARK (Polonuer et al., 2026) is an LLM agent that calls two predefined tools. A global search ranks node texts with BM25, and a one-hop neighbor- hood search can filter the neighbors of a node by node and edge type and rank them by a subquery. Three agents run in parallel for at most 20 steps each, and the nodes they select are fused by vote count. We report its GPT-5.2 results from Table 5 in the appendix of the paper. Our graph tools call ARK’s implementations of these two tools (Ap- pendix C). E.3 KG Reasoning Methods Adapted to STaRK Yang et al. (2025) adapt three KG reasoning meth- ods to STaRK and run them with GPT-4. We report their H@1 and MRR from Tables 2 and 10 of that paper. ToG (Sun et al., 2024) runs an LLM-guided beam search on the KG that alternates relation and entity exploration and stops once the LLM judges the retained reasoning paths sufficient or the search reaches a maximum depth. RoG (Luo et al., 2024b) generates relation paths grounded in the KG as plans, retrieves the reason- ing paths that follow these plans and lets the LLM reason over them. In its original form, RoG’s plan- ner is Llama 2-Chat-7B instruction-tuned on We- bQSP and CWQ (Yih et al., 2016; Talmor and Be- rant, 2018). GoG (Xu et al., 2024) is a training-free KG agent that interleaves thinking, searching and generation steps, in which the LLM proposes new triples from its own knowledge and verifies them. F Closed-Book Probes The closed-book probes measure how many queries the model answers from its parametric knowledge alone (§3.3). Design. Both probes run GPT-6-Luna in Pi with reasoning effort high, and the model answers in a single closed-book turn (prompts in Appendix B). The ID probe asks for up to 20 STaRK node IDs, ranked by confidence, and is run on the full test sets of all three datasets (7,108 queries). Since node IDs are arbitrary integers, a correct ID could indi- cate that the model has memorized benchmark files. The name probe asks for up to 20 answer names (exact paper titles for MAG and exact PrimeKG entity names for Prime), which we map to node IDs offline. Because Amazon product titles are long and rarely match exactly, it is run on the full MAG and Prime test sets (5,466 queries). The 12,574 probe runs cost $8.31 in total, and the 4 runs that failed count as wrong. Name mapping. The mapping uses the exported node files. MAG papers are indexed under their title and OriginalTitle, and Prime nodes un- der their name, details.name and every entry of details.alias.
