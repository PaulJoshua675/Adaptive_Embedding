C Harness Details All runs of a configuration use the same harness, and each query has its own scratch directory. The agent writes its programs inline in its commands, and they are discarded after each query. All runs that we conducted, including the validation runs and the closed-book probes, used GPT-6-Luna or GPT-6-Astra through an API in September and October 2026. Pi. We use DCI-Agent-Lite (Li et al., 2026) at upstream commit 271f37e (1 June 2026). DCI- Agent-Lite builds on the Pi coding agent (Zechner and Pi Contributors, 2026),1 using a fork of Pi version 0.65.0 to which it adds runtime context management. We use both as released. Our three small changes to DCI-Agent-Lite’s runner script are in our code release. The one that affects scoring reads the final answer from the last assistant mes- sage, so that an attempt that ends with a tool call or an error counts as failed. Pi runs in its offline mode with two tools, read and bash, and with its default system prompt, which lists the available tools and gives the date and the working directory. Its skills, prompt templates, themes and extensions are disabled, except for the extension that regis- ters the graph tools. The model is GPT-6-Luna (GPT-6-Astra for the stronger-backbone rows) with reasoning effort high, a context window of 272,000 tokens and at most 32,000 output tokens per re- quest. For context management, we use level 3 of DCI-Agent-Lite, the lightweight setting that it uses for its own benchmarks, which truncates large tool outputs and compacts the history by replacing older tool results with a placeholder. Each attempt may take at most 300 turns and 1,800 s of wall-clock time. Head-and-tail truncation, described below, is our one change to how Pi returns tool outputs. Codex CLI. Full DKGI (Codex) runs the codex exec command of Codex CLI 0.156.12 with the same model, reasoning effort and context window as Pi, and its budget is Pi’s time limit per attempt. User configuration, rules and project documents are ignored, sessions are ephemeral, and approval is never requested. Web search, network access and 1https://github.com/badlogic/pi-mono 2https://github.com/openai/codex optional features such as multi-agent use, memory, plugins and browser use are disabled. Codex’s own system prompt and tool are used unchanged. With this tool, the model writes short JavaScript programs, each of which can run several shell com- mands in one call. Codex keeps its own output truncation, which lets the model raise the limit for an individual call, and we apply head-and-tail trun- cation in Pi. Sandbox. Both harnesses run in the same outer sandbox, a deny-by-default Landlock policy under which system libraries, the harness code and the working directory are read-only. The working di- rectory is the graph directory or, for the graph-tool variants, a directory that holds a single README file. The writable paths are an installation-ID file of Codex and the run directory of the query, which holds the scratch directory, the logs and a per-query home directory. In Pi, shell commands run in a second sandbox layer with a clean environment, a second Landlock policy and a seccomp filter that blocks network sockets. In Codex, they run in Codex’s own sandbox with network access dis- abled. Only the harness process itself connects to the model endpoint, and no variant has a web- search tool. Before the model is first called, a check inside the sandbox confirms that the working direc- tory is read-only and that the query and label files, the original benchmark files and the user’s home configuration are unreadable. The scoring process reads the labels after the agent has finished. Head-and-tail truncation. In every Pi variant with a shell, Pi’s bash tool runs its commands through a wrapper that implements the head-and- tail truncation of §2.4. The wrapper saves the complete output of every command in <scratch dir>/full_outputs/, where the agent’s later commands can read it. An output of at most 18,000 bytes and 1,800 lines is returned as it is. For a longer output, the wrapper returns the first 9,000 bytes or 900 lines, whichever limit is reached first, then a notice on a separate line, and then the last 9,000 bytes or 900 lines.
