BitSparse: Compact Activation Storage A Memory usage during training Reference model and assumptions. Here, we describe in more detail the memory usage involved in training LLMs. We assume Bfloat16 storage is used everywhere for this analysis (2 bytes per element). Let P be the number of parameters in a model, W be its width, D be its depth and FFN expansion factor r. For LLM training, let the sequence length be n and total number of tokens be N, equal to sequence length times batch size. The model parameters require storage of 2P bytes. The optimizer states require either a buffer for every parameter, like Muon Jordan et al. (2024b) and SGDM, or 2 buffers for optimizers such as Adam Kingma and Ba (2014). Hence at least 2P bytes are needed. If gradients are all stored, an additional 2P bytes of storage are needed. However, gradient overhead can be removed by fusing the optimizer into the backward step, where the momentum buffers are updated as soon as gradients are computed, removing the need for gradient storage Lv et al. (2024). Hence, in this setup for LLM training or finetuning with Muon, a static memory overhead of 4P is required. The rest of the memory used is for the activations. These scale linearly with input size. While attention complexity is the square of sequence length, the peak memory required is only linear Rabe and Staats (2022). Furthermore, Flash attention Dao et al. (2022) provides a highly optimized attention implementation, where the intermediate computations are recomputed in the backward pass rather than stored. This reduces the cache size to O(N). State-space methods such as Mamba Gu and Dao (2024) also use fused checkpointed kernels for the backward pass for good memory efficiency without saving the full intermediate computation graph. The storage used is O(DWN). The feedforward layers make up the other major portion of the activation cache. A feedforward block consists of an up projection, activation and down-projection, y = activation(xW ⊤ 1 )W ⊤ 2 . This projection to the high dimension activation requires a large amount of storage, since its hidden dimension is rW. The input to the FFN layer is cached. Since the activation is pointwise, it can be recomputed leading to total memory usage O(D(r + 1)WN). Finally, we have pointwise and normalization operations, such as RMS and LayerNorm. These pointwise operations can be efficiently checkpointed with fused kernel implementations; hence these layers do not require significant storage. A.1 Nemotron-H memory usage We will use Nemotron-H (Blakeman et al., 2025) as a reference for size and shapes. Its configuration contains 52 blocks: 24 MLP, 24 Mamba, and 4 attention blocks, with hidden width 4096, MLP width 21,504 (an expansion factor of 5.25), and vocabulary size 131,072, totaling approximately 8.1 billion parameters that occupy 15.089 GiB in Bfloat16. In this paper, we will use BF16 precision for training for simplicity. Activations and intermediate tensors. Unless stated otherwise, the tensor sizes below are for a micro-batch of 4096 tokens, so that they can be compared directly with the per-token figures in Table 5. A single BF16 residual-width tensor occupies 0.03125 GiB at this length, whereas an expanded MLP tensor occupies 0.16406 GiB. Keeping one expanded tensor for each of the 24 MLPs costs 3.9375 GiB. A conventional ReLU2 backward graph may retain both the unsquared ReLU output and the squared tensor consumed by the down-projection, requiring two such sets (7.875 GiB), in addition to the MLP inputs and normalization intermediates. The precise saved set depends on fusion and checkpointing. Mamba’s projected gate, convolution inputs, and time-step values span 18,560 features per token; one projected tensor per Mamba block totals 3.398 GiB. Convolution outputs, scan intermediates, and normalization can require additional storage, depending on the kernel and chunking strategy. Attention Q, K, and V together span 6144 features per token, totaling 0.188 GiB across four blocks. Materializing one BF16 attention-score tensor per block would add 4 GiB at length 4096, or 16 GiB at length 8192; memory-efficient attention avoids retaining the full score matrices. Finally, the vocabulary projection produces 1 GiB of BF16 logits at 4096 tokens, and the implementation casts these to FP32, whose footprint is 2 GiB. Loss computation and the cast can introduce further temporary allocations. Implementation optimizations. Two lossless changes to the Nemotron-H implementation keep its measured footprint close to the model’s intrinsic memory use. The RMS normalization is fused into a single kernel, so its intermediate statistics and normalized values are recomputed during the backward pass rather than retained. The vocabulary projection head is evaluated in chunks along the vocabulary dimension, so the full FP32 logits tensor described above is never materialized at once and only the chunk being processed is live. Neither change alters the computation performed, only where its intermediates are stored, so the results match the unfused formulation up to floating-point rounding. Both are applied to the dense baseline as well as to BitSparse, so the comparisons in Section 6.4 reflect the choice of activation storage rather than incidental implementation differences. 12
