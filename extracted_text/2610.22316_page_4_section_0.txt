Consider an agent system executing a task with goal g. We define an observation space O through a function O that exposes the goal and available execution context, and an action space Asteer = {pass}∪Aint, where pass lets execution continue and Aint contains the interventions supported by the system. At steering decision t, the steering agent reads the observation ot = O(g, st) ∈O, where st is the underlying execution state that collects the goal and the interaction so far, and returns a steering action: at ∼πθ (· | ot) , (1) where the steering policy πθ, realized by an LLM with parameters θ, maps each observation to a distribution over Asteer. The system applies the sampled action at before resuming execution. This steering interface can achieve different steering granularities depending on the observation and action spaces. For example, exposing every execution step of a single agent enables fine-grained supervision, while exposing only inter-agent handoffs enables coarse- grained supervision over a multi-agent system. We formalize the steering process as a partially observable Markov decision process (POMDP) (Sutton & Barto, 2018; Kaelbling et al., 1998), where the agent system being supervised acts as the environment. At decision step t, the steering agent observes ot rather than the full execution state st, takes the action at, and the agent system transitions from st to st+1 ∼T (· | st, at) , (2) where the transition T is realized by the system resuming execution until the next observation update. The task reward R is received when execution terminates and measures goal completion. As shown in Figure 3(a), each observation update marks a state transition in observation space and triggers a steering decision. The steering agent then judges whether the current state needs intervention and generates the intervention when it does. These two demands split the agent into a fast path and a slow path (Kahneman, 2011; Su et al., 2025; Lampson, 1983; Clark et al., 1989). The fast path judges the need for intervention at low cost, and the slow path produces the reasoning and action for intervention. Both paths share the same LLM backbone parameterized by θ. Fast path. To process each observation update at low cost, the fast path judges the need for intervention within a single LLM forward pass. It operates by estimating the steering priority of the current state, which measures how much a steering action at this state can change the final outcome. This allows the steering agent to achieve a larger impact with a fixed intervention budget. Specifically, the fast path measures steering priority vθ(ot) by a yes/no judgment, which is calculated by reading the probabilities of the two tokens: zθ(ot) = log pθ(yes | Pfast(ot)) −log pθ(no | Pfast(ot)), vθ(ot) = σ(zθ(ot)), (3) where Pfast(ot) denotes the fast-path LLM input built from ot, pθ is the token probability given by the shared LLM backbone, zθ(ot) is the log-odds between the two tokens, and the logistic function σ normalizes it to steering priority vθ(ot) ∈(0, 1).
