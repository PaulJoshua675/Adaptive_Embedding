For tutorial labyrinths, the public map reveals all internal walls and features, including the positions of keys, treasure, rivers, and pits. We use tutorial labyrinths only in the curriculum- learning experiments with the labyrinth-set environment. For non-tutorial labyrinths, the public map shows only the external boundary and the player’s initial position, visualizing information already provided in the text. Dynamics and observations. Actions encode the labyrinth-defined choices as JSON objects. After each action, the environment returns state.txt, containing textual feedback and inventory information. Termination. The environment ends when the labyrinth is solved or the agent uses five times the max_steps reference budget provided by AGI Maze. 5.3 AGI Maze: labyrinth set One environment contains an ordered sequence of labyrinths. The agent remains in the same run throughout the sequence, allowing it to use experience from earlier labyrinths when solving later ones. Environment description. The environment description asks the agent to solve all labyrinths efficiently and states that the first few are tutorials with an open map showing the player’s position; later maps are hidden. Appendix A.3.1 reproduces it verbatim. Dynamics and observations. The agent starts each labyrinth with {"id":"start"}. The response includes labyrinth_description.md, containing the environment description used in the single-labyrinth setting, and state.txt, containing the same state information as in the single-labyrinth environment with the labyrinth index added. Tutorial labyrinths additionally return the current map and player position as map.txt; non-tutorial labyrinths omit this file. This map is also supplied by AGI Maze. Each labyrinth receives the same fivefold action budget as in the single-labyrinth setting. Solving it or exhausting that budget produces message.md, reporting the outcome. When another labyrinth remains, the environment then waits for the next start action. This separates feedback about the previous labyrinth from initialization of the next. In particular, the failure message asks the agent to consider what went wrong before continuing. These messages are fixed environment inputs, and Appendix A.3.3 presents their exact text by the situation in which each is sent. Termination. The set ends only when the final labyrinth is solved or reaches its action limit. Failure on an earlier labyrinth does not terminate the set: the agent proceeds to the next one. A terminal set therefore means that the sequence is complete, not that every labyrinth was solved. 5.4 Terminal-Bench 2.1 One environment contains a single Terminal-Bench task. Unlike the turn-based game settings, it can evolve while the agent deliberates. The task specifies a wall-clock time limit for solving. Environment description. The environment description is generated from the template in Appendix A.4, inserting the public task instruction as {instruction} and the solving budget in seconds as {budget}. The template gives the complete action interface and timing conventions. The environment description also explains that the task sandbox has a separate filesystem from the agent’s workspace and that task files are accessed through environment actions. 11
