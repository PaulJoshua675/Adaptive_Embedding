I Naive Search with Partial Distance Computation A reasonable question about any index is whether it earns its complexity. We added a naive variant—a linear scan—to the same harness, using the same early-exit (“partial distance”) Eu- clidean kernel and the same distance counter as every other implementation. Building it with no-early-exit yields the full-distance twin. Both perform identical n2 distance calls, so any runtime difference is purely the per-call dimension work that early exit skips—this isolates the partial-distance effect on the simplest possible baseline. Corel is the instructive case: early exit is worth 2.5× in the linear scan but nothing in the cover tree (Table 1), consistent with the tree having already pruned most of the far candidates whose distance computations early exit would otherwise cut short. The benefit of a kernel-level optimization thus depends on the structure that calls the kernel, not only on the data. The absolute numbers also answer the “is an index worth it?” question directly. Naive all-NN on mnist requires 3.6×109 distance calls (43–70 minutes) and on covtype 3.4×1011 (6–10 hours), against milliseconds to minutes for the trees. At the same time, on the smallest datasets the naive scan is competitive in absolute terms—another reason the tiny-dataset results in this paper should not drive implementation decisions. 46
