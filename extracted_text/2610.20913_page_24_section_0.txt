TransX: Technical Report Throughput-oriented execution. Behavioral trajectories have a highly skewed length distribution, so fixed user-count batches would either waste computation on padding or allow a small number of long histories to determine the execution shape. We instead process workload under a behavior-token budget and form length-aware variable-length batches. Since causal attention preserves user boundaries without padded tokens, long trajectories can be processed in bounded chunks while carrying encoder continuation state across chunks, and these chunks are co-scheduled with shorter trajectories to reduce long-tail stragglers. Context parallelism is used selectively when an individual trajectory remains too large for efficient single-device execution. Across the production workload, this path processes approximately 0.7M valid behavior tokens/s/H200 at 61% encoder MFU and 34 GiB peak HBM, a 1.5× throughput improvement over the naive bulk implementation without chunking. Freshness-aware continuation-state routing. The cost of an incremental update depends jointly on the arriving behavior delta and the continuation state needed to advance it. Routing therefore considers  |Δ𝐻|, |𝐶(𝑢) 𝜏 |, state locality, worker queue, freshness slack  . Updates are preferentially routed to workers that already hold compatible continuation state, avoiding unnecessary state movement. When queueing at the current owner would consume the remaining freshness slack, however, the update may be reassigned to another worker. Compatible updates are microbatched across users subject to their freshness deadlines, while state transitions for each user remain causally ordered. Under matched update load, this locality- and freshness-aware routing policy reduces p90 freshness lag by approximately 30% relative to locality-agnostic FIFO routing. Immutable publication and recovery. A behavior-memory snapshot becomes visible only after its payload and producing state have been validated. Publication then atomically advances the user- visible snapshot descriptor, while each request pins one compatible immutable snapshot for its lifetime. Continuation state is checkpointed asynchronously together with its source cursor and version metadata, allowing worker loss to be recovered by restoring a compatible checkpoint and replaying the retained behavior-log suffix.
