LCT: Losslessly Compressed Tensors Center estimation takes one deterministically jittered sample per input region. Integer hashing generates the offsets without a random-number buffer and reduces repeated sampling of the same matrix columns. Shifting the lookup tables once per tensor lets the encoder index raw exponent bytes and the decoder recover uncentered exponents directly, removing the centering transformation from the per-symbol loop. C.2 Encoding and decoding Bit representation and invertibility. Let ui be the unsigned 16-bit pattern of element i. Its exponent byte ei and side byte ri are ei = (ui ≫7) & 255, (8) ri = (ui & 127) | ((ui ≫8) & 128). (9) The exponent is coded and ri is stored verbatim. Reconstruction, ui = (ei ≪7) | (ri & 127) | ((ri & 128) ≪8), (10) recovers the original 16-bit pattern, including signed zeros, subnormals, infinities, and NaN payloads, without floating- point conversion. Packing and lookup. The encoder processes two symbols per iteration. Each table entry stores the code bits and length; since a complete code is at most 16 bits, a pair occupies at most 32 bits and crosses at most one output-word boundary. Partial words remain in registers until written. The decoder uses a 64-bit window spanning two payload words to decode a pair of symbols. Direct codes return an exponent and consumed length; escapes extract an eight-bit literal from the same window. In the full-block path, the next payload word is loaded only when a lane crosses a word boundary. Decode-table loads retain cache entries, side bytes use global-cache loads, and dense outputs use streaming stores. Loop unrolling and autotuned warp counts, pipeline depths, and register limits control instruction scheduling and register pressure. C.3 Overflow compaction and allocation Compaction uses local prefix sums to assign positions within each tile and atomic additions to reserve ranges across tiles. Reservations occur per tile rather than per symbol. Separate gather and scatter kernels access only the raw tails, keeping variable-length overflow handling outside the main packing and decoding loops. C.4 Overflow Buffer The allocator tracks occupied address ranges, uses first-fit search to reserve aligned regions, and writes device descriptors for subsequent kernels. Freeing a region marks it available; coalescing adjacent free regions reduces fragmentation. During an update, old and replacement allocations may coexist. On the same CUDA stream, the old region can be released after its final consumer is launched, preserving execution order. C.5 Fused pointwise operations Table 13 summarizes the supported operations. Operator and output-format choices are resolved at compile time, eliminating branches from the inner loop. For a compressed and a dense operand, a correction kernel handles raw overflow tails. For two compressed operands, preparation maps stream identifiers to overflow offsets so each lane can select coded or raw exponents without searching compact metadata. Both operands must share stream geometry, escape length, and overflow-storage mode. For compressed output, sign–fraction bytes are written directly to their final locations, leaving only exponent bytes for subsequent centering and encoding.
