Standardized interaction is also established infrastructure: Gymnasium exposes an action– observation API, and OpenEnv provides isolated environments with network-accessible inter- faces [16, 17]. EnvTraverse uses a common interaction contract to separate agent implementations from environment specifications, which are held fixed when comparing agents. 2.2 Coding agents and scaffolding ReAct interleaves reasoning with actions and environmental feedback [18]. CodeAct uses executable Python as an action representation, supporting tool composition and revision in response to execution results [2]. SWE-agent shows that the commands and feedback provided for repository navigation, file editing, and execution can materially affect software-engineering performance [3]. StateM organizes execution through persistent workflow states, runbooks, and checked transitions [19]. These approaches motivate distinguishing access to computational tools from the organization and control of their use. Programmatic world modeling provides examples of constructing and using task-specific computational aids. WorldCoder builds Python world models from interaction for planning, while GIF-MCTS generates and repairs code world models from descriptions and collected trajectories [20, 21]. In ARC-AGI-3, OPINE-World combines interactive exploration, object- centric modeling, predictive checks against recorded transitions, and planning [22]. Tycho studies when a coding agent should construct, repair, use, or bypass a programmatic model [23]. Our earlier study compared textual and executable-model scaffolds with simplification and verification [9]. In the present study, the environment-agnostic variants leave the choice of task- solving models and auxiliary tools to Codex. We examine a small change to general guidance across environments and use the ARC-AGI-3 comparisons to study the remaining benefit of supplied organization and control. 2.3 Reflection and learning from experience Self-Refine uses the same language model to generate an output, provide feedback, and revise it without additional training [6]. Reflexion generates verbal reflections from task feedback and retains them in memory for subsequent trials, also without updating model weights [24]. These methods explicitly organize how feedback is produced and reused. Benefits from reconsideration are not automatic: Huang et al. find that self-correction without external feedback can reduce performance on the reasoning tasks and models they examine [25]. Experience can also be retained as executable behavior. Voyager accumulates reusable skills through interaction in Minecraft and retrieves them when solving later tasks [26]. This provides an example of organizing experience into computational tools. These studies motivate examining how agents revisit information and use prior experience. Our Stop-and-report instruction encourages Codex to return when it encounters difficulty, after which the controller resumes the conversation with a goal reminder, without prescribing a separate critique-and-revision procedure. The AGI Maze comparison separately tests whether preceding tutorial experience benefits the unchanged agent. 2.4 Test-time computation Research on test-time computation examines how model performance depends on the amount and organization of inference.
