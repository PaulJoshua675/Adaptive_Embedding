Our earlier ARC-AGI-3 studies motivate this question. The first combined executable world modeling, prompted simplification, and replay verification in a Codex-based agent [8]. The second compared textual and executable-model variants, finding that gains from model capability and reasoning effort often exceeded differences among those variants [9]. These findings are consistent with the hypothesis that stronger models may increasingly construct useful task-specific procedures themselves, reducing the advantage of developer-supplied scaffolding. This possibility is related to Sutton’s emphasis on general methods that exploit increasing computation [10]. However, all variants in our earlier studies retained ARC-AGI-3-specific organization and control, leaving the contribution of that scaffolding unclear. We therefore ask two related questions. First, can an environment-agnostic agent be improved on some environments without material regressions on others? Second, with the underlying model fixed, why can changes in guidance and control improve performance without supplying new task facts or general-purpose tools? We investigate these questions using one Codex-based agent in two nearly identical prompt variants, each deployed unchanged across ARC-AGI-3, AGI Maze, and Terminal-Bench. A short instruction encouraging the agent to stop and report difficulties improves mean scores on ARC- AGI-3 and AGI Maze, while Terminal-Bench shows small changes with no consistent direction. The focus is on demonstrating and studying a concrete cross-environment improvement, rather than optimizing the agent for the highest possible benchmark scores. ARC-AGI-3-specific control provides further gains, including with GPT-5.6-sol, showing that supplied procedures still matter for the models tested here. A complementary AGI Maze experiment examines whether the agent benefits from tutorial experience. Together, these experiments connect a practical improvement to a broader problem: an agent can have useful information and tools available without reliably using them effectively. Scope and approach. We use environment-agnostic to describe an unchanged agent imple- mentation, not a guarantee of success in every environment. For a given variant and model–effort configuration, its code, prompts, and initial agent-owned tools remain fixed across environments, with no developer-authored environment-specific control logic. Each environment supplies an environment description and optional files, then accepts JSON actions and returns observation files through a common interaction contract. These environment specifications are held fixed in agent comparisons. The agent may construct specialized tools or strategies during a run; the developer does not supply a different scaffold for each environment. Our environment-agnostic Baseline is a simplified version of the ARC-AGI-3-specific textual agent from our earlier study. A small scripted controller and an environment-agnostic client provide access to the task, while Codex performs the reasoning, computation, and action selection. Stop-and-report changes only one instruction, included in both the initial and continuation prompts. It encourages Codex to return control when it encounters difficulty or uncertainty. The controller resumes the same conversation with a reminder of the goal and a suggestion to reread the environment description when needed, but supplies no human feedback or task-specific advice. Both variants have access to the same reminder; the modified instruction changes when Codex is encouraged to return. We evaluate GPT-5.5 at high and xhigh reasoning effort and GPT-5.6-sol at xhigh and max. The environments span visual rule discovery in ARC-AGI-3, stateful labyrinths in AGI Maze, and practical command-line tasks in Terminal-Bench 2.1 [11–14]. AGI Maze is evaluated both as independent labyrinths and as sequences of seven tutorials followed by a target labyrinth. Findings and contribution. Stop-and-report increases mean ARC-AGI-3 Relative Human Action Efficiency (RHAE) by 1.37–7.29 percentage points across the four configurations.
