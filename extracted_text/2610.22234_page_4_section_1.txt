Grounding RL optimizes low-level GUI localization or action selection with specialized visual rewards (Lu et al., 2026b; Yuan et al., 2025; Zhou et al., 2026b; Tang et al., 2026a; Feizi et al., 2026). Agentic RL instead optimizes complete trajectories in executable environments with rule-based or verifiable rewards. Recent CUA work has begun to tailor the optimization algorithm to this setting: ComputerRL (Lai et al., 2026) introduces Entropulse, which alternates online RL with SFT to miti- gate entropy collapse; CUA-Gym (Wang et al., 2026a) trains CUA checkpoints with GSPO (Zheng et al., 2025); and ScaleCUA (Lv et al., 2026) adopts GRPO-style RL (Shao et al., 2024; Yu et al., 2026) together with frontier sampling and visual-context segmentation. EvoCUA-1.5 (Huang et al., 2026) proposes Step-Level Policy Optimization for decomposed multi-turn samples. Nevertheless, how to systematically train a single policy to route between native GUI and code actions while main- taining stable optimization across heterogeneous action granularities remains underexplored. Our work addresses this setting through hybrid SFT and online agentic RL with Step-balanced GSPO, mitigating optimization imbalance and enabling more effective native coordination. 3 OS-HELIX 3.1 OVERVIEW An overview of the OS-Helix pipeline is shown in Figure 2. OS-Helix is built around a simple premise: a real computer-using agent should treat GUI interaction and code execution as two com- plementary ways of changing the same digital state. Rather than attaching a shell tool to a GUI model at inference time, we construct a unified pipeline in which environments, instructions, trajec- tories, and reinforcement signals are all designed for hybrid GUI/code execution. Formally, let q denote the user instruction, hi the history context before step i, and oi the current screen observation. The policy selects an action from a unified hybrid action space: ai ∼πθ(· | q, hi, oi), ai ∈Ahybrid = AGUI ∪Ameta | {z } Anative ∪Acode. Here, AGUI denotes GUI actions such as clicking and typing; Ameta denotes episode-level meta- actions such as task termination; actions in Acode execute either Python or Bash directly in the operating system. Each code action runs in a fresh process. Its stdout and stderr are appended to the current-turn context as a tool response for subsequent decision-making. 4
