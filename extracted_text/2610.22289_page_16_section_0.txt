Because Terminal-Bench is wall-clock limited, we report its service tier explicitly; we did not separately measure its effect on scores. 7.5 All-or-nothing policy for irrecoverable failures Technical interruptions can affect trajectories unevenly. On the same task, an agent that struggles may run longer than one that quickly finds a solution, giving it more opportunity to encounter a service interruption or host failure. Replacing only interrupted task runs could therefore preferentially replace difficult trajectories and bias the reported performance upward. Following our earlier study [9, Section 5.5], we use an all-or-nothing policy at the evaluation-unit level. If an irrecoverable technical failure prevents an evaluation unit from being completed, the entire unit is discarded and rerun from scratch, including any tasks that had already finished. For ARC-AGI-3 and Terminal-Bench, the unit is a complete evaluation block. For AGI Maze, the policy applies separately to the 53-target 0005 and 0009 execution batches. No task result from a discarded unit is reused in its replacement. During this campaign, we replaced one accidentally interrupted AGI Maze batch, three Terminal-Bench blocks in which a server-container startup timeout prevented some tasks from starting, and one twma_v1.61 block affected by a model-service capacity error before the first action of a game. For twma_v1.61, whose inherited runner does not recover failures before the first action, the capacity error was classified as an operational startup failure. 16
