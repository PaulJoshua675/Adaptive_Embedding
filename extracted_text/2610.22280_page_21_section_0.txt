LEASH: Uncertainty-Aware Weak-to-Strong Escalation and Oversight for Computer-Use Agents B. Additional Experimental Results B.1. Experimental Details Evaluation setting. We evaluate on OSWorld with screenshot observations and a shared budget of 50 actions per task. The lightweight backbones are EvoCUA-8B (Xue et al., 2026), Qwen3.5- 35B-A3B (Qwen Team, 2026a), Nemotron-3-Nano-Omni (30B-A3B) (Deshmukh et al., 2026), and Qwen3.8-27B (Qwen Team, 2026b). Claude Opus 5 (Anthropic, 2026a) serves as both the Manager and strong executor, and Claude Sonnet 4.5 (Anthropic, 2025) is an additional always-on reference. The always-on references run the strong model alone, without the Manager, so they measure strong- model capability without the Manager or escalation framework. Configurations and evaluation sets. Manager adds subgoal planning and verification; Escalation further enables initial and runtime handoff; and LEASH additionally enables post-handoff Shadow monitoring and corresponding intervention. These configurations are cumulative. Shared results below follow Tables 1 and 4. The evaluation task pool contains 262 tasks. Reference banks and calibration. We use a held-out reference set that is disjoint from the 262 evaluation tasks. We obtain task-grouped 10-fold out-of-fold scores, keeping all observations from a task in one fold; preprocessing and estimator fitting use only the training folds. Initial scores use final task outcomes and runtime scores use Manager-assigned subgoal outcomes. Thresholds are order statistics of the held-out scores targeting a 25% initial and 50% overall escalation frequency, with runtime calibration based on per-task maximum scores. Refitting slightly changes the score scale, and differences between the reference and evaluation sets can further affect the realized escalation rate; hence the observed rates (43–64%) need not exactly match the calibration targets. Post-handoff execution. After handoff, Shadow probes query the lightweight model every three strong-agent steps. Probe actions are not executed; their hidden representations provide the monitor- ing scores. Higher scores indicate greater uncertainty and can trigger an intervention that asks the strong agent to reassess its current strategy while retaining control. Cost estimation. We estimate inference cost from recorded token usage using OpenRouter reference prices, accounting for cached tokens where applicable. Total cost includes lightweight-agent, Manager, strong-executor, and monitoring calls. For locally served models, we report reference inference-cost estimates rather than measured hardware costs. B.2. Uncertainty Estimation and Reference-Bank Sensitivity Estimator comparison. We compare pooled LDA with Euclidean distance, kNN, and probability- based baselines. The probability-based baseline considers negative log-probability, chosen-token probability, predictive entropy, and nucleus-set size under several aggregation schemes; we report the strongest statistic in each setting. Performance varies across backbones and execution stages, with pooled LDA providing the strongest overall discrimination in most settings. Runtime AUROC reflects discrimination of Manager-assigned subgoal-segment outcomes rather than individual action correctness. Reference-bank size. Table 6 reports initial-stage AUROC as the bank is subsampled, it also shows that estimates become more stable as the bank grows: the standard deviation decreases from roughly 0.10 at 40 tasks to about 0.02 at 99 tasks. Because thresholds are quantiles of this same pool, a small bank also gives coarse control of the realized escalation rate. 21
