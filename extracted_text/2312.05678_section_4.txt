Our efficient method leverages the binary nature of PMS data to produce estimates of plan utility that are computed consider- ably faster than the utility estimates estimated through MCMC integration. Synthesis with importance sampling addresses estimate bias in settings with many nodes and many tests. The expected loss is approximated through three key sets: an MCMC set of SFP-rate vectors drawn from the posterior for the SFP rates under existing data; a set of new data sets simulated using these posterior draws; and an MCMC set of SFP-rate vectors drawn from the posterior for the SFP rates under existing and new data. An SFP-rate draw from the posterior under existing data, p(γ|dprior), is taken as the latent truth. New data, d, are simulated under this latent truth as well as the sampling plan, n. Draws from a posterior under these new data and existing data, p(γ|dprior, d), are used to identify a Bayes estimate and the loss associated with the Bayes estimate. Averaging the loss across latent SFP-rate draws approximates the expected loss. The key algorithm parameters are the size of the sets of SFP-rates, h0, and the number of simulated new data sets, h1. Low values for h0 induce bias: Bayes estimates are identified using an insufficient representation of p(γ|dprior), such that the true expected loss is underestimated. Low values for h1 induce variance: the range of possible data sets is insufficiently explored. The equivalence of (11) means that incorporating the likelihood of each SFP rate with respect to each simulated data set is sufficient for approximating the expected loss: no further MCMC sampling is needed. A key matrix for this algorithm, D, stores these likelihoods: each row corresponds to an SFP-rate vector and each column corresponds to a simulated data set. We suggest choosing h0 as large as computational resources will allow, and h1 as large as needed to meet variance tolerance. Algorithm 3 runs significantly faster than the MCMC integration of Algorithm 2. Our case study uses h0 = 75, 000 and h1 = 2, 000, as these values produce consistent allocation decisions (Wick- ett, 2024). This processing rate means utility estimation takes about 10 minutes on a laptop with an Intel Core 1.6GHz processor. B.3 Using importance sampling to reduce bias and variance The quality of utility estimates produced through the efficient estimation algorithm is im- pacted by four key factors: the size of the set of MCMC draws from p(γ|dprior), h0; the size of the set of MCMC draws simulating data sets, h1; the number of nodes, |A| + |B|; and the number of tests in a prospective sampling plan, N (Wickett, 2024). A sufficiently high number of nodes or number of tests means a small subset of SFP-rate vectors in the MCMC set will have a large impact on the resulting loss estimate, i.e., the significant region of SFP rates will be underrepresented. The significant region of SFP rates can be be better represented through importance sampling. We form loss estimates through an additional MCMC set of SFP-rate vectors better capturing this significant region, drawn using an “expected” set of traces and test results. These loss estimates are then adjusted to account for the oversampling of the sig- nificant region. Let dimp be the expected data set under sampling plan n. Algorithm 4 requires one additional parameter as compared with Algorithm 3: h2, the number of data sets to generate for forming dimp. Generating these data sets is computation- ally inexpensive. We use h2 = 5, 000 for the loss estimates of the case study, as evaluations showed this value yielded consistent resulting dimp sets. Calculating dimp in this case requires only a few seconds on a standard laptop. Thus, this step contributes little to the overall calculation time as compared with MCMC generation, which requires a few minutes for our case study. The principal disadvantage of Algorithm 4 is the additional MCMC generation required, which can be computationally expensive. This disadvantage compounds when evaluating multiple plans; the ability to evaluate multiple plans efficiently is a key goal of our work. Whereas Algorithm 3 can use a single MCMC set of SFP-rate vectors for evaluating any number of plans, Algorithm 4 requires additional MCMC generation for each plan. However, the importance sampling of Algorithm 4 addresses a bias issue arising for Algorithm 3 under sufficiently high dimensionality and a given maximal size of the MCMC set. Future work will aim to discern when to apply each algorithm. It is not clear how to use supply-chain size and computational limits to determine when importance sampling should be used: the bias of a loss estimate is a function of the set of MCMC draws, the number of nodes in the supply chain, and the underlying SFP rates. One approach is to calibrate the amount of bias as a function of sampling budget by applying each algorithm at fixed sampling intervals, using a uniform allocation across test nodes. Any bias can then be estimated as the difference in loss estimate between the two algorithms. B.4 Utility approximations for case study Approximations of sampling plan utility depend significantly on the MCMC set of SFP-rate vectors used to generate the approximation. Application of importance sampling requires new MCMC generation for approximations at each considered sampling budget. Using differ- ent MCMC sets at each budget introduces variance. We address this variance by re-running Algorithm 4 ten times with h0 = 75, 000, h1 = 2, 000, and h2 = 5, 000. Estimating sourcing probability The sourcing-probability matrix for the supply chain, Q, is a crucial element of understanding what data may result from a proposed sampling plan. National sourcing records, aggregated records from sub-national or outlet echelons, and track-and-trace records can all be used to form Q. Our case study uses supply-chain observations from a previous PMS iteration to estimate Q, and we use bootstrap samples of these observations to form sourcing probabilities for untested nodes in the all-provinces case. We used 44 independent draws from the first iteration’s data set to form the sourcing probabilities for each test node; 44 was the average number of samples per test node in the first iteration. The uncertainty associated with an estimated Q may be incorporated into analysis through similar bootstrap samples that are integrated with MCMC draws of the SFP-rate vector, γ. In the efficient estimation algorithm (see Appendix B), each member of the set of SFP-rate draws would be coupled with a bootstrap sample of Q during the data-generation step.
