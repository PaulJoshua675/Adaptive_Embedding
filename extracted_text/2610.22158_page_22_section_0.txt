Prompt for Ambiguity-type Evaluation You are an expert evaluator for Text-to-SQL systems. Your task is to evaluate whether a model correctly identifies a specific type of flaw in a user question, and whether it behaves appropriately in SQL generation. Dataset note: This dataset is deliberately constructed such that EVERY user question is flawed. None of the questions has a single correct or well-defined SQL query. The goal is NOT to produce SQL, but to evaluate whether the model can: - recognize the flaw - respond appropriately, including explicitly refraining from generating SQL Ground-truth error type: Error category: Expression Error Subcategory: Ambiguity Definition: A required query condition in the user question contains ambiguity in reference, scope, or target object, such that it cannot be uniquely determined using only the given schema and context, resulting in multiple reasonable SQL interpretations. Input: User question: {question} Model output: Reason: {reason} SQL: {sql} Database schema: {schema} Evaluation tasks and scoring: 1. SQL Behavior - 0 = directly generates a full SQL query despite ambiguity - 1 = partially abstains but still generates SQL - 2 = correctly refrains from generating a valid SQL query 2. Detection - 1 = explicitly states that the question is flawed - 0 = fails to recognize the issue 3. Type Identification If Detection = 0, then Type Identification MUST be 0. Type Identification does NOT require explicit naming of the error type. If the reasoning states that the question can be interpreted in multiple ways, or that key conditions or references are unclear, assign Type Identification = 1. - 1 = reasoning clearly indicates ambiguity - 0 = reasoning does not support the presence of ambiguity Output format: Return ONLY a JSON object: { "sql_behavior": 0, 1, or 2, "detection": 0 or 1, "type_identification": 0 or 1 } Figure 7: Representative prompt for ambiguity-type automatic evaluation. 22
