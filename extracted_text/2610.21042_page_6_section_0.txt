ReviewPilot follows the screening and extraction procedures in Sections 3.3 and 3.4. It uses a fixed five-field extraction schema, with review-specific screening guidance and coding rules generated by the Prompt Agent. All methods receive the same papers and use the same reference annotations. Prompt Agent uses the same model as its down- stream stage. The agent receives the review objec- tives, criteria or field definitions, and samples of evaluation records or papers. Expert decisions and reference extraction values are excluded from the agent’s inputs. ReviewPilot’s screening procedure and prompt-design skill are refined using evalua- tion scores from these PERG pools. The pools are therefore not held out from method development. We report one complete run per method and model. Decoding settings and output limits dif- fer across methods and are recorded with each run (Appendix D). Transport errors and incomplete re- sponses trigger retries. ReviewPilot also retries unparseable screening outputs. GLM-5.3-Flash ex- hausted its 65,536-token output limit on one paper. That paper is excluded from all three methods’ re- sults on this model, leaving 177 papers. All table entries are single-run point estimates and do not characterize variation across repeated model runs. Screening metrics. We pool the records and com- pute precision, recall, and F1 separately for the include and exclude classes. Each metric is then macro-averaged over the two classes. The review share, (TP + FP)/N, is the proportion of records retained for full-text review, where TP and FP de- note retained expert-included and expert-excluded records, and N is the pool size. Macro recall aver- ages recall for both classes and does not measure include-class recall alone. Extraction metrics. Predicted and reference val- ues are normalized with a fixed synonym mapping shared by all methods. At the paper–field level, matching values count as true positives, additional predicted values as false positives, and reference values absent from predictions as false negatives. Under AgentSLR’s empty-field convention, a field empty in both prediction and reference counts as one true positive. This convention applies to model type, stochastic or deterministic status, and code availability.
