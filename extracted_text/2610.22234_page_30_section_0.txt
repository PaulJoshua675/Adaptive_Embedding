D.2 ADDITIONAL ANALYSIS The diagnostic experiments in this subsection are conducted with Qwen3-series models (Bai et al., 2025), which differ from the Qwen3.5-series base models used in the experiments above. The training data and data recipe, however, are kept exactly the same, so the comparison isolates how the same OS-Helix training signal behaves on a different backbone family. All experiments in this subsection use supervised fine-tuning (SFT) only and do not include rein- forcement learning (RL). Accordingly, the analyses below study the transferability of the learned GUI/code behavior and the information content of the SFT data, rather than the contribution of online policy optimization. D.2.1 GROUNDING ABILITY CHECK Table 13 reports grounding benchmark performance on Qwen3-VL-32B-Instruct and an OS-Helix- 32B variant with the same data recipe as our Qwen3.5-series models. The reproduced base model obtains 61.35 on OSWorld-G (Xie et al., 2026) and 95.05 on ScreenSpot-V2 (Wu et al., 2025), while OS-Helix-32B obtains 57.21 and 93.47, respectively. This decrease is expected rather than contradictory to our main results. The training objective does not only optimize pixel grounding; it also teaches the model to format tool calls, reason over files, in- voke code when programmatic execution is more reliable, and recover from multi-step environment feedback. In this sense, the model reallocates some capacity away from isolated grounding bench- marks toward hybrid desktop execution. The key observation is that even when pure grounding slightly decreases, code-capable action selection can compensate for this loss in end-to-end tasks 30
