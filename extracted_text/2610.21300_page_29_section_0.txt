Supplementary Note 1: the prompts of Experiment 1 The system prompt (SHA-256 1181bf6aa31300b525d1fc20e6d24e0c 8e00d27c6b69414d47d6e6db46fcc0d9 over its UTF-8 bytes, with straight quotation marks and the line breaks shown) is reproduced verbatim: You review FDA 510(k) premarket documents for a blood glucose monitoring system and decide whether the documents show that the device meets each require- ment taken from FDA guidance. Use only the docu- ments provided. Decide one requirement at a time. Choose exactly one label: - Satisfied: The documents show the requirement is met. - Not satisfied: The documents show the requirement is not met. - Cannot determine: The documents do not address the requirement. Answer with JSON only, in this form: {"label": "<one of the labels>", "comment": "<two or three sentences explaining the decision>", "evidence": [{"document": <document number>, "quote": "<a passage copied verbatim from that document>"}]}. Quote passages exactly as they appear in the doc- uments. If the label is Cannot determine, return an empty evidence list. The user prompt is the numbered documents, each introduced by a line “=== Document n: title ===”, followed by “Requirement: item” and “Answer with JSON only.”. The item ends with “(FDA guidance section: heading)”, where the heading is in fact that of the device’s decision-summary section matched to the item, not a section of the guid- ance; the same text is used in both experiments, so this misnomer does not affect the comparisons. The JSON schema sent where accepted requires an object with exactly the keys label (one of the three labels), comment (string) and evidence (an array of objects with an integer document and a string quote) and no other properties. Experiment 2 uses the same label definitions. All 70 prompts and their SHA-256 are in the supplementary material (prompts index.jsonl); full texts are reconstructible from the public docu- ments. Supplementary Note 2: changes during the study The measures, operations and conditions were fixed before the runs, and every change was recorded when it was made. The positive-control runs (“Ours”), the concurrency test, the extension of day 2 to all tiers and the infusion-pump runs were added during the study and are exploratory. The changes were as follows. Experiment 1. (i) Device–item pairs whose 510(k) summary had under 1,000 characters of text (two PDF portfolios) were skipped in favour of the next pair. (ii) On Amazon Bedrock, claude-haiku-4-5 was measured on 4–5 October in place of claude-opus-5-5, so that both Claude routes carried the same model; claude-opus-5-5 through Bedrock and claude-haiku-5-5 through both Claude routes were added on 12–13 October, with claude-opus-5-5 through the Claude API sent again on those days for the route comparison (its 4– 5 October measurement remains the one reported in Tables 2 and S13). An earlier attempt on 8 Octo- ber was interrupted after 105 Bedrock calls and is not used. (iii) The Claude API credit balance ran out for 16 seconds; the 78 failed calls were resent. (iv) The second day was extended from mid prompts to all tiers, and the self-hosted judgment stage was added with the same prompts and schedule. (v) Azure OpenAI was measured on 7–8 October through an existing subscription, with the OpenAI API’s short prompts sent on the same days for the route com- parison. (vi) gemini-3.5-flash through the Gemini API had been planned for the mid prompts only; short and long prompts were added on 7–8 October so that every deployment has the same 70 prompts. On 13 October, the identifier gemini-3.5-flash returned the version gemini-3.6-flash through the Gemini API (it had returned gemini-3.5-flash on 4–8 October), while Agent Platform still served gemini-3.5-flash under it, so the two routes could no longer be compared on the same days under that identifier; we therefore measured gemini-3.6-flash through both Google routes on 13–14 October and report it in place of the earlier measurement, which remains in the supplementary ledger but appears in no table; Google’s release notes of 8 October 2026 record the deprecation and the automatic routing [71]. (vii) The cost cap was raised in steps from $480 to $1,300. (viii) The count of label changes between days was defined after the data were col- lected, as in Measures and statistics; a count of prompts with any differing pair of runs across days, used in drafts, also counted variation within a day. The within- and across-day probabilities that two runs differ, defined before the runs, are reported unchanged. (ix) The reduced-reasoning and retrieved- passage measurements (Supplementary Tables S12 and S11) were added on 14 October after internal review, pre-registered before sending, and run on 14– 15 October; their first launch sent no calls because the runner skips completed (route, model, prompt, run) tuples, so the reduced-reasoning runs use run numbers 31–40, mapped to 1–10 in the tables.
