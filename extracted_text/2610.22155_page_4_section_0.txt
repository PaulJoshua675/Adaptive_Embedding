Preprint requires models to determine which action will remain useful when executed, including whether to wait or act immediately and what action to take. These dimensions jointly shape how an agent responds to an evolving environment. For example, an agent purchasing a ticket must track the sale status and assess whether observed availability is still current (RT-Perceive), limit further deliberation when the purchase window is closing (RT- Deliberate), and choose between waiting for sales to open and purchasing while tickets remain available (RT-Act). 3.2 CLOCK PROTOCOLS As shown in Figure 2, we use three clock protocols to distinguish task performance under actual inference latency, performance without inference delays, and performance under a standardized temporal cost of token generation. • Wall Clock. To evaluate performance under real-world inference latency, Wall Clock ad- vances the environment according to the actual time spent on inference. The environment continues to evolve while the model generates a response, so action timing depends on both model computation and serving infrastructure. • Paused Clock. To assess task performance without the temporal cost of inference, Paused Clock pauses the environment while the model generates a response. This provides an idealized reference for Wall Clock, allowing us to compare performance when inference does and does not delay actions in environment time. • Token Clock. To retain the temporal cost of deliberation while removing dependence on serving speed, Token Clock advances the environment at a fixed rate per generation token. An action is applied at the simulated time reached when it is committed, so consuming more tokens delays execution regardless of actual inference latency. To formalize Token Clock, let B denote the number of generation tokens corresponding to one observation interval and f the observation rate in frames per simulated second. The token-to-time rate is κ = Bf, measured in generation tokens per simulated second. If the model generates n tokens after receiving an observation and before committing to an action, the action is applied after a simulated-time delay of ∆t = n κ = n Bf . In both Token Clock and Wall Clock, when generation spans multiple observation intervals, inter- mediate frames are skipped, and the model receives the most recent scheduled frame available at the resulting simulated time. This provides a simplified analogue of humans returning attention to the current scene after deliberation, and tests whether the model can respond before relevant events or action opportunities pass. Both protocols thus require the model to balance the benefits of additional deliberation against the cost of delayed action. 4 BENCHMARK DESIGN 4.1 DESIGN PRINCIPLES.
