Rendering cameras and alignment. For given-geometry evaluation, we replay the 16 camera poses and front-light settings stored in each ground-truth asset’s transforms.json; the designated input camera defines the reference view, and the other 15 cameras define novel views. Ground-truth and predicted assets use identical cameras and lighting, rendered with Blender 3.0.1 and Filmic color management. Where geometric alignment is required, we use iterative closest point (ICP) and silhouette-based refinement to estimate a similarity transform to the ground-truth geometry before rendering. This alignment is used only for evaluation. DINOv3 Fréchet distance for given-geometry texturing. For Table 1, we extract the 1024-dimensional final-layer CLS token of DINOv3 ViT-L/16 without additional ℓ2 normalization. We alpha-composite each shaded rendering onto black, resize its shorter side to 256 pixels using bilinear interpolation, center-crop to 224 × 224, and apply ImageNet mean and standard-deviation normalization. These features are computed in FP32 with TF32 disabled using Transformers 4.57.3. We compute the Fréchet distance between the feature means and unbiased covariances of the generated and corresponding ground-truth image sets, using float64 statistics. Each object provides a ground-truth mesh and a forward-lit reference image from a specified view; every method textures the ground-truth mesh from this image through its own interface, and we render 16 views comprising the reference view and 15 novel views. We compare against the texturing stages of the native 3D generators TRELLIS.2 and Pixal3D⋆and of the pipelines Hunyuan3D 2.1 and Step1X-3D (Xiang et al., 2026; Li et al., 2026a; Tencent Hunyuan3D Team, 2025a; Li et al., 2025a), and against the dedicated texturing methods LumiTex, MVPainter, MV-Adapter, TEXGen, UniTEX, and Ink3D (Bao et al., 2026; Shao et al., 2025; Huang et al., 2025b; Yu et al., 2024; Liang et al., 2026; Han et al., 2026). TRELLIS.2, Pixal3D⋆, Hunyuan3D 2.1, LumiTex, and MVPainter output PBR materials and are evaluated on shaded renderings, albedo, metallic, and roughness; the remaining methods output RGB textures and are evaluated on shaded renderings only, with unavailable channels marked “–”. We use the official implementations and released checkpoints for all baselines, providing the reference camera to every method that supports camera conditioning. End-to-end comparison. When geometry is also predicted, reference fidelity depends on geometry reconstruction, surface correspondence, and material generation together. This is the setting the observation interface is most exposed to: the anchors now land on a predicted mesh through a predicted camera, so any geometry or correspondence error propagates into the materials. Each method takes the reference image alone. Pixal3D⋆and SUPRA-Tex share the same predicted geometry and apply their respective appearance-generation pipelines; the other baselines use their own geometry-generation pipelines. SUPRA-Tex textures this predicted mesh with the pipeline of Sec. 3.5. We compare with TRELLIS.2, Pixal3D⋆, Hunyuan3D 2.1, Step1X-3D, UniLat3D, and CUPID (Xiang et al., 2026; Li et al., 2026a; Tencent Hunyuan3D Team, 2025a; Li et al., 2025a; Wu et al., 2026a; Huang et al., 2026), covering native latent generation, staged geometry-then-texture pipelines, and joint object–pose modeling. Since output material attributes differ across these systems, we compare complete assets through rendered appearance only. For scoring, outputs are brought into a common coordinate frame using their coordinate transforms or, for methods marked †, similarity alignment to the ground truth; this alignment plays no role in generation. Reconstruction metrics take the reference view as anchor and compare four rendered views against the ground truth: the reference direction, its two sides, and the back. The side and back views thus test the completed surface, not only the reference view. CLIP-I compares the reference-view rendering with the input image. FDDINOv3, FDCLIP, FID, and CMMD compare the set of 16 rendered views of generated assets with the corresponding ground-truth set within each dataset. Reconstruction and CLIP-I measure fidelity to a specific object; the distribution metrics measure the visual quality of the generated population. Baselines. We use the authors’ released checkpoints and implementations for the open-source baselines, following their inference recipes with method-specific sampling, resolution, and texture-export settings. Integration includes input-format conversion and repairs to mesh preprocessing, UV construction, and export. For given-geometry texturing, each method receives the designated reference image and GT mesh with its original materials removed, using the method’s texturing interface; the reference camera is supplied where the interface supports it. No GT material maps or additional GT images are provided. For image-to-3D generation, each method receives the same single reference image.
