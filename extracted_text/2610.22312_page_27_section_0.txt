C Evaluation Protocol C.1 Shared evaluation and model settings The six models receive the same 1,488 instances from 248 reference trajectories, producing 8,928 retained outcomes. The main experiment contains 192 trajectories and 1,152 instances. Seven additional workload conditions contribute 56 trajectories and 336 instances; combining them with four reused main conditions gives the 528-instance workload view. Each generation condition has eight trajectories, and each trajectory supplies six separately queried prefixes. At one main length, task and dimension summaries contain 24 and 64 instances, respectively. Table 9 records the full model identities and request parameters. GPT-5.6 Sol, Claude 5 Sonnet, and GPT- 5.4 Mini use the NAIRR gateway; GLM-5, Kimi K2.5, and MiniMax M2.5 use native Bedrock streaming (Amazon Web Services, 2026a,b,c). Collection took place on 16–24 September 2026 UTC. All requests use prompt 0.4, one completion, a 128,000-token combined reasoning-and-answer ceiling, no tools, and a 7,200- second deadline. Temperature, top_p, and seed are omitted. Five models receive the high-effort setting; MiniMax M2.5 uses native always-on thinking without an effort field. Each instance is submitted as one user message, with no task-specific system message or preceding conver- sation. Scoring uses the delivered answer text. Technical failures before a scorable outcome can be retried; delivered outcomes are retained regardless of correctness, format, or termination. There is one retained outcome per model–instance pair.
