Overview of XViewRank. Three query views are searched independently with BM25, merged into a candidate pool, represented by six score-overlap features, and reranked by a lightweight fusion scorer. are not directly comparable, scores are normalized within each query-view ranked list using min-max normalization. For a view v, the normalized score is denoted as ˆsv(q, d). If the maximum and minimum BM25 scores in a view are equal, the normalized score for that view is set to zero. If d is absent from the ranked list of view v, the corresponding score feature is also set to zero. This yields three normalized score features: ˆsori(q, d), ˆshy(q, d), ˆsst(q, d). (2) These features keep the evidence from the original query, the hypothesis view, and the step-back view separate. At the query level, XViewRank records how much the views agree with each other. Let Dτ q,v be the top-τ documents retrieved by view v. For each pair of views u and v, we compute the Jaccard overlap between their top-τ result sets: Ju,v(q) = |Dτ q,u ∩Dτ q,v| |Dτq,u ∪Dτq,v|. (3) We use τ = 500 in all experiments. The three overlap features Jori,hy(q), Jori,st(q), and Jhy,st(q) describe whether the generated views are mostly redundant with the original query or provide complementary evidence. The final feature vector for candidate d is: x(q, d) = [ˆsori, ˆshy, ˆsst, Jori,hy, Jori,st, Jhy,st]. (4)
