To locate a call in its trajectory, we divide the n calls of a query, including read calls, into five equal segments, so that the i-th call, counting from 0, lies in segment ⌊5i/n⌋+ 1. Over the calls of all queries, read and other calls make up the largest share in the first segment, rg calls in the second and Python calls in each later segment, with both models (Figure 2a for GPT-6-Luna). Python commands and edge files. A Python com- mand is a shell call that runs python3. It refers to edge files if its code or arguments mention the edge directory or an edge file. With GPT-6-Luna, 41.1% of the Python commands refer to edge files. Revisions. The similarity of two programs is the ratio that Python’s difflib.SequenceMatcher computes for their first 4,000 characters. Before comparing, we remove boilerplate lines: imports, comments, path constants, loops over node shards or over the lines of a file, json.loads of a line, and try/except-continue lines. A program is counted as revising an earlier program in its tra- jectory if its similarity to the most similar earlier program is at least 0.5. This holds for 36.5% / 33.7% of the programs. With each model, in 99.7% of the revisions the program being revised was is- sued in an earlier turn, so its output was visible when the revision was written. IDs from earlier outputs. A program contains an ID from an earlier output if its text contains a 4- to 8-digit integer that an output of an earlier turn showed as the ID of a node record, in an edge row, as a list element or at the start of a line. Years, multiples of 1,000 and numbers that appear in the prompt are excluded. This holds for 48.4% / 59.9% of the programs, and 83.1% / 95.9% of the queries with Python have such a program. Operation types. We label each program by rules over its source code, and a program can have sev- eral labels. A full node scan iterates over all node files. A one-hop traversal reads an edge file, and a multi-hop traversal filters an edge file by IDs that an earlier edge filter of the same program returned, or expands an adjacency index from a loop over seed nodes. Each program that reads an edge file gets one of these two traversal labels. The set oper- ations label covers intersections and differences of ID sets. Scoring or ranking sorts candidates, keeps the top ones or accumulates scores or counts. A check of earlier IDs contains an ID from an earlier output, as defined above, and looks it up in the node files, the edge files or the list of candidates. Two of these types, the one-hop traversal and the check of earlier IDs, have counterparts among the predefined graph tools (Table 5). neighbors per- forms a one-hop traversal, and get_node looks up a known ID, as a check of earlier IDs does. The closest counterpart of a full node scan is search, which returns the k ≤30 best BM25 matches for a query. The other three types can require several calls or code. Failures and the next program. A program fails if it exits with a non-zero status, prints a Python traceback or syntax error, or times out. The 164 / 66 programs with an interpreter start error are excluded from both the failures and the successes. Of the programs that ran, 7.4% / 8.5% failed (2,089 / 2,426). The next program after a given program is the first program issued in a later turn. It is counted as revising the given program if their similarity, computed as above but with the boilerplate lines kept, is at least 0.5. Section 3.4 and Table 9 use the 2,033 / 2,395 failed and 19,534 / 19,369 successful programs that have a next program. In 85.6% / 91.1% of these failures, the next program revises the failed one and runs successfully. Lineages and gold IDs in outputs. We link each program to the most similar program issued before it in the same query if their similarity, computed with the boilerplate lines kept, is at least 0.5. The programs connected by these links form a lineage, whose first and last versions are its earliest and latest programs. There are 7,282 / 7,621 lineages with at least two versions. A call shows a gold ID if its output that the model saw contains the ID of a gold node as a standalone number. For the first and last versions of the lineages, this holds for 40.0% / 49.4% of the first versions and 72.0% / 67.9% of the last versions. The test accepts the ID in any position of the output. Over the 5,080 queries that GPT-6-Luna answers correctly, the first call that shows a gold ID is a program in 68.5%, an rg search in 29.7% and another command in 1.8%, while programs make up 38.2% of all calls, read calls included.
