We use a Gaussian HYB bitshift trellis with tail-biting. For each row, the encoder searches for a low-error path through the shared trellis and stores its transi- tion symbols as ci. The reconstruction function f recovers the corresponding vector from these sym- bols using a small shared lookup table and arith- metic operations. All rows use the same coding rule and code rate, without an additional coordinate ro- tation. Although the shared source model describes nor- malized row contents, the magnitude of each em- bedding also affects the signal passed to the model. A least-squares reconstruction scale can shrink the decoded vector when its direction differs from the original row. CP instead restores the original row norm by setting αi = ∥ei∥2/∥f(ci)∥2. This pre- serves the magnitude of the learned representation, even when doing so increases coordinate recon- struction error. The scale is computed once during encoding and stored with the corresponding row. 3.4 Independent Storage and Selective Execution CP stores each row as an independently address- able record containing its compressed code and local scale. For a row of dimension d encoded at b bits per coordinate, storing one 16-bit scale gives a rate of b + 16/d bits per parameter before align- ment. The shared reconstruction rule incurs only a table-wide storage cost. Because each record can be addressed independently, compressed rows can be fetched and cached without accessing unrelated entries. At inference time, the original address function determines the requested rows A(x). For each ad- dress i ∈A(x), CP fetches the corresponding code and scale, reconstructs the embedding using Equa- tion 6, and passes it to the existing readout in the original lookup order. A fused kernel performs fetching and reconstruction for the selected records without decoding unrelated rows. The address func- tion, backbone parameters, and downstream com- putation remain unchanged. 4 Experiments We evaluate how well CP preserves model qual- ity under reduced table storage. We first compare downstream task performance at low bit rates, then examine the trade-off between storage and output- distribution fidelity across a wider range of rates. 4.1 Experimental Setup Models. We evaluate Conditional Program (CP) on three models that employ n-gram lookup tables: DeepSeek, Qwen, and LongCat, as described in Section 2.1. To isolate the effect of compression, we compress only the lookup tables while keeping all other model components unchanged. Benchmarks. To assess the impact of compres- sion across different model capabilities, we eval- uate 40 tasks spanning five categories: common- sense, knowledge, reading comprehension, mul- tilingual understanding, and math and code. Be- yond knowledge-intensive benchmarks, we include GSM8K and HumanEval to evaluate mathemati- cal reasoning and code generation, both of which require generated answers. We first compare against the origi- nal lookup tables and table removal, where every lookup returns zero, to assess the contribution of the stored entries. For quantization baselines, we include round-to-nearest (RTN), which indepen- dently rounds values to the nearest quantization level, and NVFP4 and MXFP4, which use four-bit floating-point formats (Rouhani et al., 2023). To further examine the benefits of CP’s design, we adapt the trellis quantization of QTIP (Tseng et al., 2024b), originally developed for dense weights, to lookup tables. Specifically, we construct a trellis- based baseline with within-row rotation and a global scale shared across the table, allowing us to distinguish the benefits of trellis quantization from those of CP’s row-wise magnitude separation. 4.2 Results Benchmark Performance. We first examine whether CP can substantially reduce lookup-table storage while preserving model performance. As shown in Table 1, CP compresses the original ta- bles by approximately 4 to 8 times while retaining most of their benchmark performance. In particular, CP largely preserves performance on knowledge- intensive tasks where removing the lookup table causes substantial degradation. Compared with ex- isting quantization methods, CP outperforms RTN on the knowledge benchmarks for Qwen and Long- Cat, while achieving comparable performance to QTIP in the paired evaluations.
