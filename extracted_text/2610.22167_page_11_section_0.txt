A Training Setup Hardware used Supervised initialization uses 1 NVIDIA H100 GPU for training. Reinforcement learning uses 3 NVIDIA H100 GPUs. A.1 Supervised Initialization We use the GPT-6 family of models to refine the sampled reasoning traces. We select the stage 1 checkpoint by mean macro F1 across tasks on 24 held-out targets (eight per task), excluding all rows sharing these targets from SFT. We use AdamW with weight decay 0.01 and the settings in Table 5. SFT runs for two epochs, with one example per device, four gradient accumula- tion steps, and seed 42. The learning rate warms up over 1% of training, then decays linearly to zero. The input embedding and lm_head matri- ces remain frozen except for the <evidence> and </evidence> rows, which use ten times the LoRA learning rate and no weight decay. To account for the different lengths of reasoning and answers, we allocate 15% of each completion’s loss weight to final-label tokens and 85% to the remaining tokens, including the end-of-turn token. A.2 Reinforcement Learning RL uses AdamW with weight decay 0.01, (β1, β2) = (0.9, 0.99), and the settings in Table 5. We train for 723 updates with eight prompts per update and K = 8 completions per prompt, keep- ing the input embedding and lm_head matrices frozen. The learning rate warms up from 5 × 10−7 to its peak over 19 updates, remains constant through update 506, then decays by cosine to its initial value. For both RL variants, we evaluate the final training checkpoint without additional evaluation for checkpoint selection. We first use full conversations ordered by in- creasing difficulty within each task, then mix them with contexts containing the target and its preced- ing 5, 10, or 20 turns. Accuracy-Only RL uses the same data mix. For CLUE, unusable groups re- ceive up to three resampling attempts, followed by up to two replacement prompts. SFT checkpoint selection and RL rollouts use temperature 1, top-p 1, no top-k truncation, and no separate reasoning budget.
