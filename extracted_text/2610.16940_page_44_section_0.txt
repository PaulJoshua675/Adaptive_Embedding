H KD-Tree Baseline: Ablation and Cross-Codebase Comparison This appendix supports Section 5.5. The KD-tree is a median-split tree implemented inside RUSTKNN (src/kdtree/), reusing the Distance trait (including distance with bound, the early-exit kernel), the same k-NN candidate structure, the same thread-local distance counter, and the same loader and timing code as the cover trees. Correctness was verified against brute-force search on every dataset (maximum coordinate discrepancy 10−16). Because it shares the kernel, it runs the same five feature-flag ablations. Table 13 gives the KD-tree’s distance counts, which make the curse-of-dimensionality crossover explicit: on mnist the KD-tree issues 594M distance computations (each up to 784-dimensional), versus 312M for the simplified cover tree in single-tree mode (Table 9), because axis-aligned box pruning stops discriminating at high d. For the cross-codebase column we used kiddo 5.3.2, an actively maintained independent Rust KD- tree crate, via its ImmutableKdTree with nearest n::<SquaredEuclidean>. It was run under the same 20-allocation protocol as the main tables (all-NN, k=1); because kiddo is compiled as part of the same Rust project, it inherits the same RUSTFLAGS (including target-cpu=native), so the ISA disparity noted in Appendix B does not apply to this comparison. kiddo necessarily uses its own distance kernel and candidate structure, which is why it cannot run our ablation flags and why we implemented an in-harness tree for the controlled comparison: an external library alone would reintroduce exactly the cross-codebase confounding this paper is about.
