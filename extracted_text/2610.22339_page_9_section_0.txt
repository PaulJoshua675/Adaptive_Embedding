LS = LeanSearch, LGS = LEANGRAPHSEARCH, Std. = Standard Mode, Reas. = Reasoning Mode. For each of the 10 configurations, we compute total API cost divided by the number of solved problems on the union of 210 theorem-proving instances. Solved counts are measured by pass@32. Lower values indicate better cost efficiency. Failure memory improves proving performance under limited reflection budgets. At k = 8, enabling failure memory increases the total number of solved problems across all four retrieval con- figurations. In Standard Mode, the count rises from 106 to 111 for LEANGRAPHSEARCH and from 99 to 105 for LeanSearch v2. In Reasoning Mode, memory also improves completion, increasing the aggregate pass@16 count for LEANGRAPHSEARCH from 132 to 138. These results show that failure memory can help the prover complete more proofs under limited reflection budgets. Graph retrieval lowers API cost per solved problem. Fig. 3 reports API cost per solved prob- lem for each retrieval configuration across all 210 theorem-proving instances, calculated as total API expenditure, including unsuccessful runs, divided by the number of problems solved within 32 turns. LEANGRAPHSEARCH in Standard Mode achieves the lowest cost per solved problem. LEAN- GRAPHSEARCH in Reasoning Mode with memory achieves the highest aggregate completion, solv- ing 151 of 210 problems, while maintaining a lower cost per solved problem than LeanSearch v2. Our qualitative analysis suggests that, by following multi-hop dependencies, LEANGRAPHSEARCH uncovers supporting lemmas used in related proofs that direct query matching may miss. Retrieving these premises contributes to improved downstream theorem proving. Examples illustrating this mechanism are provided in Appendix C. 6
