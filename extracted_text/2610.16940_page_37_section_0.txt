B Experiment Details Hardware. All experiments run on a multi-node SLURM cluster. Each compute node contains two Intel Xeon Platinum 8490H processors (Sapphire Rapids, 60 cores per socket, two hardware threads per core, 112.5 MiB of L3 per socket, maximum clock 1.90 GHz, i.e., no turbo boost) with 2 TB of RAM, running Ubuntu 22.04 LTS (Linux 5.15). Every benchmark job is allocated one physical core (--cpus-per-task=1 under core-granularity scheduling) and its own memory, so jobs never share a core; they do share each socket’s L3 cache and memory bandwidth with the other jobs on the node. Node load. That sharing matters on the large datasets. On an otherwise idle node, N pinned copies of the mnist all-NN, split evenly across the two sockets, slow down by 1.48× (N=15), 1.61× (N=30), and 1.99× (N=60) for the C++ reference, and by 1.43× (N=15) and 2.07× (N=60) for RUSTKNN single-tree search (each copy pinned to its own physical core): the two degrade at the same rate, so ratios between implementations measured under the same load are stable even though absolute times are not. Because the clock is fixed, the slowdown is cache and memory- bandwidth contention rather than frequency scaling. We therefore ran every campaign with the nodes held at a similar, high load (about 110 memory-heavy benchmark jobs per 120-core node), using filler jobs that run the same mnist workloads while a campaign’s last allocations finished, so that no configuration was measured on an emptying node. One of the three nodes ran large-dataset allocations 1.1–1.5× slower than the other two at the same job count; allocations were spread across nodes, so this mainly widens the upper confidence bounds on covtype and mnist rather than moving the medians. On pima and pendigits, per-allocation timings are bimodal for reasons we have not isolated (Section 4.2). Software. The Rust implementation is compiled with rustc 1.94.1 (stable, 2026-03-25) us- ing --release with LTO enabled and codegen-units=1. The reference C++ cover tree of Beygelzimer et al. [7] is compiled with g++ 11.4.0 (-O3 -ffast-math -funroll-loops). ml- pack 4.7.1 [15] is compiled with g++ 11.4.0 (-std=c++17 -O3 -DNDEBUG). All implementations use a cover-tree base parameter of 1.3 unless otherwise noted (sensitivity analysis in Appendix A.4). Note that the Rust binaries are built on the cluster’s login node (Xeon Platinum 8358, Ice Lake) with RUSTFLAGS="-C target-cpu=native", i.e., AVX-512 code that also runs on the Sapphire Rapids compute nodes, while the C++ builds use g++’s default instruction set (SSE2); this favors the Rust implementation on vectorizable distance computations and is itself a confounder of the kind this paper argues about. Timing runs use un-instrumented builds; distance counts come from a separate pass with the instrument build (Section 5). 37
