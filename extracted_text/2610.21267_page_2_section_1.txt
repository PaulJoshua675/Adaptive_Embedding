Matching requests to fixed tool representations. Retrievers over large registries rank tools by sim- ilarity to the request (Qin et al., 2024; Patil et al., 2024; Gan and Sun, 2025; Liu et al., 2026; Repan- tis et al., 2026). Description matchers differ only in how that match is trained (Zheng et al., 2024; Molfetta et al., 2025; Sengupta et al., 2026); Tool2Vec (Moon et al., 2024) matches past requests rather than documentation; and MCP-Zero (Fei et al., 2025) has the model write its own query, better aligned to tool descriptions than the user’s words. Each improves the query; all still score it against a representation fixed in advance. Fixed once, it cannot separate several plausible candi- dates, and it cannot register that one tool serves different purposes at different points. Past usage at that point does both. Relating tools to one another. TGR (Gao et al., 2025) smooths each tool’s embedding toward the tools it depends on, so prerequisites are retrieved alongside what needs them; ProTIP (Anantha et al., 2023) retrieves progressively, subtracting the em- beddings of tools already chosen so the query car- ries what remains. While these take real steps, they ignore what makes tool-calling dynamic: ev- ery choice must be read against the calls and turns that came before it. TGR pools dependency over all prefixes, fixing once a relationship that holds only sometimes, and ProTIP’s subtraction keeps no record of the order the previous calls came in. Conditioning on execution. ToolNet (Liu et al., 2024b) offers the successors of the last call, weighted by bigram counts; AutoTool (Jia and Li, 2026) widens that to two and blends the count with SimCSE similarity at a constant α=0.5, using the result to bypass the model. Neither asks how the current conversation resembles the ones that pre- viously took each transition: ToolNet has no such signal, and AutoTool’s compares against a tool’s description (21 points worse on API-Bank in our ablation). Both also fix the blend once.
