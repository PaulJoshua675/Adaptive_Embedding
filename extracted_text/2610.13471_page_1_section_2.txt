Controller tuning by simulation can be computationally expensive because every candidate gain vector requires a MATLAB/Simulink electromagnetic-transient (EMT) simulation. In the EAF–STATCOM application considered here, the adopted tuning protocol uses exactly 1040 objective evaluations. This is much smaller than the largest CEC2022 [1] budgets, so optimizer rankings obtained only at competition budgets should not automatically be assumed to represent behaviour around 103 evaluations. Benchmark reports commonly emphasize final-quality performance at comparatively large evaluation budgets, whereas the intended application here operates near 103 objective evaluations, and the ranking observed at a com- petition budget need not preserve the same ordering when the methods are reconfigured to spend far less. Schedules that anneal a search radius, a mutation scale, or a step length over the run behave differently when the run is short, so a method configured for a large budget and halted early is a different configuration from the same method configured for a small budget. For an application that can afford only about 103 evaluations, the useful question is how the methods compare at that budget when each budget is run as an independently configured experiment rather than read from an early point of a long run. The optimizer studied here belongs to the multiplayer battle-game family. The Multiplayer Battle Game Optimizer (MBGO) [6] models candidates as players that improve through pairwise contests; the Efficient Multiplayer Battle Game Optimizer (EMBGO) [7] streamlines that scheme for numerical optimization. REMBGO augments the EMBGO search structure with elitism, a fitness-weighted centroid, normalized neighbourhood control, additional perturbation operators, stagnation handling and partial restart, with the aim of improving search when evaluations are limited, while retaining the battle-game core. The study therefore addresses two linked questions: whether the REMBGO refinements improve on EMBGO when objective evaluations are scarce, and whether optimizer-selected controller gains retain their performance when exposed to unseen stochastic EAF trajectories. Budget-dependent benchmarking evaluates an optimizer at several function-evaluation budgets rather than judging it only by its final result at one large budget.
