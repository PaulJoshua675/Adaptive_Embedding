The serialization σ(N) is the safetensors encoding of four integer vectors: (i) the bias of each unit, in the order of N; (ii) the number of predecessors of each unit, in the same order; (iii) one signed entry per edge, its magnitude the index of the predecessor plus one and its sign the weight, the edges of a unit consecutive and in the order the unit lists them; (iv) for each state bit, the index of the signal computing its next value. The file is an eight-byte little-endian header length, a JSON header object, and the concatenated tensor data in little-endian order. The biases are stored as eight-bit integers, and the fan-ins, the edges and the next-state indices as sixteen-bit integers when their values fit and as thirty-two- bit integers otherwise. Seven thirty-two-bit scalars record the address width, the data width, the number of memory words, the width of the program counter, the number of state bits, the number of units and the version of the format. Four choices that a general-purpose serializer leaves open are fixed. The header object begins with the key metadata , whose value lists the machine name, the quantization tag, the state layout and the device addresses of Table 1, in that order. The remaining entries are the tensors, ordered by element type and then by name, with the data in the same order. The JSON has compact separators and no non-ASCII escaping. Spaces pad the header so that the tensor data begins at an eight-byte boundary. The fixed choices make σ a function. Every predecessor carries the weight ±1, so the sign of an edge entry gives its weight, and the fan-in vector cuts the edge vector into the predecessor list of each unit; every index refers to a signal that these vectors define. So N, the order of its units included, is recovered from σ(N) alone. For Nhost the metadata has machine subleq8 and weight quantization ternary. Its signal registry is the first string below, the state layout of Construction 5.8 by first coordinate and width, with the number of words for the memory, and its io is the second, the addresses of Table 1: {"halt":[8,1],"mem":[9,256,8],"pc":[0,8]} {"c eot":250,"c rd":252,"c rw":251,"c wr":249,"halt pc":255,"r in":253,"r out":254} The scalars are the I32 tensors manifest.addr bits, data bits, memory words, pc width, state bits, units and version, holding 8, 8, 256, 8, 2057, 17,598 and 6, and the vectors are net.fanin, net.next and net.pred of type I16 and net.bias of type I8. The netlists Nα K,S,L are written as files of little-endian 32-bit integers: the numbers of state bits, units and edges; the bias of each unit; the fan-in of each unit; one signed entry per edge, as in σ; and, for each state bit, the index of the signal computing its next value. The state bits are numbered first, in the order of Theorem 3.2, and the units after them, in the order of the Rocq definition. An image of records, such as the organism or the stored host, is the sequence of its records, each laid out as in Definition 3.1, in the order of the Rocq definition, with the window cells of Construction 4.3 or 7.1; in the stored host the cells of the units, of the levels and of the device follow the state bits, in that order.
