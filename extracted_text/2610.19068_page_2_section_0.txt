The closest prior work to the paradigm we study is TOOLQP (Fang and Glass, 2026), which generates multi- round query reformulations to improve API retrieval, trained with reinforcement learning. Our approach differs in three ways: stubs are generated in a single zero-shot prompt call with no training, we generate hypothetical function signatures rather than query reformulations, and we study PtR as a controlled paradigm rather than proposing a new system. Despite this active area, no prior work has directly compared these two retrieval paradigms in a controlled setting at large registry scale, characterized how the trade-off changes with query complexity, or analyzed how retrieval differences cascade into planner behavior. We term the dominant paradigm Retrieve-then-Plan (RtP) and the alternative Plan-then-Retrieve (PtR), and present the first systematic apples-to-apples comparison at industrial scale (50k APIs). A key analytical lens we introduce is Intent-Registry Coupling: the semantic gap between how users describe tasks and how APIs are documented. Our PtR instantiation generates Abstract Tool Stubs (hypothesized function signatures) as retrieval queries in a single zero-shot prompt call with no training. Our contributions: (1) a complexity- dependent crossover (RtP wins on simple queries, PtR wins on multi-tool queries) robust to retrieval budget, registry size, and model family; (2) a characterization of stub hallucination as a dual mechanism: it degrades retrieval when queries have high Intent-Registry Coupling, and improves it when they do not; (3) an analysis of token overhead showing that directing single-tool queries to RtP and multi-tool queries to PtR reduces discovery-call overhead by ∼36% with no retrieval quality loss, motivating complexity-adaptive routing as a practical direction consistent with prior work on complexity-aware retrieval (Jeong et al., 2024). 2 Method 2.1 Architectures Figure 1 illustrates both pipelines.
