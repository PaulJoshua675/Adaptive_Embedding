A.5 REFINEMENT ROUNDS, HISTORY, AND OUTPUT SELECTION Round execution and task prioritization. Pre-round stages are cached, whereas every round executes fresh through a fixed verification chain: code synthesis, build with bounded repair, geometric measurement, deterministic gates, multi-view rendering, VLM judgment, and Git archival. A failed build triggers up to three targeted repair sessions supplied with the error location, traceback, lint diagnostics, and relevant cookbook snippets, and every completed round is committed with a journal entry of its telemetry, verdicts, renders, and token usage. Refinement tasks are compiled from the preceding round in strict priority order—deterministic gate errors with numerical fix hints, then unverified mandatory checklist items, then the judge’s perceptual instructions—and deduplicated by part and defect category. At most six tasks are dispatched per round, and truncation applies only to perceptual suggestions, so gate errors and mandatory items are never dropped; reference-conditioned runs append a silhouette task whenever outline IoU falls below 0.60. Termination and best-of-N initialization. The standard profile allocates up to T = 4 refinement rounds and a 60-minute wall-clock ceiling; refinement stops early once all verification tasks are resolved, a round makes no code change, or the budget is reached, while monetary cost is logged for accounting only.
