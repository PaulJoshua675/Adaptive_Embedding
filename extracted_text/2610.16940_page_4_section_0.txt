The base parameter b controls the ratio between covering and separating distances. The original formulation uses b = 2, but Beygelzimer et al. [7] found empirically that b = 1.3 reduces distance computations by 10–71% on benchmark datasets. Our experiments default to b = 1.3. Each node also caches maxdist(p) = maxq∈descendants(p) d(p, q), the greatest distance from p to any of its descendants, which is upper bounded by covdist(p) · b/(b−1) (a geometric series over descendant levels; this equals 2 · covdist(p) when b=2 and ≈4.3 · covdist(p) at the default b=1.3). This value enables the key pruning rule during queries: a subtree rooted at q can be skipped entirely when d(query, q) −maxdist(q) > dbest, because even the closest descendant of q must be farther than the current best candidate. From Beygelzimer et al. [7], the maximum number of children per node is O(c4) and the maximum tree depth is O(c2 log n). 3.3 Algorithmic Variants The original cover tree [7] was defined as an implicit infinite structure in which every internal node also appears as its own child—the nesting invariant. The explicit representation stores O(n) nodes. Izbicki and Shelton [8] observed that the nesting invariant is unnecessary for the runtime analysis and introduced two improved variants that eliminate self-children, reducing the node count to exactly n. Simplified cover tree construction. The simplified insertion of Izbicki and Shelton [8] builds a tree via depth-first search: starting from the root, the algorithm finds the first child whose covering distance accommodates the new point and recurses; if no child qualifies, the point becomes a new child at level −1. If the new point lies beyond the root’s covering distance, the root level is raised. The tree contains exactly n nodes, one per data point, eliminating the self-children of the original formulation. Construction runs in O(c6n log n) time. Nearest ancestor cover tree construction. This variant adds a fourth invariant: for every point p with ancestor q1 and sibling q2 of q1, we require d(p, q1) ≤d(p, q2)—every point’s ancestor at each level is the closest possible. Insertion sorts children by distance to the new point and invokes a rebalance procedure that extracts descendants violating the invariant and reinserts them under the new point. Construction is costlier, but the resulting tree has tighter maxdist values, leading to more aggressive pruning; the trees are also deeper, so querying is not always quicker than the simplified variant. Parallel cover tree construction. Two cover trees are merged by matching children between them at each level, enabling parallel construction: partition the dataset across processors, build indepen- dent trees, then merge via binary reduction in O(log p) rounds. Roughly 1% of distance computa- tions occur during the merge; the bottleneck is cache performance in the parallel construction phase. Nearest-neighbor search traverses the tree depth-first from the root, visiting children in order of increasing distance to the query. A child q is pruned when d(query, q) − maxdist(q) > dbest, yielding O(c6 log n) runtime. Batch single-tree query. This algorithm, derived from the code of Beygelzimer et al. [7] but not described in detail in their paper, organizes the query set into its own cover tree and maintains cover sets—lists of candidate reference nodes, indexed by scale level—that are passed top-down through the query tree hierarchy. At each scale level, three cases arise (Figure 20 in the appendix): (i) ref- erence descent—expand each candidate reference node by replacing it with its children, computing distances and pruning; (ii) query split—when a query node has children at the current scale, each query child receives a filtered copy of the parent’s cover sets with distances recomputed and entries pruned against the child’s bound; the parent point continues as a “virtual self-child,” inheriting the cover sets directly; (iii) base case—at the leaf scale, score remaining candidates. The key mecha- nism is cover-set inheritance: once a reference candidate is pruned from a query node’s cover set, no descendant query point will ever see it. A mutable upper bound threaded through the recursion means any improvement from scoring one query point immediately tightens the threshold for sib- lings and descendants.
