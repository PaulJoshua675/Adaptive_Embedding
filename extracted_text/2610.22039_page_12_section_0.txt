Algorithm 1: Dependency DAG Assembly Require: Repository R, merged PRs {p1, . . . , pn} (by timestamp), threshold θ, budget K, search radius ∆ Ensure: Set of candidate DAGs G 1: // Phase 1: Typed Change Loci Extraction 2: for each pi ∈{p1, . . . , pn} do 3: L(pi) ←Last(pi)∪Lsym(pi)∪Lcfg(pi)∪Ldecl(pi)∪ Ldep(pi) 4: Apply exclusion rules (test files, generated code, ven- dored) 5: end for 6: // Phase 2: Candidate Edge Generation 7: Ecand ←∅ 8: for each pair (pi, pj) with |t(pj) −t(pi)| ≤∆do 9: Compute sR(pi, pj) = P ℓ∈L(pi)∩L(pj ) wR(ℓ) P ℓ∈L(pi)∪L(pj ) wR(ℓ) 10: if sR(pi, pj) ≥θ then 11: Ecand ←Ecand ∪{(pi, pj)} 12: end if 13: end for 14: // Phase 3: Mechanical-Change Filtering 15: Remove reverts, backports, release-branch refs, near- duplicates from Ecand 16: // Phase 4: Component Partitioning 17: Compute connected components C from (V, Ecand) 18: G ←∅ 19: for each component Ci ∈C do 20: if |Ci| ≤K then 21: Orient edges by timestamp; break cycles 22: G ←G ∪{DAG(Ci)} 23: else 24: while ∃subgraph S ⊆Ci with |S| ≥2, mean weight ≥θ do 25: Extract densest-first subgraph S with |S| ≤K 26: Orient edges; break cycles; G ←G ∪{DAG(S)} 27: Ci ←Ci \ S 28: end while 29: end if 30: end for 31: // Phase 5: Degenerate Filtering 32: Remove star graphs, trivially serial chains, disconnected DAGs from G 33: return G Degenerate structure filtering. A subset of assembled DAGs are structurally uninformative for evaluation despite passing coupling and size thresholds. We apply three topo- logical filters: • Star graphs, where a single hub node accounts for >80% of all incident edges with no inter-leaf connections, typ- ically indicate a utility-file artifact rather than a genuine multi-party dependency chain. • Trivially serial chains with uniformly low edge weights (below the 25th percentile of the repository’s weight dis- tribution) and no branching structure, which provide lim- ited evaluation signal beyond what single-PR benchmarks already capture. • Post-filtering disconnection: DAGs that become dis- connected after mechanical-change removal are re- partitioned into their connected components and re- evaluated independently. A.3 Rollback Construction and Test Attribution Base state construction. Given a candidate DAG G = (V, E) and the repository state Sgold where all constituent PRs have been merged, we construct the base state Sbase by removing the changes introduced by all nodes in V . The primary mechanism is reverse-topological revert: we compute a topological ordering σ of V and process nodes in reverse order σ−1 (leaves first), applying git revert -no-commit for each node’s merge commit. PRs external to G that were merged between the earliest and latest con- stituent PRs are preserved in Sbase, ensuring the base state reflects realistic repository evolution outside the task scope. When git revert produces non-trivial merge conflicts— typically caused by overlapping modifications from interven- ing commits or cross-cutting refactors—we employ an agent- assisted carve as a fallback. In this path, an LLM-based agent receives the PR metadata (title, description, and code diff) and removes the target changes from the current repository state while preserving surrounding code. The carve operates semantically rather than mechanically: the agent identifies which hunks correspond to the target PR’s contributions and removes them while maintaining syntactic and build validity. After either path, the resulting Sbase is validated: it must compile successfully and all P2P (pass-to-pass) tests must pass. Candidates where neither revert nor carve produces a valid base state are discarded. Construction success rates. Approximately 35% of can- didate DAGs are discarded during construction because nei- ther revert nor carve produces a valid, test-passing base state. Among the successfully constructed instances (which form the final WEAVE-Bench and WEAVE-Train corpora), 73% are built via clean git revert and 27% require agent-assisted carve. The higher carve rate for Java and Kotlin tasks reflects stricter type-system constraints that propagate through revert sequences, while Python and JavaScript tasks exhibit higher clean-revert rates due to fewer cross-module compilation de- pendencies. Test attribution. For graph-conditioned scoring, each F2P test must be associated with one or more PR nodes in the task DAG. The primary attribution mechanism is isolated revert: for each node v ∈V , we construct Sv = Sgold \ {v} by reverting only v’s changes, then execute all F2P tests against Sv. If exactly one node v causes test t to fail, t is at- tributed to v; if multiple nodes independently cause failure, t is marked ambiguous; if t fails only under joint reversion, it is unattributed. In cases where isolated revert is infeasible for individual nodes (e.g., due to compilation dependencies between constituent PRs), an agent-based attribution step supplements the automated procedure by analyzing test se- mantics against the PR change descriptions.
