Positioning Relative to Retrieval and Routing Candidate pre-selection and retrieval-first orchestration are established ideas in tool and agent systems. ToolRet [5] studies large-scale tool retrieval; ToolScope [7] reduces tool context through consolidation and filtering; Tool-to-Agent Retrieval [8] and Agent-as-a-Graph [9] exploit tool–agent relationships; and ACE-Router [10] and AgentRouter [36] study learned routing. Adaptive shortlist depth further treats candidate count itself as a decision variable [18]. The contribution of this work is therefore not candidate pre-selection, IDF weighting, or inverted indexing in isola- tion. Rather, we formulate candidate-context scalability for Agent Card discovery, propose SSR as an Agent-Card-native retrieval mechanism, and characterize how retrieval coverage, retrieval computation, candidate context, cost, latency, relia- bility, and LLM arbitration evolve under controlled registry growth. BM25 candidate pre-selection provides an important control because it separates the general effect of maintaining a compact candidate context from properties specific to SSR. Table VI summarizes this conceptual positioning relative to representative retrieval and routing approaches. SSR also provides score-level traceability: matched struc- tural signals and their IDF contributions remain identifiable for each retrieved Agent Card. This property applies to the retrieval stage and should not be interpreted as making subse- quent LLM arbitration explainable. C. Limitations Several limitations qualify the conclusions. First, RQ2 and RQ3 use a document-derived Agent Card abstraction. MS MARCO provides natural text and large-scale relevance judg- ments, but not native Agent Cards, structured skills, interfaces, authentication requirements, or operational metadata. The results therefore characterize retrieval and candidate-context behavior under this abstraction rather than in a production agent registry. Second, SSR-AgentBench is synthetic and uses one des- ignated target per query. Its controlled construction supports reproducible registry scaling but does not capture the full heterogeneity, documentation quality, capability evolution, ac- cess constraints, or multiple valid agents found in operational ecosystems. Third, SSR deliberately relies on explicit lexical unigrams and bigrams. Vocabulary mismatch can reduce recall, and the MS MARCO results show that this representation does not outperform BM25. More expressive field-derived, semantic, or hybrid retrieval may improve coverage. Fourth, although independent validation supports K = 20, the original sensitivity analysis and end-to-end evaluation reuse the same 200 RQ3 queries. A cleaner prospective design would select and freeze K on validation data and evaluate it once on a disjoint end-to-end test set. Finally, RQ3 uses 200 queries and one LLM/API configu- ration, and the BM25 run was executed separately from the SSR/full-catalog run. Absolute latency, token usage, cost, and the observed full-catalog failure point should therefore not be generalized across models, providers, prompts, or context limits. Reported online latency also excludes offline index construction, so preprocessing, storage, and maintenance costs remain outside the present evaluation. D. Future Directions Future work should first investigate query-adaptive can- didate depth, using score concentration, margins, or other confidence signals to choose K(q) while preserving a hard maximum candidate budget [18]. Second, SSR could pro- vide inexpensive candidate generation followed by semantic retrieval or reranking when lexical evidence is weak; Tool- Dreamer illustrates one semantic reformulation strategy [14]. Third, retrieval could become execution-aware, recomputing queries or candidate pools as a plan evolves, as suggested by DTDR and ToolQP [15], [16]. Evaluation should also move toward native public Agent Card and skill collections, multi-relevance judgments, prospec- tive validation/test splits, and dynamic registry updates. Large distributed deployments further motivate incremental, authorization-aware, and federated indexing.
