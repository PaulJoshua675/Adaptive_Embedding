Legend entries give the fitted slope in units of MiB per token. 6.4 Memory and runtime in LLMs As a larger training example, we evaluate peak VRAM usage and per-step latency when training Modded-NanoGPT and Nemotron-H across a range of sequence lengths (Appendix D.4), comparing dense activation storage, BitSparse(-sb), and activation checkpointing. Again, no optimizer buffer is used. A numerical equality check confirms that all methods reproduce the gradients up to floating-point rounding. Figures 3 and 4 report the memory and runtime results, respectively. Across the measured token counts, VRAM per token on Modded-NanoGPT decreases from 0.402 MiB to 0.277 MiB with BitSparse and 0.276 MiB with BitSparse-sb. On Nemotron-H, the corresponding values are 2.719, 1.894, and 1.890 MiB. This corresponds to an asymptotic VRAM reduction of 31% on Modded-NanoGPT and 30% on Nemotron-H. BitSparse incurs a negligible performance penalty. Checkpointing uses less memory but generally incurs a notable runtime cost.
