This con- trol condition helps identify gender-based preferences independent of age effects. This alternating design ensures balanced representation of both conditions across the dataset. Names were sampled uniformly at random from the top 500 most popular names in each decade-gender category from the Social Security Administration (SSA) database. The uniform sampling strategy ensures equal rep- resentation across the name frequency spec- trum, avoiding bias toward the most popular names. Within each query, the presentation order of the two options was randomized to mitigate position bias. Rationale. The same-gender comparisons are critical for isolating age bias. By hold- ing gender constant, any systematic preference for one name over another can be attributed to age associations rather than gender stereo- types. The different-gender comparisons serve as both a control and a separate investigation into potential gender biases in the same sen- tence contexts. This design enables us to dis- tinguish between age-based and gender-based preferences in model responses. 4.3 Task and Prompting Sentence Templates. We constructed 30 gender-neutral fill-in-the-blank sentences spanning diverse contexts that vary in age- indicativeness. Templates include explicit age markers (e.g., “ just celebrated a 45th birthday”), age-suggestive contexts (retire- ment planning, school activities), and neutral scenarios (travel, purchases). All sentences use a single blank placeholder to maintain consistency in task difficulty. Prompt Format. To ensure consistency across all models and avoid confounding ef- fects from prompt variations, we used a single standardized prompt template: Sentence: <sentence template> Which fits best: "<name1>" or "<name2>"? Answer with just the text of the choice. The prompt format is deliberately minimal and neutral. The instruction “Answer with just the text of the choice” constrains re- sponses to one of the two provided names, min- imizing extraneous generation and facilitating automated analysis. All models used the sys- tem message “You are a helpful assistant” to maintain consistency. Generation Parameters. We employed consistent generation parameters across all models to ensure comparable stochasticity. The temperature was set to 0.7, balancing be- tween deterministic and highly random behav- ior. This moderate temperature allows models to express subtle preferences while maintain- ing reasonable consistency across repeated tri- als. The maximum token limit was set to 512, though responses typically required fewer than 10 tokens. 4.4 Data Collection Protocol Data collection proceeded iteratively for each model. In each iteration, the system: (1) de- termined the comparison type based on itera- tion parity, (2) randomly selected appropriate name lists, (3) uniformly sampled two names, and (4) queried the model with all 30 sentence templates using randomized option orders. This process yielded 30 responses per it- eration. We collected 2,000 iterations for each open-source model, generating 60,000 re- sponses per model. The cumulative dataset comprises 300,000 model responses. 4.5 Infrastructure All experiments were conducted on the Nexus- vulcan cluster. Open-source models were deployed on NVIDIA RTX A5000 (24GB VRAM) and RTX A6000 (48GB VRAM) GPUs. We utilized vLLM (Kwon et al., 2023) for efficient model serving with OpenAI- compatible API endpoints. Key serving pa- rameters included: maximum context length of 2048 tokens (sufficient for our short prompts), maximum batch size of 8 concur- rent sequences, and GPU memory utilization of 0.85 to prevent out-of-memory errors during extended collection runs.
