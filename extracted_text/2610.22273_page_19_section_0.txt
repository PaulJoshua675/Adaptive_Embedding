The answering agent and evaluator also remain fixed throughout builder optimization. The training reward measures the downstream usefulness of the evolving filesystem. We probe answerability every eight builder turns, with at most four probes per construction trajectory, and assign reward according to the change in answerability between consecutive probes. A terminal reward evaluates the final filesystem using downstream answer correctness. We use 𝛾= 1 and no explicit filesystem-structure reward, navigation-cost reward, or construction-cost shaping in the primary run (𝛼= 0). Filesystem maturity, organization, and navigation measurements reported in the analysis are therefore diagnostic statistics rather than direct components of the optimization objective. The matched BRIGHT evaluation uses temperature 0.7 and top-𝑝= 1 for answer sampling, while single-answer evaluations use deterministic decoding. Within each comparison, all methods use the same source corpus, answering model, response count, answer-generation budget, and scoring procedure. Evaluation questions are never shown to the builder during construction or used to select the reported checkpoint. A.8. Tool Definitions for Filesystem Action Space The builder agent interacts with the filesystem by delegating a limited set of discrete operations to specialized tool-calling agents. These tools are made available to the builder LLM through structured JSON schemas and can be invoked as needed. We follow the Qwen Tool Calling Format: https: //qwen.readthedocs.io/en/latest/framework/function_call.html.
