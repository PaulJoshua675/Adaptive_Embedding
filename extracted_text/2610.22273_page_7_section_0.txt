We optimize the builder policy with GRPO (Shao et al., 2024), a policy-gradient method used for RL-based fine-tuning of language models. By default, we treat the answering agent 𝜋ans as fixed during builder optimization. This isolates the learning problem: the builder learns to construct memories that are useful to the answering agent, which may be a language model or another long-context reasoning system such as RLM (Zhang et al., 2025a). We can also consider an alternative joint-training variant in which the answering agent is adapted using the same downstream correctness signal. In this setting, optimization can alternate between updating the builder and updating the answerer via a cooperative multi-agent RL framework, following methods such as RLAD (Qu et al., 2025a). Each rollout constructs a memory, evaluates it with a fixed answering agent, and updates the builder with GRPO using periodic answerability changes and terminal answer correctness. Having formulated anticipatory workspace construction as an MDP in Section 2, we evaluate whether Librarian Agents improves the reasoning performance and inference efficiency of downstream an- swering agents on long-context document reasoning tasks. We compare Librarian Agents with prior reactive retrieval and pre-computation methods to address four questions: (1) Does Librarian Agents improve in-distribution long-context reasoning performance? (2) What amortization benefits do Librarian Agents provide when serving multiple queries over a shared document set? (3) Does the builder agent’s anticipatory construction capability generalize zero-shot to out-of-distribution retrieval settings? (4) Qualitatively, how do the builder and answering agents behave during the construction and answering phases, and do these behaviors reflect the intended anticipatory capability? We examine each question in turn below. Task Definition. The main domain we consider for long-document reasoning is BrowseComp- Plus (Chen et al., 2025), a curated corpus of deep-research web tasks. We split this dataset into two sets for training and evaluation: 680 tasks for training and 50 held-out tasks for all evaluations (sampled at random). For training 𝜋build, each task consists of an independent set of raw documents and a downstream query to be answered based on the set of documents. We additionally evaluate the performance of Librarian Agents on the BRIGHT Benchmark (Su et al., 2025), which comprises tasks from diverse domains (StackExchange, LeetCode, and math competitions), to assess the builder agent’s efficacy on unseen distributions. Comparisons and baselines. We evaluate our approach against several representative baselines. First, we compare with standard reactive retrieval methods: an Embedding with optional Reranker baseline (Zhang et al., 2025c) and Late Interaction Embedding (Chaffin & Sourty, 2025), which represent conventional retrieve-and-read RAG systems that process each query from scratch. Second, we compare with Graph RAG (Peng et al., 2025), a knowledge graph baseline that uses precomputation. Third, we include Agentic RAG (Singh et al., 2025), which represents multi-agent approaches that dynamically interleave retrieval and reasoning at query time. Next, we compare autocompaction methods such as those that periodically summarize the computation performed, such as RC (Wu et al., 2026). These baselines cover both ends of the design space, with some doing all cross-document reasoning per query and others doing it once up front. We also include an ablation of our own framework: a builder agent without RL fine-tuning. This isolates the contribution of our MDP-based policy optimization.
