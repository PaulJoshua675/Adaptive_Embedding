Hard caching walks the fixed grid of scheduled nodes one node at a time, deciding only whether to refresh or reuse. SoftCache also sets the step size: a reused step the cache still supports skips several nodes and lands between them (inset). We observe that this ignored distance is infor- mative. Below the threshold, the signal closely tracks the reuse error, the gap between the cached computation and a fresh one at the cur- rent node. The distance from the threshold, which we call the headroom, measures how safely the cache can be trusted, and we use it to set the step size instead of only the refresh deci- sion: this is soft caching. When the headroom is large, the cache is still reliable, so the sam- pler takes a long step that skips several sched- uled nodes and can land between them (Fig. 1). When the headroom is small, refresh is near, so the step shrinks back toward the scheduled one. We call this method SoftCache: the headroom sets the step continuously rather than picking how many nodes to skip, and every node a step passes over is one the sampler no longer visits. Set against both kinds of cache, this is a different form of adaptivity. A fixed schedule refreshes at the same nodes for every prompt. A dynamic cache refreshes at nodes that vary with the prompt, but at scheduled nodes all the same. Here the steps vary with the prompt too, and they also land where no node was scheduled. This freedom translates into fidelity: on FLUX, HunyuanVideo and Wan2.1, against caches of both kinds at comparable speed, SoftCache reproduces the uncached model most faithfully on every metric at every operating point we test. Adaptivity, then, does not stop at deciding when to refresh. It also decides where the sampler goes next. Our main contributions are: (1) We identify that the refresh signal of a dynamic cache carries more than a binary decision: its headroom below the threshold tracks the reuse error, so it measures how far the cached computation can still be trusted. (2) We propose SoftCache, which reads the headroom as a step size: cached steps jump off the scheduler’s grid in proportion to it, the tail is re-spaced so that every node passed is dropped from the trajectory, and the cached residual is extrapolated linearly to the landing, at no extra network cost. (3) On image and video backbones, SoftCache adds no per- backbone settings and is ahead of every cache we compare on all four fidelity metrics in every speed band from 3.5× to 6.9×. 2
