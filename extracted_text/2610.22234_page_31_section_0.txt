D.2.2 BACKBONE REPLACEMENT ANALYSIS To test whether the training signal transfers beyond the original backbone, we repeat the SFT exper- iment with Qwen3-VL-32B-Instruct and Qwen3-VL-32B-Thinking. Table 14 reports the complete OSWorld breakdown; arrows in the OS-Helix rows denote absolute-point changes relative to the Qwen3-VL baseline under the same Setting. With the Instruct backbone, adding Code without training a hybrid policy slightly decreases the baseline from 34.17% (GUI) to 32.68% (Hybrid). After SFT, however, OS-Helix-32B reaches 50.56%, a +17.88-point improvement over the matched Hybrid baseline. With the Thinking backbone, the unadapted Hybrid baseline is somewhat better than GUI (42.88% versus 39.08%), but OS-Helix-32B-Thinking still improves it by +8.79 points to 51.67%. Thus, the result isolates two effects: Code availability is not itself sufficient for reliable hybrid execution, while the SFT training signal transfers across both backbones and converts the available action space into a substantially stronger policy. The domain-level changes clarify what is learned. For Instruct, OS-Helix-32B improves all five domains over the matched Hybrid baseline. The corresponding gains in OS, Office, Daily, Prof., and Work. are 16.67, 19.66, 16.83, 12.24, and 19.76 points, respectively. The gains are therefore broad rather than being explained by a single application family, with the largest improvements in Office and multi-application tasks in the Work. category. This pattern is consistent with learning cross-step state management and modality routing, rather than simply improving visual grounding on isolated screens. For Thinking, the gains remain broad in OS (+8.33), Office (+11.94), Daily (+11.40), and Work. (+9.40), but Prof. decreases by 2.83 points. The single negative domain is a useful qualification: backbone replacement does not erase model-specific priors, and SFT can redistribute capability unevenly across application families. Nevertheless, the positive average and the gains across the OS, Office, Daily, and Work. categories show that the central hybrid behavior is not tied to one backbone’s pretrained tool-use bias. These results also strengthen the distinction between action-space access and policy learning in the main claim. The Instruct baseline provides a controlled counterexample in which the same model becomes slightly worse when Code is merely exposed at inference time. In contrast, the trained model gains most strongly on domains where successful execution requires coordinating GUI observations, executable operations, and persistent task state. The improvement should therefore be interpreted as evidence for learned coordination and routing, not as an artifact of giving the model an additional tool. D.2.3 TRAINING RECIPE AND CONTEXT ANALYSIS We next isolate how the structure of demonstrations and test-time history affects performance, using Qwen3-VL-32B-Instruct with OSWorld. The normal recipe reaches 50.56%. Removing CoT from training and retaining actions only reduces performance to 37.74% (-12.82 points), while keeping the training data unchanged but removing CoT from the inference context yields 37.82% (-12.74 points). The near-identical degradation is important: the reasoning trace is not merely an auxiliary training target. It also functions as an execution-time state representation that helps the model maintain intent, resolve intermediate observations, and select between GUI and code actions across multi- step execution. Removing only historical CoT is less damaging, but still lowers the average to 43.22% (-7.34 points). This partial recovery indicates that the current-step decision can retain useful local information, yet removing the accumulated reasoning history weakens temporal credit assignment and state tracking. The effect is especially visible in the Work. category, where success falls from 38.54% to 28.87% without training CoT, 31.43% without inference CoT, and 31.30% without historical CoT. Multi- application tasks therefore expose the central role of structured context most clearly: their difficulty lies not only in individual grounding decisions, but in preserving a coherent plan while the active application and tool modality change. Finally, mixing in trajectories rejected during filtering reduces the score to 47.06% (-3.50 points). This smaller but consistent decline suggests that data quality is not interchangeable with data quan- tity.
