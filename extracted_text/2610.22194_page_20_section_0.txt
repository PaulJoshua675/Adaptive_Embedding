What a verdict leaves behind is a short statement of what it means for later rounds. A later round may disagree with an earlier statement by saying so in its own entry. Nothing already written is edited: a registered prediction cannot be changed and a decided round is not re-judged, so the memory holds what the run believed at the time rather than a version tidied up afterwards. B.3. Skill library A skill is a written procedure owned by one role. Skills do not call one another, and the sequence belongs to the agent that runs them. Table 3 lists the library by role. The four analysis skills are the reason four subagents disagree productively. They share their proposal section word for word, so all four return the same kind of object, and they differ only in the evidence each is told to start from. Diversity comes from the starting point rather than from handing each subagent a different menu of actions, which is consistent with none of them being shown the action space of Section 2.2. Figures 11 to 13 show one skill from each role. B.4. Synthesis constraints and verification Generation constraints. The subagent phrases each capability requirement without reproducing evaluation wording, and the generated rows pass an 𝑛-gram overlap check against the evaluation sets before delivery, so a batch teaches the capability rather than the benchmark. Rows must come from model API calls rather than from a script, which prevents a worker from assembling responses that satisfy the verifier without genuinely demonstrating the capability. Internal verification. The subagent attributes each evaluation subset’s requirements to an underlying capability, translates them into acceptance criteria, and builds a verifier for those criteria.
