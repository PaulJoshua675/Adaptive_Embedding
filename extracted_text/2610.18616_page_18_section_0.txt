Graph tools, Retrieval only and Graph tools + code access the graph through the tools in Table 5. The tools are based on those of ARK (Polonuer et al., 2026). The search and neighbors tools call ARK’s released implemen- tations of its global search and one-hop neigh- borhood search, which run on ARK’s prepared graph (BM25 over ARK’s node names and sum- maries), and get_node and get_schema return a node record and the schema file of our graph export. The agent, the prompt and the step budget come from our harness. The tools are served by a pro- cess outside the sandbox, and the graph files also stay outside it. In Graph tools and Retrieval only, the tools are registered in Pi as native function- calling tools with the descriptions in Table 5, and Pi’s built-in tools are disabled, so every action of the agent is a graph-tool call. In Graph tools + code, the agent has Pi’s read and bash tools and calls the same four tools from Python through a client whose methods take the same arguments and return the same text. On the test subset, Graph tools + code made an average of 45.1 graph-tool calls per query within 6.8 bash calls, compared with 18.4 tool calls per query for Graph tools. Shell only. The shell can start a fixed list of 15 pro- grams (rg, cat, sed, head, tail, wc, cut, sort, comm, ls, find, pwd, xargs, echo and bash). A Landlock execute rule enforces this list, also for find -exec and xargs. Before each query, a check confirms that these programs run and that starting python3, awk, perl or node fails, testing python3 also through its absolute path, find -exec, xargs and the dynamic loader. Pipelines, bash loops, ar- rays and arithmetic remain available, and grep, awk and jq are unavailable. The graph directory is a hard-link copy of the graph export, and its DATA_FORMAT.txt omits the last line. Pi’s read tool and head-and-tail truncation are as in Full DKGI. One program.
