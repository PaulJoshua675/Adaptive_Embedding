Datasets and Evaluation Metrics Datasets. We evaluate TRACE on six thin-structure segmen- tation benchmarks spanning 2D and 3D data, including bi- nary and multiclass tasks. DRIVE [21] is used for retinal ves- sel segmentation and contains 40 RGB fundus images, split into 20/10/10 for training/validation/testing. DeepCrack [15] contains 537 RGB images for surface-crack segmentation (270/30/237), while DeepGlobe Roads [7] contains 6,226 RGB satellite images for road segmentation (4,980/622/624). For DSCA [27], we convert 224 cerebral digital subtraction angiography sequences, annotated for the main arterial trunk and bifurcated vessels, into 2D minimum-intensity projec- tions and use a 144/36/44 split. MSD Hepatic Vessel [2] contains 303 portal-venous-phase 3D CT scans with hepatic vessel and tumor annotations; we treat tumor voxels as back- ground for binary vessel segmentation and use a 243/30/30 split. TopCoW [26] contains 125 3D CT angiography scans with multiclass annotations for 13 Circle of Willis vessel segments, split into 100/12/13 cases. Metrics. We evaluate segmentation quality using com- plementary metrics for connectivity, topology, boundary accuracy, and region overlap. We first report clDice [20] to measure centerline consistency and connectivity preser- vation. We also report the absolute Betti number error, β = |∆β0| + |∆β1| [22], to quantify topological errors associated with structural connectivity. The 95th-percentile Hausdorff distance (HD95) [23] assesses boundary accuracy by measuring spatial disagreement while limiting outlier sensitivity. Finally, Dice [9] measures region overlap and assesses whether improved structural consistency is achieved without sacrificing overall segmentation accuracy. We com- pute each metric independently for each foreground class in every test sample. For multiclass datasets, we average the class-wise values to obtain one score per metric per sample, then average these per-sample scores over the entire test set. 4.2. Main Comparison Setup Baselines. Our primary focus is connectivity preservation; therefore, we conduct extensive comparisons with represen- tative skeleton-based losses, including clDice [20], clDice with topology-preserving skeletonization (Topo-clDice) [17], clCE [1], cbDice [19], and SkelRecall [13]. We also include the recent multiclass extension of Betti Matching [3] as a consistent global-topology reference across binary and mul- ticlass benchmarks, using the projection-based protocol of [14] for 3D volumes. To isolate the effects of the train- ing objective, the main benchmark evaluates representative methods using standard semantic outputs while keeping the prediction head and inference pipeline fixed. We exclude methods that require alternative output formulations, aux- iliary or correction modules, or post-processing from this controlled comparison. Training protocol. We use a common nnU-Net [12] train- ing setup for all methods to ensure a controlled comparison. Following Eq. (11), we use Dice loss combined with cross- entropy loss (Dice + CE), the default nnU-Net objective, as Lseg, and replace LTRACE with each compared struc- tural loss while keeping all other training settings fixed. For TRACE and the skeleton-based losses, we select λ from {0.10, 0.30, 0.60, 1.00} based on the validation Dice score. Betti Matching is tuned separately because exces- sive topological weighting can degrade segmentation perfor- mance [22]; its weight is selected on the validation set from {0.00001, 0.0001, 0.001, 0.01}. 4.3. Topology Preservation and Training Efficiency Topology preservation. We assess whether each method’s target-side skeleton representation preserves topology across deep-supervision scales. We use clDice [20] as a representa- tive differentiable soft-skeletonization method, Topo-clDice [17] as its topology-preserving counterpart, and SkelRecall [13] as a target skeleton-based method. At each active scale, we construct the skeleton from the corresponding training target using each method and record a topology violation if the Betti numbers change for the foreground union or any present semantic class. We report the percentage of target–scale pairs exhibiting at least one violation. Training efficiency. We evaluate the training overhead of TRACE against the same representative methods under an identical nnU-Net setup, with Dice + CE as the reference. We report training time per epoch and peak process GPU memory on an NVIDIA H200 (140 GB); runs exceeding the available GPU memory are reported as out of mem- ory (OOM). Topology preservation can still be evaluated in OOM cases, whereas training efficiency cannot be assessed without a completed epoch. 4.4.
