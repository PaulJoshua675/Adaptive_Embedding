The three Hy-Memory rows are scenario configurations of one harness family, not three unrelated frameworks. “All trained harnesses” means these five configurations from three harness families. 3.2 Data hierarchy An interaction sequence contains chronological sessions. Each session contains turns (one request and its response). A chunk is one harness write input, usually about ten turns, and never crosses a session boundary. A window is up to five consecutive chunks processed in one RL step and may span session boundaries. 3.3 Memory writing as an MDP For chunk t, let Mt be the persistent memory bank and xt the raw interaction chunk. The policy receives a harness-generated prompt containing xt and selected information from Mt, then produces one or more structured LLM outputs at. The harness executes those outputs and creates the next bank: st = (Mt, xt, h), at ∼πθ(· | st), Mt+1 = Th(Mt, at), (1) where h denotes the harness configuration. The state lives primarily in the external bank, not in a continuous model context. Every LLM call may start from a fresh prompt, but the decisions are sequential because the bank carries their consequences. This creates two training requirements: rollouts from one candidate must write to an isolated bank copy, and later windows must start from a bank the policy itself produced, not an annotation-derived ideal bank. 3.4 Three-model separation The policy (Hy3-30B-A3B) sees the harness write prompt and produces all memory-write outputs; it is the only model trained in Stage 2. The answer model sees the question and the retrieved memory block, and reads what the bank exposes. The judge sees the question, answer, reference, and rubric, and assigns semantic credit. The answer model never sees the reference or rubric. The judge never sees the retrieved memory block. Freezing both makes the memory bank the only changing component in the reward path. 4
