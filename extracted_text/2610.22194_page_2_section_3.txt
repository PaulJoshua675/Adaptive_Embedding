We write these six kinds of change as a data action space (Section 2), and use it only after a run to measure how much of that space the agent reaches. We first study this question with a single agent, restarting each round from the same base checkpoint. The agent collapses onto one action family, repeats related recipes, and spends most of its context on raw command output rather than data analysis. Section 3 examines these failures, the trace evidence, and our fix, explaining why an undivided research loop is hard to sustain. One agent analyzes behavior, proposes data changes, executes experiments, and interprets logs, so execution competes with analysis for context and a single proposal stream reinforces recent choices. This yields two requirements: isolate execution from data analysis, and maintain complementary views of the same model behavior during proposal generation. AutoSFT (Section 4) is a multi-agent system built around these two requirements. A meta agent owns each round and delegates to three kinds of subagent. An executor runs training, conversion, and evaluation separately, returning file paths and a short status report so the meta agent can spend its context on data. Analysis subagents read the same round from four angles: training data, failures, training signals, and earlier rounds, each returning one proposed data action. A synthesis subagent writes new data for capabilities the pool barely covers, which neither of the first two can add. We add the three components one at a time, fixing the base model, initial pool, token budget, training script, and evaluation within each comparison, so any difference is attributable to the added component (Section 5). The executor halves context loss, the analysis subagents broaden the range of changes and raise best IFEval by +6.5, and synthesis adds +3.4 IFEval and +2.9 IFBench by covering undersupplied capabilities.
