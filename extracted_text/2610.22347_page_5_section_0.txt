The draft can be compared with clean content or its own previous estimate, motivating a training-free verifier. The generator’s intermedi- ate features provide additional contextual information, which a learned verifier uses to predict the convergence gap. Since latent tokens encode content across multiple output frames, isolated accep- tance decisions can affect both spatial and temporal coherence. We therefore apply a spatiotemporal smoothing operator S to each verifier’s scores before thresholding, encouraging coherent decisions across neighboring tokens. 3.3.1 TRAINING-FREE VERIFIER At the first step, only one draft exists, so a token’s own change cannot be observed. We therefore rely on its redundancy with content that is already clean. From the second step on, we judge convergence by how much the token’s consecutive drafts differ. Redundancy-based verification. We observe that drafts resembling previously generated or refer- ence content often have smaller remaining changes (Figure 2). This motivates similarity to clean content as a proxy for convergence. At the first step, we score each token by the distance from its draft to the most similar clean latent token, sred(i) = minh∈H ˆx(1) 0 (i) −h 2 , where H contains clean latent tokens from previous chunks within the generator’s attention window and any reference frames, including those retained as attention sinks. The search covers all spatial positions within this bank to accommodate camera and object motion. Tokens with S[sred](i) ≤τred are accepted. Stability-based verification. From the second step on, two consecutive drafts of the same active token are available. Their difference measures how much the token’s estimate has changed over the latest denoising step, s(k) stab(i) = ˆx(k) 0 (i) −ˆx(k−1) 0 (i) 2 , for 2 ≤k < K. Active tokens with S[s(k) stab](i) ≤τstab are accepted. Both thresholds are calibrated on held-out data. Tokens whose drafts closely match clean content can thus be committed at the first step, while tokens with sufficiently small changes between consecutive drafts can be committed at later steps. Tokens that satisfy neither condition run the full schedule. 3.3.2 LEARNED VERIFIER Redundancy and stability are proxies for convergence rather than convergence itself. A token can match the history and still need refinement, or change little between two steps and yet remain far from its final value. The learned verifier instead predicts the convergence gap directly from the generator’s own features. A shallow convolutional head suffices for this prediction, indicating that the intermediate features contain information about each token’s remaining discrepancy to the full- step output. Training. The head takes the hidden state of a selected backbone layer at step k and outputs a pre- dicted gap ˆrk(i) for each token. It consists of layer normalization followed by three 3D convolutions and is shared across all steps.
