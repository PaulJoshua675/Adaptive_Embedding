B IMPLEMENTATION DETAILS B.1 RETRIEVAL BACKEND AND DEPENDENCY GRAPH Corpus and graph representation. The implementation builds on the Mathlib v4.28.0-rc1 corpus released with LeanSearch v2 (Gao et al., 2026), retaining its declaration metadata, infor- mal descriptions, and precomputed embeddings. The released dependency graph contains 310,579 declarations and 4,528,330 forward edges extracted with jixia (frenzymath, 2024). The builder resolves structured references to declaration names, removes self-references and duplicate targets, and ignores references whose targets are absent from the graph. Its dependency-only profile uses for- ward dependency edges with unit weights. The transition matrix is stored in compressed sparse row format, with a separate indicator for dangling nodes. Inclusion of theorem proof-body references is controlled at graph-construction time and recorded in the graph metadata. Semantic retrieval and relevance scores. Queries are encoded with Qwen3-Embedding- 8B (Zhang et al., 2025) and ℓ2-normalized before cuVS CAGRA search. Qwen3-Reranker-8B scores each query–declaration pair using the final-position logits for the tokens yes and no: qi = exp(zi,yes) exp(zi,yes) + exp(zi,no). (6) These nonnegative scores define the seed weights in Section 3.3. Both reranking passes use the same checkpoint and query, with each formatted pair limited to 8,192 tokens. Matched retrieval budgets. In all mathematical retrieval and theorem-proving evaluations, both retrievers return at most K = 50 declarations per query, and LEANGRAPHSEARCH uses N = 200 PPR-ranked expansion candidates. For LEANGRAPHSEARCH, K specifies both the number of se- mantic seeds and the number of declarations returned after final ranking, while N specifies the number of PPR-ranked graph candidates considered for expansion. LeanSearch v2 also returns its top 50 declarations for each query. Thus, the paired comparisons use the top-50 results of each retriever; graph expansion increases the internal candidate pool without increasing the per-query output budget. The same setting applies to direct benchmark queries, reasoning-based subqueries, and reflection-time queries. Multi-query aggregation is a separate operation and can combine decla- rations from several top-50 lists. Propagation and candidate refinement. The retrieval configuration uses 50 semantic seeds, 200 PPR-ranked graph candidates, and a refined candidate pool of at most 100 declarations. These inter- nal budgets are separate from the per-query output budget of K = 50. PPR uses restart probability r = 0.15, at most 50 iterations, and an ℓ1 convergence tolerance of 10−6. The computation uses double precision and returns dangling mass to the seed distribution.
