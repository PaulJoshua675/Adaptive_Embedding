Preprint A EVALUATION IMPLEMENTATION A.1 OBSERVATIONS AND ACTIONS Observations. The agent receives a screenshot and a read-only description of currently inter- actable elements. Screenshots preserve the desktop aspect ratio and are resized to a maximum dimension of 768 pixels, yielding 768 × 432 images for the 1920 × 1080 desktop. We adopt this reduced resolution to reduce visual processing overhead and inference latency. Recent studies also suggest that SoM representations preserve visual grounding performance under downsampling with minimal loss (Xie et al., 2024; Kaesberg et al., 2026).The Set-of-Marks representation uses P# for discrete target points and R# for continuous regions. A region location is specified as R#@u,v, where u, v ∈[0, 1000] are local coordinates. Marks refer only to the observation in which they appear. Raw screenshot coordinates remain available when no suitable mark exists and are mapped to desktop coordinates before execution. Actions. Each decision produces a GUI action. Table 1 gives the shared action schema. Action Arguments Semantics click target, button Click the specified point. right click target Right-click the specified point. double click, triple click target Apply the corresponding click sequence. mouse down, mouse up target, duration Press or release the mouse button. move target, duration Move the pointer. type text Enter the supplied text. key key, repeat Tap a key or key combination. hold key key, duration Hold a key or key combination for the specified time. scroll target, dx, dy Scroll horizontally or vertically. drag start, end, duration Drag between two points. wait duration Advance without issuing another GUI input. Table 1: Shared GUI action schema. Arguments include optional fields; action durations lie in [0, 10] seconds and key.repeat lies in [1, 100]. A.2 CLOCK EXECUTION AND TOKEN ACCOUNTING Action timing. For a decision based on an observation at time ti, the token clock assigns an action timestamp tact i = ti + ni/(Bf), where ni is the charged output-token count. The harness advances the environment to this timestamp before applying the action. Finishing early does not provide an extra observation: the next observation follows the scheduled frame grid. If generation crosses observation boundaries, the corresponding intermediate observations are skipped. Physical inference and GUI execution latency do not advance simulated time. Browser animation updates use a persistent 60 Hz simulation grid, separate from the agent’s observation rate, so splitting an interval around an action does not change the number of animation updates. Charged tokens. For API-based models, we charge both reasoning tokens and output tokens us- ing the usage reported by the API for the complete response. As Gemini Live natively produces audio rather than text, we configure it to emit GUI actions through native function calls instead of spoken responses. We charge its reported thought tokens and non-audio response tokens, excluding generated audio. A.3 CONTEXT MANAGEMENT Visual and textual history are retained separately. When the active visual history reaches 21 obser- vations, the oldest 10 screenshots and their associated interactables are replaced with fixed place- holders, while the corresponding text and action records remain.
