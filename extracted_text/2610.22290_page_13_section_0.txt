A Method Details A.1 Algorithm Algorithm 1 summarizes the two stages of ELITEREPLAY. We first construct an archive with the frozen base model, then use the archived solu- tions to guide GRPO post-training. A.2 Behavior space We first sample verified seed solutions from the frozen base model and present representative ex- amples to a separate LLM, the labeler. Rather than restricting search to the approaches observed in the seeds, the labeler uses these examples to induce a broader vocabulary of possible approaches. It then assigns each verified solution a primary ap- proach label. Because solutions with the same approach label can still differ in structure, we re- fine each label with structural features computed deterministically from the solution, such as which constructs appear in its parse tree. The resulting descriptor b(y) identifies the solution’s cell in its question-specific archive Ax. Each cell contains at most one verified solution, or elite. The descrip- tor only guides search; diversity is evaluated with a separate representation that involves no labeler (Appendix B.5). A.3 Archive search Search runs on a subset DA of the training ques- tions; no evaluation questions are used. All can- didates come from the frozen base model π0, prompted with the original task, and only candi- dates accepted by the verifier enter the archive. Each question receives a number of initial samples, followed by several rounds of mutations. Target selection. For each question, the labeler proposes a set of applicable approaches. For each mutation, we first restrict target selection to applica- ble approaches not yet represented by any elite for the current question; if all are represented, we con- sider all applicable approaches. Within this pool, we prioritize approaches with the fewest previous targeting attempts for that question, then those rep- resented by the fewest questions across the archive. Variation and insertion. For each attempt, the frozen base model receives the original task, the tar- get approach, and a verified parent solution, prefer- ably using a different approach. The generated candidate is verified and assigned to the cell cor- responding to the approach it actually uses, which might not be the requested one. A candidate fills an empty cell or replaces its current elite if shorter. Af- ter search, we select verified elites across questions to form the replay set, each paired with its original task prompt.
