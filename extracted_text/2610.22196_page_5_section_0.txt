The outlined cell is the final bank with the highest ∑t si[t], which becomes the parent of the next window. 4 Two-Stage Training 4.1 Why two stages Direct RL from a generic instruction model wastes samples on protocol failures: malformed JSON, wrong operation names, missing fields, and invalid multi-stage control flow. Conversely, pure distillation teaches the model to follow a strong teacher but cannot rank the many valid memory representations by downstream usefulness. OPD learns how to act inside each harness, with dense token-level supervision on the student’s own prompts and outputs. RL learns which valid actions produce useful banks. 4.2 Stage 1: Memory on-policy distillation Sequence construction. Chronologically ordered interaction sequences are segmented into chunks while preserving session boundaries. Chat emphasizes personal facts and preference changes; Working emphasizes tasks, decisions, deadlines, and organizational context; Coding emphasizes repositories, files, commands, implementation decisions, and changing technical state. Each chunk is paired with the harness state produced by preceding student writes, so OPD supervision follows the state distribution encountered during deployment. On-policy rollout. Each OPD row advances one (sequence, harness configuration) snapshot chain by one chunk. The rollout restores the selected parent bank Mt−1, invokes the unmodified harness write path, routes every harness LLM call to the student, applies the student’s operations to produce a candidate Mt, and promotes one candidate as the parent of the next chunk. The teacher does not generate a separate ideal trajectory. It scores tokens on the trajectory the student generated. Supervision is placed on student-visited prefixes, reducing the exposure mismatch of static teacher demonstrations (Gu et al., 2024). For memory writing, the benefit extends beyond token prefixes: the future prompts also contain memory states created by the student. Objective.
