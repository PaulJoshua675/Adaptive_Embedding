Neither method pads non-matching results or falls back to the full catalog. If the retrieved pool is empty, no LLM call is made and the case remains an unsuccessful end-to-end outcome. 1) Candidate-Budget Selection and Independent Validation: The original RQ3 protocol evaluated SSR retrieval sensitivity for K ∈{5, 10, 20, 50} on the same 200-query sample later used for end-to-end eval- uation, without using LLM selection outcomes. The reported end-to-end experiments use K = 20, with the same maximum budget applied to BM25. To assess whether this operating point was sample-specific, the 200 RQ3 queries were excluded and 1,000 queries were sampled uniformly from the remaining 6,780 using seed 2027. The validation reused the same nested registry sizes, SSR configuration, and candidate budgets, and made no LLM calls. The decision rule selected the smallest K whose candidate recall was within 0.02 absolute of the best tested recall at every registry size: K∗= min n K : R(N, K) ≥max K′ R(N, K′) −0.02, ∀N o . The independent validation selected K = 20, corroborating the operating point used in the reported end-to-end experiments. Because this validation was retrospective, a fully prospective protocol would select and freeze K before evaluation on a disjoint end-to-end test set. 2) Effectiveness and Paired Statistical Analysis: For candi- date pre-selection, candidate recall is the fraction of query– registry pairs for which at least one relevant candidate is retrieved. Conditional selection accuracy is the fraction of retrieval-hit cases in which the LLM selects a relevant can- didate, and end-to-end accuracy is the fraction of all query– registry pairs for which the complete pipeline returns a relevant candidate. Retrieval misses, empty pools, API failures, invalid indices, and irrelevant selections remain end-to-end failures. For each N, 95% Wilson score intervals are reported for marginal end-to-end accuracy. Because SSR and BM25 are evaluated on the same 200 queries and query-specific registries, their primary paired comparison uses a two-sided exact McNemar test on query-level end_to_end_correct outcomes, with Holm correction across the four registry sizes. Candidate recall is analyzed analogously as a secondary paired outcome. Nonsignificant results are interpreted as no statisti- cally detectable difference under the evaluated sample, not as evidence of statistical equivalence. E. Implementation and Reproducibility LLM configuration. RQ1 and RQ3 use gpt-4o-mini, temperature 0, and JSON-mode responses. Candidates are represented by sequential one-based indices, and the returned selected_index is validated and mapped to the underly- ing Agent Card or passage identifier. Accounting uses fixed rates of $0.15 per million input tokens and $0.60 per million output tokens. Retrieval implementation. SSR retains at most 64 struc- tural signals per representation and uses the normalization and IDF definition in Section III. BM25 is implemented with SQLite FTS5 bm25() over the same normalized unigram tok- enization used for indexed documents and queries; lower FTS5 scores rank first, with passage identifier used for deterministic tie-breaking. The implementation uses k1 = 1.2 and b = 0.75. Offline index construction is excluded from reported online latency for both methods. Execution environment. The full-scale RQ2 experiment was executed on an Amazon SageMaker ml.m5d.8xlarge instance running Ubuntu 22.04.5 LTS with 32 logical CPUs, approximately 124 GiB RAM, an Intel Xeon Platinum 8259CL 2.50 GHz processor, Python 3.12.9, and SQLite 3.48.0.
