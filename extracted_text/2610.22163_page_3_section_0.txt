Unlike typical computer science projects that require students to implement well- known data structures or algorithms, DS projects involve sequential (numbered) analysis tasks on given datasets, making it important for the model to receive the original question’s details. Furthermore, this step is irreplaceable by RAG as both embedding-based and keyword- based retrieval methods face challenges in extracting the exact question from the course materials only using the question number. Embedding-based methods struggle due to the short and numeric nature of these references, while keyword-based systems encounter difficulties due to variability of question number abbreviations (e.g., "Project 2 Question 10" and "Fall 2022 Midterm 2 Question 10"). To address these issues, we used the Llama 3 8B model to generate standardized question numbers from student posts. This model is hosted using Ollama on a machine with a Nvidia GeForce RTX 4090. This link, https://bit.ly/3Lv3Eiw, provides the few- shot prompt we used for the QE task. The prompt is structured as follows: the task description, the input format accompanied by a brief description of the course materials, the expected output format, and several examples of input and output. The generated standardized question number enables us to accurately fetch the question content from a question bank using a rule-based algorithm. The question bank is created as text files by parsing past exams and solutions (PDFs) and Canvas quizzes using fitz and Canvas API, respectively. QE is a crucial step that ensures the subsequent RAG process retrieves the most relevant content related to the specific questions in the student’s posts, thereby improving the accuracy and relevancy of the generated responses. 3.2.3 RAG We structured our RAG using LangChain [7] with a comprehensive vector store of all course materials. This includes lecture notes (Python scripts and Jupyter Notebooks), PowerPoint slides, work- sheets (PDFs), complementary readings (Python scripts and Jupyter Notebooks), project and lab repositories (Python scripts, Jupyter Notebooks, and Markdown), and the course website pages (HTML). Various parsers and splitters were employed to manage these di- verse data types. For parsing, we converted Jupyter Notebooks to Python scripts using nbconvert, and PowerPoint slides and PDFs to Markdown using pptx2md and fitz. Markdown and HTML content are initially split using corresponding Langchain Markdown and HTML Header Text splitters, and further split by RecursiveChar- acterTextSplitter in Python for excessively long chunks. Jupyter Notebooks, which are already formatted using Markdown headers, are first split using a modified version of LangChain Markdown- HeaderTextSplitter for Jupyter Notebooks and then further split by the RecursiveCharacterTextSplitter. We also included the source name in the split chunks to allow reference to course materials in the generated response. The vector store is then created using FAISS [13] with OpenAI’s text-embedding-ada-002 embedding. In similarity search phase, we input both the student post and any extracted questions. We exclude past exams and Canvas quizzes from our search to avoid skewing results towards similar exam or quiz questions, which could prevent the retrieval of lecture materials. We retrieve the top 10 most relevant results. 3.2.4 Response Generation Responses are generated using the Microsoft Azure OpenAI GPT-4 API. This link, https://bit.ly/3SeXvLg, provides the system and user prompts for the generation task. In the system prompt, we direct the model to function as an AI tutor for non-native English speaker students, stipulating that it should not directly reveal solutions but rather provide hints, explanations, or suggestions. We instruct the model to avoid writing code snippets. We also ask the model to cite RAG results accordingly using the source path. The response is required to be in both English and Mandarin. Any technical vocabulary or error messages that might challenge non-native English speaker students is asked to be compiled into a glossary at the end of the response to aid understanding. In the user prompt, we include the original student post, any extracted question numbers and content, and the results from the RAG. 4 Results 4.1 Examples We will present the results from all four stages of our pipeline for one conceptual and one programming question. This link, https://bit.ly/3VbHpT8, illustrates the outcomes for a conceptual post in Mandarin, which asks whether "the Document Object Model (DOM) is a tree or a directed acyclic graph (DAG)". The translation accurately captures the student’s query. The question extractor successfully identifies the relevant questions from Spring 22 Exam 2 Question 2 and Quiz 5 Question 2. The RAG retrievals include definitions of trees and DAGs from lecture notes and readings. The response effectively resolves the student’s confusion by outlining the definitions shown in the RAG retrievals and clarifying that a tree is a type of DAG. This link, https://bit.ly/3Ra5Hf2, displays the results for a programming post asking for tips on P5 Q7. The question extractor accurately identifies the targeted question. The first helpful RAG retrieval provides information about the dataframe, while the second introduces the necessary function from the EDGAR utils module. The response correctly offers general guidance for the question without revealing the solution. For both questions, the Mandarin translation and technical term glossary were of high quality. 4.2 Quantitative Results All four stages of our pipeline were evaluated by two native Mandarin- speaking authors. In instances of evaluative discrepancies, the third author, who is also a native Mandarin speaker and the course instructor, made the decisive evaluation.
