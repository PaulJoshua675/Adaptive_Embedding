Most experiments report mean ± SD over the paired seeds stated in each protocol; Appendix D.2 lists the number of seeds in every experiment. D.2 Seeds and Computing Infrastructure Random seeds. Paired comparisons use the same optimization seed for both arms, so the two arms share initialization, data order, and dropout masks. All seed pools were fixed before the corresponding experiments, and no seed was selected retrospectively from a larger pool. A three-seed core pool was fixed before the multi-seed cross-scale comparisons and the three-seed 101M comparison. Three-seed experiments use this pool: the three-seed 101M comparison, the hard-rebalancing Lion comparison, the Lion state ablation, the OpenWebText replication, the 123.8M and 296.7M scale replications, the 354M stress test at λ = 0.2, the 22M multi-seed cross-scale comparison, and the 101M one at λ = 0.2. Four additional seeds, fixed before the primary seven-seed comparisons, extend the core pool to seven seeds for the seven-seed 101M comparison, the 31M architecture and tokenizer replication, and the soft-rebalancing Lion comparison. The branched checkpoint-surgery resume and the optimizer-state diagnostics use a separate seven-seed pool, which also contains the core pool and was fixed before those experiments. Two seeds from the core pool are used in the natural-drift experiment, the deep-model stress test, the 101M multi-seed cross-scale comparison at λ = 0, and the 354M one. A single seed from the core pool is used in the 354M stress test at λ ∈{0, 0.1}, the SwiGLU stress test, the 101M rescaling-strength sweep, and the 1.2B training comparison. Compute. The main experimental suite was run on NVIDIA H100 80GB GPUs, using 4×H100 single-node runs with distributed data parallel (DDP) training for the largest configurations. The implementation also supports Intel Data Center GPU Max devices through the PyTorch XPU backend; DDP runs use NCCL on CUDA devices and XCCL on XPU devices. The 31M architecture and tokenizer replication, the 123.8M scale replication and branched checkpoint-surgery resume, the 31M optimizer-state diagnostics, and the 296.7M scale replication were executed on Aurora Intel Data Center GPU Max 1550 XPU tiles. Runtime depends on the recipe and hardware. For example, the 1.2B training comparison records 2,494 to 2,518 seconds per configuration on four H100s, equivalent to 41.6 to 42.0 minutes or approximately 2.8 H100-hours per configuration. These values are training timers, including periodic evaluation, rather than end-to-end times including data and model setup; these timers should not be extrapolated from parameter count alone. D.3 Implementation Implementation checks. We verify the implementation on CPU and replay the same suite on Aurora using an XPU device. The checks confirm exact forward preservation, the closed-form gradient law, and SAGGS forward preservation for Q–K, V–O, and MLP pairs on both the GPT-style model and the RMSNorm, RoPE, SwiGLU, and GQA model of the architecture and tokenizer replication. The checks also verify the optimizer-state co-transform used in the Lion state ablation by confirming that Adam-family first- and second-moment buffers receive the chain-rule scale factors after a hard SAGGS orbit move and after an explicit exact reparameterization surgery. Both runs pass all checks: The largest relative gradient-law error is below 3 × 10−7, and the optimizer-state relative error is zero. Reference implementation.
