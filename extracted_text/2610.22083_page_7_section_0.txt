The multiplier is determined per encoding by binary search: the smallest factor at which every trained value causes the output neuron to fire. Each trained value is searched independently and the maximum taken, then rounded up to the next multiple of 0.01 so that the network does not operate exactly at the firing boundary. The search resolves the factor to 0.01, which bounds the precision of the tolerance measurements in Section 4.4. Classification is then measured exhaustively: every value in the range is presented and the output recorded. A value is accepted when the output neuron fires for it. Accepted values that were trained are true positives (𝑡𝑝) and those that were not are false positives (𝑓𝑝); rejected values are true negatives (𝑡𝑛) and false negatives (𝑓𝑛) respectively. The main text reports accuracy and precision, which are the two that discriminate between encodings here; sensitivity is unity throughout, since the homeostatic search guarantees that every trained value fires, and serves as a check that train- ing succeeded rather than as a measure of performance. The complete set is tabulated for each experiment in Appendix A. The false-positive count follows Davies et al. (2025), but it does not distinguish two quite different outcomes. An accepted value adjacent to, or lying between, trained values is generalisation over a neighbourhood, and for an encoding that preserves semantic distance it is the behaviour sought; an accepted value far from every trained value is an error in the ordinary sense. We refer to the first as a neighbouring activation. Sections 4.2 and 4.3 report where accepted values lie as well as how many there are, so that the two can be told apart. Several independent replicas of the testing network share each simulation, each with its own generator, rails and output neuron and injecting at a staggered time. Across the four experiments reported here, 216 trained networks were measured against every value in their range, giving 131,072 individual classifications on hardware. No result below is sampled or extrapolated. All experiments were run on first-generation SpiNNaker hardware using the sPyNNaker implementation of PyNN (Rhodes et al., 2018; Davison, 2008), with the default in- coming spike buffer, which holds 255 packets, and a time scale factor of 100, so that each 1 ms timestep spans more than a millisecond of wall-clock time; latencies are therefore reported in timesteps. The input-capacity measurements of Section 3.4 were additionally made on SpiNNaker2; every other result is from first-generation SpiNNaker. Input Capacity and Spatial Code Width Because all bits of a spatial code word are presented simultaneously and each bit fires on exactly one rail, a code of width 𝑊delivers 𝑊spike packets to its output neuron within a single timestep. Any limit on the number of packets a neuron can receive at once is therefore a limit on code width. We measured this limit on both platforms. 3.4.1. SpiNNaker sPyNNaker places incoming packets in a circular buffer on each core, allocated with 256 slots by default, of which one is always kept empty, so that at most 255 packets can be held; packets that arrive when the buffer is full are discarded without error. Training an output neuron on code words of increas- ing width under the default configuration, the number of synapses potentiated tracked the width exactly up to 255 and then stopped, at 255 or occasionally 256 when a packet was consumed during the burst, for widths of 300, 480 and 992. Raising the buffer to 1024 slots removed the limit: every synapse was potentiated at every width tested. The bound is therefore a default of the software rather than a property of the hardware. It is, however, silent: the network learns a truncated pattern while reporting no fault, and the downstream metrics remain plausible. To see whether the limit is a fixed capacity, the mea- surement was repeated under the default buffer with static synapses, as used in the testing network, counting the inputs delivered from the deflection of a non-leaking membrane. Here the limit is neither fixed at 255 nor abrupt: every input arrived up to 385, and beyond that about two in five additional inputs still did. Spreading the same inputs across two and four source populations raised the point at which loss began to 426 and 435.
