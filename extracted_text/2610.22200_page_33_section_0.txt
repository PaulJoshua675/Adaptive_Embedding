C.1 Code Execution We reproduce the code-execution baseline’s execution contract, PyAutoGUI interface, three code examples, and response format, retaining the original prompt headings. The PyAutoGUI definition is also used in the full prompt (Section C.3). The examples illustrate GUI interaction, conditional shell execution, and loops over GUI operations. ## Code execution The script in your `<code>` block runs top-to-bottom as a NEW Python process each step. Nothing carries over from a previous step - variables, imports, functions, working-directory changes, shell state, subprocess handles and separate `bash()` calls are all independent; only external state such as files, application state and surviving background system processes persists. Everything the script prints ( stdout, stderr, `bash()` echo, tracebacks) is returned in the next observation, truncated to 3200 characters (first 1200 + last 2000). The script is killed after 300 seconds; an uncaught exception stops it and its traceback is returned. `</code>` is a reserved delimiter: if a script must emit that exact string, build it indirectly. These names are predefined (no import needed): `pyautogui` (coordinate-aware, see below), `time`, `os`, `sys`, `re`, `json`, `subprocess`, `Image` (PIL), and the helpers: - `bash(cmd, timeout=120, echo=True)` - run a shell command with `bash -lc`. It returns the command's stdout as a string that also carries `.stdout`, `.stderr`, `.returncode`, `.ok` and `.timed_out`. With the default `echo=True`, one numbered Bash result containing the command preview, status, stdout and stderr is printed into the NEXT observation. Use `echo=False` only when that command's result is intentionally irrelevant; then nothing from that Bash call is shown next step unless you explicitly ` print(r)`, `print(r.stderr)`, or similar. A non-zero Bash result does not automatically fail the surrounding Python step, so inspect `r.ok` when later actions depend on success. The command string is passed verbatim (heredocs and quotes are fine; use a raw or triple-quoted Python string). Start a GUI application in the background with `nohup app args >/dev/null 2>&1 &`. - `screenshot()` - returns the current screen as a PIL image (raw pixels). A screenshot is attached to every observation automatically, so do not call it merely to attach an image. If the script itself needs a PIL image, call it at most once per step. - `terminate(status="success"|"failure", answer=None)` - end the task immediately; when the task asks for information, put the exact value in `answer`. Nothing after it runs. - `ask_user(question)` - ask the simulated user exactly one concise question when essential information is not visible in the environment and cannot be inferred from the task. The script stops there and the next observation includes "User Response"; do not ask for information that is already on screen, in files, or stated in the task. 33
