The validation set reported in this paper therefore takes the 888 questions realised on the validation graph and completes the under-filled family with 90 collect_global_collect questions generated on a second corpus from the same pipeline, for 977 in total. Gold-evidence set size. Gold-evidence set size reflects the number of independent facts needed to establish an answer, not where the answer value happens to sit. A local extraction is usually one chunk: q0000 asks how long a person worked at an organisation and its gold-evidence set is the single job chunk holding that record. Aggregation scales with the organisation: a question about tenure lengths across a company’s staff carries one job chunk per employee. An argmax carries its competitors—q0180 asks who is most experienced in a given skill and its gold-evidence set is the 15 job chunks that mention it, because the maximum cannot be verified without them. Compositional questions union the two steps’ evidence, and three-hop questions produce the largest sets, up to 15 chunks spanning employer-to-employee, employee-to-university, and university-to-peer links. Determinism and materialisation. Sampling and template choice draw from Python’s global random generator, seeded once before generation. Each question receives a stable identifier of the form q0000, and questions.jsonl stores one deterministic JSON record per question: answer sets are serialised as sorted lists and gold-evidence node identifiers are sorted, so downstream evaluation joins on persistent identifiers rather than on text order or container iteration. Question embeddings are held in a separate vector collection, produced by the same embedding engine used for the graph-node collections, so query and document vectors share an embedding model by construction. Questions are stored as a plain model rather than as a graph data point, which keeps them out of any retriever’s default collection scan.
