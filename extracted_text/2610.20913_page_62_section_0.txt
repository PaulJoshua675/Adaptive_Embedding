B.4 Behavior-Memory KV Snapshot Storage and Version Rollout Shared-store layout. The backing store holds compressed projected KV as a derived payload of the versioned snapshot V(𝑢) 𝜏. Each record contains packed code indices, vector magnitudes, tensor shapes, and codec/layout identifiers. Rotation matrices, bit allocations, and codebooks are shared across users through immutable codec identifiers. Retaining the underlying memory 𝑀(𝑢) 𝜏 adds storage but permits reprojection or requantization without re-encoding history when that memory remains compatible. Encoder continuation checkpoints are managed separately. For small snapshots, per-object I/O overhead can dominate payload transfer. The backing implementation therefore packs records into indexed, immutable storage segments and coalesces reads within request deadlines. Updates append new records; online-prediction-visible payloads are never modified in place. Snapshot refresh. Fresh KV is encoded on the prefill path from compatible materialized memory, not repeatedly transcoded from older lossy payloads.
