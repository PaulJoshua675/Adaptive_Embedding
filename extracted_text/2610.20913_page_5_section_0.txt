Together, these results suggest that efficient scaling is a compute-allocation problem: additional capacity should be allocated according to component-wise marginal returns rather than increased proportionally across all computational roles. The disaggregated infrastructure preserves the benefit of this allocation in execution by amortizing history-dependent computation outside the online serving path, relaxing the coupling between history-side model capacity and online serving cost. Finally, we reuse the same behavioral memory interface for capability specialization across recommendation tasks. We first train the TransX backbone on response prediction, then post-train capability-specific memory readers and output heads for retrieval, preference ranking, and generative recommendation. Core training learns a reusable behavioral memory interface; post-training specializes how each capability queries it and maps it to task-specific outputs. The contributions of this work are: • Recommendation as request-conditioned sequence transduction. We formulate recommendation as repeated request-level queries over an evolving behavior stream, and expose a compute–state decomposition into sequence encoding, behavior memory, and candidate-conditioned fusion. This decomposition identifies the model states that can be shared across serving events and candidate fanout. • Model–infrastructure co-design for amortized execution. The same compute–state decomposition defines the reuse and recomputation boundaries preserved by multi-prefix sequence-to-sequence training, sequence–fanout parallelism, tiered KV residency, and disaggregated serving. Expensive sequence computation can therefore be amortized across overlapping prefixes and executed outside the request path until behavioral state changes. • Empirical characterization of scaling returns and compute allocation. Controlled experiments vary behavioral-encoder compute, behavior-memory resolution, and candidate-conditioned fusion compute, revealing unequal marginal returns across these scaling axes: encoder returns saturate beyond moderate depth at fixed fusion capacity, increasing supervision shifts the validation-selected allocation toward candidate-conditioned fusion, and the memory resolution needed to preserve quality remains roughly stable as model capacity grows. • Capability specialization over a shared behavior-memory interface. We post-train capability- specific memory readers and output heads for retrieval, preference ranking, and generative recom- mendation while preserving the behavior memory interface. Production deployment of the core, retrieval, and ranking variants further validates the framework across recommendation quality, training efficiency, and serving economics. We evaluate TransX in a large-scale social recommendation application serving approximately 20K requests per second with roughly 0.5K–1.2K candidates per request. In separate production A/B experiments, TransX-Base improves click-through rate (CTR) by 6.02% and conversion by 4.45% over the production sequential model baseline ; TransX-Retrieval improves CTR by 2.96% over the sequential two-tower production model baseline; and TransX-Ranking improves conversion by 1.33% over a DLRM learning-to-rank baseline. Under matched training conditions, the optimized execution pipeline increases supervised-target throughput by 84%. Production serving further demonstrates that history-dependent computation can be moved off the online serving path while maintaining bounded behavior memory KV, nearline freshness, and latency-critical candidate scoring. Taken together, these results motivate a view of recommendation scaling as a joint problem of compute allocation and amortized/disaggregated execution. The central question is not simply how much computation to add, but where additional capacity yields the greatest predictive return, when each component must be recomputed, and over what scope its state can be reused.
