An LLM-based agent combines a language model with a harness: the prompts, tools, memory mechanisms, and control logic that support its interaction with an environment [1]. For this study, we distinguish three components: the backbone LLM; environment-independent scaffolding, such as shell access, a file system, and generic context management; and environment-specific scaffolding, such as controllers and observation layouts designed for a particular environment family. These components interact. A capable agent may depend heavily on its harness without requiring that harness to be environment-specific. Existing research shows that agent performance depends on how models are prompted and connected to tools. CodeAct investigates executable code as an action representation, while SWE-agent examines how agent–computer interface design affects performance [2, 3]. AgentBench and AgentGym provide multi-environment evaluation and learning frameworks, and Exgentic compares general-purpose agent architectures across heterogeneous benchmarks without per-environment task-solving customization [1, 4, 5]. Research on iterative self-refinement and test-time computation further motivates distinguishing the model from the procedures and inference used to apply it [6, 7].
