Of the 61 papers surveyed: • Only 7 (11%) discuss implementation-level micro-optimizations, indicating that the vast majority of metric space search work operates at the algorithmic level without examining how implementation details interact with algorithmic choices. • Only 9 (15%) report both wall-clock runtime and distance computation counts, despite the fact that these two metrics can diverge significantly (e.g., fewer distance computations does not guarantee faster runtime when per-computation cost varies or overhead dominates). • Only 6 (10%) compare batch/bulk querying against single-item querying—and these are almost exclusively the dual-tree and GPU-parallelism papers. • Only 16 (26%) explicitly test with held-out query points distinct from the indexed dataset, despite the fact that production workloads nearly always involve queries unseen at index- construction time. These gaps motivate the four contributions of this paper: our optimization ablation (addressing gap 1), joint runtime and distance reporting (gap 2), query-mode comparison (gap 3), and all-NN vs. held-out evaluation (gap 4). 49
