A normalized-gauge stream still incurs the per-tensor round trip but avoids this additional fine-grained management cost. The migration alternative. Scale migration provides another way to manage activation ranges, as reviewed in App. C. SmoothQuant moves calibrated per-channel activation scales into adjacent weights offline (Xiao et al., 2023), while calibrated per-channel scales provide analogous range control for a stored stream. Rotation-based schemes redistribute coordinate magnitudes by changing the basis (Ashkboos et al., 2024). All of these methods can be applied to trained models. Migration reduces the measured quantization error on the same trained models. SmoothQuant with α = 0.5 and per-site static calibration reduces the worst-baseline W8A8 envelope of Table 10 from +0.270 to +0.061 nats, with QK-Norm worst after migration. Per-channel static scales reduce the worst-baseline residual-stream envelope from 1.10 to +0.003 nats, with LLaMA-style worst after migration. At 1B the worst value is +0.007, compared with 5.51 before this treatment. For GCT, the two treatments produce loss changes of +0.008 and +0.000 nats, respectively. At 1B, the stream treatment changes GCT’s loss by +0.000 nats. The serving stack can manage scale externally, or the architecture can control scale before deployment. Static migration and channel scales require a calibration pass for each deployment target, using 8 held-out batches here, and may require recalibration under distribution drift. The dynamic per-token route carries fine-grained metadata on every cache and offload path, with the 1.02× runtime ratio and 48 KB per 1024 tokens measured above. Both routes require kernel support for the chosen granularity. The normalized-gauge architectures meet the int8 loss threshold with per-tensor scales in this setting, while retaining the ordinary quantization and dequantization cost.
