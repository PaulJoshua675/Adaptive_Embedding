As in real-world projects, documents may be outdated, legacy code may reflect incorrect assumptions, and important information may not be explicitly stated in the available materials. 2.2 Task Instruction Levels The four task instruction levels (Table 1) distinguish the challenges of implementation, constraint discovery, and problem clarification by varying the task instruction while keeping the environment and evaluation criteria fixed. The L0 instruction explicitly states the underlying problem, relevant rules and constraints, and scoring criteria, leaving the agent to design and implement a solution. The L1 instruction withholds the rules and constraints, while the L2 instruction also provides only a vague description of the problem. The L3 instruction presents the sponsor’s original request, requiring the agent to assess whether the request addresses the underlying problem. We use L3 as the primary evaluation setting because this level most closely reflects the starting point of real-world customer delivery projects. L0 does not eliminate the need for engineering decisions. By specifying the rules while leaving solution design open, L0 measures what an agent can build when all underlying facts are provided. 2.3 FDE-Gym Score FDE-Gym evaluates a delivered system by the improvement it achieves on the customer’s business metric, measured on held-out production data. For example, an after-sales system is assessed by its net financial benefit, while a drilling system is assessed by the downtime hours correctly attributed to a contractor for compensation claims. We define the following metrics to assess agent performance on these delivery tasks. Normalized Business Uplift (U).
