Specifically, everything it does is one cycle of submitting a job, monitoring it to completion, and collecting its artifacts: the cycle runs once on the training job to obtain the round’s model 𝐶𝑡, and then once on each of the 𝐾benchmarks to obtain the evaluation results for 𝐶𝑡, with the raw logs and intermediate outputs staying in its own context. When the workflow finishes, the executor saves the feedback artifacts and a structured execution report to files and returns only their paths. The meta agent and the analysis and synthesis subagents can then read the relevant files as needed, without receiving the full execution logs. 4.2. Analysis subagents Section 3.1 shows that all 33 rounds of the single agent stay inside the mixture family: it pursues the objective through one kind of strategy. To break out of the limitation, we introduce four analysis agents, each of which examines the current round from a different evidence source: the training data, failure cases, learning dynamics, or research history. The four subagents examine each round using complementary evidence. The training-data subagent reads 𝐷𝑡and 𝑅𝑡, assesses the selected data for quality, difficulty, coverage, and redundancy, and proposes changes to its content or composition under the fixed token budget. The failure-case subagent compares successful and failed cases in 𝐹𝑡to identify recurring failure patterns and propose supervision to address them. The learning-dynamics subagent analyzes the training loss and other monitoring signals in 𝐹𝑡in relation to the data used for training, seeking evidence that explains stalled learning progress. The history subagent reads 𝐻<𝑡, distinguishes failed interventions from ideas that have not been adequately tested, and proposes corrections or renewed trials. Each subagent returns one executable data proposal with supporting evidence. 4.3. Synthesis subagent In practice, the initial pool 𝐷0 may not cover every capability the benchmarks require, and for others it holds examples but too few to constitute effective supervision. We therefore introduce a synthesis subagent to generate examples for undersupplied capability targets. Such a target is convenient to state and to verify in the instruction-following setting: it is a single checkable constraint, or a combination of constraints that co-occur, such as repeating the instruction verbatim while using no comma, and in either case a programmatic verifier decides whether an example satisfies it. Concretely, the synthesis agent is invoked in every round, reads the evaluation results, and derives a set of targets to strengthen. For each target whose supply in 𝐷𝑡is insufficient, it synthesizes examples that pass the target’s verifier. If no target is undersupplied in a given round, the synthesis agent generates no data. Generated data pass verification of the target’s constraint, an independent semantic review, and an 𝑛-gram overlap check against the evaluation sets, described in Appendix B.4. Those that pass enter 𝐷𝑡+1, and whether the round trains on them remains the meta agent’s decision. 5.
