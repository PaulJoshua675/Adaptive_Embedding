Its “Provided Artifacts” section specifies the observation files, and its “Provided Helper Programs” section describes ascii_to_png.py, supplied in the initial workspace. # Environment Description ## 1. General Description Of The Environment You are playing a dynamic visual puzzle game. Your objective is to reach `WIN`, avoid `GAME_OVER`, and use as few actions as possible. The game consists of levels. Levels usually form a curriculum: later levels often extend earlier mechanics rather than replacing them. If you reach `GAME_OVER`, use `RESET` to begin another attempt at the current level. `RESET` counts toward the action budget and does not reset the current level's action count, so avoid using it unless the state is `GAME_OVER`. The game is deterministic: every attempt starts from exactly the same state, so the same action sequence produces exactly the same results. You cannot return to already solved levels. The game is shown as a `64 x 64` visual frame made from color indices `0..15`. A single action may produce multiple frames. When this happens, the last frame is the final settled state, but the intermediate frames are important evidence. Multiple frames usually mean something meaningful happened, such as animation, collision, damage, item use, state transition, level completion, or failure. Explore such animations with your own eyes. This is a visual puzzle. ASCII frames are exact data, but PNG frames show the game more like a human would see it. Inspect PNG files with your own eyes. ## 2. Actions Actions are JSON objects.
