AI Model TF September, 2026 B.6.1 Judge Scoring Prompt The judge prompt ( EVAL SYSTEM PROMPT in trainer.py) instructs the judge model to grade a response on a 0–10 scale while remaining blind to the gold answer. Its key requirements are: (i) solve the problem independently before grading, never assuming the model’s answer is correct; (ii) 10 means the final answer is correct, 0 means wrong or missing, with partial credit (1–9) for substantive progress on incorrect solutions; (iii) the feedback must locate the methodological error and how to fix it without ever revealing or hinting at the final answer (no numbers, letters, or expressions); (iv) no restating of the question or response. Question: {question}\n\nResponse: {response}\n\nEvaluate this response. Provide detailed feedback and a score. The judge returns its output in the format <FEEDBACK>...</FEEDBACK><SCORE>0-10</SCORE>; the score drives judge-select (Appendix B.3) and the feedback becomes the input to the backward pass below. B.6.2 Backward (Text Gradient) Prompt The backward prompt (BACKWARD SYSTEM PROMPT in llm backward prompts.py) asks the en- gine to act as the “gradient” with respect to the context variable: given the current system prompt, the question, the model’s response, and the judge feedback, produce criticism of the context—strategies, explanations, and methods to change—but never a rewritten version of the variable (that is the optimizer’s job). It carries the same no-leakage and conciseness clauses as the judge prompt. The gradient is injected through a structured conversation template: <LM SYSTEM PROMPT>{system prompt}</LM SYSTEM PROMPT> <LM INPUT>{prompt}</LM INPUT> <LM OUTPUT>{response}</LM OUTPUT> <FEEDBACK>{feedback}</FEEDBACK> Note that the full response is embedded in the backward prompt; this is the main driver of the judge-context length budget (∼14.5k tokens at peak for our longest responses). B.6.3 Optimizer (Context Rewrite) Prompt The optimizer prompt (OPTIMIZER SYSTEM PROMPT in optimizer prompts.py) implements the TGD update: improve the context variable using the feedback, returning the improved vari- able wrapped in {new variable start tag} {improved variable} {new variable end tag} tags so it can be extracted and replace the old context directly, with an instruction to keep the improved variable concise. The update instruction passes the variable’s role, its current value, and the gradient from the backward pass. What shapes the rewrite most is the role description attached to the context variable: “system prompt to guide the model’s behavior. A good system prompt establishes the model as a domain expert relevant to the task (e.g. ‘You are an expert chemist . . . ’), states the key reasoning approach and pitfalls to avoid, and specifies the required output format. Avoid generic phrases; be specific to the question’s domain. Do NOT reveal or hint at the actual answer.” This steers the E-step away from generic encouragements (“think carefully”) toward sub- stantive, domain-specific guidance, which is what the M-step steering vector can then convert into a decoding-time correction. Optional momentum (past iterations), constraints, and in-context-example sections exist in the template but are disabled in all experiments reported in this paper.
