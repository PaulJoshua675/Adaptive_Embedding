Preprint Dynamically evolving environment. Environment states should change over time, independently of the model’s actions. These changes may include moving game elements, changing availability, or continuously updated information. For example, available seats change during cinema booking, while obstacles move across the screen in games. Temporally constrained interaction. Success should depend on both what actions the model takes and when it takes them. Deadlines, limited action windows, and transient opportunities require timely responses. For example, a model must reserve a seat before it becomes unavailable or dodge an obstacle before a collision. 4.2 TASK CONSTRUCTION. Guided by the above criteria, we construct web tasks based on realistic application scenarios and adapt game tasks from popular open-source games. We adjust task goals and temporal constraints so that success requires timely action, while ensuring that tasks remain feasible for humans. This process yields 50 tasks: 30 web tasks and 20 game tasks. Each task has task-specific success criteria, such as successfully purchasing a ticket before the countdown expires. 4.3 TASK EXAMPLES AND DISTRIBUTION. At each scheduled observation frame, the model receives the current screenshot together with the retained interaction history. To prevent GUI grounding from becoming a bottleneck for evaluating real-time decision making, we augment the screenshot with a read-only Set-of-Marks (SoM) representation following common GUI-agent practice (Yang et al., 2023), which identifies currently interactable elements and exposes their associated semantics and supported actions. At each decision step, the model generates executable GUI actions from a common GUI action space (e.g., click, type, scroll, and wait) (Xie et al., 2024).
