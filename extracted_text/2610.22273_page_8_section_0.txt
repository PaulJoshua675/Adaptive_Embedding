More details on the baselines and hyperparameters are available in Appendix A.7. (1) In Distribution Performance of Librarian Agents on BrowseComp-Plus. We evaluate the performance of Librarian Agents on the BrowseComp-Plus domain in Figure 4. Here we find that Librarian Agents with RL fine-tuning significantly outperforms all reactive and pre-computation baselines. When using the frozen Qwen3.5-4B answering agent, Librarian Agents achieves an accuracy of 0.75, representing a substantial improvement over the Embedding (0.42) and Reranker (0.44) baselines. A similar trend is observed with Gemini 3.1 Flash Lite, where Librarian Agents reaches 0.77, compared with baseline scores of 0.30 and 0.42. Crucially, the ablation without RL fine- tuning (No FT) additionally underperforms below Librarian Agents, highlights that policy optimization with RL is essential for teaching the builder agent to structure memories effectively for downstream consumption, a task the base model was not trained for. (2) Memory reuse and cost per correct answer. Filesystem construction is a one-time cost that helps all queries using the same document set. We therefore measure the amortized cost in a dataset we extend so that each document set serves multiple queries. As shown in Table 1, Librarian Agents incurs an upfront construction cost of 179K tokens and achieves an accuracy of 0.77, compared with 0.36 and 0.04, respectively. To examine how this cost is distributed when a filesystem is reused, we evaluate 443 frozen synthetic queries across 50 document sets, with 7–10 queries per document set, generated by Gemini 3.1 Flash Lite few-shot prompted with sample DeepDive (Lu et al., 2025) questions. On these queries, the same evaluation filesystems yield an accuracy of 0.64 versus 0.24 for the base builder at an answer-time cost of 9.3K tokens per query. At a hypothetical reuse load of 20 queries per document set, spreading the reported construction cost across those queries gives a projected total of roughly 18K tokens per query (Table 2).
