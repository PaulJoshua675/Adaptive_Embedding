At initialization, the environment supplies a textual description of the task and interaction interface, optionally accompanied by files. The agent then submits JSON actions and receives observation files and terminal status. The agent remains unchanged across environments, while each environment defines its own actions, observations, and termination conditions. 3.2 Implementation The implementation runs the agent and the environment server in separate Docker containers. Actions are JSON objects exchanged over HTTP, and responses carry observation files and termi- nal status. Initialization delivers the description text and an initial observation; supplementary files are placed in the agent’s workspace before interaction begins. The server-side infrastructure can access the agent’s designated workspace, while the agent has no reciprocal direct access to the task implementation or task sandbox. Terminal-Bench uses this convention for send_path: the agent names a source file or directory and a destination, and the environment copies the requested contents (see Appendix A.4). In the evaluated setup, the agent container accesses the Internet only through an allowlisted proxy that permits connections to the domains needed by the LLM service. This restriction does not apply to the environment. An environment may use the Internet itself or provide Internet access to the agent through its actions. Evaluation-specific access controls are described in Section 7.3. Implementation documentation is available through the EnvTraverse project page. 4 Environment-Agnostic Agents We study one environment-agnostic agent in two prompt variants: Baseline (agent_v1) and Stop-and-report (agent_v1_01_wstop). They use the same code, controller, and tools; only one short instruction differs. Each variant is deployed unchanged across environments for a given model–effort configuration. The agent simplifies the textual agent described in Section 4, “Architecture and Agent Variants,” of our earlier ARC-AGI-3 study [9]. We retain its Codex- based architecture while removing ARC-AGI-3-specific control and requirements to maintain a world model. 4.1 Agent architecture Figure 2 shows the agent’s four components: a controller, a Codex coding agent, an environment- agnostic client, and a persistent Linux workspace. Codex performs the task-solving work: it reads observations, reasons about the task, writes and executes programs, and selects environment actions. It submits those actions through the provided client, which is part of the agent rather than the environment. The client provides the same interface across environments and contains no environment-specific logic. 6
