Modern language-model agents use tool calling to resolve user requests (Schick et al., 2023; Yao et al., 2023), often executing multi-turn sequences of function calls over registries of internal services and external APIs (Barres et al., 2025). Systems such as Claude Cowork (Anthropic, 2026), Copilot Cowork (Microsoft, 2026), and Codex (OpenAI, 2025) illustrate the growing use of tool-mediated interaction in agentic workflows (Xu et al., 2026). A central challenge is selecting and invoking the right tool from a potentially large registry. Expos- ing many tool schemas simultaneously increases context and token costs, while long, detailed inputs can make relevant information harder to use reli- ably (Sakizli, 2026; Liu et al., 2024a). However, description-based retrieval can confuse semantically similar tools, and retrieval errors can propagate to downstream execution. As registries grow, tool selection and schema management there- fore remain important sources of inefficiency and unreliability despite progress in tool retrieval and tool-use training (Liu et al., 2026; Gillespie and Perry, 2026; Qin et al., 2024; Patil et al., 2024; Gan and Sun, 2025). The core gap is that each step is treated as in- dependent search, when tool retrieval is really se- quential prediction: which call comes next, given those already made. Within a single turn, a τ 2 re- tail request is resolved in a logical order: identify the customer, pull their account, open the order in question, then act on it. The calls already made therefore constrain the next one. Built on this intuition, we propose TRACER (Trie Retrieval Across Contextual Edges, Reweighted), a state-conditioned front-end that offers a small, ac- curate candidate set at every step and still leaves the final choice to the model (Figure 6, Appendix A.8). It rests on three ideas.
