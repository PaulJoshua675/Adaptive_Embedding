A workbook task reveals a difference in how models translate task requirements into programs. GPT-6 Astra builds a reusable solver, checks it against seven supplied examples, and identifies question rows from the workbook contents. Its program generates answers for all 125 questions. Qwen3.8-Max also uses functions and loops, but processes fixed row ranges that cover only 85 questions. Although its program reports this count, Qwen3.8-Max does not check for omitted questions. An audit of the saved workbooks confirms that GPT fills all 125 required Level answer cells, while Qwen3.8-Max leaves 40 empty (Figure 11). The gap is therefore not simply whether a model can write executable code with loops and conditions, but whether it can use code correctly to cover the full task and check for incomplete work. 5 Roadmap Open Generalist CUA aims to make generalist computer use a shared research effort in which models, execution systems, and real-device evaluation advance together. This first release provides an initial basis for that work. 5.1 From Design Validation to Model Release The model-side contribution of this report is empirical validation of agent design using existing models, rather than a newly trained model. We study code execution and harness-to-model decision transfer, and release implementations, prompts, and evaluation trajectories alongside preliminary versions of the real-device harness and cross-device SDK. A GCUA model is the central addition planned for the next release. We aim to unify computer and browser use and turn the designs studied here into learned capabilities: coordinating visual and programmatic operations through code, requesting observations when needed, maintaining task state throughout execution, and particularly enhancing the capability in real-device scenario. 23
