Shading marks what the action changes. 2.2. Data research actions A recipe is built out of rows, where a row carries an instruction, a response, and the metadata that describes it. An action states which rows to train on, how often each appears, in what order, and whether any row is edited or newly written. Agents write recipes in free form with no field schema, operator list, and statement that a particular kind of change is available. Figure 3 describes the six families of data action a data researcher makes most often. Each family is fixed by what happens to the rows and by the level at which the change is decided, which ranges from a whole category through a single row and a capability to the recipe as a whole, so an action can be labelled from the recipe diff without reading the agent’s stated reason. Every family is reachable in every configuration we run, since an agent that can write a recipe can also call a model to rewrite a response or produce a new row. We apply the labels only after a run and report how many families a run covered alongside its scores. Actions that leave the recipe unchanged, such as holding out a per-category validation set or evaluating a checkpoint more times, are research actions rather than data actions and stay outside A. 3. Pilot study: What limits single agents in SFT data research We study how a single agent behaves when it owns an entire SFT data research loop. We reproduce the open-ended PostTrainBench setting [Rank et al., 2026] for Qwen3-1.7B-Base [Yang et al., 2025] on IFEval [Zhou et al., 2023b], in which the agent receives one H100, unrestricted internet access, and a ten-hour wall-clock budget. Six design choices in this setting interfere with measuring what the agent does with data, and we correct them before running the loop: we fix the training algorithm to SFT, provide an initial dataset pool instead of Internet search, add a second benchmark IFBench [Pyatkin et al., 2025], retrain from the base checkpoint each round, replace the wall-clock allowance with benchmark targets, and return richer feedback including training loss, category-level scores, and per-example failures.
