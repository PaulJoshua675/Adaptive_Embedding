C2 (Retrieval Bottleneck) constructs scenarios where facts are correctly stored but queries are phrased to produce low embedding similarity (vocabulary mismatch, different abstraction level). The memory is correct, only retrieval fails. C3 (Classification Accuracy) tests whether the system correctly classifies each observation as a create, update, re- inforce, or conflict operation, decisions extrinsic evaluation cannot observe directly. C4 (Synthesis Quality) tests whether multiple observa- tions from different artifacts merge into correct, well-formed facts, with ground truth specifying which should form a sin- gle fact versus separate facts. C5 (Temporal Correctness) tests whether the memory state correctly reflects temporal evolution: linear progression (A→B→C), retraction, and gradual drift across artifacts. C6 (Multi-Author Attribution) tests whether source identity affects consolidation correctly: corroboration from different authors should raise confidence differently than rep- etition from one, and disagreement should trigger conflict detection. 3.2 Difficulty Levels At L1 (Table 2), target claims appear almost verbatim in gen- erated documents with minimal surrounding noise. At L2, claims are embedded within realistic document context and require extraction from longer passages. At L3, claims must be inferred from combinations of statements, and documents contain substantial unrelated content that could mislead ex- traction systems. 3.3 Trajectory Schema Each trajectory is defined as a JSON structure specifying: • A unique trajectory ID, category, difficulty, and domain assignment. • A type indicating the evolution pattern (linear-evolution, contradiction, scope-expansion, retraction, stable, or gradual-drift). • A sequence of states, each containing a set of atomic claims representing the expected memory contents after processing documents up to that state. • Per-state docClaims, the subset of claims that the docu- ment for that state should contain (new information only, not cumulative repetition). • An expected action per state transition (create, update, reinforce, conflict, or supersede). • Author role and document type metadata for multi-author trajectories. Claims are required to be atomic (one assertable proposi- tion per claim) and self-contained (understandable without reference to other claims). This ensures scoring is unambigu- ous: each claim either is or is not entailed by the system’s fact store. The key design choice is docClaims vs. claims: docu- ments contain only new information per state. The system must retain prior knowledge across document ingestions, testing actual memory persistence, not single-document ex- traction. 3.4 Distribution FEB-30 contains 30 trajectories across 6 categories, dis- tributed across difficulty levels (10 at L1, 10 at L2, 10 at L3). Trajectories span 6 technical domains (infrastructure, secu- rity, financial operations, machine learning, data engineering, and containers) to avoid domain-specific bias. These trajec- tories instantiate the benchmark in a technical and business- operations setting, but the methodology is domain-agnostic as the same paradigm-inversion construction can produce tra- jectories for any domain in which facts evolve across multi- author artifacts, by substituting the domain’s own topics and observation categories. The total corpus comprises 147 gen- erated documents: 127 trajectory state documents and 20 noise documents (4 per C2 trajectory to test retrieval under distraction). 4 Document Generation Pipeline We adopt paradigm inversion (Roig 2025): rather than anno- tating ground truth on real documents (expensive and subjec- tive), we generate documents from known fact trajectories, making the trajectory itself the ground truth. Algorithm 1 formalizes the pipeline. 4.1 Multi-Model Rotation Documents are generated using 6 models across 5 providers, rotated per state index within each trajectory to simulate dif- ferent human authors with different writing styles. No single model generates more than 30% of total documents. Fol- lowing evidence that multi-source synthetic data mitigates distribution collapse (Schaffelder and Gatt 2026) and re- duces single-generator bias (van Elburg, van der Putten, and Marx 2025), this additionally simulates the natural stylistic variation of multi-author corpora. The generation models are all different from the system’s extraction model (which uses a different LLM family), avoid- ing the stylistic bias that inflates scores when the same model generates and extracts (van Elburg, van der Putten, and Marx 2025). 4.2 Style-Grounded Generation Documents follow a realism gradient across difficulty levels: 1. Style-grounded (L1/L2): An LLM generates a new doc- ument for the trajectory claims but mimics the tone, vo- cabulary, and structure of a real reference document. 2. Hybrid injection (L3): Claims are inserted into actual human-written documents from unrelated domains, pro- ducing text that is approximately 90% authentic.
