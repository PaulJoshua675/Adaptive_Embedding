C Implementation Details This appendix provides full implementation details for RUSTKNN, supplementing the overview in Section 4. C.1 Architecture and Trait-Based Generics The core abstraction enabling arbitrary metric spaces is the Distance<T> trait: pub trait Distance <T> { fn distance (&self , p: &T, q: &T) -> f64; fn distance_with_bound (&self , p: &T, q: &T, upper_bound: f64) -> f64 { self.distance(p, q) } } Users implement a single method; the library provides optimized built-in implementations for Eu- clidean and Manhattan metrics. The optional distance with bound method enables early-exit distance computation: the built-in Euclidean implementation uses four independent accumulators with 8-element unrolled loops for instruction-level parallelism, checking partial squared sums every 16–64 dimensions. If the partial sum exceeds upper bound2, the function returns a sentinel value without computing the final square root. The generic node structure Node<T: Clone> stores the data point, level, cached maxdist, cached parent distance d parent, children as Vec<Box<Node<T>>>>, and an is duplicate flag for merge-created duplicates. Fields are ordered for cache locality: hot query fields (point, maxdist, d parent) appear first. The library is organized into three variant modules (simplified/, nearest ancestor/, packed/) sharing common algorithms in a core/ directory. A zero-cost CoverTree enum wrapper delegates via pattern matching. C.2 Packed Trees and Cache Optimization After construction, the pointer-based tree is converted to a PackedCoverTree via a single depth- first traversal. All nodes are stored in a contiguous Vec<PackedNode<T>>, with child relationships in a separate shared Vec<usize> array. Each PackedNode carries u32 fields (child index start, child index count) as indices into the shared array. This yields compact nodes: PackedNode<f64> occupies approximately 40 bytes, with hot query fields spanning ≤32 bytes—fitting within a single 64-byte cache line. Using u32 saves 8 bytes per node versus usize. Approximately 1,000 nodes fit in a 32 KB L1 cache. During packing, children are sorted by d parent (ascending) so closer children appear first in mem- ory, tightening the pruning bound sooner. C.3 Dual-Tree Traversal The dual-tree traversal requires several adaptations for cover trees without self-children. When expanding one side’s children while holding the other constant, the held-constant node’s point must still score against the expanded children. Two helper routines (point vs subtree, subtree vs point) simulate the missing self-child. When both nodes have children, the traversal proceeds in three phases: (1) query point × ref- erence children, (2) query children × reference point, and (3) child–child pairs using trian- gle inequality lower bounds from phases 1 and 2 as free pre-filters: lb = max(|d(qp, rcj) − dparent(qci)|, |d(qci, rp) −dparent(rcj)|). Pairs whose lower bound minus combined maxdist exceeds the pruning threshold are skipped without additional distance computation. Per-query-point bounds are cached in a flat Vec indexed by node index. Two bound modes are supported: full recursive B1/B2 bounds with epoch-based cache invalidation (the default), and a Beygelzimer-style bound. A cheaper per-point kth-distance bound was removed: it drops the per- subtree margin and can prune true neighbors. 38
