Other differences concern how Codex is instructed to work. In particular, twma_v1.61 requires a persistent textual world model and uses a more structured prompt sequence. The general agent can also create and maintain such a description, but is left to decide whether and how to do so. Our motivation is to examine the value of prescribing useful procedures instead of leaving the agent to construct them. The claim that twma_v1.61 supplies no additional game rules or solutions is a qualitative comparison of the supplied game information, not a claim of identical prompts or control logic. We choose the textual rather than the verification variant from the earlier study because the latter additionally supplies predefined model interfaces, templates, and verification programs [9]. These are ready-made procedures, not hidden game solutions, but they introduce further differences in the tools initially supplied to the agent. twma_v1.61 makes the distinction between available task information and prescribed organization easier to examine. Nevertheless, its differences from the general agent remain bundled, so this comparison does not identify the contribution of any single component. 6.2 Targeted specialization: Controlled_RESET To obtain a more controlled comparison, we start from Stop-and-report and add only the ARC-AGI-3-specific reset-management intervention. We call this variant Controlled_RESET (test_arc3_agent_v1_02_wstop_wreset). Its main prompt adds: If the game is in the GAME_OVER state, you should report it, and I will give you another attempt on the same level. You are forbidden to call RESET by yourself. The prohibition is a prompt instruction; the client’s action interface remains unchanged. When Codex returns in GAME_OVER and the evaluation stopping conditions have not been met, the controller issues RESET through the client. It then resumes the same Codex conversation with the normal continuation prompt, a short reset notice, and the resulting client output. The reset observation is therefore available before Codex continues. This branch adds RESET before ordinary continuation; unlike the earlier textual agent’s reset protocol, it adds no separate failure-analysis stage. The Stop-and-report instruction, tools, and step-indexed observation layout are retained. In particular, the intervention does not introduce twma_v1.61’s level-and-attempt organization or its textual-model requirement. It tests the effect of transferring reset management from the coding agent to a script, using a convention already stated in the environment description. It is environment-specific because the controller interprets GAME_OVER and applies ARC-AGI-3 reset semantics. Restricting reset decisions is not claimed to be optimal. If an agent recognizes that an attempt has become unrecoverable before GAME_OVER, an early RESET could save actions otherwise spent reaching the failure state. This is a possible benefit of agent-managed resets, not an effect evaluated here; the current description advises avoiding RESET outside GAME_OVER. The experiment asks whether explicitly implementing the stated convention improves the present agent.
