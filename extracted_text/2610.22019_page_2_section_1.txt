Midtraining in frontier coding models. Although midtraining is growing in popularity, only a few works have presented detailed recipes and ablation results to the community. Qwen3-Coder- Next provides one such recipe, midtraining at a 256K context on trillions of tokens, including 600B tokens of repository-level data across 370 programming languages (Cao et al., 2026). Its recipe sug- gests combining mined PR data with agentic traces but does not explain exactly how to do so. GLM- 5 reports midtraining on approximately 1.55T tokens with progressive context extension, including 160B tokens of software-engineering data constructed from roughly 10M issue–PR pairs (GLM-5 Team, 2026), but does not provide details of the recipe. Kimi-Dev, one of the primary works on which we build, provides a more detailed recipe (Yang et al., 2026). It performs midtraining on approximately 150B tokens of diff patches, commit sequences, and synthetic agent interactions, and shows that a model with this prior needs far fewer SFT tokens than the raw base model to reach the same agent performance. daVinci-Dev advocates trajectory-style midtraining data and matches Kimi-Dev’s performance using fewer than half as many tokens (Zeng et al., 2026). Composer 2 shows that code-focused continued pretraining improves downstream RLVR performance (Cursor Research, 2026). AgentFounder similarly shows that continued pretraining benefits search agents (Su et al., 2026), while Liu et al. (2026a) study when midtraining effectively bridges the distribu- tions of pretraining and post-training data. Relative to these works, we provide the ablation-level detail missing from the technical reports and evidence that the gains persist through full SFT. Repository-level data construction. StarCoder2 concatenates repository files in random order (Lozhkov et al., 2024); DeepSeek-Coder orders files by import dependencies (Guo et al., 2024); SPLiCe shows that structured packing improves long-context use (Staniszewski et al., 2025); Pro- Long randomizes on purpose to avoid recency bias (Gao et al., 2025). Sapronov & Glukhov (2025) find that most of the gain from repository-level pretraining for project-level code completion comes from adapting to a longer context rather than from how the repository context is assembled.
