Per-subset divergence values for the full registry are reported in Appendix D. 3.3 Agent Trajectory Divergence We define the agent trajectory as the set of APIs the planner names and the steps it describes in its output. Since we do not execute API calls, all measurements reflect the planner’s intended behavior. Trajectory divergence measures whether the two architectures lead to the same intended tool calls (via Jaccard similarity). Trajectory fidelity measures whether the planner stays within the retrieved set (100% = planner always names an API it was given). Trajectory fidelity is at least 96% across all subsets: the planner almost always selects from the retrieved set, confirming retrieval is the binding constraint on what the agent can do. Figure 4 shows five dimensions of trajectory divergence. The Jaccard similarity of planner-selected APIs decreases from 0.40 (G1) to 0.28 (G3), meaning even at the planner-selection level the architectures produce increasingly different tool call sequences. PtR’s planner uses a higher fraction of retrieved APIs (27–29% vs. 21–27%), suggesting its stub- guided retrieval produces a more coherent candidate set that the planner trusts. On G3, PtR generates more ambitious plans (4.1 intended steps, 1.4 APIs named) while RtP produces sparser plans (3.6 steps, 1.1 APIs named), suggesting PtR’s multi-stub retrieval gives the planner richer material to work with.
