The subagent selects a target when the pool contains far fewer than the 1000 rows it treats as sufficient, and it records the count it finds. For example, the R9 targets matched only 4 to 161 staged rows each. The subagent excluded capabilities that already had ample data, reasoning that generating new examples cannot help a capability the pool already covers. A capability with a high aggregate score can therefore still be a target, because what is scarce is a specific constraint combination rather than the capability as a whole. An example is repetition together with a number word, as opposed to number words on their own. The score of an exact combination cannot be measured directly, because the benchmark contains at most one question for it. Experimental Details and Resource Usage All experiments share one implementation for agent execution, supervised fine-tuning, and evaluation. A research agent coordinates each round and makes the data decisions, while a separate batch- inference backend generates and reviews synthesized examples. Every candidate recipe is fine-tuned from the same base checkpoint, and only the research history and the evaluation feedback carry across rounds. Table 5 lists the settings common to every run.
