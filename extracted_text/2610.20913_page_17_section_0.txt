The architecture determines which computation and state can be reused; the infrastructure determines how these objects are partitioned, placed, transferred, and cached. Execution must preserve two contracts. During training, each event reads only causally valid behavioral state, candidates share one event memory, and fanout gradients rejoin before entering the shared trajectory graph. During serving, continuation state remains maintenance-only, published behavior-memory KV is immutable and version-compatible, and state recovery remains outside the online serving path. 5.2 Training Infrastructure Section 4 defines training logically as a multi-prefix computation over packed behavioral trajectories: multiple serving events read different causal prefixes of the same trajectory, and multiple candidate losses within each event read the same event-specific memory. The training system must realize this objective without changing its semantics while avoiding the duplicated work that would arise from materializing each (𝑢, 𝑡, 𝑗) target independently.
