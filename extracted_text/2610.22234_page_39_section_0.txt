F.5 FAILURE ANALYSIS: EVALUATION COVERAGE AND CROSS-MODALITY HANDOFFS Figure 8 presents two representative failures that expose a gap between task specification and evalu- ation coverage, as well as a state-handoff problem at the GUI–code boundary. Rather than indicating a deficiency of either modality in isolation, these traces identify systematic challenges for a hybrid policy in interpreting visual intent and maintaining persistent state across modalities. The top trace illustrates a specification–evaluation coverage gap. “Preserve the original formatting” defines a visual equivalence condition involving row banding, numeric display, borders, and other rendered attributes. When the instruction and validation signal do not fully characterize these at- tributes, or do not cover admissible solution paths equivalently, they create an underspecified proxy objective that can favor one modality. After code-based conversion, the agent detects a mismatch through the GUI but attributes it to missing currency symbols, adding dollar signs rather than restor- ing the missing alternating row shading. A natural GUI solution would select the Calc table and paste it into Writer, preserving its rendered appearance; serialization through code instead requires the visual formatting to be reconstructed explicitly. This case motivates aligning user intent, ren- dering semantics, and verification coverage so that the benchmark recognizes the full set of valid solutions without presupposing an action modality. The bottom trace exposes a cross-modality state-handoff failure. The agent first completes the first subgoal correctly through the GUI. When code subsequently edits and saves the second subgoal, it writes only a local disk-side state and does not incorporate the preceding modification that remains in the GUI-resident state. The GUI then mistakes the code-side save for a global commit and selects “Don’t Save”, discarding the correct update for the first subgoal.
