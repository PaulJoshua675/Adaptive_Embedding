E Training Details The same dependency graph that defines evaluation tasks and Graph Credit scoring also structures the training pipeline. This section details how WEAVE leverages the PR depen- dency DAG to generate high-quality SFT trajectories and graph-structured RL rewards, completing the unified frame- work from construction through optimization. E.1 Trajectory Generation and Quality Filtering Trajectory generation setup. Training trajectories are generated using the Cline scaffold with the following config- uration: • Generator model: GLM-5.2. • Max turns: 200. • Context window: 128K tokens. • Temperature: 0.6 (for diversity). • Tasks attempted: 3,200 (all of WEAVE-Train). • Attempts per task: 3 (best-of-3 by Graph Credit). Choice of generator. We generate with GLM-5.2 rather than the strongest evaluated configuration (Claude Opus 4.7 + Cline, per the RQ2 results in the main text) for three reasons. First, GLM-5.2 has openly released weights, so the resulting corpus can be published without the derived-data restrictions that proprietary model outputs carry, and the generation stage is self-hostable and therefore independently reproducible. Second, GLM-5.2 is the second-strongest configuration on WEAVE-Bench (43.0% versus 48.7% Resolved); the best- of-3 protocol absorbs most of this 5.7 pp gap at the corpus level. Third, generator and student share a broadly similar tool-invocation format, which reduces format adaptation dur- ing distillation. The cost is throughput: GLM-5.2 averages 138.2 turns and 7.52 M cumulative tokens per benchmark task, against 46.8 turns and 2.11 M for Claude Opus 4.7. This 3.6× generation overhead is why we cap attempts at three per task rather than sampling more widely. Quality filtering. Generated trajectories pass through five filters. These are deliberately strict: a trajectory that satis- fies downstream tests while leaving upstream prerequisites unimplemented exhibits precisely the phantom credit that WEAVE-Bench is designed to expose, and distilling such behavior into the student would be self-defeating. We there- fore gate on Graph Credit rather than on flat test pass rate. 1. Dependency-consistent success filter: Retain trajecto- ries satisfying both GraphCredit(GA) ≥0.85 and minv∈VA cv ≥0.50. The first condition requires near- complete resolution of the task graph. The second is applied per node and forbids any single node from re- maining grossly unimplemented; because cv is already bottlenecked by its ancestors under the recursive defini- tion of Graph Credit in the main text, it constrains every dependency path simultaneously. A trajectory with high Flat-F2P but an unresolved upstream node fails this filter by construction. 2. Length filter: Discard trajectories shorter than 8 turns, and any trajectory that terminated by exhausting the 200- turn or context budget rather than by submitting a patch, since truncated rollouts are incomplete by construction. The resulting effective upper bound is 150 turns, 75% of the interaction cap. 3. Regression filter: Discard trajectories exhibiting any P2P regression. Failing P2P tests are re-executed three times and counted as regressions only when they fail consis- tently, so that flaky tests do not discard otherwise valid trajectories. 4. Degenerate pattern filter: Remove trajectories with three or more consecutive identical tool calls (same tool, same arguments), or with edit churn above 0.5— the fraction of edit operations subsequently overwritten or reverted within the same trajectory—which indicates thrashing rather than incremental progress. 5. Leakage filter: Discard trajectories in which the agent recovered the original change through repository history or network access, detected by scanning tool-call argu- ments for git log, git show, .git traversal, and outbound requests. Task instantiation already removes re- coverable target commits and repository history; this filter enforces the same guarantee at the trajectory level, where an agent could otherwise reach them at run time. Surviving rollouts are deduplicated per task: we keep the attempt with the highest Graph Credit, break ties by shorter trajectory length, and treat remaining attempts whose final patches exceed 0.9 normalized edit-distance similarity to the retained one as duplicates.
