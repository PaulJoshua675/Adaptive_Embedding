B. Comparing Compressed File Formats Each compressed file format has been developed to address certain use cases, and their structure have strong implications about their data bandwidth performance for accessing data from within the compressed image. In this subsection we will compare three formats that are commonly used to make datasets available: tar.gz, zip, and SquashFS. The tar (tape archive) format is commonly compressed with gzip, and it is the oldest of the formats. In this format, each directory and file in the archive has a metadata preamble (which contains directory and content information) and a data section. In order to access a directory or file in the directory hierarchy of the tar.gz file, the handler process must visit each metadata preamble until it gets to the directory or file content that has been requested. This involves many seeks and scans throughout the tar file. The zip file format is more modern in that in combines all of the metadata information of a directory into one metadata preamble section, with the data contents of the files in the directory sequentially stored after the preamble. Thus, there are fewer seeks and scans to get to the directory or file that has been requested. Finally, SquashFS images store all of the metadata in several metadata tables stored at the very beginning of the SquashFS image (not interspersed within the data). This means that the metadata tables can be loaded into memory and lookups do not require seeks and scans throughout the compressed image file. As we will see, these metadata and data layouts make a difference when creating SquashFS images.
