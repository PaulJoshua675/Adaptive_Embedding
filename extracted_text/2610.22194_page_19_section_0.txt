When a benchmark provides nothing, the agent derives the groups from the failures it observes. Every leaf of the resulting taxonomy is a requirement a program can decide, such as answering without using a comma, and carries the program that decides it. Rows in the pool are labelled by the leaves they satisfy, which is what allows the meta agent to select data by capability rather than by source and gives the synthesis subagent stable names to write against. Memory The history 𝐻<𝑡of Section 2.1 is the only thing a from-base loop carries between rounds, and AutoSFT puts more in it than a list of recipes and scores. Alongside those, it records the hypothesis a round registered before training, the verdict that hypothesis received, the lesson the verdict left, and the proposals the meta agent read but did not take. Each entry is keyed by round, so a later round can read what an earlier one expected as well as what it got. Registering the hypothesis first is what makes it worth recording. A round states the data change it plans, why that change should move the metric, the round its result will be compared against, the direction it expects, and the finer observation that would show the change working as intended. The submission path refuses a round whose hypothesis was never written down. A prediction written after the results are known can always be adjusted to fit them, which is what the ordering prevents. A verdict is read on two separate questions. The first asks what the benchmark mean did against the comparison round, judged only as a direction and only against the variation measured between repeated rounds. The second asks whether the finer observation actually appeared in the evaluation outputs. Keeping them apart matters because they can disagree, and a disagreement is informative.
