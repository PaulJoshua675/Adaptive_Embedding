This as- pect is often overlooked, but proprietary language models such as GPT, Claude or Gemini restrict or prohibit their use for the development of commer- cial models. Hence, we excluded all datasets where there is evidence that entries were generated using models with such restrictive licensing, regardless of the license applied to the dataset itself. We con- sider as "evidence" of non-permissive model use any dataset mentioning in its card, git repository or paper the use of commercial models. Whenever a dataset is released under a permissive license but a portion of its entries were generated using a restricted model, we opted for selective regenera- tion: the affected entries were regenerated using permissively licensed open-weight models, specif- ically: Mistral-small2, Qwen3-VL-235B-A22B3, and Qwen3.5-122B-A10B4. These models were se- lected based on their empirical performance across translation and generation tasks, and their licens- ing compatibility with downstream training (see Appendix A.2 for details). Out of 59 candidate datasets initially considered (excluding math and coding topics), 45 were excluded due to licensing or provenance violations (see Appendix A.1). A sample of regenerated examples is provided in Ap- pendix A.3. 3.2 Translation Pipeline Translated datasets were produced through an it- erative, expert-driven pipeline. For each target language, a native or near-native linguist indepen- dently developed a translation prompt, selecting the generation model and temperature in collabora- tion with the team. An initial batch of samples was generated and evaluated blind by a separate QA re- viewer with equivalent language expertise. Based on the reviewer’s feedback, the prompt, model, or parameters were revised and the process repeated until the output quality was deemed satisfactory. A special case within the translation pipeline is multi-smol_summarize, which combines transla- tion and generation. In the original Smoltalk sum- marization dataset, source documents are paired with summaries generated from a very small set of instruction variants. Crucially, we expanded the original instruction set by introduc- ing additional variants expressing formal output requirements, such as producing the summary as a bulleted list or as a Markdown table, thereby in- creasing both the linguistic and structural diversity of the dataset. 3.3 Synthetic Data Generation Five datasets in the collection were constructed through synthetic generation. For each, the same expert validation process described in Section 3.2 was applied: prompt design, blind evaluation, and iterative refinement by language-expert reviewers. Multi-AdvBench. The original multilingual Ad- vBench dataset consists of harmful prompt– unsafe response pairs. We retained the prompts and regenerated all responses using Qwen3-VL-235B-A22B-Instruct, with the ex- plicit objective of producing safe, refusal-oriented completions. To avoid any overlap across lan- guages, the original 520 prompts were randomly partitioned into five disjoint blocks of 104, one per language, so that each prompt appears in exactly one language. All generated pairs were manually reviewed. Multi-AyaRedTeaming. Starting from the En- glish, French, and Spanish subsets of the Aya Red- teaming dataset, we repurposed this adversarial resource for SFT by transforming harmful prompts into instruction-following examples with safe tar- get responses. We generated the expected safe responses using Qwen3-VL-235B-A22B-Instruct. For Italian and German, where no source data was available, we used the English prompts as seeds: the same model was prompted to produce cultur- ally appropriate questions in the target language and then to generate the corresponding safe re- sponses. All examples were manually reviewed and corrected. Multi-Dialogues. It consists of synthetically gen- erated multi-turn everyday conversations, produced by adapting the SODAverse pipeline from Kim et al. (2023). The original SODA dataset was built from social common-sense triples extracted from the ATOMIC10x knowledge graph (West et al., 2022): each triple is first expanded into a short narrative, which is then used to prompt a model to generate a dialogue.
