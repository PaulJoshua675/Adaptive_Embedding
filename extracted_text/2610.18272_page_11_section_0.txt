Appendix A Experimental Details A.1 Implementation The main configuration uses GPT-5.5 with medium reasoning effort as System Two and Jev-1.13.0 as System One. Each task has a 300-second research budget and a submission reminder at 210 seconds. Evidence memory is maintained separately for each question or topic. Candidate Retrieval. On both benchmarks, pas- sages contain a title and up to 250 body words, and min-max normalization maps constant score lists to zero. On BrowseComp-Plus, document and passage BM25 each return 1,000 hits, using (k1, b) = (25, 1) and (0.9, 0.4), respectively. Fu- sion ranks the union of their parent documents, with a missing score component set to zero. The ranked documents then form retrieval units: doc- uments of at most 8,000 UTF-16 code units re- main whole, while longer documents contribute up to two ranked passages. On NeuCLIRBench, passage scores refine the top 500 document can- didates, with both document and passage BM25 using (k1, b) = (0.9, 0.4). Passage scoring uses document-level inverse document frequency and a mean passage length of 144.7 analyzed tokens. Each document remains one retrieval unit. Evidence Processing. When scanning a candi- date ranking, the reader inspects retrieval units in batches of ten, up to 60 units per request. Ex- plicitly named QA sources form the initial batch. Local judgments run in parallel across source re- gions for QA and across documents for ranking; regions within a ranking document are read sequen- tially. QA uses up to 16 overlapping regions per retrieval unit, each covering at most 60,000 UTF-8 bytes of source text. For ranking, source pages are text excerpts of at most 4,000 UTF-16 code units; consecutive pages form regions containing at most 48,000 UTF-8 bytes of source text. Each response includes at most 100,000 UTF-16 code units of source text and preserves original source coordinates. For QA, evidence localization uses up to six lo- cal evidence questions supplied by System Two. For each question, the reader estimates whether a source region contains information addressing it. A region qualifies for evidence selection when this probability reaches τloc = 0.5 in Equation 6. Within a qualifying region, the reader selects the original block with the highest Choice probability. If that probability is below 0.8, it also selects the second most probable block, provided that the sec- ond block’s probability is at least 0.15. Adaptive reading can add up to two pages of surrounding context before reassessing whether the requested questions are supported. For ranking, relevance assessment first reuses completed document judgments. When scanning a candidate ranking, continuation judgments begin after twenty candidates requiring fresh assessment and are repeated after each later batch. This judg- ment estimates whether further inspection will find additional relevant documents; the reader contin- ues if that probability is at least 0.5. Fully assessed documents are retained when their probability of being relevant or highly relevant reaches θ = 0.25 in Equation 7. Incompletely assessed candidates remain eligible. Within retained documents, a page is selected when its probability of being useful for assessing relevance is at least 0.5. Pages without a completed usefulness judgment also remain eligi- ble. If no page is selected, a document meeting the relevance cutoff supplies its best available page. Evidence Discovery. Evidence discovery uses Sys- tem One to assess additional retrieved candidates against the original question or topic while System Two continues its research. We set the candidate inspection depth to K = 60. After each search, the first K retrieval units in its ranking are eligible for discovery. Units that have already been assessed or scheduled are excluded, without replacement from lower ranks, so the number of newly inspected units can be smaller than K. A new discovery batch starts only when at least 45 seconds remain before the submission reminder. For QA, the branch splits the original question at sentence and clause boundaries into up to six clue statements. Evidence localization identifies pas- sages addressing them. Only sources with at least one located clue are eligible to be returned. Their priority score follows Equation 8: each located clue contributes 1/nj, where nj counts the documents containing that clue in the assessed batch. Sum- ming these contributions combines clue coverage with specificity, giving more weight to clues found in fewer documents.
