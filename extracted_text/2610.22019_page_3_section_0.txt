Agentic benchmarks are unreliable before post- training, so Composer 2 selects among base models using held-out codebase perplexity, state track- ing, and adversarially built QA instead (Cursor Research, 2026). Other benchmarks target specific skills. LoCoDiff measures file-state reconstruction from git history (Mentat AI Team (AbanteAI), 2025), RepoBench and CrossCodeEval measure cross-file completion (Liu et al., 2024; Ding et al., 2023), and APTBench converts agent tasks into a format base models can answer (Qin et al., 2025). Whether such base-model measures predict downstream ability is still contested (Liu et al., 2023; Chen et al., 2025). In our experiments, they did not track post-training results reliably (§4.1). 3 THE MIDTRAINING RECIPE Figure 1 summarizes the blend, which is designed for diversity. Most of it is natural software- engineering data, with a small share of synthetic agent traces. We render these traces in the Nemotron chat template and keep them to 10–15% of the blend to avoid overfitting to SFT-like data, which can hurt later RL trainability (Liu et al., 2026b; Kang et al., 2025; Zhang et al., 2026). Everything else stays in natural formats, without chat templates. Every source keeps only permissive licenses and goes through decontamination against SWE-bench and Terminal-Bench, secret redac- tion, and loss masking of content the model should not imitate, such as repeated delimiters, hashes, and timestamps. Issue–PR. We construct a large-scale code-change corpus from merged pull requests in public GitHub repositories, combining repository snapshots with PR descriptions, linked issues, review discussions, and observed patch evolution when available. We restrict collection to repositories with at least ten stars in supported programming languages. We deduplicate examples by repository and PR identifier and remove records with unavailable repositories, missing Git objects, failed patch reconstruction, empty or excessively large changes, generated content, or other low-quality patches. Each example is laid out as a sequence in which repository metadata, date, file tree, and code context condition the model’s reconstruction of the submitted changes.
