BitSparse: Compact Activation Storage D.4 Language-model memory and runtime setup Models and data. We evaluate two models. The first is the 162M-parameter Modded-NanoGPT checkpoint from Section 6.1, trained by us according to the Track 3 baseline and evaluated at step 3300 (12 layers, 768 hidden dimensions, 50,304-token vocabulary). The second is NVIDIA’s official pretrained Nemotron-H-8B-Base-8K model. Both run in BF16 on a single GPU: an RTX 3090 with 24 GiB for Modded-NanoGPT and an RTX 5090 with 32 GiB for Nemotron-H. Models are evaluated on text from the FineWeb10B validation dataset Penedo et al. (2024), truncated to the target length. Batch size. Modded-NanoGPT is evaluated with a fixed batch of 4 sequences, sweeping the sequence length from 256 to 16,000 tokens, so the number of tokens per step ranges from 1,024 to 64,000. Nemotron-H is evaluated one sequence at a time at each length. Configurations. Each model is measured with dense activation storage, activation checkpointing on every feed- forward block, BitSparse, and BitSparse with sign-bit packing. Both models use ReLU2 feed-forward activations. BitSparse compresses each activation at the sparsity the model exhibits naturally (Section 6.1). We modify both models to use the same fused RMS normalization, and chunk the Nemotron-H vocabulary projection head, to keep incidental memory overhead low (Appendix A.1). Workload. Each step performs a forward pass and the backward pass of the language-model loss over that step’s tokens. Model parameters are never updated and gradients are released as they are produced, so no full-model parameter-gradient buffer or optimizer state is retained. Transient parameter gradients still contribute to peak memory. Timing and memory. The timing and peak memory consumption in a training step are measured. Times are averaged per step over repeated iterations after warmup. Memory is tracked using torch.cuda.max_memory_ allocated("cuda"). As in Appendix D.3, peak memory covers model parameters, activations, and temporary tensors. Warmup steps are used to ensure accurate timing. E Additional results E.1 Activation sparsity measurement in LLMs The experiments in Section 6.1 characterize feed-forward activation sparsity during Modded-NanoGPT training and in a pretrained Nemotron-H model. We evaluate both models on contiguous sequences from the FineWeb10B validation set, with fixed weights and without BitSparse compression. Both experiments use 256 evaluation batches, but the batch composition differs: the Modded-NanoGPT runs place four 4096-token sequences in each batch, while the Nemotron-H runs process a single sequence per batch. Measurement and aggregation. Following Section 2.2, we report activation sparsity ρ; larger values indicate a greater fraction of zeros. For each layer ℓand evaluation batch j, we measure ρℓ,j over all tokens and feature dimensions of the ReLU2 output, counting exact zeros without a magnitude threshold. With Q evaluation batches and measured layers I, we compute ρℓ= 1 Q Q X j=1 ρℓ,j, ρℓ,min = min 1≤j≤Q ρℓ,j, (21) ρbatch,min = min 1≤j≤Q 1 |I| X ℓ∈I ρℓ,j. (22) These are the per-layer mean sparsity, the per-layer minimum sparsity, and the minimum batch-wise mean sparsity across layers, respectively. The last quantity captures the densest observed batch averaged over layers; individual layers may reach their minima on different batches. Layers receive equal weight. All minima refer to the evaluated batches, rather than bounds on unseen inputs. Measurements are taken after squaring, so finite-precision underflow may produce additional zeros relative to the unsquared activations saved by BitSparse. Modded-NanoGPT during training.
