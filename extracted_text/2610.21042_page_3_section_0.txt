Their extraction workflow combines source- derived table standardization, iterative correction, and targeted human review. The commercial Elicit workflow proposes editable criteria and extraction fields and lets users return to earlier steps (Byun, 2025); it also provides evidence quotes, exclusion reasons, and PRISMA 2020 flow diagrams (Vard- haan and Mohanty, 2026). These workflows al- ready combine stage automation, customization, evidence access, and human oversight. To address these gaps, we develop ReviewPilot, a PRISMA-guided multi-agent system that coordi- nates literature search, screening, full-text retrieval, and information extraction. Researchers can tailor eligibility criteria and extraction schemas through dialogue, while agents generate screening guidance and per-field coding rules. Project memory retains configurations and corrections to support revision across stages (Sections 3.2 and 3.6). We evalu- ate the complete system on PERG and examine its workflows and screening agreement with human annotators in two case studies. 3 ReviewPilot Development ReviewPilot is a conversational multi-agent system that covers five stages of a systematic literature review: search, screening, full-text retrieval, in- formation extraction, and semantic categorization (Figure 2). Researchers can configure the review through dialogue or direct editing, inspect each stage’s outputs, and can override screening deci- sions or correct extracted values. 3.1 Architecture and Orchestration A Lead Agent coordinates four specialized agents and two tools through action contracts (Ap- pendix A.1). The Search Condition Agent designs the search strategy, and the Prompt Agent writes review-specific instructions (Section 3.2). The Screening Agent deduplicates and assesses records, and the Extraction Agent extracts structured in- formation. The Literature Search Tool executes queries, and the PDF Download Tool retrieves full texts. The Lead Agent categorizes values itself. The Lead Agent starts a stage only when its pre- requisites are met and the outputs it depends on are current. It reports completion only after check- ing the expected artifacts and their required fields. Agent skills are structured Markdown instructions specifying procedures for search strategy, screen- ing, prompt design, extraction, and categorization. A fixed mapping appends the matching skill to the LLM system prompts for these tasks (Appendix G). 3.2 Review-Specific Prompt Design The Prompt Agent writes the review-specific parts of the screening and extraction instructions, follow- ing the prompt-design skill. After the eligibility criteria are confirmed, it writes screening guidance G from the review objectives, criteria, search con- cepts, and up to 200 candidate records (titles and abstract openings). This guidance defines the re- view focus, domain terms, include and exclude categories, and tie-breaking rules. After screening, it drafts an extraction schema from the objectives, the requested fields, and the abstract openings of up to three included papers. Once the schema is confirmed, it writes the coding rules C from up to 25 included papers, using their abstract openings and full-text sentences selected for each field. The guidance and the coding rules are each drafted and then revised in a second LLM pass against the skill’s checklist (Madaan et al., 2023). Reviewer decisions and reference extraction values are not among the generation inputs. Researchers can edit the guidance, schema, and rules and must confirm each before the stage that uses it runs (Ap- pendices G.3, G.4.1, and G.5.1). 3.3 Search & Screening Search. The Search Condition Agent identifies the concepts required for eligibility and proposes alternative terms for each concept. It builds a Boolean query by joining alternatives with OR and required concept groups with AND (Ap- pendix A.2). Analytical dimensions that do not determine eligibility are omitted from the required groups. Researchers refine the concepts and query through dialogue or direct editing and review the sources, date range, and per-source limits. The Literature Search Tool then searches titles and ab- stracts in PubMed, arXiv, and OpenAlex. The saved query, settings, counts, and errors document the search as run. Screening.
