If static item properties account for the operational advantage, then explicitly adding the same information to DR should reproduce it without autoregressive decoding. 5.3 Transferring the Static Prior to DR To test whether static item value can close GR’s lead in BV, we rerank DR’s top 200 candidates for each user. We call this method DR+prior. DR+prior scales the DR similarity scores to 0, 1 within each pool, then average each score with the item’s value 𝑣𝑖(w) using the default weights from BV in Sec 4.3. Because BV uses the same item value, this test checks whether an explicit catalog prior can reproduce GR’s measured lead. This requires no retraining or decoder at serving time. Its Recall@50 declines from raw DR but stays above GR. 6 Robustness Beyond Exact-Match Evaluation The public results show that the item prior closes GR’s value gap. We now test whether GR does better on cold targets or when useful alternatives to the held out target receive credit. For the latter, we use public substitute evidence and graded judgments on an industrial recommendation dataset. 6.1 Cold Items We test whether generation helps retrieve targets absent from in- teraction training. GR finds none of 296 cold targets on 2014 and 5 of 1,899 on 2023. DR finds 47 and 27, while DR+prior finds 36 and 21, respectively. We next test graded relevance on the industrial dataset. 6.3 Industrial LLM-Judged Relevance The industrial evaluation uses real e-commerce interaction histories and a product catalog. GR uses a Qwen3 14B model that generates semantic IDs, while DR uses a GTE encoder with about 300 million parameters. GR has roughly 47× as many parameters. A substitute- aware LLM judge calibrated with 250 human labels scores each candidate’s relevance from zero to one, allowing partial credit for useful alternatives. Because the models differ in backbone and size, this evaluation tests whether the public result also holds in this setting. It cannot isolate the effect of retrieval architecture.
