C.4.3 asks whether it matters where the jumps fall. SoftCache jumps wherever the headroom allows, so every prompt gets its own positions. Each alternative instead fixes in advance which grid nodes may jump, the same for every prompt: nodes spread evenly over the trajectory, nodes near its end, or nodes drawn at random. A last variant never jumps. A listed node jumps only if it is cached, so these variants jump less often and run slower than SoftCache, and each row is reported as its PSNR gain over SeaCache at that row’s own speedup. For the random lists we report the mean of five draws and the best one, chosen after scoring. Nodes near the start are omitted as a list because almost none of them are cached. At τ=0.3 SoftCache leads every fixed list, by 1.2 dB over the next best. At τ=0.8 the fixed lists trail by 0.1 to 1.3 dB, and never jumping costs 1.5 dB. Because the fixed lists also jump less often, the table shows that where the jumps fall matters, but it does not isolate the value of choosing them per prompt.
