Long behavioral histories provide recommendation systems with evidence about persistent preferences, evolving interests, and immediate intent (Boka et al., 2024). Recent efforts to scale recommendation models have focused largely on increasing sequence-handling capacity: consuming longer histories, allocating more model computation to them, and engineering the serving stack to sustain the resulting workload (Zhai et al., 2024; Chai et al., 2025). When additional computation is placed on the online serving path, however, its cost scales directly with online prediction demand. Recommendation scaling is therefore not only a question of predictive gain, but also of where computation is placed and how often it must be executed. This raises two more fundamental questions that are easily obscured by generic compute scaling: Which computational components should scale to advance the recommendation-quality frontier, and must advancing that frontier increase online serving cost proportionally? Answering these questions leads naturally to a model–infrastructure co-design problem. The first is a model-design question: the architecture must expose the computational components whose capacities can be scaled along different axes. The second is an infrastructure-design question: those components should execute at their designated amortization scope and trigger, rather than all at request time. These two design problems are coupled through the model’s compute–state decomposition. The same computational decomposition that exposes distinct scaling axes also defines the state boundaries across which computation can be amortized, recomputed, and disaggregated. We develop TransX, a sequence-transduction framework that instantiates this model–infrastructure co-design principle. Its model architecture exposes three distinct computational roles: 1. Sequence encoding. A causal encoder transforms the evolving behavioral trajectory independently of the current candidate, allowing computation over overlapping prefixes to be amortized across prediction events. 2. Behavior memory. A bounded global–local memory separates the amount of history processed from the behavioral representation exposed to downstream prediction, making memory resolution an explicit scaling axis while exposing the memory as a reusable state boundary. 3. Candidate-conditioned fusion. Candidate queries cross-attend to the shared memory as part of the task-specific prediction path. Behavior memory KV is shared across candidate fanout while preserving candidate-specific fusion. This decomposition makes the amortization boundary explicit: behavioral-state construction over shared prefixes and its incremental refresh are amortized across requests and candidate fanout, while only prediction-conditioned computation scales with request and candidate demand. The infrastructure preserves and exploits the same decomposition in execution, translating the model design into substantial system-level efficiency gains. During training, variable-length behavioral prefixes from each trajectory share one causal encoding, while candidate fanout at each prefix shares one event state. During serving, bulk (offline) and nearline workers construct and refresh behavioral states on model rollout and behavior updates, while online workers consume bounded, immutable behavior memory KV cache for candidate-conditioned prediction. Thus, history-dependent computation is performed primarily when behavioral state is initialized or refreshed, while the online serving path is concentrated on state access and request- and candidate-conditioned prediction. This decomposition also lets us study how different compute allocations advance the recommendation- quality frontier.
