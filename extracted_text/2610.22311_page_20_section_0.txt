Preprint D.1 GLOBAL-ALIGNED GILBERT TOKEN ORDER Let a latent chunk contain T frames, spatial grid height H, spatial grid width W, and S = THW tokens. The row-major token index is λ(t, y, x) = tHW + yW + x, 0 ≤t < T, 0 ≤y < H, 0 ≤x < W. Here t, y, and x are the frame, row, and column indices within the chunk. Velox uses a global-aligned Gilbert map Γ : {0, . . . , (c+1)S −1} →{0, . . . , (c+1)S −1} over the visible prefix, where Γ maps a global row-major token index to its global Gilbert rank. The implementation builds a single-chunk Gilbert rank map γ once, then fills each chunk with a parity-dependent reflection. If (cT) is even, chunk c uses the single-chunk map directly. If (cT) is odd, the chunk-local coordinates are reflected by the base-frame exit quadrant before ranks are offset by cS. For the chunk-local reflection Fc, the global rank is: Γ(cS + λ(t, y, x)) = cS + γ(Fc(λ(t, y, x))) . This incremental rule is rank-identical to building the full-sequence Gilbert curve over all visible frames. D.2 GLOBAL GILBERT KV STORAGE Velox writes each chunk’s KV cache directly in its global-aligned Gilbert order. Let Kc,λ,a,: and Vc,λ,a,: denote the linear-layout key and value vectors for chunk c, token λ, and attention head a. Let κ denote a within-chunk Gilbert rank, and let Gc(κ) be the gather index that maps κ back to the corresponding chunk-local linear token. The stored tensors are: eKc,κ,a,: = Kc,Gc(κ),a,:, eVc,κ,a,: = Vc,Gc(κ),a,:, 0 ≤κ < S. Each chunk slot is front-padded as needed so the current chunk’s query blocks align to the global block ids in the visible prefix, and padded positions are zero-filled. The sparse kernel therefore sees a chunked contiguous address range whose block boundaries match βglob. The implementation uses separate query and KV sequence lengths, because current-chunk queries attend to a growing history cache. This rectangular interface is what lets Velox replace only historical visual attention while leaving the pretrained chunked generator interface unchanged. 20
