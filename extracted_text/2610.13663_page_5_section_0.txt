The Human Researcher configures the task, agent-modifiable block(s), target metric, and software contract once. At each iteration, the LLM Analyst reads the experiment log and produces a technical specification, which the LLM Coder converts into contract-constrained code. The generated module is first functionally tested and then evaluated in a Docker sandbox; runtime errors are returned to the Coder, while a successful evaluation is passed to the LLM Recorder. The Recorder appends a structured JSON record to the experiment log, which serves as the external memory for the next iteration. The detailed-prompt mode additionally provides the Analyst with a method-class taxonomy and a dynamically updated coverage map. Only task-specific prompts, the software contract, the editable model block, and the target metric change between tasks; the agent roles and loop structure remain unchanged. The technical specification describes the method proposed by the Analyst, whereas the software contract defines the interface and constraints for the generated code. The agents may modify only the selected block; the rest of the task pipeline remains fixed. This separation allows generated code to be inserted and tested automatically. Applying the framework to a new task requires a new prompt, software contract, target metric, and baseline, but the agent roles and execution loop remain unchanged. Baseline record. Each framework run starts with a task-specific baseline record in the experiment log. This record evaluates the fixed pipeline with the simple baseline implementation of the modifiable block and provides the initial reference value of the target metric.
