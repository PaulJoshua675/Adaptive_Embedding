Automated subject indexing assigns a set of descriptors from a con- trolled vocabulary to a bibliographic record. The earliest indexing models were lexical models that match document text with label names. Associative models learn the correlation of labels in the document text. Annif [21] is a popular CLI-based toolkit that consol- idates several models, including lexical models such as tfidf, mllm and associative models like fasttext [2], omikuji [18][12]. It provides various methods to ensemble these models together, including a neural network variant. It has become a de facto reference point for library indexing across vocabularies and languages. Concept drift analysis on short text [22] for the task of automated subject index- ing also found that fusion approaches outperformed other methods. However, all of these methods consider subjects as a large label list and do not take into account the structural relation between the subject from a thesaurus. The large number of subjects in the thesaurus inflates the label list to be considered for each document. Thus, subject indexing is most often cast as an XMLC task. Models that are designed to handle the challenges of XMLC are either a one-vs-all classifier, such as DiSMEC[1], Parabel[18] and its variant bonsai[12]. These are tree-based methods that reduce the label space through label co-occurrences. A more recent model, the XRTransformer[4, 29] uses transformer based model that operates in three stages, first cluster- ing the label space to reduce the label size, followed by a matcher module that identifies the correct cluster, and a rerank step to rescore the labels inside the cluster. This restricts the labels in the retrieved clusters, thus affecting the label coverage. All the afore- mentioned models offer competitive performance on head labels but fail to generalize to tail labels, especially with 0 scores for unseen labels. Models that exploit dual-encoders such as DEXML[8] and retrieval- augmented encoders such as RAE-XMC[24] target the tail by embed- ding inputs and label text in a shared space, trading the strong head- label training signals for tail generalisation. Our Stage-1 adopts this retrieval view to maximize recall, but rather than commit to a single OVA/DE trade-off, we defer the precision decision to a structure-aware second-stage reranker. Retrieve-rerank pipelines shortlist a comparatively larger list of candidates than the result set with an efficient retriever and defer to a more complex model to rescore them. Multi-vector and dense retrievers-ColBERT[13]-style late interaction and the unified dense/sparse/multi-vector encoding of BGE-M3[5] supply strong first-stage recall, while LLM-based cross-encoders that read query and candidate jointly provide accurate but expensive reranking. Infer-retrieve-rank [7] model performs the XMLC task within the same pipeline. It generates labels in a few-shot setting using frozen LLMs and a retriever that reranks the result. TAGHN follows this two-stage process, but its reranker does not score candidates inde- pendently. It scores them jointly over a per-document subgraph. Message passing over a graph was introduced with Graph Neural Network (GNN). Graph convolution neural network[14] aggregated its neighbors with a fixed weight. GAT[23] extended this idea with a content-dependent attention on the neighbors. GATv2[3] makes that attention dynamic rather than static-the variant adopted by TAGHN’s node-level channel B. Multi-relational heterogeneous graphs are effectively processed by R-GCN[20], which learns a sep- arate transformation per relation type. HGT[9] extends it to include node types by parameterizing attention between node and relation type. TAGHN draws these ingredients together, but conditions all of them on the document. Channel A gates each relation type with a document-dependent scalar, and Channel B computes node-level attention jointly from the target node, the neighbor, and the docu- ment embedding. While R-GCN and HGT learn type parameters that remain fixed at inference, TAGHN recomputes its per-relation gates and attention weights for every document. A parallel line of work injects label dependencies into classifica- tion. In XMLC, ECLARE[17] and GalaXC[19] augment label repre- sentations with correlation graphs built from co-occurrence statis- tics, and BGNN-XML[31] extends this to bilateral text–label graphs. In hierarchical text classification, HiAGM[30] and HGCLR[25] en- code a global taxonomy with graph or Graphormer[26] encoders and fuse it with the text representation. Methods like K-HTC[16] incorporate label hierarchy into hierarchical classification by con- structing a graph-based encoder over the label taxonomy and a contrastive-learning objective that aligns text representations with label representations.
