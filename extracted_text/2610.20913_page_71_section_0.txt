We therefore sample candidate slates 𝑆(1), . . . , 𝑆(𝑀) ∼𝜋sample(· | 𝜉𝑡) and score them using a frozen slate-aware preference function 𝑅𝜔(𝜉𝑡, 𝑆). The preference teacher 𝑅𝜔is trained on a separate mature-feedback split and frozen before slate-pair construction. Teacher-preference accuracy therefore measures agreement with 𝑅𝜔, not independent recommendation quality, which is reported separately on held-out evaluation data. Matched-length pairs are retained only when 𝑅𝜔(𝜉𝑡, 𝑆+) −𝑅𝜔(𝜉𝑡, 𝑆−) ≥𝛿pref. Controlled ordering or selection corruptions of a high-quality slate may supply additional hard negatives when they remain valid and satisfy the same preference-margin criterion. The retained slate pairs are optimized using the preference objective in Eq. (D.1). Candidate representations and behavioral memory remain fixed across the chosen/rejected likelihood evaluations, so the additional preference multiplicity is confined to the autoregressive slate readout. Shared TransX backbone configuration. The task-specific configurations are as follows: • TransX-Base. The prediction readout contains two stacked DCNv2 cross layers (Wang et al., 2021) with rank 256, followed by MLP of dimensions 2048–1024–512–256 and a parallel Deep&Wide tower with the same MLP dimensions. The resulting representation is mapped to the binary click and conversion outputs. • TransX-Retrieval. Retrieval replaces the candidate-wise prediction readout with a context-level retrieval representation. A context-query encoder with dimensions 512–256–128 attends to the shared behavior memory using 128-dimensional key and value projections, producing a 128-dimensional user embedding. The item tower reuses the corresponding base item tokenizer and applies a projection head to the same 128-dimensional retrieval space. • TransX-Ranking. TransX-Ranking reuses the TransX-Base candidate encoder, candidate-to- memory fusion, and interaction network. Post-training replaces the binary response output with a scalar ranking head and changes the supervision to the Bradley–Terry preference objective; this isolates the effect of preference specialization without changing the serving architecture. 71
