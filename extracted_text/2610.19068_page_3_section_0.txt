Let T be the tool registry, q the user query, dt the documentation of tool t, sim(·, ·) the cosine similarity between embeddings, and π(·) the agent’s execution plan given a retrieved tool set. RtP embeds the raw query and retrieves the top-k most similar APIs: RRtP(q) = TopKt∈T sim(q, dt); the planner then produces plan πRtP(q, RRtP(q)). PtR first sends q to the planner without any tool definitions, generating stubs S(q) = {s1, . . . , sm} (JSON objects with a hypothesized tool name and reasoning). Each stub is embedded and matched against the index; the union of top-k results (deduplicated, re-ranked) forms RPtR(q) = TopKt∈T maxs∈S(q) sim(s, dt), which is passed back to the planner to produce πPtR(q, RPtR(q)). An unfiltered baseline is infeasible at this scale: ToolBench categories contain up to 4,455 APIs (Sports) and 3,583 (Data), and Ground-Truth APIs are distributed across each category such that any fixed-size truncation misses them in the vast majority of cases. 2.2 Data and Metrics ToolBench (Qin et al., 2024b) provides three test subsets: G1 (single-tool, n=200), G2 (intra-category multi- tool, n=200), and G3 (cross-category multi-tool, n=100; smaller set, so G3 differences have lower statistical power). We report retrieval recall and precision computed at the fixed budget k=5 against the Ground- Truth API set from each query’s ToolBench gold trajectory (all APIs executed in the reference solution). RtP retrieval is deterministic (the query is embedded by GTE-base, a fixed model, and matched against the FAISS index via exact nearest-neighbor search; no LLM call, no sampling), so its precision and recall carry no run-to-run variance and are reported without a standard deviation. All remaining quantities — PtR’s precision and recall, and pass rate for both architectures — are averaged over 4 independent runs and reported as mean ± std, since both stub generation and planner output vary across runs. Statistical comparisons use a one-sample t-test for precision and recall (PtR’s 4-run mean vs. the deterministic RtP value) and a two-sample t-test for pass rate. All experiments use the full 46,984-API registry unless otherwise noted. Evaluation proxy. We evaluate against ToolBench gold trajectories as a retrieval proxy rather than end-to-end API execution. Trajectory fidelity (at least 96%; §4.3) supports this as a valid proxy for planner behavior: the planner almost always selects from the retrieved set, so retrieval quality upper-bounds task completion. Parameter correctness and final answer quality are not assessed and constitute a limitation noted in §5. 3
