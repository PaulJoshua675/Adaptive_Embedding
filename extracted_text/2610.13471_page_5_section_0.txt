On the symmetric CEC2022 bounds the reference point defaults to the box midpoint (the origin), so the multiplicative group returns identical reference copies; the reported results are conditional on this implemented behaviour, and a matched diagnostic using an alternative non-degenerate reference is documented in Supplementary Material S3. 3.4 Evaluation accounting Elite handling carries a stated cost. Each generation copies the Ke=3 elites into the trial population and generates only N −Ke = 37 new trials, yet the implementation evaluates all N = 40 trials and restores the stored elite fitnesses before selection, so one generation spends 40 evaluations for 37 new candidates and a run of T generations costs N(T + 1) evaluations including initialization. When B is not an integer multiple of N beyond initialization the final generation is evaluated only partially (Algorithm 1), so the requested budget is met exactly. Every algorithm receives the same budget with objective calls counted identically, so the comparison is matched in objective-call budget rather than in newly generated candidates: REMBGO spends three of every forty generation-level calls re-evaluating copied elite rows (3/40 = 7.5%), which the other four methods do not, amounting at the 1040-evaluation budget to 25 × 3 = 75 of 1040 calls (7.21%); this overhead is retained without compensation. Excluding objective evaluation, one REMBGO generation requires O(ND) arithmetic for population statistics, trial generation and boundary repair together with O(N logN) sorting, with O(ND) population storage. In the intended EAF–STATCOM application this internal overhead is negligible relative to the EMT objective evaluations.
