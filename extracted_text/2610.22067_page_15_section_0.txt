Characterising the Difficulty of Long-Context Reasoning LongCite (Zhang et al., 2025) is a benchmark assessing current LLM’s performance in Long-Context Question Answering with Citations (LQAC), covering various scenarios such as document QA, summarisation, and coding. LongMemEval (Wu et al., 2024) is a comprehensive benchmark designed to evaluate five long- term memory abilities of chat assistants: information extraction, multi-session reasoning, temporal reasoning, knowledge updates, and abstention. LongMIT (Chen et al., 2025) is a long-context instruction tuning dataset that is built from a Multi- agent Iterative Multi-hop Generation (MIMG) framework. LongReason (Ling et al., 2025) is a synthetic long-context reasoning benchmark constructed by synthesizing long-context reasoning questions from a varied set of short-context reasoning questions through context expansion. Loong (Wang et al., 2024) is a long-context benchmark aligning with realistic scenarios through ex- tended multi-document question answering. Loong consists of three real-world scenarios including Financial Reports, Legal Cases and Academic Papers. LVEval (Yuan et al., 2024) is a challenging long-context benchmark with 5 length levels reaching up to 256k words. LVEval features two main tasks, single-hop QA and multi-hop QA, comprising 11 bilingual datasets. Subsets included: hotpotwikiqa, loogle CR, loogle MIR. SciTrek (Li et al., 2026a) is a diagnostic question-answering benchmark designed to probe long- context numerical reasoning in LLMs. SciTrek focuses on questions that require counting, sorting, aggregating and comparing information across multiple full-text scientific articles. HotpotQA (Yang et al., 2018) is a question answering dataset featuring natural, multi-hop questions; the inputs are short Wikipedia snippets. In this work we use the extended version of Li et al. (2026b), which extends each instance by appending the full Wikipedia articles cited by the original context articles. We use the original context as evidence. B DATA FILTERING We apply six filters to select instances suitable for studying long-context reasoning. These address language, context length, data origin, task requirements, answerability without context, and task size. Language. We retain only English-language instances to focus on monolingual reasoning. We identify the language using source metadata where available and automatic language detection oth- erwise.2 Context length. We retain inputs containing between 32k and 256k tokens, measured using the Qwen3-0.6B tokenizer. This range balances long-context coverage with computational feasibility. Data origin. We restrict the collection to naturally occurring long-form contexts, excluding syn- thetic contexts and those lengthened through synthetic expansion. We allow contexts built by ap- pending real documents, as in the extended HotpotQA (Appendix A). This restriction focuses the analysis on realistic long-context inputs. Task requirements. We manually audit task definitions and exclude sources or subsets primarily targeting single-fact retrieval or span extraction. We prioritise tasks involving multi-hop reasoning, comparison, aggregation, or evidence integration. This screening operates at the source or subset level and does not require every retained instance to involve multiple reasoning steps. The retained tasks are listed in Table 3. Zero-context screening. We provide each question to Gemini 2.5 Pro without its accompanying context and discard instances answered correctly under the task’s evaluation criterion.
