D.3 DINOV2 CONTEXT A frozen DINOv2-B/14 encoder (Oquab et al., 2024) extracts conditioning-frame features, while a learned 128-D action GRU summarizes the intervening 14-D actions. For each of N task-configured sampled frames, the CLS and mean patch features are projected to 256 dimensions. The N −1 adja- cent visual–action transition features (640-D each) are concatenated; a 640(N −1)→1024→1024 MLP and final projection produce the 32-D context. Multiple conditioning-trajectory summaries are averaged before that final projection. At each training update, we sample a set of trajectories Qe from a training environment and select a subset Ce ⊆Qe for conditioning. All trajectories in Qe serve as training queries. The number of conditioning trajectories is sampled from the task- configured choices (typically one or two; one to four for Soft Pull), so the predictor learns to use different conditioning-set sizes. Every query in Qe is predicted using only the context inferred from Ce; training minimizes the mean query-video flow-matching loss. The context head, BWM DiT, action encoder, and two context projectors are trained jointly, while DINOv2 remains frozen. The model and context-head learning rates are 10−5 and 10−4, respectively. At test time, context comes from a forward pass over the observed test-time interaction trajectories, with no gradient update. D.4 TTT-KQV We adapt a video test-time-training fast-weight module (Dalal et al., 2025) to the BWM backbone. Gated two-layer GELU MLP modules with expansion factor four are inserted after eight approxi- mately evenly spaced attention blocks. Training randomly shuffles the chunks from each sampled environment in a batch. Within each training stream, all chunks use the same sampled flow-matching timestep (but independent noise), matching the same-timestep processing of observed interactions and query videos at inference. At position i, the preceding chunks form the observed prefix and the current chunk is the query. Fast weights reset to a learned shared initialization at the start of each stream. For each chunk, the module causally writes its key–value tokens before reading its output. Each query then takes an independent update–then–read branch on its own noisy tokens. Query ground truth never enters the update, and fast state is not carried between queries or denoising timesteps.
