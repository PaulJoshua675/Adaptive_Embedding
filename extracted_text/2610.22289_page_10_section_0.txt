The broad contract in Section 3 allows these different tasks to be exposed through the same interface. We distinguish the underlying benchmark from the environment defined for our experiments. An environment includes its environment description, comprising text and optional files; the dynamics that accept JSON actions, reject invalid requests, and return observation files; and its termination conditions. These choices define the environment, rather than merely documenting its implementation. Changing the ARC-AGI-3 description, omitting its PNG observations, or adding a direct exec action to Terminal-Bench would therefore produce a different environment specification, even with the same underlying task. Comparisons between agents keep the specification fixed. The following subsections describe these three elements for each setting. Appendix A reproduces the information supplied to the agent; we refer to those descriptions for the full instructions and action syntax rather than repeat them here. 5.1 ARC-AGI-3 One environment contains a single ARC-AGI-3 game, including its successive levels and attempts. Environment description. The same general description is supplied for every game. It explains the objective, action conventions, observation files, and reset behavior, but provides no game-specific mechanics or solution. It also encourages visual inspection of the observations. Appendix A.1 gives the complete description and identifies the supplied rendering helper. Dynamics and observations. The agent selects among the available game actions and receives the resulting visual frames and metadata. The full file inventory is given under “Provided Artifacts” in Appendix A.1. The important representational choice is to provide each frame both as exact ASCII color-index data and as a corresponding PNG image, including intermediate frames when present. This lets the agent process the frame numerically or inspect it visually, consistent with the visual nature of the task. The initialization files also include ascii_to_png.py, which the agent can use to render reconstructed or transformed frames. Supplying only ASCII, with or without a rendering helper, would be another environment version; we do not compare those representations here. Termination. The environment ends at WIN or when the current-level action counter exceeds 1,500. The counter includes RESET actions, spans all attempts at the same level, and is cleared when a new level is reached. We use the 1,500-action threshold discussed in Section 5.4, “Interaction rules and stopping conditions,” of our earlier study [9]. That budget is an evaluation choice, not a native ARC-AGI-3 limit, and may restrict games requiring longer exploration. A larger budget could be used in an evaluation aimed at maximizing performance, but would change the environment specification. 5.2 AGI Maze: single labyrinth One environment contains a single labyrinth. AGI Maze already supplies rules, task information, action identifiers, and textual feedback, so only a thin interface layer is needed. Environment description. The environment description combines AGI Maze’s own rule description with the labyrinth’s public task information, available actions, and public map. All of this information is provided by AGI Maze.
