A long-term agent accumulates records that may no longer describe its user. Residence, occupation, employer and preferences can change several times across sessions [1–3]. Earlier records still matter when a question refers to the past. The agent therefore needs to know which version applies to the question, including whether the latest record is relevant at all. Suppose a user moves from Shanghai to Chengdu and then to Suzhou. Suzhou answers “Where does the user live now?” The question “Where did the user live before moving to Chengdu?” requires Shanghai. A memory that keeps only the latest address cannot answer both. Keeping all three addresses makes the historical answer available, but the model still has to identify the right one. Persistent memory, action feedback and experience-based reflection have extended agents’ use of past interactions [4–6]. Work on hierarchical storage, memory updates, associative retrieval and temporal graphs has also improved access to this information [7–14]. Repeated updates pose a particular problem: several retrieved values may be equally relevant to a question yet refer to different states. We examine how the memory can convey these version relationships to the answering model. TEM records cross-session changes as fact versions without retraining the backbone. New facts are appended, and the status of earlier records is updated from their source order. At query time, relevance scores select the evidence. TEM then orders the selected facts by source and labels historical versions. This separates evidence selection from the presentation of temporal information. Event memory and original turns supply details that the fact records do not capture. Our contribution is a history-preserving update rule that assigns state over complete fact-version groups. The evidence construction procedure carries this status into retrieval output, so an older record stays historical when the latest version is not retrieved. We evaluate both components across multiple backbones and examine hybrid memory on public multi-session questions.
