Retrieval is a central component of retrieval-augmented generation (RAG), where external evidence is retrieved to support large language model (LLM) outputs [1]. It also supports LLM agents and long-term memory systems by identifying relevant documents, passages, or stored facts. Dense retrieval embeds queries and passages in a shared vector space and ranks candidates by vector similarity [2]. This approach is effective when supporting evidence is semantically close to the query, but may miss relevant passages connected through intermediate entities or multi-step relations. Knowledge graphs represent these connections explicitly, but using them for retrieval introduces two challenges. Traversing or reranking the graph for every query increases query-time complexity, while modifying embeddings according to graph structure may distort the semantic relationships captured by the original embeddings. This leads to the central question of this work: can graph structure be incorporated offline into graph-modified embeddings that improve retrieval without requiring graph access at query time or replacing the original embeddings? Prior work has either incorporated relational knowledge into embeddings [3, 4, 5], used graphs directly at query time [6, 7], or refined retrieval through textual feedback alone [8, 9, 10]. Our work connects these directions by examining both how graph-modified embeddings should be constructed and how they should be used in multi-stage retrieval. We construct graph-modified embeddings offline using several transformations, including local neighbourhood aggregation, random-walk endpoints, community centroids [11], and convex neighbour pull. We then compare retrieval strategies ranging from replacing the original embeddings with graph-modified embeddings to multi-stage strategies that combine both.
