Bidirectional attention. Both generators denoise all visual tokens jointly with bidirectional self- attention, so every query can attend to every frame. The order therefore depends only on the latent grid and not on a generation schedule. We compute it once per resolution and reuse it for all routed layers, heads, noise levels, and rollouts. Reordering inside attention. The order acts only inside each routed self-attention layer. After the native projections, query-key normalization, and rotary position embedding where the generator uses one, we permute the queries, keys, and values into Gilbert order. We then apply the routed mask and permute the output back to raster order. Dense attention is equivariant to a shared permutation of its queries, keys, and values, and every positional signal is attached before the permutation. The reordering thus changes which token pairs share a routing decision, but it leaves positions and the dense computation unchanged. At inference, RPO runs the stock dense attention without any reordering. Each query block keeps its own block as its safety set, Sq = {q}, so every query token attends at least to the other tokens of its own patch. The candidate set Cq contains every other block of the image or video, in any frame. Because attention is bidirectional, a route can add context from earlier and later frames alike. Routing acts only on visual self-attention. Stable Diffusion 3.5 runs a joint attention over image and text tokens, and we route only the image-to-image pairs. Every pair that involves a text token stays dense, so each image query keeps the full text band in addition to its route. The second, image-only self-attention of Stable Diffusion 3.5 has no text band and relies on its route alone. Wan2.2 injects text through cross-attention, which is never routed. A.3 BLOCK COUNTS IN THE REFERENCE CONFIGURATIONS Table 2 reports the token grid, the block counts, and the routing options of both reference configura- tions. For Wan2.2, the video autoencoder compresses 13 frames at 704 × 1280 by a factor of 4 in time and 16 in space, and patchification halves each spatial side, which gives a 4 × 22 × 40 token grid. For Stable Diffusion 3.5, a 512 × 512 image gives a 32 × 32 image grid. The text tokens are never routed, so the counts exclude them. On Stable Diffusion 3.5, a sparse query block keeps its own block and one of seven candidates, so it sees a quarter of the image. On Wan2.2, it keeps its own block and one of 27 candidates, so it sees about 7% of the video. The dense option and the anchor layers keep the remaining computation dense.
