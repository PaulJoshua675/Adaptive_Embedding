We study the effect of RQ-VAE [19] codebook size on the semantic-ID hierarchy by comparing codebook sizes of 64, 128, and 256 with three quantization levels, while keeping all other settings fixed. The results characterize the trade-off between cluster purity and cluster fragmentation. As the codebook size increases, the available semantic-ID space grows from 643 = 262,144 to 2563 = 16,777,216, substan- tially exceeding the 44,446 catalog items. Consequently, larger codebooks produce increasingly fragmented clusters, reducing the number of items sharing the same semantic-ID prefixes. Table 5. In our benchmark construc- tion, we therefore use the codebook configuration size of 64 which provides the desired balance between semantic purity and cluster density. 8.0.2. Query Generation Methodology. Signature construction. For each semantic-ID prefix, we derive attribute signatures using combinations of masterCategory, subCategory, articleType, brandName, baseColor, gender, usage, price, and productDisplayName. We construct two comple- mentary signature sets. Discriminating signatures identify highly specific cluster characteristics, requiring at least 10% cluster coverage and 90% precision against the full cata- log; the top eight are retained based on exclusivity, pre- cision, and coverage. These signatures guide query gen- eration toward attributes that distinguish the target cluster from its siblings. Coverage signatures require at least 5% coverage and 50% precision, with the top 20 retained, and are used to ensure that queries collectively cover the ma- jor product types within the cluster. The primary product- type axis is selected as the most specific attribute whose dominant value provides the highest cluster purity, with masterCategory as the fallback. Query generation. For each qualified prefix, the Gemini prompt combines fixed generation instructions with cluster- specific evidence. The instructions require natural and complete-sentence queries, coverage of all product types accounting for at least 5% of the cluster plus a catch-all for minority types, and discrimination from sibling clusters. Queries are grounded in productDisplayName and de- scription language while avoiding queries based solely on an attribute value unless that value is shared by all clus- ter items. The prompt further provides the major product types and their frequencies, sibling-level attribute contrasts, and a structured DATA CONTEXT containing the prefix metadata, attribute signatures, attribute distributions, parent statistics, and sibling differences.
