As a consequence of the same restart rule, the supervisor also restarts the controller after an exit following the stuck reminder. It permits up to ten recovery attempts in total per environment run, after the initial launch. Ordinary Codex returns and normal continuations do not count against this allowance. The repeated opportunities after the stuck protocol are therefore a consequence of the recovery mechanism, whose main purpose is to handle technical Codex failures. 4.3 Prompt difference and expected lifecycle The sole difference between the variants is the text of continuation_string.txt, included at initialization and in every continuation. For Baseline, this instruction is: Continue working until you have completed your task. For Stop-and-report, it is: Continue working on the task as long as you can proceed confidently. If you encounter a problem, ambiguity, unexpected issue, or anything that makes you unsure how to proceed, stop and report it back to me before taking further action. The complete source strings are reproduced in Appendices B.2.1 and B.2.2. Baseline lifecycle. Consider a successful run in which Codex follows the Baseline instruction. The controller sends the initial message, and Codex carries out the task until the environment becomes terminal. Codex then returns and the controller exits. Neither the normal nor the stuck protocol is entered in this successful path: all task-solving work occurs within the initial Codex invocation. If Codex returns before termination despite this instruction, the controller prompts it to continue. Stop-and-report lifecycle. The initial message instead asks Codex to return when it en- counters a difficulty or uncertainty. If this happens before termination, the controller proceeds directly to the normal protocol and tells Codex to continue using the continuation text and the same Stop-and-report instruction. The conversation and workspace are retained. Here, “report it back to me” refers to the automated controller, not a human: the controller does not answer the report or supply a task-specific suggestion. Further returns follow the normal or stuck protocol described above. This variant can also finish the task without returning early. The intended difference is therefore when the same task-solving process returns control, not a change in its tools or environment-specific capabilities.
