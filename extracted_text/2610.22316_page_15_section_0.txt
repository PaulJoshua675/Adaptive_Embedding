A PREPRINT A Implementation Details A.1 Training Details Single agent and multi-agent experiments share the same training setup. During training, the steering agent is initial- ized from Qwen3-8B (Yang et al., 2025). The backbone of the execution agent system is Qwen2.5-7B-Instruct (Qwen et al., 2024), which is served separately and excluded from parameter updates. We train with AdamW (Loshchilov & Hutter, 2017) at a learning rate of 2 × 10−5 and a batch size of 64 tasks for 300 steps. The task reward R, first defined in Section 3.2, is instantiated as answer token F1 multiplied by a trajectory-format indicator. The F1 term measures the word-level overlap between the predicted and the reference answers, and the indicator is 1 when every executor turn commits exactly one well-formed action tag and 0 otherwise. The remaining reinforcement learning hyperparameters follow the defaults of the ASearcher framework. Each task performs m = 2 selection rounds over the state bank, and each round selects up to k = 3 states. Each selection takes a uniformly random state with probability εsel = 0.25 and otherwise the state with the highest steering priority. Every selected state receives its full group of G = 4 steering actions. Each steered and unsteered state is evaluated by N = 2 executor continuations, whose means give ¯Rs,j and the baseline bs in Equation 7. All new states reached by the continuations are added to the state bank. We train on ASearcher-Base-35k (Gao et al., 2025), a challenging QA dataset constructed from filtered open-source multi-hop questions and agent-synthesized QA pairs. The training environment is the same local retrieval server as the in-domain evaluation, using the 2018 Wikipedia dump (Karpukhin et al., 2020) as the information source and E5 (Wang et al., 2022) as the retriever. A.2 Evaluation Details We follow ASearcher (Gao et al., 2025) to report token F1 on the in-domain benchmarks, and Avg. is the mean over the seven benchmarks. Out-of-domain evaluation runs every question 4 times and reports Avg@4, the mean accuracy over the four runs, and Pass@4, the fraction of questions solved in at least one run. We follow ASearcher to judge answer correctness on these benchmarks with an LLM (Qwen3.8-max (Yang et al., 2025)) as judge, and the judge prompt template is listed in Appendix C. The in-domain evaluation data of ASearcher (Gao et al., 2025) includes seven retrieval-augmented QA benchmarks, totaling 6,125 questions with 1,000 sampled questions from each benchmark and the full 125 questions of Bam- boogle. 2WikiMultiHopQA (Ho et al., 2020) builds multi-hop questions from Wikipedia and Wikidata with annotated reasoning paths. HotpotQA (Yang et al., 2018) contains two-hop questions that bridge or compare Wikipedia entities. Bamboogle (Press et al., 2023) collects hand-written compositional questions that a standard search engine answers incorrectly. MuSiQue (Trivedi et al., 2022) composes questions of two to four hops from single-hop ones with stricter connectivity requirements. Natural Questions (Kwiatkowski et al., 2019) contains real search-engine queries answered by Wikipedia. TriviaQA (Joshi et al., 2017) contains trivia questions authored by quiz enthusiasts. PopQA (Mallen et al., 2023) probes long-tail entity knowledge with templated questions built from Wikidata triples. The out-of-domain evaluation uses three benchmarks that require deeper search over the open web. Frames (Krishna et al., 2025) contains 824 questions that combine multiple constraints and typically require evidence from several Wikipedia articles. GAIA (Mialon et al., 2024) is a general assistant benchmark, from which we evaluate the 103 text-only questions of its validation split. xBench-DeepSearch (Chen et al., 2025a) contains 100 questions targeting the deep-search ability of agents. These evaluations use an online search engine. A.3 Baseline Design The planning, verification, and filtered behavior cloning baselines use the same supervisor backbone, and the trained variants reuse the reinforcement learning algorithm, data, and hyperparameters for a fair comparison. The comparison therefore isolates the supervision placement and the learning algorithm. Planning. The planning agent is triggered once before the executor’s first action. It reads the same task requirement as the steering agent and writes a plan that the executor keeps in view for the whole task. Verification. The verification agent is triggered after the executor commits an answer and decides whether the sub- mission stands. It either passes the answer or rejects it with feedback. The feedback is read by the executor agent as a tool-return, and the executor revises and resubmits. After three rejections the latest answer is delivered without further review. 15
