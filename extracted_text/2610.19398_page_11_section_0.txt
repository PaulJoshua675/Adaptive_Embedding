RCER uses the same Qwen3.8-27B model with separate prompts for acquisition, selection, and answering. Starting from four retrieved passages, each acquisition call analyzes the accumulated evi- dence and query history, then proposes a query to retrieve two new passages for the next call. After at most four additional rounds or an early stop for query repetition, the model produces cross- evidence inferences and five selected passages, then uses both in a separate answering call. Experiments were conducted on a server equipped with eight NVIDIA RTX 3090 GPUs. Table 10 gives the shared models and RCER set- tings. Dense retrieval uses cosine similarity be- tween normalized embeddings. Passage inputs contain the title and original text. Subsequent re- trieval excludes previously retrieved passage iden- tifiers. The repetition check compares lowercase query word sets with all earlier queries, including the original question. Each acquisition request includes the original question, all accumulated passage texts, the source catalog, the latest passage identifiers, and the query history. Relational analysis is generated afresh from these inputs at each round. The final se- lector independently analyzes the completed can- didate pool and returns its analysis followed by five distinct, increasing passage indices through constrained decoding. The answer generator re- ceives the five selected passages and this final analysis, which can also retain relationships from unselected candidates. All modules use visi- ble structured analysis with the model’s separate thinking mode disabled.
