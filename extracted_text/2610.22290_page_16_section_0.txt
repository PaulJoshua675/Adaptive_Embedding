B.3 Implementation and training configuration We implement training using veRL (Sheng et al., 2025) as the distributed RL framework, integrated with Trinity-RFT (Pan et al., 2025) to support the combination of on-policy GRPO updates with the supervised replay loss. We use vLLM (Kwon et al., 2023) for rollout generation. All model parameters are trained on four NVIDIA A100 80 GB GPUs, with two allocated to policy optimization and two to rollout generation. For a consistent comparison, all methods use the same BIRD training data and are trained for 100 steps, with the principal shared settings summarized in Table 5. Each baseline fol- lows its respective training objective, specifically: MaxRL. MaxRL uses the same rollout groups and clipped policy objective but replaces GRPO’s standard-deviation normalization with mean- reward normalization: AMaxRL i = ri −¯r ¯r + ϵ , ϵ = 10−6. These advantages are used directly, without a sub- sequent GRPO standardization. MaxRL uses no replay or additional reference-model KL penalty. SetPO. We combine GRPO advantages with the authors’ set-level diversity marginals: ASetPO i = AGRPO i + λsetmi, where λset = 0.05 and the marginal-scoring pa- rameter is τ = 1.0. Marginals are computed within each eight-response group using embeddings from the frozen Qwen3-Embedding-0.6B model. DPH-F. We first sample eight responses from the frozen base model for each training question. Ques- tions for which all eight responses are correct are eligible for preservation. We then draw an indepen- dent reference response for each eligible question; questions whose reference response is incorrect re- turn to the exploration partition. This procedure yields 301 preservation questions and 4,699 explo- ration questions. Reference response tokens and base-model token log probabilities are cached. Training combines GRPO on the exploration par- tition with forward-KL preservation on 128 cached reference responses per iteration, using coefficient β = 0.01. We retain the released low-variance token-level KL estimator rather than replacing it with supervised cross-entropy. Both archives contain 1,500 verified responses. B.4 Evaluation datasets and correctness checks Text-to-SQL. We evaluate on BIRD dev (1,534 questions) and Spider 1.0 dev (1,034 questions). For each model and question, we draw n = 128 samples using temperature 1.0 and top-p 0.95. SQL correctness is determined by executing the generated and gold queries on the benchmark database and comparing their results. Invalid or non-executable queries are counted as incorrect. Execution accuracy establishes correctness on the given database, not equivalence on all possible databases. MATH-500 and AmbiQT.
