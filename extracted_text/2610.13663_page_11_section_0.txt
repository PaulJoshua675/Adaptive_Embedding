A Multi-Agent LLM System for Automated Tuning 4.4. Search baselines and budget: SNN decoder on MNIST The quality reached by the framework depends both on the search performed by the LLM Analyst and on the constraints that the Human Researcher writes into the prompt. To separate these two contributions, we compare the framework with baselines that search the same space of decoders without an Analyst. All comparisons in this subsection are performed on MNIST, where the argmax baseline gives 79.88 %. Shared search space. The decoder catalog is a fixed discrete space of estimators with grids of their hyperparameters, together with the operators that build ensembles and multistage pipelines. It is specified once as a TPOT config_dict that is listed in Supplementary Section E.2 and its classes follow the decoder taxonomy of the detailed Analyst prompt (Section 4.3, Supplementary Materials). The Analyst prompt permits exactly the decoders contained in the catalog. The restriction reaches the systems in different ways: the agent receives it as text and can in principle depart from it, whereas the baselines receive it as a constraint on the sampler. We inspected the Experiment logs of all agent runs and found no record outside the catalog. The space of admissible decoders is therefore common to all systems, and they differ in the search strategy and in the selection protocol described below. Compared configurations. Three baseline configurations are compared with the framework, each with a budget of 250 evaluated decoders per run. • Random Choice is an LLM-based sampler that draws decoder configurations from the same catalog through independent calls to Qwen3-30B-A3B-Instruct-2507 deployed on a rented GPU, without a Chain-of-Thought stage and without a debugging cycle. Each call receives a compressed description of the catalog and returns one decoder configuration in JSON, sampled independently of the previous choices. The configuration is implemented and evaluated by the same sandboxed pipeline as an agent hypothesis. A call that yields a configuration outside the catalog, a configuration that fails the functional test, or a repetition of a configuration already recorded is discarded and does not enter the Experiment log. Calls are issued until the Experiment log contains 250 evaluated decoders. • TPOT Olson, Bartley, Urbanowicz and Moore (2016) classic is the standard genetic algorithm with a population of 25 individuals and 9 generations, which together with the initial population gives 25×(9+1) = 250 evaluated candidates. • TPOT sequential uses a population of one individual and 249 consecutive generations, 1 × (249 + 1) = 250 candidates, so that the budget is preserved while population-level exploration is replaced by a single mutating lineage. In both TPOT modes the search may combine models and build multistage processing sequences, because the corresponding operators are part of the catalog. TPOT samples and mutates pipelines according to its internal grammar, whereas Random Choice draws every configuration independently under an instruction to sample uniformly over the catalog. Budget. For the framework, the budget is the number of successfully evaluated records with the OK status. Records with the With error status remain stored in the complete Experiment log but do not count toward the budget and are excluded from the filtered log view passed to the Analyst. For Random Choice, the budget is the number of successfully evaluated decoder records; invalid calls discarded as described above do not count toward it. For TPOT, the budget is the number of fitted pipelines reported by the optimizer. In every configuration the budget is 250 per run, and every configuration was run 10 times. Within one run we take the best accuracy over the 250 evaluated decoders and the position at which it was first reached; Table 3 reports the smallest and the largest of these ten per-run values. Selection and evaluation. The baselines were run on the same trained SNN instances and the same output spike matrices as the prompt comparisons of Table 2, so every baseline run is matched with the corresponding agent run and the comparison is paired. The internal scoring rules of the compared systems are not identical. In the framework and in Random Choice, a candidate is scored on a validation set formed from the training set, and the value entered in the Experiment log (for the Analyst) is the mean over three random seeds. The held-out test set is not available to the Analyst (Section 4.5). TPOT selects its best pipeline by mean accuracy in five-fold cross-validation on the training set, after which the selected pipeline is retrained on the entire training set and evaluated once on the test set.
