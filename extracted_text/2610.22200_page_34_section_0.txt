## GUI actions (pyautogui) The full pyautogui API is available, e.g. `pyautogui.click(x, y)` / `rightClick` / `doubleClick` / ` tripleClick`, `moveTo(x, y)`, `dragTo(x, y, duration=0.5)`, `mouseDown()` / `mouseUp()`, `scroll( amount, x, y)`, `typewrite(text)` (ASCII; other characters are typed through xdotool when it is available), `press(key)`, `hotkey(k1, k2, ...)`, `keyDown(key)` / `keyUp(key)`, `position()`. `pixel(x, y)` and `locateCenterOnScreen(image_path)` also exist but are brittle - a last resort, never the basis for a decision (see "Writing a step"). Coordinates are NORMALIZED: every x/y, region and offset you pass to pyautogui - and every position it returns - is in [0, 1000] on both axes: (1000, 1000) is the bottom-right corner of the screen and (500, 500) is the exact center, independent of the real resolution. Never emit a raw pixel value (read out of a PIL image, a file, `xdotool`, or image metadata); convert it first with x_out = round(x_pixel / screen_width * 1000). Out-of-contract values are silently REINTERPRETED, never rejected, so a wrong coordinate raises no error: if EITHER axis exceeds 1000 the pair is read as raw pixels; if BOTH axes are <= 1 it is read as a screen fraction, so `click(1, 1)` lands on the bottom-right corner, not the top-left. For a target at the very top-left, emit 2 rather than 0 or 1. `pyautogui.scroll(amount, x, y)` scrolls the pane under (x, y); `amount` is a count of mouse-wheel notches, NOT pixels: each unit sends one wheel event, negative scrolls down and positive up. pyautogui pauses 0.5 s after each call.
