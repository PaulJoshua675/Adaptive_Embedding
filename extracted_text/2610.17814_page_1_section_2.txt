Both may retrieve the correct knowledge-base entry. The decision to organize the complete item remains different (Figure 1). Conversely, an emerging event can warrant organization before any corresponding entry exists. Before asking which event an item refers to, we first ask whether the item should enter the event- organization pipeline at all. We call this decision item-level event admission. In pipelines that use large language models for extraction and candidate assessment, processing non-admissible items still consumes retrieval and inference resources. Better linking alone does not resolve which items warrant that processing. Evaluating this admission boundary is therefore part of assessing how open- Web information is organized. Event-linking evaluation starts from selected mentions and asks which target each refers to, including NIL when no target is avail- able [10, 17, 26]. Admission starts earlier, with the incoming Web item. This change of unit exposes a measurement problem: a pipeline must first extract candidates or construct features before it can produce an admission score. A direct strategy can score the item without those steps. Given the same 100 inputs, one system might score all 100 while another scores only 80. Their AUCs summarize different populations. The missing 20 items disappear from the second ranking metric but remain part of the stream the system must process. This selection also limits the decisions a system can make. Sup- pose only ten of twelve qualifying development items receive scores. Even admitting all ten cannot meet a 90% full-stream retention tar- get. Lowering the threshold affects scored items, not the two lost upstream. Conversely, recovering their scores exposes additional inputs to the decision rule, including inputs that should be rejected. Better upstream processing can therefore change operational er- rors without improving the ranking metric or selecting a suitable threshold. For Web monitoring and event organization, the rele- vant outcome is what enters the organized stream, not just how successfully scored items are ordered. We evaluate these dependencies together. The scored population is treated as a system outcome.
