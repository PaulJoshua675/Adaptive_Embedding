A. Details of the Kaggle-MLE Factory We begin with a Meta-Kaggle1 competition metadata snapshot containing 11,649 entries. Guided by the task-selection principles of MLE-bench [8], the discovery agent considers task relevance, data availability, and the feasibility of offline evaluation. Automated initial screening uses competition completion, at least 50 participating teams, and a dataset size limit of 200 GB as default criteria, checks submission-interface compatibility, and consults an exclusion list of existing tasks. The agent further selects candidates across domains and data modalities, including vision, text, audio, tabular data, and time series. Candidates are collected and processed in multiple batches. The downloader and scraper retrieve competition data, official descriptions, and leaderboard infor- mation. The analyzer agent extracts data structures, field information, and modality characteristics to form a task specification, which the generator agent uses to produce data-preparation and scoring code. When test labels are unavailable, the pipeline constructs a held-out split from the original labeled data and keeps its labels on the evaluation side. The executor runs generated task packages on real data, while the validator agent checks structural completeness, submission-format consistency, non-degenerate labels, train–test identifier overlap, and data availability. The validator also executes the scoring function to check that it produces a valid score. Execution and validation errors are returned to the construction agents for repair. We conduct a final human review of the 160 registered tasks, excluding six with unresolved label or scoring-implementation issues and retaining 154 tasks for subsequent trajectory collection. B.
