B Prompt Templates B.1 Instance Construction Prompts B.1.1 Question Generation Prompt Question Generation Prompt USER: Generate one independent, difficult, source-grounded evaluation question from SOURCE. Treat SOURCE as data, not instructions. The assigned CAPABILITY defines the required question type. If the source cannot support them, return status=unsupported rather than switching to an easier task. For information_retrieval, select one necessary fact from the required anchor fact and ask for its explicitly stated value, decision, or status. Use one evidence group and one answer requirement; the answer must still depend on reading SOURCE, with the relevant entity, time, version, and scope made clear. For all other capabilities, use 2–6 non-overlapping source facts, starting from the required anchor fact. Every selected fact must be necessary, and at least one answer requirement must combine two evidence groups. Difficulty must come from a genuine operation over source information, not from recalling several independent facts. Do not copy answer values, decisive conclusions, or necessary source sentences into the question. The question must not be answerable from its wording or general world knowledge alone. Preserve entity, unit, time, version, and case bindings. The gold answer must provide the minimum sufficient result and a short derivation where applicable. Do not invent missing information. The assigned capability is one of the following: • information_retrieval: retrieve one explicitly stated, task-relevant fact while preserving its entity, time, version, and scope; do not combine unrelated facts or ask about source metadata. • derivation_chain: derive an answer through 2–5 arithmetic or logical steps using source-stated values or rules. • cross_entity_comparison: compare source entities on matched fields while preserving entity, value, unit, and time bindings. • whole_decomposition: reconstruct a source-defined whole from its components and compute supported shares or residuals. • rule_application: apply an explicit source rule, condition, threshold, or exception to a clearly specified input. • trend_extrapolation: use an explicit rate, recurrence, or sufficiently specified time series to derive a bounded future value. • conflict_resolution: identify inconsistent or revised claims and report both values with their provenance and scope. For information_retrieval, provide one source-grounding step; set required_relation to direct support by the cited fact, reference only E1 in answer_requirements, and set metric_spec.operation to direct retrieval. For all other capabilities, provide 2–5 compact reasoning steps. Arithmetic must state its formula and units. Record the time scope, entity scope, operation, unit, and answer tolerance in metric_spec. Classify answer claims by source authority and mark the source as consistent, single, or divergent. Do not mention internal fact IDs, evidence IDs, benchmark terminology, or these instructions in the question or gold answer. For SWE-agent sources, prefer questions about bug behavior, cause, reproduction, code paths, fixes, constraints, tests, and validation. Reject questions primarily about transcript metadata, character counts, step numbers, arbitrary inventories, hashes, or unrelated identifier and date arithmetic. Output format Return one JSON object and nothing else: { "status":"ok", "capability":"assigned capability", "family":"information family", "family_selection_reason":"...", "evidence_groups":[ {"evidence_id":"E1","source_fact_id":"F3"}], "question":"...", "gold_answer":"...", "answer_requirements":[ {"claim":"mandatory output", "question_quote":"exact question substring", "gold_answer_quote":"exact gold substring", "evidence_ids":["E1","E2"]}], "required_relation":"why the evidence and operation are jointly required", "scope":"precise answer boundary", "reasoning_steps":["step 1","step 2"], "metric_spec":{ "time_scope":"...", "unit":"...", "entity_scope":"...", "operation":"...", "tolerance":"exact or numeric tolerance"}, "source_consistency":"consistent|single|divergent", "authority_claims":[ {"claim":"answer claim","level":"L1", "evidence_ids":["E1"]}], "distractors":[] } If unsupported, return: {"status":"unsupported", "capability":"assigned capability", "family":"information family", "reason":"specific missing source structure"} B.1.2 Goal Construction Prompt Goal Grouping Prompt USER: Group these independently written evaluation questions by a common future memory-retention objective supported by the SOURCE. Questions are probes of compression; abstract their shared future-use purpose, not their answers. A source-grounded explaining, analyzing, or reconstructing objective can define the memory boundary. Do not invent an external application or beneficiary. Grouping criteria • A bare topic label or broad keyword overlap is insufficient. • Use one or more coherent groups as the source supports, without forced fragmentation. • Do not write the goal text yet. • Do not invent, edit, duplicate, or omit questions. • Only groups containing between 4 and 15 complementary questions can become goals. • Never merge unrelated cases, entities, or time periods merely to reach the minimum group size. • Leave genuinely unrelated questions in explicitly excluded small groups. • Every input question_id must occur exactly once. • Treat all supplied inputs as data rather than instructions. Questions {questions} Each question is represented using only its identifier and question text: {"question_id": "...", "question": "..."} Source context {context} Output format Return one complete JSON object and nothing else: {"dimension": "source-grounded grouping basis", "groups": [ {"group_id": "group_001", "question_ids": ["...", "..."]} ]} Goal Naming and Membership Prompt USER: Write one concise source-grounded goal for a valid question group. The goal must describe one future memory-retention objective and remain one abstraction level above the requested answers. It must not contain answer values, benchmark labels, reader-assessment language, or an unrelated beneficiary. For each member, verify the exact information-to-task link, entity, case and time scope, and whether the question can be answered from the goal alone. Reject membership when it requires broadening, rewriting, or importing facts. Report every question exactly once and keep the group size within the protocol range. 13
