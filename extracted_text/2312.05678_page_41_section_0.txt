Losses using the scores described in Sections 4.1.1 and 4.1.2 have analytical minimizers, shown in Appendix C; thus, Bayes estimates under these scores can be found through an indexing of the weighted losses. Our Python implementation uses these analytical solutions or, for other scores, the low-memory Broyden-Fletcher-Goldfarb-Shanno (L-BFGS) minimization algorithm available in SciPy (Virtanen et al., 2020). The principal parameters of Algorithm 3 are h0, the number of MCMC draws for repre- senting p(γ|dprior), and h1, the number of data sets to simulate. Computational experiments show it is beneficial to expend more resources on Γ0 than Γ1; see Wickett (2024) for the impact of different h0 and h1 choices on utility estimates. Low values for h0 induce bias: iden- tified minima insufficiently account for a full representation of p(γ|dprior), such that the true expected loss is underestimated. This bias will tend to increase with larger PMS budgets, as the Bayes estimate is more likely to move to areas of the parameter space less represented in Γ0. Low values for h1 induce variance: the range of possible data sets is insufficiently explored. We suggest choosing h0 as large as computational resources will allow, and h1 as large as needed to meet variance tolerance. Algorithm 3 runs significantly faster than the MCMC integration of Algorithm 2. The execution of full MCMC integration needs multiple hours; this efficient implementation cal- culates around four simulated data sets per second for our case study. Our case study uses h0 = 75, 000 and h1 = 2, 000, as these values produce consistent allocation decisions (Wick- ett, 2024). This processing rate means utility estimation takes about 10 minutes on a laptop with an Intel Core 1.6GHz processor. B.3 Using importance sampling to reduce bias and variance The quality of utility estimates produced through the efficient estimation algorithm is im- pacted by four key factors: the size of the set of MCMC draws from p(γ|dprior), h0; the size of the set of MCMC draws simulating data sets, h1; the number of nodes, |A| + |B|; and the number of tests in a prospective sampling plan, N (Wickett, 2024). A sufficiently high number of nodes or number of tests means a small subset of SFP-rate vectors in the MCMC set will have a large impact on the resulting loss estimate, i.e., the significant region of SFP rates will be underrepresented. The significant region of SFP rates can be be better represented through importance sampling. We form loss estimates through an additional MCMC set of SFP-rate vectors better capturing this significant region, drawn using an “expected” set of traces and test results. These loss estimates are then adjusted to account for the oversampling of the sig- nificant region. Let dimp be the expected data set under sampling plan n.
