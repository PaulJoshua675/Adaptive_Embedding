Continual learning addresses sequential task acquisition without catastrophic forgetting [10], through methods such as Elastic Weight Consolidation [11], Learning without Forgetting [12], and Synaptic Intelligence [13]. These approaches assume a single, architecturally fixed model updated over time and therefore do not accommodate the architectural changes that accompany real-world watermarking updates. 3. Problem Formulation We first review zero-bit watermarking and then formalize the backward-compatibility objective on top of it. Zero-Bit Watermarking. Zero-bit watermarking aims to decide whether a digital signal contains a watermark. Given an input signal 𝑥∈𝒳, an embedder 𝐸produces a watermarked signal 𝑥𝑤= 𝐸(𝑥), where the perturbation 𝐸(𝑥) −𝑥is imperceptible. A detector 𝐷then produces a real-valued detection score 𝐷(𝑥𝑤) ∈R, with larger positive values indicating the presence of a watermark and smaller (negative) values indicating its absence. A binary decision is obtained by comparing the score against a threshold. The pair (𝐸, 𝐷) is typically trained end-to-end: the detector learns to distinguish watermarked from unwatermarked audio, while the embedder learns to introduce minimal perturbations that the detector can reliably detect. Backward-Compatibility Objective. We associate every training run with a discrete version index 𝑣. For the initial version, 𝑣= 1, a single pair (𝐸1, 𝐷1) is trained end-to-end. For each subsequent version 𝑣> 1, a new embedder 𝐸𝑣is trained jointly with a new detector 𝐷𝑣. The legacy chain at version 𝑣is the set of earlier embedders {𝐸𝑖: 𝑖< 𝑣}, minus a revocation set 𝑅of embedders deliberately dropped (e.g. a leaked one). The legacy chain is kept frozen during training, and 𝐷𝑣is trained against it together with 𝐸𝑣, so its compatible (in-chain) set is {𝐸𝑖: 𝑖≤𝑣} \ 𝑅. Every other embedder is out-of-chain: future versions 𝐸𝑗with 𝑗> 𝑣that did not yet exist, and any revoked 𝐸𝑖∈𝑅. Formally, the detector 𝐷𝑣at version 𝑣must satisfy: • 𝐷𝑣correctly detects watermarks produced by every embedder from set: {𝐸𝑖: 𝑖≤𝑣} \ 𝑅(high TPR within the chain). • 𝐷𝑣rejects raw audio (high TNR on clean inputs). • 𝐷𝑣rejects watermarks produced by any embedder outside its legacy chain (high TNR against out-of-chain embedders): both future versions 𝐸𝑗with 𝑗> 𝑣that did not yet exist at training, and any embedder from 𝑅. The last objective we refer to as the version boundary: the line a detector holds between the in-chain embedders it accepts and the out-of-chain ones it rejects, whether future or revoked. This is what distinguishes backward compatibility from standard multi-embedder training: an out-of-chain embedder is not merely absent, it must be actively rejected, which is precisely what makes revoking a leaked embedder possible. 3
