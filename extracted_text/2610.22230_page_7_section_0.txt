During a merge step, D.C. identifies deflated eigenvalues (which will not be modified by the merge) and updates all others by solving the secular equation. To improve data locality and reduce data movement, our implementation ensures that eigenvalues (and associated eigenvectors) are properly ordered. Eigenvectors belonging to identical eigenvalues require (possibly costly) extra preprocess- ing; rocSOLVER includes specialized code to efficiently handle matrices exhibiting several identical eigenvalues in merge steps. Lastly, newly and previously computed eigenvectors are merged using batched GEMMs for optimal performance. Distributed Shampoo partitions large precon- ditioner matrices into fixed-size blocks (typically 4096 × 4096 or 8192 × 8192) to bound per-GPU computation and enable parallel eigen decomposition across devices. These block sizes represent the practical sweet spot: large enough to preserve preconditioning quality, yet small enough for tractable eigen decomposition. rocSOLVER narrows the gap with cuSOLVER at these critical 4K and 8K dimensions, enabling competitive Shampoo-based training on AMD hardware. IV. KERNEL TUNING AND AGENTIC AI WORKFLOWS In this section, we first identify kernel optimization principles through case studies of key production kernels, and then encode them as reusable skills in an agentic AI workflow that scale to the long tail of model-specific operators. A. Triton Kernel Optimizations 1) Attention Kernels in DLRM: We focus on two important Triton kernels in Meta’s production DLRM workloads, GDPA and HSTU, and describe the AMD-specific optimization tech- niques that yield substantial speedups on MI350X. Generalized dot-product attention (GDPA). GDPA [40] extends standard attention [41,42] by fusing GeLU-activated attention and a feed-forward network into a single operator. Central to Meta’s Kunlun [43] and Interformer [44] models, the fused kernel substantially increases the compute and memory intensity, positioning the kernel as a critical optimization target. Hierarchical sequential transduction unit (HSTU). HSTU [21] is a novel sequential attention architecture designed for large-scale recommendation systems, where the input consists of variable-length user interaction histories with high sparsity. Unlike standard attention, HSTU uses variable-length batching and processes sequences with sparsity ratios as high as 0.95, meaning the effective computation is concentrated in a small fraction of the sequence. 2) Optimization Techniques: We apply five optimization techniques to the Triton kernels, each addressing a different performance bottleneck on the MI350X architecture. While we use GDPA and HSTU as examples, these optimization techniques are generally applicable to a broad set of Triton kernels for ML models. PID swizzle. MI350X features a multi-XCD (chiplet) archi- tecture where eight XCDs share an L2 cache. The default linear mapping of Triton program IDs to tiles can cause XCDs to access disjoint L2 cache regions, resulting in poor cache utilization. PID swizzle uses tl.swizzle2d to remap the two- dimensional program ID grid so that spatially adjacent tiles are scheduled on the same XCD, improving L2 cache locality. Occupancy hints. The waves_per_eu hint controls the max- imum number of wavefronts resident on each execution unit, which directly affects register allocation. By setting waves_per_eu=3 (GDPA) or exposing it as an autotunable parameter with values 0–4 (HSTU), the compiler reduces per- wavefront register usage, allowing more concurrent wavefronts to hide memory latency. This trades per-wavefront performance for higher occupancy, which is beneficial when the kernel is not fully compute-bound. MFMA instruction configuration. AMD CDNA architectures provide matrix fused multiply-add (MFMA) instructions in con- figurable tile sizes, controlled by the matrix_instr_nonkdim parameter. By setting matrix_instr_nonkdim=16, the system selects 16 × 16 MFMA tiles, which on CDNA 4 can achieve higher instruction throughput than the default 32 × 32 tiles for certain matrix shapes. Triton configuration autotuning. Triton kernel configurations (BLOCK_SIZE, num_stages, num_warps, etc.) are critical to performance, and optimal values differ between NVIDIA and AMD GPUs due to architectural differences. AMD’s 64-thread wavefronts, compared to NVIDIA’s 32-thread warps, favor larger num_warps values to achieve sufficient occupancy and hide memory latency. NVIDIA’s Tensor Memory Accelerator (TMA) on H100/B200 enables deep software pipelining (e.g., num_stages ∈[4, 7]) by efficiently managing asynchronous memory transfers. AMD MI350X lacks a TMA equivalent; high stage counts increase LDS pressure without commensurate latency hiding benefits. Empirically, AMD kernels achieve better performance with shallower pipelines (e.g., num_stages ≈2). GeLU fast math. The default fast_gelu implementation in Triton uses a tanh-based approximation, which on AMD GPUs decomposes into tanh(x) = 2σ(2x) −1, requiring a sigmoid evaluation (scaled by two) and additional arithmetic. We replace this with a direct sigmoid-based GeLU approximation using the compiler intrinsics fast_expf and fast_dividef, which map to single hardware instructions with better performance. 3) Performance Results: We evaluate these tuning techniques by incrementally applying them to the GDPA and HSTU forward and backward kernels.
