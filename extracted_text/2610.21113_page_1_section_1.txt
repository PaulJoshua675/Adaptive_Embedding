Recent advances in large language models (LLMs), in- teroperable agent protocols, and machine-readable capability descriptions are enabling multi-agent ecosystems in which autonomous agents can be dynamically discovered and orches- trated [1], [2]. Protocols such as the Model Context Protocol (MCP) and Agent2Agent (A2A) expose structured descriptions of tools and agents [3], [4]. In particular, A2A defines an Agent Card as a machine-readable description of an agent’s identity, capabilities, skills, interfaces, and related metadata [4]. We use Agent Card throughout this paper to denote such structured capability descriptions. A straightforward orchestration strategy is to present every available Agent Card to an LLM and ask it to select the most suitable agent. However, this full-catalog approach directly couples registry size to the amount of information presented to the LLM orchestrator. As the registry grows, more Agent Cards must be incorporated into the prompt, increasing context consumption, inference cost, and latency, while eventually reaching practical model or API limits. Related context-scaling concerns have motivated retrieval and candidate filtering in large tool collections [5]–[7]. Candidate pre-selection itself is therefore not new. Existing work has explored large-scale tool retrieval, context-aware filtering, learned routing, and relational tool–agent retrieval [5], [7]–[10]. Our focus is complementary: scalable agent discovery must account not only for retrieving relevant Agent Cards from a growing registry, but also for controlling the amount of candidate information ultimately presented to the LLM orchestrator. We formulate this systems problem as candidate-context scalability: registry-scale retrieval should remain operationally independent of the compact candidate context subsequently presented to the LLM. Under this formu- lation, retrieval may operate over the complete registry, while a maximum candidate budget K controls the number of top- ranked Agent Cards forwarded to the LLM orchestrator. This separation makes retrieval coverage, retrieval computation, and orchestration context distinct and independently measurable components of the discovery pipeline. To address this problem, we propose the Structural Signal Retriever (SSR), our deterministic and training-free retrieval method designed specifically for Agent Card discovery. SSR constructs an explicit retrieval representation directly from capability-bearing fields already present in Agent Cards. It deterministically derives structural lexical signals from these fields, weights matched signals using inverse document fre- quency (IDF), and uses an Inverted Signal Index (ISI) to restrict scoring to Agent Cards that share structural evidence with the user query. The resulting candidates are ranked and a compact pool of up to K top-ranked Agent Cards is presented to the LLM orchestrator for final agent selection. This design decouples the growth of the agent registry from the amount of candidate information processed by the LLM while preserving a direct correspondence between each retrieval score and the explicit Agent Card signals that produced it. The methodological contribution of SSR does not lie in IDF weighting, inverted indexing, or candidate pre-selection individually.
